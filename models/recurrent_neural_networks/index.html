Recurrent Neural Networks (RNNs)

A network with a memory: it reads a sequence one step at a time and carries a hidden state forward. Simple, and forgetful.

01 The idea

An RNN reads a sequence one item at a time. At every step it mixes the new input with a running summary of everything so far, the hidden state $h_t$, and passes that summary on to the next step.

Feed-forward networks see a fixed-size input all at once. Text, speech, sensor readings and prices arrive as sequences of any length, where order matters. An RNN handles this with one small trick: the same cell is applied at every step, and its output at step $t$ becomes part of its input at step $t+1$.

Think of $h_t$ as a short note the network keeps updating as it reads. With one hidden unit, $h_t = \tanh(w\,h_{t-1} + u\,x_t)$. If the recurrent weight $|w| < 1$, an input from 10 steps ago has been multiplied by $w$ ten times, so it fades: $0.8^{10} \approx 0.1$. If $|w| > 1$ things blow up (and tanh saturates). Training has the same problem in reverse: gradients flowing back through time shrink or explode, so vanilla RNNs struggle to learn anything that spans more than a handful of steps. That is the problem GRUs and LSTMs were built to solve.

In everyday terms

Reading a book while only allowed to keep a single sticky note: every page you overwrite a little of it, so early chapters slowly blur away.

02 How it works

  1. Start with $h_0 = 0$.
  2. At each step, combine the previous state and the new input: $h_t = \tanh(W_h h_{t-1} + W_x x_t + b)$. The same weights are reused at every step.
  3. Read out what you need: the last state $h_T$ for classifying a whole sequence, or every $h_t$ for tagging each step.
  4. Train with backpropagation through time (BPTT): unroll the loop into a deep network with shared weights and backpropagate through it.
  5. Clip gradients to stop explosions; use a GRU or LSTM when you need longer memory.

05 The maths

  1. The recurrence

    $$h_t = \tanh(W_h\,h_{t-1} + W_x\,x_t + b), \qquad \hat y = \operatorname{softmax}(W_o\,h_T + c)$$

    $W_h$, $W_x$ and $b$ are shared across all time steps, so the parameter count does not grow with sequence length.

  2. Why memory fades (and gradients vanish)

    $$\frac{\partial h_T}{\partial h_k} = \prod_{t=k+1}^{T} \operatorname{diag}\!\big(1 - h_t^2\big)\,W_h$$

    A product of $T - k$ matrices. If their size is below 1 the product shrinks exponentially with distance (vanishing); above 1 it grows (exploding). The lab shows exactly this product for a one-unit RNN.

07 When to use it

Strengths

  • Handles sequences of any length with a fixed number of parameters.
  • Small, simple and fast per step; natural for streaming data.
  • The conceptual base for GRUs and LSTMs.

Limitations

  • Short memory: vanishing gradients after roughly 10–20 steps.
  • Exploding gradients without clipping.
  • Sequential: each step waits for the previous one, so training does not parallelise over time.

Reach for it when

Short sequences, streaming or on-device settings where a tiny model matters, or to understand the ideas behind gated RNNs.

Think twice when

Anything that needs long-range memory; use a LSTM, GRU or Transformer.

08 In code

python
import torch, torch.nn as nn
from sklearn.datasets import load_digits

# read each 8x8 digit image as a sequence: 8 time steps, 8 pixels per step
digits = load_digits()
X = torch.tensor(digits.images / 16.0, dtype=torch.float32)    # (n, 8, 8)
y = torch.tensor(digits.target)

class RNNClassifier(nn.Module):
    def __init__(self, hidden=64):
        super().__init__()
        self.rnn = nn.RNN(input_size=8, hidden_size=hidden, batch_first=True)
        self.out = nn.Linear(hidden, 10)

    def forward(self, x):
        states, h_last = self.rnn(x)        # states: every h_t, h_last: final h_T
        return self.out(h_last[-1])

model = RNNClassifier()
opt = torch.optim.Adam(model.parameters(), lr=2e-3)
for epoch in range(30):
    opt.zero_grad()
    loss = nn.functional.cross_entropy(model(X), y)
    loss.backward()
    nn.utils.clip_grad_norm_(model.parameters(), 1.0)     # tame exploding gradients
    opt.step()

Common pitfalls

  • Forgetting gradient clipping and watching the loss jump to NaN.
  • Expecting a vanilla RNN to remember something from 50 steps ago.
  • Padding variable-length sequences and letting the padding flow into $h_T$; use packed sequences or masks.

09 Check yourself

Q1What makes an RNN "recurrent"?

Why: The loop $h_{t-1} \to h_t$ with shared weights is the defining feature.

Q2With a recurrent weight of 0.5, roughly how much of an input survives 5 steps later (ignoring tanh)?

Why: $0.5^5 = 0.03$. Memory fades geometrically.

Q3Why does a vanilla RNN struggle with long-range dependencies?

Why: Backpropagation through time multiplies many Jacobians together.

Q4Why does the number of learnable parameters in a vanilla RNN remain constant even when processing sequences of widely varying lengths?

Why: In an RNN, recurrence shares the parameter tensors across time: step 1 and step 100 use identical weights $W_h$ and $W_x$. Sequence length affects run time, not parameter count.

Q5Why is gradient clipping (such as clip_grad_norm_) commonly applied when training vanilla RNNs with Backpropagation Through Time (BPTT)?

Why: When eigenvalues of the recurrent weight matrix exceed 1, repeated multiplication over time steps causes gradients to explode exponentially. Clipping scales down the gradient vector whenever its norm exceeds a threshold, keeping optimisation stable.

Q6A single-unit RNN cell computes $h_t = \tanh(W_h h_{t-1} + W_x x_t + b)$. Given $W_h = 0.6$, $W_x = 0.4$, and bias $b = -0.1$, if the hidden state at step 1 was $h_1 = 0.50$ and the new input at step 2 is $x_2 = 1.5$, what is the pre-activation value before applying $\tanh$?

Why: The pre-activation is $W_h h_1 + W_x x_2 + b = (0.6 \times 0.50) + (0.4 \times 1.5) - 0.1 = 0.30 + 0.60 - 0.10 = 0.80$.

Q7Why cannot the forward training pass of an RNN over a sequence of length $T$ be parallelised across the time dimension on a GPU, unlike a Transformer?

Why: Because $h_t = f(h_{t-1}, x_t)$, step $t$ cannot begin until step $t-1$ has finished. This recurrence forces sequential computation along $T$, making vanilla RNNs and gated RNNs difficult to scale horizontally during training compared with non-recurrent attention architectures.

Q8In PyTorch's nn.RNN, calling states, h_last = rnn(x) on an input tensor with batch_first=True yields two outputs. For whole-sequence classification, which tensor is typically passed to the linear output classifier head?

Why: h_last[-1] contains the summary vector produced after consuming the entire sequence up to step $T$. For whole-sequence classification, this final state vector is projected through a linear layer to produce class logits.

Q9Under the standard recurrence equation $h_t = \tanh(W_h h_{t-1} + W_x x_t + b)$, an RNN cell processes an input vector $x_t \in \mathbb{R}^8$ with a hidden state vector $h_t \in \mathbb{R}^{16}$. How many total learnable scalar parameters are contained in $W_h$, $W_x$, and $b$?

Why: $W_x$ maps 8 inputs to 16 hidden units ($16 \times 8 = 128$ weights). $W_h$ maps 16 recurrent units to 16 units ($16 \times 16 = 256$ weights). The bias vector $b$ has 16 parameters. Total $= 128 + 256 + 16 = 400$ parameters.

Q10In a scalar RNN $h_t = \tanh(w h_{t-1} + u x_t)$ with recurrent weight $w = 1.0$, suppose the hidden unit reaches activation $h_t = 0.80$. What is the local gradient factor $\frac{\partial h_t}{\partial h_{t-1}} = (1 - h_t^2) w$ at this step?

Why: The derivative of $\tanh(z)$ with respect to its pre-activation is $1 - \tanh^2(z) = 1 - h_t^2$. With $h_t = 0.80$, this gives $1 - 0.80^2 = 1 - 0.64 = 0.36$. Multiplying by $w = 1.0$ yields $\frac{\partial h_t}{\partial h_{t-1}} = 0.36$, demonstrating how even non-decaying weights ($w=1$) suffer severe gradient vanishing when activations saturate.

Q11Consider a linearised 1-unit RNN where $\frac{\partial h_t}{\partial h_{t-1}} = 1.5$. Over a sequence of $T = 8$ backward steps, by what factor does the gradient grow before clipping is applied?

Why: By the chain rule across 8 unrolled steps, the backward gradient is multiplied by the transition factor at each step: $\prod_{t=1}^8 1.5 = 1.5^8 \approx 25.63$. A learner who mistakenly multiplies $1.5 \times 8 = 12.0$ overlooks the exponential nature of backpropagation through time.

Q12Why is the vanishing gradient problem in RNNs fundamentally harder to resolve during optimisation than the exploding gradient problem?

Why: Exploding gradients point in the correct descent direction, so renormalising them via gradient clipping preserves the update trajectory and prevents overflow. Vanishing gradients, however, decay exponentially toward machine precision ($\approx 0$), depriving the optimiser of any directional signal for long-range dependencies.
