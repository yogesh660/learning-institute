01 The idea

XGBoost is gradient boosting made precise and fast. It uses both the gradient and the curvature (Hessian) of the loss, and penalises tree complexity directly in the split gain.

Classic boosting fits a tree to gradients and then works out leaf values. XGBoost uses a second-order Taylor expansion of the loss, which gives a closed-form optimal value for each leaf and an exact formula for how much a split improves the objective, penalty included.

Two regularisers are built in: $\lambda$ shrinks leaf values (like ridge on the tree’s outputs), and $\gamma$ is a minimum gain required to make a split at all, so splits that do not pay for themselves are never made. Add column subsampling, sparsity-aware split finding for missing values, and a cache-aware implementation, and you get the library that dominated Kaggle for years.

In everyday terms

Boosting with a more careful editor: each correction is sized using both the slope and the curvature of the error, and small corrections that are not worth the ink are skipped.

02 How it works

  1. Compute gradients $g_i$ and Hessians $h_i$ of the loss for every row.
  2. Grow a tree level by level; for each candidate split compute the exact gain from sums of $g$ and $h$.
  3. Skip splits with gain below $\gamma$; set each leaf to $-G/(H+\lambda)$.
  4. Add the tree scaled by $\eta$; repeat with early stopping.

03 Try it

A small XGBoost-style booster written in the browser: second-order leaf values with $\lambda$, and splits pruned when gain is below $\gamma$.

Things to try
  1. Raise $\gamma$: watch the leaf count per tree fall as weak splits are refused.
  2. Raise $\lambda$: leaf values shrink, so each round moves the fit less.
  3. Compare final test RMSE at $\gamma = 0$ and $\gamma = 0.5$.

04 The maths

  1. Second-order objective for one tree

    $$\tilde{\mathcal L} = \sum_i \Big[g_i f(x_i) + \tfrac12 h_i f(x_i)^2\Big] + \gamma T + \tfrac{\lambda}{2}\sum_{j=1}^T w_j^2$$

    $T$ is the number of leaves and $w_j$ the leaf values. For squared error, $g_i = \hat y_i - y_i$ and $h_i = 1$.

  2. Optimal leaf and split gain

    $$w_j^* = -\frac{G_j}{H_j + \lambda}, \qquad \text{Gain} = \tfrac12\Big[\frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda}\Big] - \gamma$$

    $G$ and $H$ are sums of gradients and Hessians in a node. A split is kept only if its gain is positive.

06 When to use it

Strengths

  • Excellent accuracy on tabular data.
  • Built-in regularisation and missing-value handling.
  • Fast, parallel, GPU support, mature tooling.

Limitations

  • Many hyperparameters.
  • Level-wise growth can be slower than LightGBM on very large data.
  • Categorical features need encoding (native support is newer and more limited).

Reach for it when

Tabular competitions and production models where accuracy is the priority.

Think twice when

Tiny datasets or when a linear model is good enough and easier to explain.

07 In code

python
import xgboost as xgb

model = xgb.XGBRegressor(n_estimators=3000, learning_rate=0.03, max_depth=5,
                         subsample=0.8, colsample_bytree=0.8, reg_lambda=1.0, gamma=0.0,
                         early_stopping_rounds=100, eval_metric="rmse", random_state=0)
model.fit(X_tr, y_tr, eval_set=[(X_te, y_te)], verbose=False)
print("best iteration:", model.best_iteration)

Common pitfalls

  • Early-stopping on the test set you then report. Use a separate validation split.
  • Cranking up depth instead of rounds; deep trees overfit fast.

08 Check yourself

Q1What is $\gamma$ in XGBoost?

Why: It is subtracted from each split’s gain, so splits must improve the objective by at least $\gamma$.

Q2With squared error, the optimal leaf value $-G/(H+\lambda)$ reduces to:

Why: $h_i = 1$, so $H$ is the count; $-G/(n+\lambda)$ is the mean residual with ridge-like shrinkage.

Q3What mathematical expansion enables XGBoost to compute optimal leaf weights and split gains in closed form?

Why: XGBoost approximates any smooth convex loss by $\mathcal{L} \approx \sum [g_i w + \frac{1}{2}h_i w^2] + \Omega(w)$. Differentiating this quadratic with respect to leaf weight $w$ yields the analytical closed-form solution $w^* = -G / (H + \lambda)$.

Q4How does XGBoost handle missing values in input features during training and prediction?

Why: XGBoost only scans non-missing values to calculate gradients, then evaluates placing missing values into the left or right node. The direction with maximum gain becomes the default path, handling missingness natively without imputation.

Q5What is the role of the regularisation parameter reg_lambda ($\lambda$) in XGBoost?

Why: In the optimal leaf weight formula $w^* = -G / (H + \lambda)$, $\lambda$ acts as Ridge regularisation in the denominator, dampening leaf values especially when sample size $H$ is small.

Q6For squared error loss $L(y_i, \hat{y}_i) = \frac{1}{2}(y_i - \hat{y}_i)^2$, what are the gradient $g_i = \frac{\partial L}{\partial \hat{y}_i}$ and Hessian $h_i = \frac{\partial^2 L}{\partial \hat{y}_i^2}$ for an observation with residual $e_i = y_i - \hat{y}_i$?

Why: $\frac{\partial \frac{1}{2}(y_i - \hat{y}_i)^2}{\partial \hat{y}_i} = -(y_i - \hat{y}_i) = -e_i$. Differentiating again with respect to $\hat{y}_i$: $\frac{\partial (-y_i + \hat{y}_i)}{\partial \hat{y}_i} = +1.0$. Thus the Hessian sum $H$ simply equals the number of samples in the leaf ($n$).

Q7What is "column subsampling" (colsample_bytree and colsample_bylevel) in XGBoost, and what benefit does it provide?

Why: Borrowing from Random Forests, column subsampling introduces diversity across boosted trees by restricting feature consideration, reducing correlation and protecting against overfitting dominant features.

Q8In the split gain formula $\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{G_P^2}{H_P + \lambda}\right] - \gamma$, what happens if the calculated Gain is negative?

Why: $\gamma$ specifies the minimum gain required to split a node. If the improvement in loss (the bracketed term) does not exceed $2\gamma$, Gain is negative and the split is not made.

Q9Why does XGBoost use "approximate quantile sketching" instead of exact greedy split searching on very large datasets?

Why: Sorting billions of floats in memory is a massive bottleneck. XGBoost's weighted quantile sketch constructs candidate split points based on Hessian-weighted distributions, evaluating only a fixed number of bins per feature.

Q10In a regression leaf with L2 regularisation $\lambda = 2.0$, the sum of sample gradients is $G = -18.0$ and the sum of Hessians is $H = 7.0$. What is the optimal leaf prediction weight $w^* = -\frac{G}{H + \lambda}$?

Why: $w^* = -\frac{G}{H + \lambda} = -\frac{-18.0}{7.0 + 2.0} = -\frac{-18.0}{9.0} = -(-2.0) = +2.00$. Regularisation $\lambda = 2$ shrinks the unregularised weight $-(-18)/7 \approx 2.57$ down to $2.00$.

Q11A candidate split in XGBoost has parent gradients $G_P = -10, H_P = 8$. It splits into a left child with $G_L = -8, H_L = 4$ and a right child with $G_R = -2, H_R = 4$. If regularisation is $\lambda = 0$ and $\gamma = 1.0$, what is the split gain $\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L} + \frac{G_R^2}{H_R} - \frac{G_P^2}{H_P}\right] - \gamma$?

Why: Left term: $\frac{(-8)^2}{4} = \frac{64}{4} = 16.0$. Right term: $\frac{(-2)^2}{4} = \frac{4}{4} = 1.0$. Parent term: $\frac{(-10)^2}{8} = \frac{100}{8} = 12.5$. Bracketed sum: $16.0 + 1.0 - 12.5 = 4.5$. Multiplying by $1/2$: $4.5 / 2 = 2.25$. Subtracting $\gamma = 1.0$: $\text{Gain} = 2.25 - 1.00 = 1.25$. Since $\text{Gain} = 1.25 > 0$, the split is accepted.

Q12Under squared error loss with learning rate $\eta = 0.10$ and leaf L2 regularisation $\lambda = 1.0$, a leaf contains 3 rows with residuals $e = [4.0, 5.0, 6.0]$ (where $g_i = -e_i$ and $h_i = 1.0$). What is the shrunk update $\eta w^*$ added by this leaf?

Why: Sum of gradients: $G = -(4 + 5 + 6) = -15.0$. Sum of Hessians: $H = 1 + 1 + 1 = 3.0$. Optimal leaf weight: $w^* = -\frac{G}{H + \lambda} = -\frac{-15.0}{3.0 + 1.0} = \frac{15.0}{4.0} = 3.75$. Applying learning rate shrinkage: $\eta w^* = 0.10 \times 3.75 = +0.375$.
