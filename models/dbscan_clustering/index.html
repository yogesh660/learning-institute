DBSCAN (Density-Based Clustering)

Finds clusters as dense regions of any shape and labels sparse points as noise. No need to choose k.

01 The idea

DBSCAN calls a point a core point if at least min_samples points lie within distance $\varepsilon$ of it. Clusters are groups of core points that reach each other, plus their borders; everything else is noise.

Think of $\varepsilon$ as a radius you draw around each point. Where points are packed together, the circles overlap into a connected chain: that chain is a cluster, whatever its shape. Lonely points whose circle is nearly empty and that are not close to any core point are noise. That makes DBSCAN great for crescents, rings and data with outliers.

The catch: one global $\varepsilon$ means one density level. Clusters of very different densities cannot all be captured with one setting. HDBSCAN and OPTICS remove this limitation.

In everyday terms

Finding crowds at a festival: someone with enough people within arm’s reach is in a crowd, and crowds connect through people standing close together.

02 How it works

  1. Scale the features.
  2. For each point, count neighbours within $\varepsilon$.
  3. Mark core points (count ≥ min_samples).
  4. Connect core points within $\varepsilon$ of each other into clusters.
  5. Attach border points to a neighbouring core point’s cluster; label the rest as noise (−1).

04 The maths

  1. Neighbourhood and core points

    $$N_\varepsilon(p) = \{q : d(p, q) \le \varepsilon\}, \qquad p \text{ is core} \iff |N_\varepsilon(p)| \ge \text{minPts}$$

    The point itself counts toward minPts in scikit-learn.

  2. Density-reachability

    $$q \text{ reachable from } p \iff \exists\, p = o_1, \dots, o_m = q:\; o_{i+1} \in N_\varepsilon(o_i),\; o_1..o_{m-1} \text{ core}$$

    A cluster is a maximal set of points that are density-connected to each other.

  3. Choosing ε: the k-distance plot

    $$d_k(x) = \text{distance from } x \text{ to its } k\text{-th nearest neighbour}, \;\; k = \text{minPts} - 1$$

    Sort $d_k$ for all points and look for the knee: points left of it live in dense regions.

06 When to use it

Strengths

  • Finds arbitrary shapes.
  • Detects outliers explicitly.
  • No need to choose k.

Limitations

  • One density level for the whole dataset.
  • Sensitive to eps; struggles in high dimensions.
  • Border points can be assigned differently depending on order.

Reach for it when

Spatial and GPS data, anomaly detection, non-convex clusters with noise.

Think twice when

Clusters with very different densities (use HDBSCAN) or high-dimensional data.

07 In code

python
import pandas as pd
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("datasets/raw/mall_customers.csv")
X = StandardScaler().fit_transform(df[["Annual_Income_k", "Spending_Score"]])
from sklearn.cluster import DBSCAN
from sklearn.neighbors import NearestNeighbors
import numpy as np

k_dist = np.sort(NearestNeighbors(n_neighbors=5).fit(X).kneighbors(X)[0][:, -1])  # look for the knee
db = DBSCAN(eps=0.3, min_samples=5).fit(X)
print("clusters:", len(set(db.labels_)) - (-1 in db.labels_), "noise points:", (db.labels_ == -1).sum())

Common pitfalls

  • Running on unscaled features, which makes $\varepsilon$ meaningless.
  • Treating noise points as a cluster in downstream metrics.

09 Check yourself

Q1A point with fewer than minPts neighbours but within $\varepsilon$ of a core point is:

Why: It joins the core point’s cluster but cannot extend it further.

Q2Why can DBSCAN find crescent-shaped clusters while k-means cannot?

Why: No centre, no convexity assumption.

Q3In DBSCAN, what condition must a point satisfy to be classified as a core point?

Why: A core point is defined as any point whose $\varepsilon$-neighbourhood contains at least min_samples observations: $|N_\varepsilon(p)| \ge \text{min\_samples}$.

Q4What label does scikit-learn's DBSCAN assign to points classified as noise?

Why: In scikit-learn, DBSCAN labels noise points with integer -1, distinguishing them from valid clusters (which are indexed $0, 1, 2, \dots$).

Q5How does the k-distance graph help an analyst choose an appropriate value for $\varepsilon$ in DBSCAN?

Why: In a k-distance plot, points in dense clusters have small distances to their $k$-th neighbour (flat lower part), while noise points have large distances (steep rise). The "knee" represents the optimal transition threshold $\varepsilon$.

Q6What is the primary failure mode of DBSCAN when clustering datasets containing groups of widely varying densities?

Why: DBSCAN applies one fixed $\varepsilon$ radius across the entire dataset. When clusters have different densities, no single global $\varepsilon$ works simultaneously for both tight and diffuse groups.

Q7Why can border points in DBSCAN produce non-deterministic cluster assignments depending on the processing order of data?

Why: If a border point is reachable from core points belonging to two distinct clusters, it gets attached to the first cluster that processes it, making border assignments slightly order-dependent.

Q8What is a common rule of thumb for setting the min_samples parameter in DBSCAN for a dataset with $p$ features?

Why: A widely adopted guideline (Ester et al., 1996) recommends choosing $\text{min\_samples} \ge 2 \times \text{dimensions}$, with a practical minimum of 4 to suppress noise.

Q9Why is feature standardisation especially critical prior to fitting DBSCAN with Euclidean distance?

Why: The neighbourhood radius $\varepsilon$ defines a sphere in feature space. If one feature has variance 10,000 and another 0.1, the distance is driven solely by the first feature, rendering neighbourhood searches meaningless along the second.

Q10Consider 4 points on a 1D line: $A = 1.0, B = 2.0, C = 3.0, D = 5.0$. DBSCAN is run with $\varepsilon = 1.0$ and min_samples = 3 (where a point's count includes itself). Which points are core points?

Why: Point $B$ has three points in its $\varepsilon$-neighbourhood ($A, B, C$ are all within distance $1.0$), satisfying $\text{min\_samples} = 3$. Point $A$ only has 2 points ($A, B$), Point $C$ only has 2 points ($B, C$), and Point $D$ has 1 ($D$). Thus, only $B$ is a core point.

Q11Following the previous 1D scenario ($A = 1.0, B = 2.0, C = 3.0, D = 5.0$ with $\varepsilon = 1.0$ and min_samples = 3), what are the resulting DBSCAN cluster labels for points $A, B, C, D$?

Why: $B$ is a core point and establishes Cluster 0. $A$ and $C$ are within $\varepsilon = 1.0$ of $B$, so they join Cluster 0 as border points. $D$ is too far ($|5.0 - 2.0| = 3.0 > 1.0$) and has no core neighbours, so it is labelled as noise ($-1$).

Q12In scikit-learn, what is the length of set(db.labels_) - {-1} for a fitted DBSCAN model where 100 points are assigned to Cluster 0, 80 points to Cluster 1, and 20 points are labelled as noise (-1)?

Why: The distinct labels in db.labels_ are $0, 1$, and $-1$. Removing the noise label $\{-1\}$ leaves $\{0, 1\}$, whose length is 2 (representing the 2 genuine clusters found).
