01 The idea

Grow many deep trees, each on a bootstrap sample of the rows and with a random subset of features at every split, then average their predictions. Averaging cancels out the trees’ individual mistakes.

A single deep tree has low bias but high variance. Averaging $B$ independent estimates divides variance by $B$, but trees trained on the same data are correlated, and correlation limits the gain. Random forests attack the correlation by forcing each split to consider only a random subset of features.

Each tree only sees about 63% of the rows. The rest are "out-of-bag", a free validation set for that tree. Combining them gives an honest error estimate without a separate hold-out.

In everyday terms

Asking many independent appraisers who each looked at different houses and focused on different details, then averaging their estimates.

02 How it works

  1. For $b = 1..B$: draw a bootstrap sample of rows.
  2. Grow a deep tree on it; at each split, consider only a random subset of max_features features.
  3. Predict by averaging all trees.
  4. Use out-of-bag predictions to estimate test error and permutation importance.

04 The maths

  1. Variance of an average of correlated trees

    $$\operatorname{Var}\Big(\frac1B\sum_b T_b(x)\Big) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2$$

    As $B$ grows the second term vanishes, leaving $\rho\sigma^2$. Feature subsampling lowers the correlation $\rho$, which is where the forest’s strength comes from.

  2. Out-of-bag fraction

    $$P(\text{row not in a bootstrap sample}) = \Big(1 - \tfrac1n\Big)^n \to e^{-1} \approx 0.368$$

    About a third of the rows are left out of each tree and serve as its validation set.

06 When to use it

Strengths

  • Strong accuracy with almost no tuning.
  • Robust to outliers and irrelevant features.
  • Free out-of-bag error estimate; parallel training.

Limitations

  • Large models with slower prediction than a single tree.
  • Cannot extrapolate.
  • Less interpretable than one tree; impurity importances are biased toward high-cardinality features.

Reach for it when

A reliable, low-effort baseline for almost any tabular problem.

Think twice when

You need the last few percent of accuracy (try boosting) or tiny, fast models.

07 In code

python
from sklearn.ensemble import RandomForestRegressor
from sklearn.inspection import permutation_importance

rf = RandomForestRegressor(n_estimators=500, max_features=0.5, oob_score=True,
                           n_jobs=-1, random_state=0).fit(X_tr, y_tr)
print("OOB R2:", round(rf.oob_score_, 3), "test R2:", round(rf.score(X_te, y_te), 3))
imp = permutation_importance(rf, X_te, y_te, n_repeats=10, random_state=0)
print(sorted(zip(imp.importances_mean.round(3), X.columns), reverse=True)[:5])

Common pitfalls

  • Trusting impurity-based feature_importances_; prefer permutation importance on held-out data.
  • Tuning n_estimators as if it could overfit. It cannot; it only costs time.

09 Check yourself

Q1Why does a random forest sample features at each split?

Why: Without it, every tree would split on the same strong feature first and they would make similar mistakes.

Q2Adding more trees to a random forest generally:

Why: More trees means the average converges; it does not add flexibility to each tree.

Q3What is the Out-of-Bag (OOB) score in Random Forest Regression?

Why: Because each bootstrap draw samples with replacement, about 36.8% of rows are left out of any given tree. Evaluating each row against the trees that never saw it gives a built-in cross-validation estimate with zero data leakage.

Q4In scikit-learn's RandomForestRegressor, what is the default value of max_features (unless specified otherwise)?

Why: While RandomForestClassifier defaults to max_features='sqrt', scikit-learn's RandomForestRegressor historically defaults to max_features=1.0 (all features), though setting max_features=1.0/3 often yields better decorrelation.

Q5Why can a Random Forest Regressor NOT extrapolate continuous linear trends outside the range of targets observed in the training set?

Why: An ensemble of regression trees is still fundamentally a piecewise constant estimator. For inputs beyond the training envelope, instances route to boundary leaves whose predictions cannot exceed the maximum training leaf mean.

Q6Why does increasing the number of trees (n_estimators) in a Random Forest from 100 to 1,000 NOT cause overfitting?

Why: Unlike gradient boosting where each tree fits previous errors (and can overfit), random forest trees are trained independently. Increasing $B$ reduces Monte Carlo sampling variance until test error plateaus.

Q7When evaluating feature importance in Random Forest Regressor, why is permutation importance on held-out data preferred over default MDI (Mean Decrease in Impurity)?

Why: Impurity-based importance evaluates variance reduction on training data. High-cardinality features can split on idiosyncratic training noise, receiving high MDI despite having zero predictive value on unseen data.

Q8If you reduce max_features from 1.0 (all features) down to 0.33 in a Random Forest Regressor, what is the expected impact on individual trees and the ensemble as a whole?

Why: Subsetting features forces trees to explore alternative predictive signals. Each tree has slightly higher bias, but the pairwise correlation $\rho$ between trees drops sharply, leading to lower total ensemble variance.

Q9How does setting bootstrap=False in RandomForestRegressor alter the algorithm?

Why: With bootstrap=False, row subsampling is disabled. Every tree sees all $n$ training instances, so the only source of tree diversity is the random selection of max_features at each split node.

Q10In a dataset of $n = 5$ observations $\{A, B, C, D, E\}$, what is the exact probability that observation $A$ is NOT included in a bootstrap sample of size 5 drawn with replacement?

Why: On each draw, the probability of selecting an observation other than $A$ is $4/5 = 0.80$. Across 5 independent draws with replacement, the probability that $A$ is never drawn is $(4/5)^5 = 0.80^5 = 0.32768 \approx 32.77\%$. As $n \to \infty$, this approaches $(1 - 1/n)^n \to e^{-1} \approx 36.79\%$.

Q11Individual trees in a Random Forest Regressor have variance $\sigma^2 = 9.0$ and pairwise correlation $\rho = 0.20$. What are the ensemble variances when the forest has $B = 4$ trees and in the theoretical limit as $B \to \infty$?

Why: Ensemble variance is $\operatorname{Var}(\bar{T}) = \rho \sigma^2 + \frac{1 - \rho}{B}\sigma^2$. For $B = 4$: $0.20(9.0) + \frac{0.80}{4}(9.0) = 1.80 + 0.20(9.0) = 1.80 + 1.80 = 3.60$. As $B \to \infty$: the second term vanishes, leaving $\rho \sigma^2 = 0.20 \times 9.0 = 1.80$.

Q12A Random Forest of 5 trees is evaluated on a row with true target $y = 50.0$. In training, this row was included in the bootstrap samples for Trees 1, 2, and 4, but was out-of-bag for Trees 3 and 5. The five trees predict: Tree 1 ($48.0$), Tree 2 ($52.0$), Tree 3 ($44.0$), Tree 4 ($50.0$), Tree 5 ($46.0$). What are the standard ensemble prediction and the Out-of-Bag (OOB) prediction for this row?

Why: Standard prediction averages all 5 trees: $(48 + 52 + 44 + 50 + 46) / 5 = 240 / 5 = 48.0$. OOB prediction averages only the trees that did NOT see this row during training (Trees 3 and 5): $(44 + 46) / 2 = 90 / 2 = 45.0$.
