Gated Recurrent Units (GRUs)

An RNN with two gates that decide, at every step, how much of the memory to keep and how much to overwrite.

01 The idea

A GRU adds a learned switch to the RNN. The update gate $z_t$ decides how much of the old state to keep and how much to replace with new content. When $z_t \approx 0$, the state passes through untouched, so memory and gradients survive for many steps.

A vanilla RNN rewrites its memory at every step whether it wants to or not. A GRU instead blends: $h_t = (1 - z_t)\odot h_{t-1} + z_t \odot \tilde h_t$. With $z_t$ near 0 it copies the old state forward; near 1 it replaces it with the candidate $\tilde h_t$. Because the gate is computed from the current input and state, the network learns when to write.

The reset gate $r_t$ controls how much of the old state is used when proposing the candidate. With $r_t \approx 0$ the candidate ignores history, which helps the network start a fresh thought, for example at the start of a new sentence. GRUs have fewer parameters than LSTMs and often perform about as well.

02 How it works

  1. Compute the update gate $z_t = \sigma(W_z x_t + U_z h_{t-1})$ and reset gate $r_t = \sigma(W_r x_t + U_r h_{t-1})$, each between 0 and 1.
  2. Propose new content using the reset-scaled history: $\tilde h_t = \tanh(W x_t + U(r_t \odot h_{t-1}))$.
  3. Blend: $h_t = (1 - z_t)\odot h_{t-1} + z_t\odot\tilde h_t$.
  4. Read out from $h_T$ (or every $h_t$) as with an RNN.

05 The maths

  1. Gates

    $$z_t = \sigma(W_z x_t + U_z h_{t-1} + b_z), \qquad r_t = \sigma(W_r x_t + U_r h_{t-1} + b_r)$$

    The sigmoid keeps each gate between 0 (closed) and 1 (open), elementwise per memory unit.

  2. Candidate and update

    $$\tilde h_t = \tanh\!\big(W x_t + U(r_t \odot h_{t-1}) + b\big), \qquad h_t = (1 - z_t)\odot h_{t-1} + z_t\odot\tilde h_t$$

    An interpolation between keeping and replacing.

  3. Why gradients survive

    $$\frac{\partial h_t}{\partial h_{t-1}} \approx \operatorname{diag}(1 - z_t) \quad\text{when } z_t \text{ is small}$$

    If the gate stays near 0, the Jacobian is close to the identity, so the product over many steps does not vanish. Compare with the RNN, where every step multiplies by $W_h$ and a tanh derivative.

07 When to use it

Strengths

  • Remembers much longer than a vanilla RNN.
  • Fewer parameters and faster than an LSTM (two gates, no separate cell).
  • Strong default for small and medium sequence tasks.

Limitations

  • Still sequential: slow to train on long sequences.
  • Memory still degrades over very long ranges.
  • Usually outperformed by Transformers when data is plentiful.

Reach for it when

Time series, sensor streams and text classification with modest data or compute.

Think twice when

Long documents and large datasets, where Transformers parallelise better and capture longer context.

08 In code

python
import torch, torch.nn as nn
from sklearn.datasets import load_digits

# read each 8x8 digit image as a sequence: 8 time steps, 8 pixels per step
digits = load_digits()
X = torch.tensor(digits.images / 16.0, dtype=torch.float32)    # (n, 8, 8)
y = torch.tensor(digits.target)

class GRUClassifier(nn.Module):
    def __init__(self, hidden=64):
        super().__init__()
        self.gru = nn.GRU(input_size=8, hidden_size=hidden, batch_first=True)
        self.out = nn.Linear(hidden, 10)

    def forward(self, x):
        _, h_last = self.gru(x)
        return self.out(h_last[-1])

model = GRUClassifier()
print(sum(p.numel() for p in model.parameters()), "parameters")   # ~3x an RNN of the same width

Common pitfalls

  • Confusing conventions: some papers (and PyTorch) swap the roles of $z_t$ and $1 - z_t$. The idea is the same.
  • Using a GRU where a simple moving average or gradient boosting on lag features would do.

09 Check yourself

Q1What does the update gate $z_t \approx 0$ mean (in the convention used here)?

Why: $h_t = (1 - z_t)h_{t-1} + z_t\tilde h_t \approx h_{t-1}$.

Q2What is the reset gate for?

Why: It scales $h_{t-1}$ inside the candidate computation.

Q3Compared with an LSTM, a GRU:

Why: Two gates and one state vector instead of three gates plus a cell.

Q4Why do the update gate $z_t$ and reset gate $r_t$ in a GRU use the sigmoid activation function $\sigma(\cdot)$ instead of $\tanh(\cdot)$?

Why: Gates represent proportions or probabilities of keeping/filtering information. The sigmoid function maps real-valued linear projections onto $(0, 1)$, where 0 corresponds to fully closed and 1 corresponds to fully open.

Q5In the interpolation equation $h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde h_t$, what happens when the update gate vector is close to 1 ($z_t \approx 1$)?

Why: When $z_t \approx 1$, the retention term $(1 - z_t) \odot h_{t-1} \approx 0$, while the update term $z_t \odot \tilde h_t \approx \tilde h_t$, so the hidden state is almost entirely replaced by the new candidate.

Q6A GRU cell has a previous hidden state $h_{t-1} = 0.80$. For the current time step, the network computes an update gate value of $z_t = 0.25$ and a candidate state of $\tilde h_t = -0.40$. Using the formula $h_t = (1 - z_t)h_{t-1} + z_t \tilde h_t$, what is the new hidden state $h_t$?

Why: Retention of previous state is $(1 - 0.25) \times 0.80 = 0.75 \times 0.80 = 0.60$. Contribution of candidate is $0.25 \times (-0.40) = -0.10$. Blending them yields $h_t = 0.60 + (-0.10) = 0.50$.

Q7When the reset gate $r_t$ in a GRU evaluates to 0 for all units, what does the candidate state $\tilde h_t = \tanh(W x_t + U(r_t \odot h_{t-1}) + b)$ represent?

Why: When $r_t = 0$, the historical context $r_t \odot h_{t-1} = 0$, so $\tilde h_t = \tanh(W x_t + b)$. This allows the GRU to discard irrelevant past history when starting a new sequence segment (such as the beginning of a sentence).

Q8For the same input dimension $d_{\text{in}}$ and hidden size $d_{\text{hid}}$, roughly what is the ratio of trainable parameters in a GRU compared with a standard LSTM?

Why: A GRU computes 3 sets of projections (update gate $z_t$, reset gate $r_t$, and candidate $\tilde h_t$). A standard LSTM computes 4 sets of projections (forget gate $f_t$, input gate $i_t$, output gate $o_t$, and candidate $\tilde c_t$). Therefore, a GRU has approximately $\frac{3}{4} = 75\%$ of the parameters of an LSTM of identical width.

Q9According to the GRU gradient relation $\frac{\partial h_t}{\partial h_{t-1}} \approx \operatorname{diag}(1 - z_t)$ (when $z_t$ is small), how does the GRU prevent the vanishing gradient problem across many time steps?

Why: If the network chooses not to update its memory ($z_t \approx 0$), the Jacobian $\frac{\partial h_t}{\partial h_{t-1}} \approx I$. Gradients backpropagated through time are multiplied by values close to 1, creating an effective shortcut across dozens or hundreds of steps.

Q10A 1-unit GRU computes its candidate state as $\tilde h_t = \tanh(W x_t + U(r_t \cdot h_{t-1}) + b)$. Given $W = 0.5$, $U = -0.5$, bias $b = -0.3$, input $x_t = 1.0$, previous state $h_{t-1} = 0.80$, and reset gate $r_t = 0.50$, what is the candidate state $\tilde h_t$?

Why: First scale the historical state by the reset gate: $r_t \cdot h_{t-1} = 0.50 \times 0.80 = 0.40$. Next, compute the linear pre-activation: $W x_t + U(0.40) + b = (0.5 \times 1.0) + (-0.5 \times 0.40) - 0.3 = 0.50 - 0.20 - 0.30 = 0.00$. Finally, $\tanh(0.00) = 0.00$.

Q11The lesson defines the GRU update as $h_t = (1 - z_t)\odot h_{t-1} + z_t\odot\tilde h_t$. However, PyTorch's official nn.GRU documentation defines it as $h_t = (1 - z_t)\odot n_t + z_t\odot h_{t-1}$ (where $n_t$ is the candidate). Under PyTorch's convention, what does a gate value of $z_t \approx 1$ indicate?

Why: In PyTorch's notation, $z_t$ multiplies $h_{t-1}$ directly while $(1 - z_t)$ multiplies candidate $n_t$. Thus when $z_t \approx 1$, $(1 - z_t) \approx 0$, so $h_t \approx h_{t-1}$, retaining the old memory. The lesson highlights this notation swap as a common pitfall when reading papers versus codebase implementations.

Q12A GRU unit receives zero inputs ($x_t = 0, \tilde h_t = 0$) while its update gate stays fixed at $z_t = 0.10$. Starting from $h_0 = 1.0$, what is the value of the hidden state $h_3$ after 3 time steps?

Why: With $\tilde h_t = 0$, $h_t = (1 - z_t) h_{t-1} = 0.90 \times h_{t-1}$. Over 3 steps, $h_3 = 0.90^3 \times h_0 = 0.729 \times 1.0 = 0.729$. Assuming a linear reduction of $0.10 \times 3 = 0.30 \implies 0.70$ is a common pitfall that overlooks geometric decay.
