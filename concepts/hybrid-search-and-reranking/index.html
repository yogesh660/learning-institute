Hybrid search and reranking

Hybrid search and neural reranking combine the complementary strengths of lexical keyword matching and dense semantic retrieval to deliver state-of-the-art information retrieval. While dense bi-encoders excel at conceptual paraphrasing and sparse BM25 excels at exact keyword and entity lookups, neither is sufficient alone. Modern multi-stage search pipelines deploy hybrid retrieval fused via Reciprocal Rank Fusion (RRF), followed by high-capacity cross-encoder rerankers that evaluate deep query-document cross-attention to maximise precision.

01 The idea

Search for "Error code 0x80070005 access denied" in a pure dense semantic vector database, and it will return general articles about Windows permissions, completely missing the specific support thread for that exact hexadecimal code. Search for "how to fix a flickering screen" in a pure BM25 index, and it misses articles titled "troubleshooting monitor refresh stutter". Real-world search demands hybrid capabilities: combining sparse lexical inverted indexes with dense neural vectors, refined by cross-encoder rerankers.

The complementary strengths of sparse and dense retrieval: - Sparse Retrieval (BM25): Fast inverted index lookups based on term frequency and document length. Excels at exact matches, rare acronyms, product serial numbers, and specialized jargon. Fails on vocabulary mismatch and synonyms. - Dense Retrieval (Bi-Encoders): Continuous vector matching based on cosine similarity. Excels at conceptual paraphrasing, high-level intent, and multilingual cross-linguality. Fails on rare out-of-vocabulary entities and exact alphanumeric codes. Hybrid retrieval fuses both search paradigms to ensure no relevant document is missed.

Reciprocal Rank Fusion (RRF) vs Score Normalisation: How do you combine BM25 scores (ranging from 0 to 45+) with cosine similarities (ranging from -1 to +1)? - Score Normalisation (Min-Max): Maps scores to [0, 1] and computes a weighted sum alpha * S_dense + (1 - alpha) * S_sparse. However, score distributions vary wildly across queries, requiring constant calibration. - Reciprocal Rank Fusion (RRF): Ignores raw scores entirely and operates strictly on ordinal ranks: RRF(d) = sum_m 1 / (k + r_m(d)), where k = 60 is a smoothing constant. RRF is scale-invariant, robust, and consistently outperforms score normalisation across diverse benchmark suites.

The Two-Stage Retrieval Paradigm: 1. First Stage (Retrieval): Low-latency, high-recall candidate generation. Sparse and dense search run in parallel across millions of documents, retrieving the top 50 to 100 candidate documents in sub-10ms time. 2. Second Stage (Reranking): High-precision cross-encoder scoring. The top candidates are passed through a cross-encoder that evaluates full cross-attention between every query token and document token, reordering the candidates to place the most accurate answers in the top 3 positions.

In everyday terms

Think of recruiting a specialised aerospace engineer. Stage 1 (Hybrid Retrieval) is an automated resume filter: it runs a keyword scan for mandatory certifications like "FAA Part 21" (sparse BM25) while simultaneously running a semantic match for "propulsion systems engineering experience" (dense retrieval). This narrows 50,000 applicants down to 50 top candidates. Stage 2 (Cross-Encoder Reranking) is bringing those 50 candidates into an in-person technical interview with the Chief Engineer, who spends twenty minutes probing their actual problem-solving depth to pick the top 3 final hires.

03 The maths

  1. Reciprocal Rank Fusion (RRF) formulation

    \operatorname{RRF}(d) = \sum_{m \in \mathcal{M}} \frac{1}{k + r_m(d)}

    Here $\mathcal{M} = \{\text{BM25}, \, \text{Dense}\}$ is the set of retrieval models, $r_m(d) \in \{1, 2, \dots, K\}$ is the ordinal rank of document $d$ in system $m$, and $k$ (typically $k = 60$) is a rank smoothing constant that prevents top-ranked items from drowning out lower-ranked consensus items.

  2. Cross-encoder relevance scoring function

    s(q, d) = \mathbf{w}^\top \operatorname{Encoder}\left( [\operatorname{CLS}] \, q \, [\operatorname{SEP}] \, d \, [\operatorname{SEP}] \right) + b

    Unlike bi-encoders which compute independent vectors, the cross-encoder computes full all-to-all cross-attention between every query token and document token, capturing fine-grained token alignments at the cost of $O(N \cdot (L_q + L_d)^2)$ compute.

  3. Normalised Discounted Cumulative Gain (NDCG@K)

    \operatorname{NDCG}@K = \frac{\operatorname{DCG}@K}{\operatorname{IDCG}@K}, \quad \operatorname{DCG}@K = \sum_{i=1}^K \frac{2^{rel_i} - 1}{\log_2(i + 1)}

    NDCG measures ranking quality by rewarding relevant documents positioned near the top of the search result list with logarithmic position discounting, normalised by the ideal ranking $\operatorname{IDCG}@K$.

04 Key takeaways

  • Hybrid search combines the exact keyword precision of BM25 with the conceptual semantics of dense vector search.
  • Reciprocal Rank Fusion (RRF) merges disparate retrieval rankings using ordinal positions without requiring delicate score calibration.
  • Two-stage retrieval architectures balance latency and accuracy: fast first-stage hybrid retrieval followed by deep cross-encoder reranking.
  • Cross-encoders evaluate full cross-attention over [query; document] pairs, resolving false positives produced by bi-encoders.
  • Ranking quality is evaluated using Normalised Discounted Cumulative Gain (NDCG) and Mean Reciprocal Rank (MRR).

05 In code

python
class HybridSearchEngine:
    """
    Two-stage hybrid retrieval simulation:
    Stage 1: BM25 sparse + Dense vector search combined via Reciprocal Rank Fusion (RRF).
    Stage 2: Cross-encoder reranking simulation.
    """
    def __init__(self, rrf_k=60):
        self.rrf_k = rrf_k
        self.documents = []

    def load_documents(self, docs):
        self.documents = list(docs)

    def reciprocal_rank_fusion(self, sparse_rankings, dense_rankings):
        """
        Combine sparse and dense rankings using RRF.
        sparse_rankings, dense_rankings: lists of doc_idx in rank order.
        """
        rrf_scores = {}
        
        # Process sparse rankings
        for rank, doc_idx in enumerate(sparse_rankings, 1):
            rrf_scores[doc_idx] = rrf_scores.get(doc_idx, 0.0) + 1.0 / (self.rrf_k + rank)
            
        # Process dense rankings
        for rank, doc_idx in enumerate(dense_rankings, 1):
            rrf_scores[doc_idx] = rrf_scores.get(doc_idx, 0.0) + 1.0 / (self.rrf_k + rank)
            
        # Sort descending by RRF score
        sorted_candidates = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)
        return sorted_candidates

    def cross_encoder_rerank(self, query, candidate_pairs):
        """
        Simulate deep cross-encoder re-scoring of top candidates.
        """
        reranked = []
        for doc_idx, rrf_score in candidate_pairs:
            doc_text = self.documents[doc_idx]
            # Mock cross-encoder score combining keyword alignment and semantics
            has_error_code = "0x80070005" in query and "0x80070005" in doc_text
            has_permission = "access denied" in query.lower() and "permission" in doc_text.lower()
            
            score = 0.5 * rrf_score
            if has_error_code:
                score += 5.0  # Exact match boost
            if has_permission:
                score += 2.0  # Semantic relevance boost
                
            reranked.append((doc_idx, doc_text, score))
            
        reranked.sort(key=lambda x: x[2], reverse=True)
        return reranked

# Sample corpus
corpus = [
    "Troubleshooting Windows update failure with error code 0x80070005 access denied.",
    "General security guidelines for managing administrator permissions on corporate networks.",
    "How to resolve display panel flickering and graphics driver crashes on laptops.",
    "Windows activation errors and software license key verification procedures."
]

engine = HybridSearchEngine(rrf_k=60)
engine.load_documents(corpus)

# Simulated Query: "0x80070005 access denied error"
query = "0x80070005 access denied error"

# Simulated Stage 1 Rankings:
# BM25 finds Doc 0 first (exact keyword 0x80070005)
sparse_ranks = [0, 3, 1, 2]
# Dense vector model finds Doc 1 first (semantic concept of access denied/permissions)
dense_ranks = [1, 0, 3, 2]

# Step 1: Reciprocal Rank Fusion
fused_candidates = engine.reciprocal_rank_fusion(sparse_ranks, dense_ranks)

print(f"Query: '{query}'")
print("\n--- Stage 1: Reciprocal Rank Fusion (RRF) Candidates ---")
for rank, (doc_idx, rrf_score) in enumerate(fused_candidates, 1):
    print(f"  Rank {rank} (Score: {rrf_score:.5f}) -> Doc {doc_idx}: '{corpus[doc_idx]}'")

# Step 2: Cross-Encoder Reranking
final_results = engine.cross_encoder_rerank(query, fused_candidates[:3])

print("\n--- Stage 2: Cross-Encoder Reranked Top Results ---")
for rank, (doc_idx, text, ce_score) in enumerate(final_results, 1):
    print(f"  Rank {rank} [Score: {ce_score:.4f}] -> Doc {doc_idx}: '{text}'")

Common pitfalls

  • Reranking the entire corpus with a cross-encoder: Evaluating millions of documents with a cross-encoder takes minutes or hours per query. Only evaluate cross-encoders on the top 50 to 100 candidates retrieved by the first stage.
  • Convex combination without score normalisation: Simply adding BM25 scores (0 to 50) and cosine similarities (0 to 1) allows BM25 to completely overpower dense retrieval. Always use RRF or robust min-max normalisation.
  • Setting RRF constant k too small: Setting k = 1 causes rank 1 to receive a score of 1.0 while rank 2 receives 0.5 (a massive 50% penalty). Standard practice uses k = 60 to soften rank discrepancies and reward consensus across both retrieval systems.
  • Discarding BM25 on code or legal documents: Dense vectors frequently fail on exact variable names, error codes, and statutory section numbers. Never abandon lexical retrieval on technical or legal corpora.

06 Check yourself

Q1Why does Reciprocal Rank Fusion (RRF) outperform naive linear score combination in hybrid search pipelines?

Why: BM25 scores are unbounded positive numbers (e.g. 0 to 45), while cosine similarities range from -1 to 1. Normalising and combining them linearly requires constant query-specific tuning. RRF uses ordinal rank positions 1/(k + rank), providing scale-invariant robustness.

Q2What is the primary role of a cross-encoder reranker in a two-stage retrieval architecture?

Why: Bi-encoders evaluate queries and documents as isolated vectors, missing fine-grained token-level interactions. A cross-encoder computes full attention across concatenated [query; document] pairs, achieving superior precision on the top candidate subset.

Q3What is Normalised Discounted Cumulative Gain (NDCG) designed to measure in information retrieval systems?

Why: NDCG rewards search engines for placing highly relevant documents at top ranks. The logarithmic discount 1/log2(rank + 1) penalises engines that retrieve relevant documents down at position 10 or 20, normalised by the ideal ranking IDCG.
