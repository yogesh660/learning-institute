Interactions and Polynomial Features: Capturing Non-Linear Synergies

Constructing multiplicative feature interactions and polynomial expansions to model non-linear synergies while managing combinatorial feature explosion.

01 The idea

Linear models inherently assume that the effect of one feature on the target is entirely independent of all other features. In real-world phenomena, however, effects are deeply interactive: the impact of advertising depends on household income, and drug efficacy depends on patient body mass. Constructing interaction terms and polynomial features enables linear algorithms to capture multiplicative synergies and curved response surfaces.

In a standard linear regression $\hat{y} = w_1 x_1 + w_2 x_2 + b$, the marginal derivative $\frac{\partial \hat{y}}{\partial x_1} = w_1$ is constant. It never changes regardless of whether $x_2$ is tiny or massive.

Adding an interaction term $x_1 x_2$ yields $\hat{y} = w_1 x_1 + w_2 x_2 + w_{12} (x_1 x_2) + b$. Now the marginal effect $\frac{\partial \hat{y}}{\partial x_1} = w_1 + w_{12} x_2$ depends directly on the level of $x_2$, unlocking synergy or antagonism modelling.

Polynomial features expand individual inputs to higher powers ($x_1^2, x_1^3$), allowing linear models to fit quadratic parabolas, cubic curves, and multi-dimensional saddle surfaces.

The primary danger of polynomial and interaction expansion is combinatorial explosion. Expanding $d$ features to degree $p$ generates $\binom{d+p}{p}$ terms. For 100 features at degree 2, this produces 5,151 columns, leading to extreme multicollinearity, memory bloat, and severe overfitting unless paired with L1 regularisation (Lasso) or domain-guided selection.

In everyday terms

Imagine baking bread. Flour and yeast each contribute weight, but their true effect on loaf height occurs through their interactive combination: yeast without flour yields zero bread, and flour without yeast yields flatbread. A model that only adds individual flour weight plus yeast weight misses the multiplicative reaction entirely.

02 Step by step

  1. Domain hypothesis generation: Identify intuitive pairwise synergies based on physical or business logic (e.g. $\text{speed} \times \text{time} = \text{distance}$, $\text{price} \times \text{quantity} = \text{revenue}$) before blind generation.
  2. Feature standardisation: Standardise raw continuous variables before creating polynomial terms to prevent high-degree powers from exploding to huge numerical scales.
  3. Polynomial expansion: Generate cross-products and powers up to degree 2 or 3 using matrix operations or `PolynomialFeatures`.
  4. Filter collinear columns: Check correlation matrices and variance inflation factors (VIF) to detect near-duplicate collinear interaction terms.
  5. Regularised model fitting: Train linear models with L1/L2 regularisation (e.g. ElasticNet) to drive irrelevant cross-products to zero.

03 The maths

  1. Two-Way Multiplicative Interaction Model

    \hat{y} = w_0 + w_1 x_1 + w_2 x_2 + w_{12} (x_1 x_2)

    The interaction coefficient $w_{12}$ represents the change in the slope of $x_1$ per unit increase in $x_2$.

  2. Combinatorial Dimensionality Expansion

    D_{\mathrm{expanded}} = \binom{d + p}{p} = \frac{(d + p)!}{d! \, p!}

    Expanding a $d$-dimensional feature vector up to polynomial degree $p$ scales factorially, necessitating strict feature pruning.

  3. Marginal Rate of Substitution / Sensitivity

    \frac{\partial \hat{y}}{\partial x_1} = w_1 + w_{12} x_2 + 2 w_{11} x_1

    With both interaction and quadratic terms, the sensitivity of predictions to changes in $x_1$ is a function of both $x_1$ and $x_2$.

04 Key takeaways

  • Interaction terms allow the marginal effect of one predictor to depend on the magnitude of another.
  • Polynomial features enable linear algorithms to fit smooth non-linear curves and saddle points.
  • Combinatorial expansion generates thousands of features rapidly, creating multicollinearity and overfitting risks.
  • Regularisation methods (Lasso, ElasticNet) are critical to prune redundant interaction terms.

05 In code

python
import numpy as np
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LassoCV

# Generate synthetic non-linear interaction data: y = 2*x1 - 3*x2 + 4*(x1*x2) + noise
np.random.seed(42)
X_raw = np.random.uniform(-2, 2, size=(200, 3))  # 3 features: x0, x1, x2
y = 2.0 * X_raw[:, 0] - 3.0 * X_raw[:, 1] + 4.0 * (X_raw[:, 0] * X_raw[:, 1]) + np.random.normal(0, 0.5, 200)

# Standardise before polynomial expansion
scaler = StandardScaler()
X_norm = scaler.fit_transform(X_raw)

# Generate degree-2 interaction features (including bias and squares)
poly = PolynomialFeatures(degree=2, include_bias=False)
X_poly = poly.fit_transform(X_norm)
feature_names = poly.get_feature_names_out(['x0', 'x1', 'x2'])

# Fit Lasso to automatically select the true interaction terms
lasso = LassoCV(cv=5).fit(X_poly, y)

print("Expanded feature count:", X_poly.shape[1])
selected = [(name, round(coef, 2)) for name, coef in zip(feature_names, lasso.coef_) if abs(coef) > 0.1]
print("Lasso selected non-zero features:", selected)
# Output reveals strong weights on x0, x1, and the cross-product x0*x1

Common pitfalls

  • Expanding unscaled features: Raising variables with large raw scales (e.g. salaries of 100,000) to powers causes extreme floating point overflow and gradient instability.
  • Failing to keep main effects: Removing linear terms ($x_1, x_2$) while retaining their interaction ($x_1 x_2$) creates models whose interpretation changes drastically under simple coordinate shifts.
  • Overfitting on small samples: Degree-3 or degree-4 expansions on modest datasets fit random noise patterns perfectly, collapsing test set generalisation.

06 Check yourself

Q1What is the mathematical meaning of the coefficient $w_{12}$ on the interaction term $x_1 x_2$?

Why: Differentiating $\hat{y}$ with respect to $x_1$ yields $w_1 + w_{12} x_2$. Thus $w_{12}$ indicates how the impact of $x_1$ shifts per unit change in $x_2$.

Q2What severe issue arises when blindly generating degree-2 polynomial features on a dataset with 500 columns?

Why: Formula $\binom{500+2}{2} = 125{,}751$ terms (including the constant term). Such explosive dimensionality overwhelms memory and requires aggressive regularisation or domain pruning.

Q3Why should continuous variables be standardised prior to computing polynomial expansions?

Why: Variables with large magnitudes ($10^4$) when squared become $10^8$, creating vast disparities in feature magnitudes that destabilise optimisation algorithms.
