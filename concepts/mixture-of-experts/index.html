Mixture of Experts (MoE): Conditional Computation and Sparse Gating

Decoupling model parameter capacity from FLOP compute cost using sparse top-$k$ gating routers and load balancing auxiliary losses.

01 The idea

In dense neural networks, every single parameter is activated for every single forward pass: doubling the parameter count doubles the FLOP compute cost and training latency. Mixture of Experts (MoE) introduces conditional computation: replacing dense Feed-Forward Network (FFN) layers with an ensemble of $E$ parallel expert sub-networks, directed by a learned router that routes each token to only top-$k$ experts (e.g. 2 out of 8). MoE scales models to trillions of parameters with constant inference FLOPs.

In standard Transformers, Feed-Forward Network (FFN) layers account for $\approx 2/3$ of total model parameters. MoE replaces each dense FFN with $E$ identical-structure independent FFN blocks called "experts".

A lightweight gating router network $G(x) = \operatorname{Softmax}(\operatorname{TopK}(x \cdot W_g + \epsilon, k))$ computes routing probabilities for each token, directing the token to the $k$ experts with the highest scores.

Because each token interacts with only $k$ experts (typically $k=1$ or $k=2$), the floating point operations (FLOPs) per token remain constant, even as the total parameter count scales by $8\times$ or $64\times$.

The primary failure mode of MoE is Expert Collapse: the router quickly learns to send every single token to the same 1–2 favourite experts, leaving the remaining experts starved of gradients. MoE prevents this using an auxiliary Load Balancing Loss that penalises unequal token allocation across experts.

In everyday terms

Imagine a high-volume medical clinic. In a dense system, every single patient is examined simultaneously by 16 different medical specialists (cardiologist, neurologist, orthopaedic surgeon, dermatologist), running up astronomical bills. In a Mixture of Experts clinic, a triage nurse (the router) examines the patient's symptoms and routes them strictly to the two most relevant specialists. The clinic maintains the collective knowledge of 16 experts while paying for only 2 specialists per patient.

02 Step by step

  1. Select layer replacement: Substitute dense FFN blocks in Transformer decoder layers with MoE layers containing $E$ parallel expert networks.
  2. Configure routing top-$k$: Choose $k=1$ (Switch Transformer; maximum efficiency) or $k=2$ (Mixture of Experts; smoother routing gradients).
  3. Compute router gating logits: Project token representations through router weight matrix $W_g$ and optionally add Gaussian noise during training for exploration.
  4. Apply Top-$k$ gating and normalisation: Select top-$k$ expert indices and re-normalise their softmax gating weights to sum to 1.0.
  5. Dispatch and gather tokens: Dispatch tokens to designated expert buffers, execute parallel forward passes, and combine outputs weighted by gating coefficients.
  6. Calculate load balancing auxiliary loss: Compute the coefficient of variation or dot product between router assignment probabilities and actual batch routing frequencies, adding to main loss.

03 The maths

  1. MoE Conditional Computation Output

    y = \sum_{i=1}^E G(x)_i \cdot \operatorname{Expert}_i(x), \quad G(x) = \operatorname{Softmax}\left( \operatorname{TopK}\left( x W_g, \; k \right) \right)

    Output is the weighted sum across active experts where $G(x)_i > 0$ for strictly $k$ experts and $0$ for the remaining $(E - k)$ experts.

  2. Top-$k$ Gating Operator

    \operatorname{TopK}(v, k)_i = \begin{cases} v_i & \text{if } v_i \text{ is in top } k \text{ elements of } v \\ -\infty & \text{otherwise} \end{cases}

    Sets non-selected expert logits to $-\infty$ prior to softmax, driving their routing probabilities and compute costs to exact zero.

  3. Auxiliary Load Balancing Loss (Switch Transformer)

    \mathcal{L}_{\mathrm{aux}} = \alpha \cdot E \sum_{i=1}^E f_i \cdot P_i, \quad f_i = \frac{1}{T} \sum_{t=1}^T \mathbb{I}(\operatorname{routed}(t) = i), \; P_i = \frac{1}{T} \sum_{t=1}^T G(x_t)_i

    Minimises the correlation between fraction of tokens dispatched $f_i$ and router probability mass $P_i$, penalising expert concentration.

04 Key takeaways

  • MoE decouples model capacity from compute cost through sparse conditional routing.
  • Only top-$k$ experts are activated per token, keeping inference FLOPs constant as parameters grow.
  • A learned router network predicts softmax gating scores across parallel expert FFNs.
  • An auxiliary load balancing loss prevents expert collapse where all tokens route to one favourite expert.

05 In code

python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SimpleMoELayer(nn.Module):
    def __init__(self, d_model: int, d_ff: int, num_experts: int = 4, top_k: int = 2):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.router = nn.Linear(d_model, num_experts, bias=False)
        # Create independent expert FFNs
        self.experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_ff),
                nn.ReLU(),
                nn.Linear(d_ff, d_model)
            ) for _ in range(num_experts)
        ])

    def forward(self, x: torch.Tensor):
        # x shape: [batch_size, seq_len, d_model]
        batch, seq, d_model = x.shape
        x_flat = x.view(-1, d_model)  # [N, d_model]
        
        # 1. Compute router logits
        logits = self.router(x_flat)  # [N, num_experts]
        
        # 2. Select top-k experts per token
        top_k_logits, top_k_indices = torch.topk(logits, self.top_k, dim=-1)
        top_k_weights = F.softmax(top_k_logits, dim=-1)  # [N, top_k]
        
        # 3. Compute weighted expert outputs
        out = torch.zeros_like(x_flat)
        for k in range(self.top_k):
            expert_idx = top_k_indices[:, k]
            weight = top_k_weights[:, k].unsqueeze(-1)
            # Route tokens to corresponding expert
            for i, expert in enumerate(self.experts):
                mask = (expert_idx == i)
                if mask.any():
                    out[mask] += weight[mask] * expert(x_flat[mask])
                    
        return out.view(batch, seq, d_model)

# Test MoE layer with 4 experts, routing top-2 per token
moe = SimpleMoELayer(d_model=64, d_ff=256, num_experts=4, top_k=2)
x = torch.randn(2, 8, 64)  # 16 tokens
out = moe(x)
print("MoE Output shape:", out.shape)
print("Each token evaluated by strictly 2 out of 4 experts!")

Common pitfalls

  • Expert collapse: Without auxiliary load balancing, the router quickly routes all tokens to a single expert, reducing the model to a tiny fraction of its capacity.
  • Inference memory overhead: While FLOPs are sparse, all expert weights must reside in GPU VRAM unless offloaded, requiring high aggregate memory.
  • Communication overhead in distributed MoE: Sharding experts across multiple GPUs requires expensive all-to-all token dispatch shuffles across network interconnects.

06 Check yourself

Q1What is the primary motivation for using Mixture of Experts (MoE) over dense neural network architectures?

Why: In MoE, each token is processed by only top-$k$ experts (e.g. 2 out of 8), allowing parameter capacity to scale massively while computation cost per token stays constant.

Q2What is "expert collapse" in a Mixture of Experts model?

Why: Expert collapse occurs when a router favours a few experts early, creating a positive feedback loop where only those experts receive gradient updates.

Q3How do modern MoE models like Switch Transformer prevent expert collapse during training?

Why: The auxiliary load balancing loss penalises correlation between router probability mass and token dispatch fractions, incentivizing balanced expert utilisation.
