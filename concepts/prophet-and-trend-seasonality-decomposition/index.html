01 The idea

Classical ARIMA models require stationary transformations, differencing, and strict uniform temporal intervals. In contrast, real-world business time series exhibit multiple nested seasonal patterns (day of week, month of year), structural trend changepoints, missing observations, and dramatic holiday shifts. Prophet frames forecasting as a curve-fitting problem using a generalised additive model (GAM), providing robust automated decomposition with intuitive parameters.

Prophet (developed by Taylor and Letham at Meta) models a time series as an additive decomposition: $y(t) = g(t) + s(t) + h(t) + \epsilon_t$, where $g(t)$ is trend, $s(t)$ is periodic seasonality, $h(t)$ models holiday effects, and $\epsilon_t$ is normally distributed error.

The trend $g(t)$ is modelled as a continuous piecewise linear or logistic growth curve with automatic changepoints. A sparse Laplace prior on changepoint rate adjustments $\delta_j$ acts like L1 regularisation, allowing the model to fit flexible curves while avoiding overfitting to short-term noise.

Seasonality $s(t)$ is modelled using truncated Fourier series: $\sum [a_n \cos(2\pi n t / P) + b_n \sin(2\pi n t / P)]$. Using Fourier series allows the model to handle multi-period seasonality (e.g. weekly $P=7$ and yearly $P=365.25$) simultaneously without requiring regular integer spacing or differencing.

Holiday effects $h(t)$ are modelled using indicator matrices that assign separate parameters to user-specified dates, accommodating windows around holidays (e.g. Christmas Eve through Boxing Day). Because it frames forecasting as regression rather than autoregression, Prophet handles missing data seamlessly without imputation.

In everyday terms

Imagine tuning a musical synthesizer. Rather than trying to describe the combined sound wave with a single complex recurrence equation, the synthesizer decomposes the sound into a low-frequency bassline (trend), repetitive harmonic oscillators (daily and weekly Fourier cycles), and occasional drum hits (holidays). Tuning the sound simply involves adjusting the volume and tempo of each independent track.

02 Step by step

  1. Format input data: Prepare a two-column dataframe with timestamp `ds` (ISO date) and target `y` (continuous metric).
  2. Configure trend model: Select linear or logistic growth (defining capacity `cap` if upper saturation boundaries exist).
  3. Tune changepoint flexibility: Adjust `changepoint_prior_scale` (higher values allow rapid trend shifts; lower values enforce stiff linear trends).
  4. Configure multi-scale seasonality: Enable daily, weekly, or yearly seasonality and adjust Fourier order (higher orders capture sharper cyclical peaks).
  5. Incorporate holiday calendars: Add predefined country holidays and custom event indicators with dedicated prior scales.
  6. Generate future predictions: Extrapolate future timestamps and sample uncertainty intervals via Monte Carlo simulation of future trend changepoints.

03 The maths

  1. Additive Time Series Decomposition Formulation

    y(t) = g(t) + s(t) + h(t) + \epsilon_t, \quad \epsilon_t \sim \mathcal{N}(0, \sigma^2)

    The observed series is decomposed into trend $g(t)$, seasonal component $s(t)$, holiday effects $h(t)$, and Gaussian noise $\epsilon_t$.

  2. Piecewise Linear Trend with Changepoints

    g(t) = \left( k + \mathbf{a}(t)^T \boldsymbol{\delta} \right) t + \left( m + \mathbf{a}(t)^T \boldsymbol{\gamma} \right), \quad \delta_j \sim \mathrm{Laplace}(0, \tau)

    Trend slope changes by $\delta_j$ at changepoints $s_j$, where vector $\mathbf{a}(t)$ indicates active changepoints and $\gamma_j = -s_j \delta_j$ ensures continuity.

  3. Fourier Series Seasonality Representation

    s(t) = \sum_{n=1}^N \left( a_n \cos\left(\frac{2\pi n t}{P}\right) + b_n \sin\left(\frac{2\pi n t}{P}\right) \right)

    Captures arbitrary periodic seasonality with period $P$ using $2N$ Fourier basis coefficients estimated via linear regression.

04 Key takeaways

  • Prophet models time series using a modular Generalised Additive Model (GAM) decomposed into trend, seasonality, and holidays.
  • Piecewise linear trends use automatic changepoints regularised by a sparse Laplace prior.
  • Seasonality is flexibly represented using Fourier series, allowing multiple overlapping cycles (weekly and yearly).
  • Robust against missing data, non-uniform timestamp intervals, and large holiday shifts without imputation.

05 In code

python
import numpy as np
import pandas as pd

# Minimal implementation of Prophet's Fourier seasonality regression
def build_fourier_basis(dates: pd.Series, period: float, order: int) -> np.ndarray:
    """Construct Fourier sin/cos columns for arbitrary period P and order N."""
    t = (dates - dates.min()).dt.total_seconds() / 86400.0  # Elapsed days
    basis = []
    for n in range(1, order + 1):
        basis.append(np.sin(2.0 * np.pi * n * t / period))
        basis.append(np.cos(2.0 * np.pi * n * t / period))
    return np.column_stack(basis)

# Generate synthetic daily data with trend and weekly seasonality
np.random.seed(42)
date_range = pd.date_range('2026-01-01', periods=120, freq='D')
t_days = np.arange(len(date_range))
true_trend = 100.0 + 0.5 * t_days
true_season = 15.0 * np.sin(2.0 * np.pi * t_days / 7.0)
y = true_trend + true_season + np.random.normal(0, 2.0, len(date_range))

# Build design matrix: Intercept + Linear Trend + Fourier Order 3 Weekly (P=7)
X_fourier = build_fourier_basis(pd.Series(date_range), period=7.0, order=3)
X = np.column_stack([np.ones(len(t_days)), t_days, X_fourier])

# Fit via Ridge regression
weights = np.linalg.solve(X.T @ X + 1e-3 * np.eye(X.shape[1]), X.T @ y)
y_pred = X @ weights

print("Learned baseline intercept:", round(weights[0], 2))
print("Learned linear trend slope:", round(weights[1], 2))
print("Mean Absolute Error:       ", round(float(np.mean(np.abs(y - y_pred))), 3))

Common pitfalls

  • Over-extrapolating recent trend shifts: If `changepoint_prior_scale` is set too high, the model overfits temporary dips, projecting unrealistic downward slopes into the future.
  • Ignoring multiplicative effects: For series where seasonal swings grow proportionally with revenue volume, using additive decomposition produces severe underestimation; set `seasonality_mode="multiplicative"`.
  • Autocorrelation neglect: Because Prophet treats observations as independent conditional on components, confidence intervals do not account for residual autocorrelation, often being narrower than reality.

06 Check yourself

Q1How does Prophet model complex periodic seasonality such as day-of-week and day-of-year cycles?

Why: Prophet approximates arbitrary periodic seasonal cycles using linear combinations of sine and cosine Fourier terms.

Q2What is the role of the Laplace prior on trend changepoints $\delta_j$ in Prophet?

Why: The Laplace prior places strong probability mass at zero, acting like L1 regularisation to keep the trend smooth and prevent overfitting to noise.

Q3When should an analyst configure `seasonality_mode="multiplicative"` instead of the default additive mode?

Why: In many businesses, seasonal spikes represent a percentage of baseline volume (e.g. +20% at Christmas). As sales grow from 1,000 to 10,000, seasonal swings expand from 200 to 2,000, which requires multiplicative decomposition.
