GraphRAG: Knowledge Graph-Augmented Generation and Multi-Hop Reasoning

Augmenting Retrieval-Augmented Generation with structured knowledge graphs and community summarisation to resolve global queries and multi-hop relationships.

01 The idea

Standard vector RAG excels at retrieving localized factual snippets, but fails completely on global synthesis queries (e.g. "What are the primary themes across this entire corpus?") and multi-hop entity traversals. GraphRAG structures unstructured text into hierarchical knowledge graphs and community summaries, unlocking holistic understanding and multi-step reasoning.

Standard dense retrieval computes cosine similarity between a query embedding and isolated text chunks (e.g. 500 tokens). If an answer requires connecting three distinct facts scattered across separate documents—or requires summarising broad organizational patterns across thousands of files—semantic similarity yields fragmented, uninformative fragments.

GraphRAG bridges this gap using a multi-stage graph pipeline: 1) Extract entities and relational triples $(s, r, o)$ from source documents using LLMs; 2) Construct a global knowledge graph and cluster connected subgraphs into thematic "communities" using Leiden clustering; 3) Generate hierarchical summaries for each community. When answering a global query, the system summarises across relevant community clusters, achieving unprecedented synthesis quality.

In everyday terms

Standard vector search is like looking through a library using a flashlight that illuminates one paragraph at a time. It works well if you want a specific recipe, but fails if you ask "How has the author's philosophy on governance evolved across their 10 books?" GraphRAG is like turning on the library's main ceiling lights: it maps the family tree of themes and chapters, revealing high-level structures that individual flashlight beams completely miss.

02 Step by step

  1. Extract entity and relationship graphs: prompt an LLM to extract all entities, descriptions, and relational claims from document chunks.
  2. Construct and reconcile graph: merge duplicate entity nodes and resolve coreferences to build a connected knowledge graph.
  3. Perform hierarchical community detection: run the Leiden or Louvain algorithm to partition the graph into hierarchical clusters of related entities.
  4. Generate community summaries: synthesize pre-computed narrative summaries for each detected cluster at varying levels of abstraction.
  5. Execute global query retrieval: map the user query against community summaries, collect parallel partial answers, and synthesize a comprehensive global response.
  6. Execute multi-hop local retrieval: combine vector similarity over entity nodes with graph traversal to trace multi-hop relationship paths.

03 The maths

  1. Graph Modularity for Community Detection (Leiden)

    Q = \frac{1}{2m} \sum_{ij} \left[ A_{ij} - \gamma \frac{k_i k_j}{2m} \right] \delta(c_i, c_j)

    Measures the density of connections within communities compared to connections between communities, scaled by total edges $m$ and resolution $\gamma$.

  2. Multi-Hop Path Score Formulation

    \text{Score}(\text{Path}) = \prod_{e \in \text{Edges}} \text{Sim}(q, \text{Description}(e))

    Scores multi-hop reasoning chains by accumulating semantic alignment along connecting entity relationships.

04 Key takeaways

  • GraphRAG overcomes the "blind spots" of vector similarity by constructing relational graphs across disjoint documents.
  • Hierarchical community detection (Leiden) creates structured summaries of themes across entire document corpora.
  • Combining graph-based path traversal with semantic search enables explainable multi-hop deduction.

05 In code

python
import numpy as np

class ToyGraphRAG:
    """Demonstrates entity-relation graph construction and community retrieval."""
    def __init__(self):
        self.entities = {}
        self.edges = []
        self.communities = {}

    def add_relation(self, e1, rel, e2):
        self.edges.append((e1, rel, e2))
        self.entities.setdefault(e1, []).append(e2)
        self.entities.setdefault(e2, []).append(e1)

    def multi_hop_search(self, start_entity, target_relation):
        """Finds 2-hop connected entities matching target relation."""
        results = []
        # Hop 1: Neighbours of start entity
        for (e1, r1, e2) in self.edges:
            if e1 == start_entity:
                intermediate = e2
                # Hop 2: Relationships from intermediate entity
                for (ie1, r2, final_e) in self.edges:
                    if ie1 == intermediate and r2 == target_relation:
                        results.append((start_entity, r1, intermediate, r2, final_e))
        return results

# Populate synthetic corporate knowledge graph
graph = ToyGraphRAG()
graph.add_relation("DeepMind", "subsidiary_of", "Alphabet")
graph.add_relation("Alphabet", "headquartered_in", "California")
graph.add_relation("Alphabet", "founded_by", "Larry Page")

# Multi-hop query: "Where is DeepMind's parent company located?"
chains = graph.multi_hop_search("DeepMind", "headquartered_in")

print("GraphRAG Multi-Hop Retrieval Result:")
for chain in chains:
    print(f"  Path: {chain[0]} --[{chain[1]}]--> {chain[2]} --[{chain[3]}]--> {chain[4]}")
print(f"\nDeduced Fact: DeepMind's parent company is located in '{chains[0][4]}'")

Common pitfalls

  • Excessive LLM token cost during graph construction; parsing millions of pages into entity triples requires substantial batch processing budgets.
  • Graph fragmentation from noisy entity resolution; if "Google" and "Google LLC" remain separate disconnected nodes, multi-hop traversals break.

06 Check yourself

Q1Why does traditional vector-based RAG struggle with global queries like "What are the major themes across this entire 500-page dataset?"

Why: Global summary queries have no single localized text match; GraphRAG solves this by pre-computing hierarchical community summaries of entire topic clusters.

Q2What role does community detection (such as the Leiden algorithm) play in GraphRAG?

Why: Community detection identifies naturally cohesive topic clusters in the knowledge graph, allowing hierarchical summaries to represent entire subject areas.

Q3What is a "multi-hop" query in question answering?

Why: Multi-hop queries require traversing intermediate relationships (e.g. Entity A -> Entity B -> Entity C) where no single document states the direct link.
