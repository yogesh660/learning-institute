The agent loop: ReAct

The ReAct (Reasoning and Acting) framework establishes the foundational architectural paradigm for autonomous LLM agents. By interleaving chain-of-thought reasoning steps with environment interactions through external tool execution, ReAct enables models to perform dynamic planning, query real-time information, verify intermediate results, and self-correct trajectory errors. The execution loop operates as a cyclic state machine: perceiving current environment observations, formulating internal thoughts, selecting and parameterising tool actions, observing execution feedback, and iterating until reaching a termination condition or final answer.

01 The idea

Pure large language models suffer from two symmetric limitations: Chain-of-Thought (CoT) reasoning allows deep internal deliberation but is cut off from the outside world, unable to verify facts or query real-time data; while pure action systems (such as blind API calling) execute commands without deliberate planning, making them fragile to errors and unable to adapt when unexpected results occur. The ReAct framework synergises reasoning and acting into a unified cyclic loop. How does an agent maintain working memory, deliberate on observations, and safely navigate complex multi-step objectives?

Synergising Reasoning and Action: In human problem solving, we constantly alternate between thinking and doing. When cooking a new recipe, you don't plan 50 actions blindly upfront, nor do you sit motionless thinking without touching ingredients. You read a step (observation), deliberate on timing and proportions (thought), measure an ingredient or adjust the burner (action), inspect the colour and aroma (observation), and decide next steps. ReAct translates this human cognition pattern into AI systems.

The Thought-Action-Observation Loop: - Thought: The agent generates an internal reasoning trace analysing the current state, diagnosing previous errors, and breaking down sub-goals ("I need the stock price of Apple on 12 May 2024. First I must query the financial API"). - Action: The agent outputs a structured tool invocation with specific arguments (Action: stock_ticker(symbol='AAPL', date='2024-05-12')). - Observation: The external environment or sandbox executes the tool and injects the raw result back into the prompt context (Observation: 182.52 USD). - Loop Continuation: The agent absorbs the observation, reasons about whether the goal has been achieved, and either triggers another action or outputs Final Answer: ...

Error Recovery and Self-Correction: When an API fails with a 404 or invalid parameter error, a naive script crashes. A ReAct agent reads the error message inside its Observation step, reflects in its Thought step ("The ticker was not found. Perhaps I should search for the company's full corporate name first"), and takes corrective action.

In everyday terms

Think of an investigator solving a mystery. If they only sit in an armchair thinking (Chain-of-Thought), they cannot discover new physical clues. If they run around opening random doors and arresting people without thinking (blind Action), they cause chaos. The successful detective uses ReAct: they inspect the crime scene (Observation), deduce that the suspect must have fled through the window (Thought), check the alleyway CCTV footage (Action), view the footage showing a blue sedan (Observation), deduce that they need the registration database (Thought), query the database (Action), and finally solve the case (Final Answer).

03 The maths

  1. ReAct Trajectory Representation and State Space

    \tau_t = \left(x, \, r_1, a_1, o_1, \, r_2, a_2, o_2, \, \dots, \, r_t, a_t, o_t\right) \in (\mathcal{X} \times (\mathcal{R} \times \mathcal{A} \times \mathcal{O})^t)

    The agent trajectory \tau_t at step t begins with user prompt x \in \mathcal{X} followed by triples of thoughts r_i \in \mathcal{R} (reasoning traces), actions a_i \in \mathcal{A} (external tool commands), and observations o_i \in \mathcal{O} (environment feedback received from execution \mathcal{E}(a_i)).

  2. Autoregressive Factorisation of Reason-Action Policy

    p(\tau_T \mid x) = \prod_{t=1}^T p_\theta(r_t \mid \tau_{t-1}, x) \cdot p_\theta(a_t \mid \tau_{t-1}, r_t, x), \quad o_t \sim p_{\text{env}}(o_t \mid a_t, s_t)

    The language model \theta generates thoughts r_t and actions a_t conditioned on complete historical context \tau_{t-1}. Unlike ungrounded generation, observations o_t are sampled from the external environment p_{\text{env}} at environmental state s_t, grounding future reasoning in verifiable external reality.

  3. Loop Guardrail and Convergence Bound

    \text{StopCondition}(\tau_t) = \mathbb{I}\Big(a_t = \text{Finish}(y)\Big) \lor \mathbb{I}\Big(t \ge T_{\max}\Big) \lor \mathbb{I}\Big(\text{Cost}(\tau_t) \ge C_{\max}\Big)

    Because autonomous agent loops can experience degenerative behaviour such as infinite repetition loops or runaway API calls, safety guardrails terminate execution whenever the model signals completion, hits step limit T_{\max}, or exceeds monetary budget C_{\max}.

04 Key takeaways

  • ReAct synergises Chain-of-Thought reasoning with external environment actions into an interleaved Thought-Action-Observation loop.
  • Reasoning traces allow the agent to decompose goals, track progress, and diagnose execution errors, while actions interact with dynamic external environments.
  • Observations from tools are injected directly back into the agent's prompt history, allowing it to adapt to real-world feedback in real time.
  • Safety guardrails including maximum step limits and tool parameter validation are essential to prevent infinite thrashing loops.

05 In code

python
"""
The ReAct Agent Execution Loop
Demonstrating Thought-Action-Observation interleaving, tool execution,
working memory updates, and safety step limits.
"""

import re
from typing import Callable, Dict, Any, List

class ToolRegistry:
    def __init__(self):
        self.tools: Dict[str, Callable] = {}
        self.descriptions: Dict[str, str] = {}

    def register(self, name: str, desc: str):
        def decorator(func: Callable):
            self.tools[name] = func
            self.descriptions[name] = desc
            return func
        return decorator

    def execute(self, tool_name: str, argument: str) -> str:
        if tool_name not in self.tools:
            return f"Error: Tool '{tool_name}' does not exist. Available tools: {list(self.tools.keys())}"
        try:
            return str(self.tools[tool_name](argument.strip()))
        except Exception as e:
            return f"Execution Error in '{tool_name}': {str(e)}"

# Initialise Tool Registry
registry = ToolRegistry()

@registry.register("calculate", "Evaluate basic arithmetic expressions. Argument: mathematical expression string.")
def tool_calculate(expr: str) -> str:
    # Safe evaluator for demonstration
    clean = re.sub(r'[^0-9+\-*/(). ]', '', expr)
    return str(eval(clean))

@registry.register("lookup_price", "Look up product pricing from warehouse catalog. Argument: item name.")
def tool_lookup_price(item: str) -> str:
    db = {"laptop": 1200, "monitor": 350, "docking station": 150, "mouse": 25}
    key = item.lower().strip()
    if key in db:
        return f"{db[key]} USD"
    return f"Item '{item}' not found in catalog."

class ReActAgent:
    def __init__(self, registry: ToolRegistry, max_steps: int = 5):
        self.registry = registry
        self.max_steps = max_steps

    def _mock_llm_decide(self, trajectory: str) -> str:
        """
        Simulated LLM simulating Thought -> Action sequence conditioned on trajectory.
        In production, this calls a language model API with stop tokens.
        """
        if "Observation:" not in trajectory:
            return (
                "Thought: The user wants to know the total price for 2 monitors and 1 docking station. "
                "First, I need to lookup the unit price of a monitor.\n"
                "Action: lookup_price\n"
                "Action Input: monitor"
            )
        elif "monitor" in trajectory and "docking station" not in trajectory:
            return (
                "Thought: The monitor costs 350 USD. Now I need to check the price of a docking station.\n"
                "Action: lookup_price\n"
                "Action Input: docking station"
            )
        elif "docking station" in trajectory and "calculate" not in trajectory:
            return (
                "Thought: A docking station costs 150 USD and a monitor costs 350 USD. "
                "Now I will calculate: (2 * 350) + 150.\n"
                "Action: calculate\n"
                "Action Input: (2 * 350) + 150"
            )
        else:
            return (
                "Thought: The calculation yielded 850. I now have all required facts to conclude.\n"
                "Final Answer: The total cost for 2 monitors and 1 docking station is 850 USD."
            )

    def run(self, user_objective: str) -> Dict[str, Any]:
        """Execute the cyclic ReAct loop."""
        print(f"=== Starting ReAct Agent Loop for Objective: '{user_objective}' ===")
        trajectory = f"Question: {user_objective}\n"
        step = 1

        while step <= self.max_steps:
            print(f"\n--- Step {step} ---")
            # 1. Generate Thought and Action
            llm_output = self._mock_llm_decide(trajectory)
            trajectory += llm_output + "\n"

            # Check for Final Answer termination
            if "Final Answer:" in llm_output:
                final_answer = llm_output.split("Final Answer:")[1].strip()
                print(f"[Agent Decided] {llm_output}")
                return {"status": "SUCCESS", "steps": step, "final_answer": final_answer, "trace": trajectory}

            # 2. Parse Action and Action Input
            action_match = re.search(r"Action:\s*([a-zA-Z0-9_]+)", llm_output)
            input_match = re.search(r"Action Input:\s*(.+)", llm_output)

            if not action_match or not input_match:
                print(f"[Parse Error] Failed to parse Action/Input from:\n{llm_output}")
                return {"status": "FAILED_PARSE", "steps": step, "trace": trajectory}

            tool_name = action_match.group(1).strip()
            tool_input = input_match.group(1).strip()

            print(f"Thought: {re.search(r'Thought:(.*?)(?=Action:|$)', llm_output, re.DOTALL).group(1).strip()}")
            print(f"Action: {tool_name}({tool_input})")

            # 3. Execute Tool Environment
            observation = self.registry.execute(tool_name, tool_input)
            print(f"Observation: {observation}")

            # 4. Ingest Observation back into Trajectory
            trajectory += f"Observation: {observation}\n"
            step += 1

        print("\n[Safety Limit] Exceeded maximum allowed steps.")
        return {"status": "MAX_STEPS_EXCEEDED", "steps": step, "trace": trajectory}

# --- Demonstration Run ---
agent = ReActAgent(registry, max_steps=5)
result = agent.run("What is the total price for 2 monitors and 1 docking station?")

print("\n=== Agent Run Summary ===")
print("Status:", result["status"])
print("Steps Taken:", result["steps"])
print("Final Output:", result["final_answer"])

Common pitfalls

  • Running without step limits: When an agent encounters an unresolvable error, it will repeatedly query the broken tool indefinitely, draining token budgets and crashing servers.
  • Brittle regex parsing of actions: Standard LLM outputs often vary spacing or casing; robust agents use structured output modes (JSON schema / function calling) or resilient grammar parsers.
  • Over-reliance on reasoning without checking observations: Failing to condition subsequent thoughts strictly on the returned tool output leads to cascading delusional loops.

06 Check yourself

Q1Why does ReAct outperform pure Chain-of-Thought (CoT) on multi-step fact-seeking tasks?

Why: Pure Chain-of-Thought is isolated from the physical world and prone to hallucinating facts or dates. ReAct interleaves reasoning with external tool calls (APIs, search engines, databases), grounding its reasoning in verifiable observations.

Q2What is the purpose of the 'Observation' step in the ReAct loop?

Why: The Observation step injects the environment's response (API JSON, database rows, arithmetic answer, or error messages) into the working prompt, providing empirical evidence for the agent's next Thought step.

Q3How does a ReAct agent handle an unexpected API error (such as a 404 Not Found)?

Why: Unlike deterministic scripts that throw fatal exceptions, an agent absorbs the error message as an observation, reflects on the failure mode in its next thought, and autonomously initiates corrective actions.
