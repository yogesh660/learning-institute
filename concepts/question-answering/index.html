Question Answering: Extractive SQuAD, Multi-Hop Reasoning, and Open-Domain QA

Extractive QA (SQuAD) identifies continuous start and end token indices within a provided reference passage that answer the question. Open-Domain QA (ODQA) decouples into a retriever that scans millions of passages and a reader that extracts or synthesizes the final answer. Multi-hop QA (HotpotQA) requires gathering disjoint clues across multiple disparate documents to deduce the correct conclusion. Evaluation benchmarks evaluate exact match (EM) and token-level macro-averaged F1 score against ground-truth answer strings.

01 The idea

Question Answering (QA) tests a system's ability to retrieve, understand, and synthesize answers to natural language inquiries. Architectures range from span-extractive reading comprehension on benchmark datasets like SQuAD to complex multi-hop reasoning over knowledge graphs and retriever-reader open-domain pipelines.

When you take an open-book reading comprehension test, you read a paragraph and answer a question by underlining the exact phrase that gives the answer. This is Extractive QA (popularised by SQuAD). For instance, given the text "Marie Curie was awarded the Nobel Prize in Chemistry in 1911", and the question "When did Curie win her Chemistry Nobel?", an extractive model predicts start index 9 and end index 9 to extract "1911". In Open-Domain QA, no passage is provided: the system must first act as a search engine to retrieve the right articles from Wikipedia, then read them to find the answer. In Multi-Hop QA, answering the question requires connecting separate clues: e.g. "What team does the quarterback who won the 2021 Super Bowl play for?" requires first discovering who won in 2021, and second finding that player's team.

In everyday terms

Extractive QA is like using an index finger to point directly at a single sentence in a brochure handed to you. Open-Domain QA is walking into a multi-storey library, finding the correct aisle, pulling down the right book, and pointing at the page. Multi-Hop QA is following a scavenger hunt where Clue #1 inside an envelope in the attic directs you to open a safe in the basement to find the prize.

02 Step by step

  1. Format input pair: concatenate the question tokens and context paragraph tokens separated by a `[SEP]` delimiter.
  2. Encode joint sequence: process the concatenated tokens through a bidirectional transformer encoder.
  3. Predict span boundaries: compute linear projections of each token embedding to yield start and end probability distributions.
  4. Filter candidate spans: apply dynamic programming to select the span $(i, j)$ maximising $P_{\text{start}}(i) \times P_{\text{end}}(j)$ where $j \ge i$ and span length $\le L_{\max}$.
  5. Handle unanswerable questions: if the `[CLS]` token score exceeds valid span scores, predict that the question cannot be answered from the text.
  6. Evaluate metrics: compare extracted string against reference spans using Exact Match (EM) binary score and token-overlap F1 score.

04 Key takeaways

  • Extractive reading comprehension predicts start and end token indices of answer spans within source paragraphs.
  • Open-domain QA combines an information retriever with a reader model to locate answers across millions of documents.
  • Evaluation benchmarks evaluate Exact Match (strict binary) and token-level F1 overlap to quantify comprehension accuracy.

05 In code

python
import numpy as np

def score_extractive_span(start_logits, end_logits, max_answer_len=5):
    """Finds optimal start and end span maximising joint probability."""
    # Convert logits to probabilities
    def softmax(z):
        exp_z = np.exp(z - np.max(z))
        return exp_z / np.sum(exp_z)
        
    p_start = softmax(start_logits)
    p_end = softmax(end_logits)
    
    best_score = -1.0
    best_span = (0, 0)
    N = len(start_logits)
    
    for i in range(N):
        for j in range(i, min(N, i + max_answer_len)):
            score = p_start[i] * p_end[j]
            if score > best_score:
                best_score = score
                best_span = (i, j)
                
    return best_span, best_score

def compute_qa_f1(pred_tokens, gold_tokens):
    """Computes token-level F1 overlap score."""
    common = set(pred_tokens) & set(gold_tokens)
    if not common:
        return 0.0
    p = len(common) / len(pred_tokens)
    r = len(common) / len(gold_tokens)
    return (2 * p * r) / (p + r)

# Simulation: "Marie Curie received the Nobel Prize in 1911"
# Tokens: [CLS] When did Curie win ? [SEP] Marie Curie received the Nobel Prize in 1911 [SEP]
tokens = ["[CLS]", "When", "did", "Curie", "win", "?", "[SEP]", 
          "Marie", "Curie", "received", "the", "Nobel", "Prize", "in", "1911", "[SEP]"]

# Simulated logits from model head
start_logits = np.array([-5, -5, -5, -5, -5, -5, -5,  0.1, 0.2, 0.1, 0.0, 0.1, 0.2, 0.1, 8.5, -5])
end_logits   = np.array([-5, -5, -5, -5, -5, -5, -5,  0.1, 0.1, 0.0, 0.1, 0.1, 0.2, 0.1, 8.9, -5])

span, conf = score_extractive_span(start_logits, end_logits)
extracted_answer = tokens[span[0]:span[1] + 1]

print(f"Extracted Span Indices: {span}")
print(f"Extracted Answer:       '{' '.join(extracted_answer)}' (Confidence: {conf:.4f})")

f1 = compute_qa_f1(extracted_answer, ["1911"])
print(f"Token-Level F1 Score:   {f1:.2f}")

Common pitfalls

  • Assuming all questions are answerable from the passage; SQuAD 2.0 requires systems to abstain when the text does not contain the answer.
  • Extracting grammatically invalid spans by omitting the constraint $i \le j$, causing negative length predictions.
  • Evaluating extractive QA models on generative responses without accounting for semantic equivalence (e.g. marking "two" incorrect when gold is "2").

06 Check yourself

Q1How does an extractive QA model like BERT-SQuAD predict an answer from a context paragraph?

Why: Extractive QA identifies the answer as a continuous span within the context document by predicting the start token index and end token index.

Q2What defines a "multi-hop" question answering task (such as HotpotQA)?

Why: Multi-hop QA requires connecting intermediate reasoning steps across distinct texts where no single document contains all necessary information to answer the question.

Q3In SQuAD evaluation, what is the difference between Exact Match (EM) and F1 score?

Why: Exact Match requires character-for-character agreement with the reference answer, whereas F1 treats predicted and ground-truth answers as bags of tokens and calculates their harmonic mean overlap.
