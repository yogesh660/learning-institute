Metric Design and North-Star Metrics

Architecting primary, proxy, and guardrail metric frameworks to align algorithmic optimisation with sustainable user value and business health.

01 The idea

Every machine learning model and product feature relentlessly optimises whatever quantitative objective function it is given. If you define a naive metric like daily clicks or raw sign-ups, algorithms exploit clickbait, spam notifications, and deceptive UI patterns, causing long-term churn—an outcome known as Goodhart's Law. Robust metric design constructs a balanced hierarchy: a single North-Star Metric capturing core customer value exchange, supported by sensitive input proxies and strictly enforced guardrails.

Imagine leading product data science for a video streaming service. The executive committee announces that the primary target for the recommendation engine is "Total Video Plays". Your team tunes the recommender to autoplay 5-second teaser clips whenever a user hovers their mouse over a thumbnail. Total video plays triple within two weeks, and the leadership dashboard looks euphoric. Six months later, paid subscription renewals drop by 25%. Users were exasperated by unexpected blaring audio and irrelevant recommendations. The metric skyrocketed while genuine customer satisfaction and long-term lifetime value cratered.

A true North-Star Metric (NSM) represents the precise intersection of customer-experienced value and long-term enterprise sustainability. It is rarely raw revenue (which is a lagging accounting output) or top-of-funnel activity (which is easily gamed). For Spotify, it is "Time Spent Listening to Music" (not app launches or search clicks). For Airbnb, it is "Nights Booked" (not total search queries). For Slack, it is "Daily Active Teams Sending Messages" (measuring collaborative network utility). When the North-Star Metric increases honestly, both user utility and enterprise value expand simultaneously.

Because a North-Star Metric is often slow and lagging—measuring 90-day retention takes 90 days—teams decompose it into two operational pillars: leading input proxies and guardrails. Input proxies are sensitive, fast-moving metrics in early lifecycle stages (e.g. streaming 3 songs in the first 24 hours) that statistically correlate with downstream retention. Guardrail metrics are non-negotiable boundaries that protect customer trust and system integrity, such as page latency ceilings, unsubscribe rates, and customer support ticket frequency.

In everyday terms

A ship navigating open ocean: the North Star indicates the true navigational destination, responsive helm adjustments serve as leading input proxies, and hull depth sensors act as non-negotiable guardrails against submerged reefs.

02 Step by step

  1. Identify core value exchange: isolate the fundamental transaction where the user derives genuine utility from the product.
  2. Formulate the North-Star Metric: define a measurable rate or composite volume that reflects successful value exchanges (e.g. Weekly Active Users Streaming > 1 hour).
  3. Derive leading input proxies: run regression and correlation analyses to find sensitive behavioural actions in days 1 to 7 that predict long-term 90-day retention.
  4. Establish non-negotiable guardrails: fix strict operational thresholds on user trust and engineering reliability (e.g. p99 latency < 250ms, spam reports < 0.1%).
  5. Conduct Goodhart adversarial review: stress-test metrics by hypothesising how automated algorithms or rogue incentives could inflate numbers without creating customer value.

03 The maths

  1. Proxy metric statistical sensitivity and predictive power

    R^2 = \frac{\text{Cov}(M_{\text{proxy}}, Y_{\text{long-term}})^2}{\text{Var}(M_{\text{proxy}}) \cdot \text{Var}(Y_{\text{long-term}})}, \qquad \text{SNR} = \frac{\Delta \bar{M}_{\text{proxy}}}{\sqrt{\text{Var}(\Delta M_{\text{proxy}})}}

    Where $M_{\text{proxy}}$ is an early behavioural signal, $Y_{\text{long-term}}$ is ultimate customer retention or lifetime value, and $\text{SNR}$ is the signal-to-noise ratio in A/B test horizons. A valid operational proxy must maximise both correlation with long-term value and statistical sensitivity to short-term product changes.

  2. Multi-objective constrained metric optimisation

    \max_{\boldsymbol{\theta}} \mathbb{E}\left[ M_{\text{north-star}}(\boldsymbol{\theta}) \right] \quad \text{subject to} \quad G_j(\boldsymbol{\theta}) \le c_j \quad \forall j \in \{1, \dots, J\}

    Where $\boldsymbol{\theta}$ represents algorithmic hyperparameters or UI design variants, and $G_j(\boldsymbol{\theta}) \le c_j$ enforces $J$ guardrail constraints such as user unsubscribe rates, technical latency budgets, or regulatory compliance limits.

  3. Goodhart divergence decomposition

    \Delta \text{TrueValue} = \beta_1 \Delta M + \beta_2 (\Delta M)^2 + \epsilon

    When an indicator $M$ is converted into an aggressive target, unmodelled feedback loops induce quadratic penalties ($\beta_2 < 0$). Beyond an optimal threshold, incremental metric gains erode real customer value through annoyance, fatigue, or spam.

04 Key takeaways

  • Goodhart's Law dictates that any metric transformed into a sole target ceases to be a reliable measure due to systemic gaming.
  • A North-Star Metric captures the reciprocal delivery of customer value and sustainable business growth.
  • Pairing primary goals with non-negotiable guardrails prevents models from cannibalising customer trust or degrading infrastructure.

05 In code

python
import numpy as np

np.random.seed(42)
n_users = 200
# User early engagement: meaningful content hours vs notification clicks
meaningful_hours = np.random.exponential(2.0, size=n_users)
notification_clicks = np.random.poisson(15, size=n_users)

# True 90-day retention driven strongly by meaningful hours, weakly by clicks
retention_logit = -1.5 + 0.8 * meaningful_hours + 0.02 * notification_clicks + np.random.normal(0, 0.3, size=n_users)
retained_90d = (1 / (1 + np.exp(-retention_logit)) > 0.5).astype(int)

corr_meaningful = np.corrcoef(meaningful_hours, retained_90d)[0, 1]
corr_clicks = np.corrcoef(notification_clicks, retained_90d)[0, 1]

print(f"Proxy correlation with 90-day retention: meaningful hours = {corr_meaningful:.3f}")
print(f"Vanity metric correlation with retention: notification clicks = {corr_clicks:.3f}")
print(f"Recommended North-Star input proxy: meaningful hours (R2={corr_meaningful**2:.2f})")

Common pitfalls

  • Targeting top-of-funnel vanity metrics (e.g. app downloads, page views) that exhibit zero correlation with recurring customer retention.
  • Using long-lagging metrics directly as A/B test criteria, delaying decision velocity by months rather than using validated leading proxies.
  • Omitting negative guardrail constraints, allowing recommendation engines to inflate click numbers via clickbait or notification bombardment.

06 Check yourself

Q1What does Goodhart's Law imply in the context of machine learning product optimisation?

Why: Goodhart's Law states that when a measure becomes a target, it ceases to be a good measure because optimisation processes exploit loopholes (e.g. clickbait to drive clicks).

Q2Why is raw monthly revenue generally unsuitable as an operational North-Star Metric for iterative A/B testing?

Why: Revenue is an output outcome that lags product interventions by months. A North-Star Metric should capture the leading value exchange that ultimately drives revenue.

Q3What is the primary architectural purpose of a guardrail metric in an experimentation framework?

Why: Guardrail metrics act as protective safety checks, ensuring that interventions designed to improve a primary metric do not quietly inflict unacceptable harm elsewhere.
