01 The idea

A document can belong to Politics, Economics, and Tech simultaneously; an image can contain a dog, a frisbee, and a tree. Multi-label learning addresses non-exclusive target vectors while accounting for label correlations.

In conventional classification, classes are strictly mutually exclusive: an email is either spam or not spam (binary), or an image is either a cat, dog, or bird (multi-class). In contrast, real-world objects frequently possess multiple simultaneous attributes: a film can belong to Comedy, Drama, and Romance; a biomedical article can discuss Genetics, Oncology, and Immunology; a customer can be tagged as Churn-Risk, High-Spender, and Mobile-User.

Multi-label learning maps feature vector $x$ to a binary target vector $y = [y_1, y_2, \dots, y_L]^T \in \{0, 1\}^L$. The fundamental algorithmic choice revolves around how to handle correlations among labels.

The simplest strategy is Binary Relevance: decompose the problem into $L$ completely independent binary classification tasks, one per label. While embarrassingly parallel and scalable, Binary Relevance is blind to label dependencies: knowing an image contains a "beach" vastly increases the probability of "ocean" and "sand", but Binary Relevance cannot exploit this co-occurrence.

Classifier Chains overcome this blind spot by ordering labels into a sequence and training each classifier with both original features $x$ and the ground-truth/predicted binary labels of all preceding classifiers in the chain. Label Powerset transforms the task into multi-class classification by treating every unique observed label combination as a distinct class, which models correlations perfectly but suffers from severe class explosion on rare combinations. Modern neural architectures employ independent sigmoid heads trained with binary cross-entropy loss.

In everyday terms

Imagine assigning tags to songs in a music streaming library (e.g. Acoustic, Rock, Ballad, 90s, Instrumental). Binary Relevance hires five separate interns who sit in isolated soundproof booths and evaluate one tag each without speaking to each other. Classifier Chains seats the interns in a line: each intern listens to the song and glances at the tag decisions made by previous interns before making their own call.

03 The maths

  1. Hamming Loss

    \operatorname{HL}(Y, \hat{Y}) = \frac{1}{n \cdot L} \sum_{i=1}^n \sum_{j=1}^L \mathbb{I}(Y_{ij} \neq \hat{Y}_{ij}) = \frac{1}{n \cdot L} \|Y \oplus \hat{Y}\|_1

    Measures the fraction of individual label mistakes across all instances and labels. A lower Hamming loss indicates higher per-label accuracy.

  2. Subset Accuracy (Exact Match Ratio)

    \operatorname{Acc}_{\mathrm{subset}} = \frac{1}{n} \sum_{i=1}^n \mathbb{I}(Y_i = \hat{Y}_i)

    The strictest metric: requires the entire predicted binary label vector to match ground truth exactly. Can be low even when individual label accuracy is above 95%.

  3. Classifier Chain Conditional Factorisation

    P(y_1, \dots, y_L \mid x) = \prod_{j=1}^L P(y_j \mid x, y_1, \dots, y_{j-1})

    By the probability chain rule, joint label probability factorises into a product of conditional probabilities, implemented by conditioning each classifier on previous predictions.

04 Key takeaways

  • Multi-label classification assigns instances multiple non-mutually exclusive binary labels $y \in \{0, 1\}^L$.
  • Binary Relevance trains $L$ independent binary models; fast and scalable but ignores label co-occurrence dependencies.
  • Classifier Chains condition each label on predictions of preceding labels, capturing dependencies via the probability chain rule.
  • Standard multi-class Softmax activation is replaced with independent Sigmoids $\sigma(z_j)$ trained via binary cross-entropy loss.
  • Evaluated via Hamming Loss (per-label error rate) and Subset Accuracy (fraction of instances where all labels match exactly).

05 In code

python
import numpy as np
from sklearn.linear_model import LogisticRegression

# Multi-label classification: Binary Relevance vs Classifier Chains from scratch
np.random.seed(42)
n_samples = 300
n_features = 8
n_labels = 4

# Generate synthetic correlated multi-label dataset
X = np.random.normal(0, 1, (n_samples, n_features))
# Latent signals generating co-occurring tags
latent_topic = X[:, 0] + X[:, 1]

# Labels with strong dependencies (e.g. Label 2 often co-occurs with Label 0)
y = np.zeros((n_samples, n_labels), dtype=int)
y[:, 0] = (latent_topic + np.random.normal(0, 0.5, n_samples) > 0).astype(int)
y[:, 1] = (X[:, 2] - X[:, 3] + np.random.normal(0, 0.5, n_samples) > 0).astype(int)
y[:, 2] = (y[:, 0] * 0.7 + X[:, 4] + np.random.normal(0, 0.5, n_samples) > 0.3).astype(int)
y[:, 3] = (y[:, 1] * 0.8 + X[:, 5] + np.random.normal(0, 0.5, n_samples) > 0.4).astype(int)

# Train/Test Split
n_train = 200
X_train, X_test = X[:n_train], X[n_train:]
y_train, y_test = y[:n_train], y[n_train:]

# 1. Binary Relevance (L independent models)
br_models = [LogisticRegression(solver='liblinear') for _ in range(n_labels)]
for j in range(n_labels):
    br_models[j].fit(X_train, y_train[:, j])

y_pred_br = np.column_stack([m.predict(X_test) for m in br_models])

# 2. Classifier Chains (Sequential conditioning)
chain_order = [0, 1, 2, 3]
chain_models = []
X_train_augmented = X_train.copy()

for j in chain_order:
    clf = LogisticRegression(solver='liblinear')
    clf.fit(X_train_augmented, y_train[:, j])
    chain_models.append(clf)
    # Augment feature matrix with true labels during training
    X_train_augmented = np.column_stack([X_train_augmented, y_train[:, j]])

# Predict with Classifier Chain sequentially
X_test_augmented = X_test.copy()
y_pred_chain = np.zeros_like(y_test)

for idx, j in enumerate(chain_order):
    preds_j = chain_models[idx].predict(X_test_augmented)
    y_pred_chain[:, j] = preds_j
    # Augment test features with PREDICTED labels
    X_test_augmented = np.column_stack([X_test_augmented, preds_j])

# Evaluation
def eval_multilabel(y_true, y_pred):
    hamming_loss = np.mean(y_true != y_pred)
    subset_acc = np.mean(np.all(y_true == y_pred, axis=1))
    return hamming_loss, subset_acc

hl_br, sa_br = eval_multilabel(y_test, y_pred_br)
hl_chain, sa_chain = eval_multilabel(y_test, y_pred_chain)

print(f"Binary Relevance  - Hamming Loss: {hl_br:.4f}, Subset Accuracy: {sa_br*100:.1f}%")
print(f"Classifier Chains - Hamming Loss: {hl_chain:.4f}, Subset Accuracy: {sa_chain*100:.1f}%")
print(f"Subset Accuracy Improvement: +{(sa_chain - sa_br)*100:.1f}% by capturing label correlations")

Common pitfalls

  • Using Softmax instead of Sigmoid: Softmax enforces a sum-to-one constraint across classes, forcing classes to compete and failing on multi-label targets.
  • Error propagation in Classifier Chains: If early classifiers in a chain make erroneous predictions, downstream classifiers receive corrupted features during inference.
  • Evaluating multi-label models with multi-class accuracy: Multi-class accuracy assumes a single scalar output; multi-label problems require Hamming loss or Macro/Micro F1.

06 Check yourself

Q1Why is independent Sigmoid activation used instead of Softmax in multi-label neural network heads?

Why: Softmax forces probabilities across all classes to sum to 1, assuming mutual exclusivity. Multi-label problems require each label to possess an independent probability in [0, 1] via Sigmoid.

Q2What is the primary trade-off of Classifier Chains compared to Binary Relevance?

Why: By feeding preceding predictions as features, Classifier Chains capture label correlations. However, early classification mistakes propagate down the chain, and training cannot be fully parallelised.
