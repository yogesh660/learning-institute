SIFT, ORB and feature matching

Local feature descriptors encode image keypoints into compact mathematical representations that remain invariant to scale, planar rotation, 3D viewpoint variation, and illumination changes. SIFT (Scale-Invariant Feature Transform) detects scale-space extrema across Difference-of-Gaussians (DoG) octaves, assigns canonical gradient orientations, and extracts 128-dimensional spatial gradient histograms. ORB (Oriented FAST and Rotated BRIEF) offers a patented-free, computationally efficient real-time alternative suited for mobile robotics and visual SLAM, combining oriented FAST keypoints with intensity-centroid rotation and 256-bit binary descriptors compared via ultra-fast Hamming distance.

01 The idea

Detecting where interesting points lie in an image is only half the battle. To stitch panoramas, track drone trajectories, or locate objects across different cameras, an algorithm must match keypoints between completely different viewpoints—where the target may have rotated, shrunk to half its size, or moved under harsh glare. Raw pixel patches fail immediately under the slightest rotation or zoom. SIFT and ORB solve this challenge by building invariant local descriptors: mathematical fingerprints tied to each keypoint that allow millions of visual features to be queried and matched with high fidelity.

Scale-space and the scale-invariance challenge: When an object moves further away from the camera, its image projection shrinks. A fine corner detected by a fixed $3 \times 3$ filter at close range disappears into a smooth blur at a distance. David Lowe solved this in SIFT using Gaussian scale-space: repeatedly blurring and subsampling the image into octaves, and computing Difference-of-Gaussians (DoG) pyramids ($D(x, y, \sigma) = L(x, y, k\sigma) - L(x, y, \sigma)$). Scale-space extrema—pixels that are simultaneously greater or smaller than all 26 neighbouring pixels in a $3 \times 3 \times 3$ spatial-scale volume—establish keypoint locations with an intrinsic, scale-invariant characteristic radius $\sigma$.

Rotational canonicalisation: If a camera rotates by $45^\circ$, raw pixel neighbourhoods rotate along with it. To achieve rotation invariance, both SIFT and ORB assign a canonical orientation $\theta$ to each keypoint. In SIFT, local gradient orientations inside the keypoint's scale circle are accumulated into a 36-bin histogram; the dominant peak defines the keypoint's local coordinate system. All subsequent descriptor measurements are rotated relative to this canonical direction, rendering the descriptor rotation-invariant.

SIFT's gradient histogram descriptor: SIFT defines a $16 \times 16$ sample region centred on the keypoint, aligned with its canonical orientation. This window is partitioned into a $4 \times 4$ grid of spatial sub-blocks. Inside each sub-block, gradient magnitudes are binned into an 8-direction orientation histogram. The resulting descriptor vector contains $4 \times 4 \times 8 = 128$ floating-point values. Normalising the vector to unit Euclidean length provides invariance to linear contrast changes, while thresholding large values at $0.2$ and re-normalising mitigates non-linear saturation effects.

ORB's binary speed revolution: While SIFT's 128-dimensional floating-point vectors yield unmatched discriminative power, computing and matching them using Euclidean distances consumes prohibitive CPU cycles on embedded robotic platforms. Ethan Rublee et al. introduced ORB in 2011 as an open-source, ultra-fast alternative. ORB uses FAST for keypoint detection, computes an intensity centroid vector $C$ to measure local orientation $\theta = \arctan2(m_{01}, m_{10})$, and steers a pre-selected set of 256 pixel-pair intensity comparison tests (Rotated BRIEF). Each test yields a single Boolean bit ($I(x) < I(y)$), forming a 256-bit (32-byte) binary string. Matching two ORB descriptors requires only a bitwise XOR followed by a hardware population count (Hamming distance), executing in a single CPU cycle.

In everyday terms

Think of matching visual features like identifying suspects from security camera footage. Matching raw pixel patches is like comparing passport photos pixel-by-pixel: if a suspect turns their head by five degrees or steps into the sun, every single pixel value changes, and the computer declares no match. SIFT is like a forensic sketch artist: it measures invariant proportions—relative eye spacing, nose bridge angle, and cheekbone ratios—normalised so that distance from the camera and tilt of the head do not alter the measurements. It produces a detailed 128-point biometric dossier. ORB is like a rapid border-control checklist: it asks 256 quick yes/no questions ("Is point A darker than point B? Is point C brighter than point D?"), steering the questions to follow head tilt. Matching suspects is reduced to counting how many checkmarks disagree, allowing a smartphone to match thousands of faces per second.

03 The maths

  1. Difference-of-Gaussians (DoG) scale-space

    D(x, y, \sigma) = (G(x, y, k\sigma) - G(x, y, \sigma)) * I(x, y) = L(x, y, k\sigma) - L(x, y, \sigma)

    Here $G(x, y, \sigma) = \frac{1}{2\pi\sigma^2} e^{-(x^2 + y^2)/(2\sigma^2)}$. The difference between successive blurred scales $D(x, y, \sigma)$ provides an efficient $O(1)$ numerical approximation to the scale-normalised Laplacian of Gaussian $\sigma^2 \nabla^2 G$, whose zero-crossings and extrema denote stable multi-scale blob centres.

  2. Intensity centroid orientation (ORB)

    m_{pq} = \sum_{x, y \in W} x^p y^q I(x, y), \quad C = \left(\frac{m_{10}}{m_{00}}, \frac{m_{01}}{m_{00}}\right), \quad \theta = \arctan2(m_{01}, m_{10})

    The moments $m_{10}$ and $m_{01}$ calculate the intensity-weighted centre of mass within circular window $W$. Because the intensity centroid $C$ shifts consistently with physical patch rotation, the angle $\theta$ provides an orientation anchor that can be computed using simple addition without gradient evaluation.

  3. Hamming distance and Lowe's ratio test

    d_{\text{Hamming}}(u, v) = \sum_{i=1}^{B} (u_i \oplus v_i), \quad \text{Accept match if } \frac{\|f - g_1\|}{\|f - g_2\|} < \tau

    For binary descriptors $u, v \in \{0, 1\}^B$, Hamming distance counts differing bits via bitwise XOR ($\oplus$) and hardware population count (POPCNT). In Lowe's ratio test, $g_1$ is the best match and $g_2$ is the second-best match; threshold $\tau \approx 0.75$ eliminates over $90\%$ of false matches while retaining $85\%$ of correct matches.

04 Key takeaways

  • Local feature descriptors provide invariant representations that allow matching keypoints across rotation, scale, and lighting shifts.
  • SIFT detects extrema in Difference-of-Gaussians (DoG) scale-space, assigning scale and canonical orientation to each keypoint.
  • SIFT descriptors pool spatial gradients into a $4 \times 4$ grid of 8-bin histograms, forming a 128-dimensional floating-point vector.
  • ORB achieves real-time speed on embedded devices by combining oriented FAST keypoints with 256-bit binary BRIEF descriptors matched via Hamming distance.
  • Lowe's ratio test ($d_1 / d_2 < 0.75$) eliminates ambiguous false matches from repetitive textures by comparing nearest and second-nearest neighbour distances.

05 In code

python
import numpy as np

# Simulate keypoint orientation and binary descriptor extraction (ORB-style)
np.random.seed(42)

# 1. Create a synthetic circular patch (radius 7, diameter 15)
R = 7
y, x = np.ogrid[-R:R+1, -R:R+1]
mask = (x*x + y*y) <= R*R
patch = np.zeros((2*R+1, 2*R+1), dtype=np.float32)

# Create an asymmetric intensity pattern (e.g. brighter on one side)
patch[mask] = 50.0
patch[y > 0] += 100.0  # Bottom half is brighter

# 2. Compute intensity centroid orientation
m00 = np.sum(patch[mask])
m10 = np.sum(x * patch * mask)
m01 = np.sum(y * patch * mask)

# Orientation angle in radians and degrees
theta = np.arctan2(m01, m10)
print(f"Patch intensity moments: m00={m00:.1f}, m10={m10:.1f}, m01={m01:.1f}")
print(f"Canonical orientation angle: {np.degrees(theta):.1f} degrees")

# 3. Define 256 binary test pairs (pixel coordinates relative to center)
# In practice, these are pre-selected pairs learned by machine learning
num_tests = 256
test_x1 = np.random.randint(-5, 6, size=num_tests)
test_y1 = np.random.randint(-5, 6, size=num_tests)
test_x2 = np.random.randint(-5, 6, size=num_tests)
test_y2 = np.random.randint(-5, 6, size=num_tests)

def extract_oriented_brief(img_patch, angle):
    # Rotate test point coordinates by canonical angle theta
    cos_t = np.cos(angle)
    sin_t = np.sin(angle)
    
    rx1 = np.round(test_x1 * cos_t - test_y1 * sin_t).astype(int) + R
    ry1 = np.round(test_x1 * sin_t + test_y1 * cos_t).astype(int) + R
    rx2 = np.round(test_x2 * cos_t - test_y2 * sin_t).astype(int) + R
    ry2 = np.round(test_x2 * sin_t + test_y2 * cos_t).astype(int) + R
    
    # Binary intensity comparison test: bit is 1 if I(p1) < I(p2) else 0
    bits = img_patch[ry1, rx1] < img_patch[ry2, rx2]
    # Pack 256 boolean bits into 32 uint8 bytes
    return np.packbits(bits)

desc1 = extract_oriented_brief(patch, theta)

# 4. Simulate a matched descriptor with 5% bit noise
noise_mask = np.random.rand(num_tests) < 0.05
bits_noisy = np.unpackbits(desc1) ^ noise_mask.astype(np.uint8)
desc2 = np.packbits(bits_noisy)

# 5. Fast Hamming distance via bitwise XOR and bit counting
def hamming_distance(d1, d2):
    xor_bytes = np.bitwise_xor(d1, d2)
    return np.sum(np.unpackbits(xor_bytes))

dist_match = hamming_distance(desc1, desc2)

# Unrelated random descriptor for ratio test comparison
desc_unrelated = np.random.randint(0, 256, size=32, dtype=np.uint8)
dist_unrelated = hamming_distance(desc1, desc_unrelated)

print(f"\nDescriptor size: {desc1.nbytes} bytes (256 bits)")
print(f"Hamming distance to true match:      {dist_match} bits (low distance = match)")
print(f"Hamming distance to unrelated point: {dist_unrelated} bits (chance level ~ 128)")
print(f"Lowe's ratio (d1 / d2):              {dist_match / dist_unrelated:.3f} (< 0.75 threshold: ACCEPTED)")

Common pitfalls

  • Using Euclidean distance to match binary descriptors: Applying Euclidean distance to binary ORB or BRIEF descriptors is mathematically incorrect and orders of magnitude slower than computing bitwise Hamming distance with popcount instructions.
  • Skipping Lowe's ratio test: Matching keypoints based purely on minimum distance without comparing against the second-best match retains catastrophic false positives in regions with repetitive visual patterns (such as tiles or windows).
  • Assuming 3D out-of-plane rotation invariance: SIFT and ORB are designed for 2D in-plane rotation and modest affine perspective changes; extreme viewpoint shifts (exceeding $50^\circ$ to $60^\circ$ tilt) require affine adaptations (ASIFT) or deep feature extractors.
  • Ignoring image boundary margins: Keypoint descriptor extraction requires examining $16 \times 16$ or $31 \times 31$ pixel neighbourhoods; attempting to extract descriptors for keypoints situated along the image boundary causes array index out-of-bounds errors unless padded or pruned.
  • Unnormalised SIFT descriptors: Failing to normalise the 128-dimensional SIFT vector to unit Euclidean norm destroys invariance to multiplicative illumination changes.

06 Check yourself

Q1Why does SIFT construct a Difference-of-Gaussians (DoG) scale-space pyramid?

Why: Subtracting adjacent Gaussian blurred images ($L(x, y, k\sigma) - L(x, y, \sigma)$) computes the Difference-of-Gaussians, which provides a fast, scale-invariant approximation of the Laplacian of Gaussian operator $\sigma^2 \nabla^2 G$.

Q2How does SIFT achieve rotational invariance when extracting its 128-dimensional descriptor vector?

Why: By identifying the dominant gradient orientation $\theta$ inside the keypoint's neighbourhood and rotating the $16 \times 16$ descriptor grid by $-\theta$, all gradient measurements are recorded relative to the intrinsic orientation of the feature.

Q3What makes ORB descriptors significantly faster to match than standard SIFT descriptors in real-time robotics?

Why: SIFT requires computing Euclidean distances across 128 floating-point numbers ($128$ multiplies and additions per pair). ORB matches 256-bit binary vectors using bitwise XOR and a CPU popcount instruction, executing orders of magnitude faster.

Q4In Lowe's ratio test, why is a feature match accepted only if the ratio of the nearest neighbour distance to the second-nearest neighbour distance ($d_1 / d_2$) is below a threshold (e.g. $0.75$)?

Why: When matching points on repetitive textures (such as a brick wall or fence), many candidate points look equally plausible ($d_1 \approx d_2$, ratio near 1.0). Lowe's ratio test rejects these ambiguous candidates while accepting distinctive, unique matches.
