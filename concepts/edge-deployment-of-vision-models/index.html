Edge Deployment of Vision Models: Quantisation, Pruning, ONNX, and TensorRT

Edge deployment balances a tripartite trade-off among latency (frames per second), memory footprint (SRAM and DRAM), and task accuracy. Quantisation maps continuous 32-bit floating-point weights and activations to 8-bit integers (INT8) using symmetric or affine scaling. Post-Training Quantisation (PTQ) calibrates scale and zero-point offsets using representative data; Quantisation-Aware Training (QAT) simulates rounding errors during backpropagation. Graph optimisations (operator fusion, constant folding) and runtime engines (TensorRT, ONNX Runtime, OpenVINO) maximise hardware throughput.

01 The idea

Deploying high-accuracy vision models to resource-constrained edge hardware requires rigorous model compression and compilation. Post-training quantisation (PTQ), quantisation-aware training (QAT), structured pruning, and hardware-optimised compilation via ONNX and TensorRT reduce memory footprint, latency, and power consumption while preserving perceptual fidelity.

Research vision models are typically developed using 32-bit floating-point arithmetic (FP32) on high-power desktop GPUs. Moving those models to mobile processors, drones, or embedded automotive microcontrollers faces strict constraints: limited thermal envelopes (5–15 Watts), low memory bandwidth, and strict millisecond deadlines. Converting FP32 tensors to 8-bit integers (INT8) immediately reduces memory storage and bandwidth by 4x. Moreover, modern integer arithmetic logic units (ALUs) and Tensor Cores compute INT8 matrix multiplies up to 4x faster than FP32. Combined with layer fusion—such as merging a 2D convolution, batch normalisation, and ReLU into a single GPU kernel invocation—compiled execution engines minimise memory roundtrips and maximise throughput.

In everyday terms

Imagine shipping a sprawling encyclopaedia set across town on a bicycle courier. Sending 30 massive hardbound volumes (FP32) requires multiple heavy trips and slow reading. Quantisation is like re-typesetting the text into compact paperback digests using a clear, simplified vocabulary (INT8) that fits into a single backpack with virtually zero loss of practical meaning.

02 Step by step

  1. Select architecture suited for edge execution: prefer depthwise-separable blocks, inverted residuals, or linear bottlenecks over heavy standard convolutions.
  2. Perform operator and layer fusion: fold batch normalisation parameters directly into convolutional weights and fuse consecutive activation functions.
  3. Quantise weights and activations: apply symmetric INT8 quantisation for stationary weights and calibrated affine quantisation for dynamic activation distributions.
  4. Export to intermediate representation: serialize the model graph to ONNX format, verifying operator support and static vs dynamic input shapes.
  5. Compile with target runtime engine: build an execution engine using TensorRT, OpenVINO, or TFLite, enabling kernel autotuning for target edge hardware.

04 Key takeaways

  • Edge deployment demands aggressive memory bandwidth reduction; converting FP32 to INT8 yields immediate 4x storage and throughput gains.
  • Layer fusion algebraically incorporates batch normalisation into preceding convolutional weights, eliminating wasteful memory roundtrips.
  • Hardware compilation engines like TensorRT leverage hardware-specific kernel autotuning to match targeted GPU architectures.

05 In code

python
import numpy as np

def quantise_symmetric_int8(tensor):
    """Performs symmetric INT8 quantisation on continuous weights."""
    max_val = np.max(np.abs(tensor))
    scale = max_val / 127.0
    # Quantise and clamp to INT8 range [-127, 127]
    quantised = np.clip(np.round(tensor / scale), -127, 127).astype(np.int8)
    return quantised, scale

def dequantise_symmetric_int8(quantised, scale):
    """Reconstructs approximate FP32 tensor from INT8 and scale."""
    return quantised.astype(np.float32) * scale

def fold_conv_bn(conv_w, conv_b, bn_mean, bn_var, bn_gamma, bn_beta, eps=1e-5):
    """Folds Batch Normalisation into Conv2D weights and biases."""
    scale = bn_gamma / np.sqrt(bn_var + eps)
    fused_w = conv_w * scale[:, None, None, None]
    fused_b = (conv_b - bn_mean) * scale + bn_beta
    return fused_w, fused_b

# 1. Simulate Conv2D weights: (out_channels, in_channels, kh, kw)
np.random.seed(42)
conv_w = np.random.randn(8, 4, 3, 3).astype(np.float32) * 0.5
conv_b = np.zeros(8, dtype=np.float32)

# Simulate Batch Normalisation parameters
bn_mean = np.random.randn(8).astype(np.float32) * 0.1
bn_var = np.abs(np.random.randn(8).astype(np.float32)) + 0.5
bn_gamma = np.random.uniform(0.8, 1.2, size=8).astype(np.float32)
bn_beta = np.random.randn(8).astype(np.float32) * 0.05

# 2. Fuse Conv + BN layers into single parameter set
fused_w, fused_b = fold_conv_bn(conv_w, conv_b, bn_mean, bn_var, bn_gamma, bn_beta)

# 3. Apply Symmetric INT8 Quantisation to fused weights
q_w, scale = quantise_symmetric_int8(fused_w)
reconstructed_w = dequantise_symmetric_int8(q_w, scale)

mae = np.mean(np.abs(fused_w - reconstructed_w))
memory_fp32 = fused_w.nbytes
memory_int8 = q_w.nbytes

print(f"FP32 Weights Size: {memory_fp32} bytes")
print(f"INT8 Weights Size: {memory_int8} bytes (Compression: {memory_fp32 / memory_int8:.1f}x)")
print(f"Quantisation Mean Absolute Error: {mae:.6f}")

Common pitfalls

  • Applying post-training quantisation without a representative calibration dataset causes outlier clipping that severely degrades detection accuracy.
  • Leaving batch normalisation as separate standalone layers during inference wastes execution memory bandwidth with redundant global memory reads and writes.
  • Quantising sensitive layers (such as the initial convolutional stem or final detection classification heads) to INT8 without selective mixed-precision FP16 fallback.

06 Check yourself

Q1What is the primary operational advantage of layer fusion (e.g. folding Conv + BatchNorm + ReLU)?

Why: Layer fusion executes consecutive elementwise operations within fast on-chip registers and shared SRAM, avoiding costly off-chip DRAM memory bandwidth bottlenecks.

Q2How does Quantisation-Aware Training (QAT) differ from Post-Training Quantisation (PTQ)?

Why: QAT models the rounding and clamping error of INT8 arithmetic during forward passes while computing gradients via straight-through estimators, allowing the network to adapt to quantisation noise.

Q3Why is symmetric quantisation ($Z=0$) commonly chosen for neural network weight matrices?

Why: Symmetric quantisation centres the integer range around zero, meaning the hardware does not need to compute and accumulate zero-point cross-terms during high-speed matrix multiplications.
