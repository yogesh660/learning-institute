Dependency parsing

Dependency parsing analyses the grammatical structure of a sentence by establishing directed, typed relations between words. Unlike constituency grammars that partition sentences into nested hierarchical phrases, dependency representations connect lexical heads directly to their dependents (e.g. subject, direct object, modifier). Transition-based dependency parsers use a shift-reduce state machine to build projective parse trees in linear O(n) time.

01 The idea

When an NLP system needs to extract information from the sentence "The large enterprise acquired a promising robotics startup", it does not merely care that words occurred near each other. It must answer: Who acquired whom? What was large, and what was promising? Dependency parsing answers these semantic questions directly by revealing the grammatical skeleton: "enterprise" is the subject of "acquired", "startup" is the direct object, and "robotics" is a modifier.

Constituency versus dependency syntax: Phrase structure grammars (constituency) group words into nested syntactic brackets: sentences are divided into Noun Phrases and Verb Phrases. While mathematically elegant, constituency trees do not explicitly state which word is in charge. Dependency grammar cuts directly to the chase: words link directly to words through directed binary arcs. Every phrase has a single head word (the governor) that determines its syntactic category, and all other words in the phrase are dependents modifying that head.

The conveyor belt intuition of shift-reduce parsing: Think of transition-based parsing like an assembly line. Words arrive one by one on an input buffer (the conveyor belt). You pick up words and place them on a stack (your workbench). At each step, you decide whether to pull another word onto the workbench (SHIFT), link the top two words on the bench with a directed relationship where the second modifies the first (LEFT-ARC), or link them where the first modifies the second (RIGHT-ARC). When an arc is formed, the dependent word is removed, keeping only the head available to link with future words.

Projectivity and crossing arcs: When words are written out in linear order, a dependency tree is projective if every dependency arc can be drawn as an arc above the words without any lines crossing. Most English sentences are projective. However, languages with flexible word order (such as German, Latin, or Russian) and long-distance topicalisation produce crossing arcs (non-projectivity), requiring graph-based parsing algorithms like Chu-Liu-Edmonds maximum spanning trees.

In everyday terms

Imagine building a family tree or corporate organisational chart. Constituency parsing is like drawing circles around departments: "Engineering Department", "Backend Team", "Platform Squad". It tells you which group people belong to, but does not tell you who reports to whom. Dependency parsing is the actual reporting tree: Employee A reports to Team Lead B, who reports to Director C, who reports to the Chief Executive (the ROOT). Finding who is responsible for an action is as simple as tracing the directed arrows from manager to subordinate.

03 The maths

  1. Formal dependency tree structural axioms

    d_{\text{in}}(w_0) = 0, \quad \forall i \ge 1: d_{\text{in}}(w_i) = 1, \quad G = (V, A) \text{ is acyclic}

    A valid dependency tree over vocabulary nodes $V = \{w_0 = \text{ROOT}, w_1, \dots, w_n\}$ must be a directed spanning tree rooted at $w_0$, where every non-root word has in-degree exactly 1 with no directed cycles.

  2. Arc-Standard transition operators

    \begin{aligned} \text{SHIFT} &: (\sigma, b_0 \mid \beta, A) \implies (\sigma \mid b_0, \beta, A) \\ \text{LEFT-ARC}_r &: (\sigma \mid s_1 \mid s_0, \beta, A) \implies (\sigma \mid s_0, \beta, A \cup \{(s_0, r, s_1)\}) \\ \text{RIGHT-ARC}_r &: (\sigma \mid s_1 \mid s_0, \beta, A) \implies (\sigma \mid s_1, \beta, A \cup \{(s_1, r, s_0)\}) \end{aligned}

    Here $\sigma$ denotes the stack with elements $s_1, s_0$, $\beta$ is the buffer with head $b_0$, and $A$ is the accumulated set of dependency arcs. LEFT-ARC requires $s_1 \ne \text{ROOT}$.

  3. Unlabelled (UAS) and Labelled (LAS) Attachment Scores

    \operatorname{UAS} = \frac{\sum_{i=1}^n \mathbb{I}(\hat{h}_i = h_i^*)}{n}, \quad \operatorname{LAS} = \frac{\sum_{i=1}^n \mathbb{I}(\hat{h}_i = h_i^* \land \hat{r}_i = r_i^*)}{n}

    UAS evaluates whether token $i$ is assigned the correct head index $h_i^*$. LAS is the stricter standard metric requiring simultaneous correctness of both the parent head $h_i^*$ and the grammatical relation label $r_i^*$.

04 Key takeaways

  • Dependency parsing represents syntax as directed, labelled binary relations between head words and their dependent modifiers.
  • A well-formed dependency tree is a rooted, connected, acyclic directed graph where each word has in-degree exactly 1 except ROOT.
  • Transition-based parsers build projective trees in linear O(n) time using a shift-reduce state machine over a stack and buffer.
  • Projective trees have no crossing dependency arcs; non-projective trees require graph-based parsing algorithms or swap transitions.
  • Parsing accuracy is measured by Unlabelled Attachment Score (UAS) for head accuracy and Labelled Attachment Score (LAS) for typed relation accuracy.

05 In code

python
class ArcStandardParser:
    """
    Deterministic Arc-Standard Transition-Based Dependency Parser.
    Simulates stack, buffer, and arc transitions with an oracle policy.
    """
    def __init__(self, sentence, gold_arcs=None):
        self.words = ["ROOT"] + sentence
        self.stack = [0]
        self.buffer = list(range(1, len(self.words)))
        self.arcs = []
        self.gold_arcs = gold_arcs or []
        self.history = []

    def can_left_arc(self):
        return len(self.stack) >= 2 and self.stack[-2] != 0

    def can_right_arc(self):
        return len(self.stack) >= 2

    def can_shift(self):
        return len(self.buffer) > 0

    def shift(self):
        tok = self.buffer.pop(0)
        self.stack.append(tok)
        self.history.append(f"SHIFT -> pushed '{self.words[tok]}'")

    def left_arc(self, relation="dep"):
        s0 = self.stack[-1]
        s1 = self.stack[-2]
        self.arcs.append((s0, relation, s1))
        self.stack.pop(-2)
        self.history.append(f"LEFT-ARC ({relation}): '{self.words[s0]}' -> '{self.words[s1]}'")

    def right_arc(self, relation="dep"):
        s0 = self.stack[-1]
        s1 = self.stack[-2]
        self.arcs.append((s1, relation, s0))
        self.stack.pop(-1)
        self.history.append(f"RIGHT-ARC ({relation}): '{self.words[s1]}' -> '{self.words[s0]}'")

    def is_terminal(self):
        return len(self.buffer) == 0 and len(self.stack) == 1 and self.stack[0] == 0

    def display_tree(self):
        print("\nExtracted Dependency Arcs:")
        sorted_arcs = sorted(self.arcs, key=lambda x: x[2])
        for head, rel, dep in sorted_arcs:
            h_word = self.words[head]
            d_word = self.words[dep]
            print(f"  {d_word:<12} (id={dep}) <--[{rel}]-- {h_word:<10} (id={head})")

# Example Sentence: "The quick cat caught the mouse"
tokens = ["The", "quick", "cat", "caught", "the", "mouse"]

parser = ArcStandardParser(tokens)

# Oracle transition sequence:
parser.shift()                          # Push 'The'
parser.shift()                          # Push 'quick'
parser.shift()                          # Push 'cat'
parser.left_arc(relation="amod")        # 'cat' -> 'quick'
parser.left_arc(relation="det")         # 'cat' -> 'The'
parser.shift()                          # Push 'caught'
parser.left_arc(relation="nsubj")       # 'caught' -> 'cat'
parser.shift()                          # Push 'the'
parser.shift()                          # Push 'mouse'
parser.left_arc(relation="det")         # 'mouse' -> 'the'
parser.right_arc(relation="obj")        # 'caught' -> 'mouse'
parser.right_arc(relation="root")       # 'ROOT' -> 'caught'

print(f"Terminal state reached? {parser.is_terminal()}")
print("\nTransition History:")
for step, action in enumerate(parser.history, 1):
    print(f"  {step:2d}. {action}")

parser.display_tree()

def evaluate_scores(predicted_arcs, gold_arcs, num_words):
    pred_heads = {dep: head for head, rel, dep in predicted_arcs}
    pred_labels = {dep: rel for head, rel, dep in predicted_arcs}
    
    gold_heads = {dep: head for head, rel, dep in gold_arcs}
    gold_labels = {dep: rel for head, rel, dep in gold_arcs}
    
    uas_correct = sum(1 for i in range(1, num_words + 1) if pred_heads.get(i) == gold_heads.get(i))
    las_correct = sum(1 for i in range(1, num_words + 1) if (pred_heads.get(i) == gold_heads.get(i) and pred_labels.get(i) == gold_labels.get(i)))
    
    return uas_correct / num_words, las_correct / num_words

uas, las = evaluate_scores(parser.arcs, parser.arcs, len(tokens))
print(f"\nUAS (Unlabelled Attachment Score): {uas * 100:.1f}%")
print(f"LAS (Labelled Attachment Score):   {las * 100:.1f}%")

Common pitfalls

  • Inverting arc direction: In Universal Dependencies, arcs point from governor head to dependent modifier (head -> dependent). Reversing the direction creates an upside-down tree that fails grammatical validation.
  • Assuming all sentences are projective: While English is over 99% projective, languages with flexible word order (German, Russian, Hindi, Latin) have widespread crossing arcs that cannot be parsed by standard Arc-Standard without swap actions.
  • Cascading error propagation in greedy transition systems: Because transition decisions are hard and irrevocable, an early incorrect shift or reduction permanently corrupts subsequent stack states. Beam search or graph-based parsers help avoid early commitment.
  • Including the ROOT token in UAS/LAS scores: Evaluation standards (such as CoNLL) explicitly exclude the artificial ROOT token (id 0) from the scoring denominator. Including it artificially inflates accuracy metrics.

06 Check yourself

Q1In Universal Dependencies parsing, what is the single-head structural constraint?

Why: In dependency grammar, every word depends on exactly one syntactic governor (in-degree d_in = 1). The only exception is the artificial ROOT token, which has in-degree 0 and serves as the structural anchor of the entire sentence.

Q2Why is the computational time complexity of Arc-Standard transition-based dependency parsing strictly O(n) linear with sentence length?

Why: In Arc-Standard parsing, each token in the buffer is shifted onto the stack exactly once (n shifts) and popped during a left-arc or right-arc reduction exactly once (n reductions). The total number of state transitions is bounded by 2n, proving strictly linear time complexity.

Q3What is the difference between Unlabelled Attachment Score (UAS) and Labelled Attachment Score (LAS)?

Why: UAS (Unlabelled Attachment Score) counts a word as correct if its assigned head matches the ground truth. LAS (Labelled Attachment Score) is a stricter metric that demands that both the head index and the specific dependency relation label match ground truth.
