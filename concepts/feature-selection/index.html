Feature Selection: Filter, Wrapper and Embedded Methods

Choosing which inputs a model sees. Fewer, better features mean faster, more robust and more explainable models.

01 The idea

Feature selection removes inputs that add noise, cost or risk without adding signal. Three families: filters score features independently, wrappers search subsets with a model, and embedded methods select during training.

Filter methods are fast and model-agnostic: correlation with the target, mutual information, chi-squared, variance thresholds. They can miss features that only matter in combination.

Wrapper methods such as recursive feature elimination (RFE) or forward selection train the model on candidate subsets and keep what helps. They respect interactions but are expensive and can overfit the selection to the validation data.

Embedded methods select as part of training: L1 zeroes coefficients, trees rank features by how much they reduce impurity or by permutation importance. Usually the best trade-off.

In everyday terms

Packing for a trip: filters weigh each item alone, wrappers try packing different bags, embedded methods pack as you go and leave behind what you never used.

02 Step by step

  1. Remove obvious junk: IDs, constants, near-duplicates, leaky columns.
  2. Filter by a cheap score to cut a very wide set down.
  3. Use an embedded or wrapper method with cross-validation on what remains.
  4. Check stability: does the same set survive across CV folds?
  5. Keep selection inside the CV pipeline so it does not see validation data.

03 Try it

Ten candidate features, three of which actually drive the target. Compare what a filter (correlation), an embedded method (lasso) and a wrapper (greedy forward selection) pick.

Things to try
  1. Find the feature that only matters through an interaction: the filter misses it, forward selection may not.
  2. Raise the noise and see which method still finds the true three.

04 The maths

  1. Mutual information

    $$I(X; Y) = \sum_{x,y}p(x,y)\log\frac{p(x,y)}{p(x)\,p(y)}$$

    Zero when the feature and target are independent; captures non-linear relationships that correlation misses.

  2. Permutation importance

    $$\mathrm{PI}_j = \text{score}(X) - \mathbb E\big[\text{score}(X^{\pi_j})\big]$$

    The drop in held-out score when feature $j$’s column is shuffled. Model-agnostic and honest, but shared between correlated features.

05 Key takeaways

  • Selection done outside cross-validation leaks: the selected set has already seen the validation folds.
  • Correlated features split importance between them; dropping one can make the other look more important.
  • Fewer features are worth a small accuracy loss when they make the model cheaper, more stable or easier to explain.

06 In code

python
from sklearn.pipeline import make_pipeline
from sklearn.feature_selection import SelectKBest, mutual_info_regression, RFECV
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import cross_val_score

filt = make_pipeline(SelectKBest(mutual_info_regression, k=5), LinearRegression())
print("filter CV R2:", cross_val_score(filt, X, y, cv=5).mean().round(3))

rfe = RFECV(LinearRegression(), step=1, cv=5).fit(X, y)                   # wrapper
print("RFE keeps:", list(X.columns[rfe.support_]))

Common pitfalls

  • Selecting on the full dataset and then cross-validating the model. Put selection inside the pipeline.
  • Trusting impurity importances for high-cardinality features.
  • Dropping a feature because it is weakly correlated with the target, when it matters through an interaction.

07 Check yourself

Q1Which family uses the model itself to evaluate subsets of features?

Why: Wrappers (RFE, forward/backward selection) train and score the model on candidate subsets.

Q2Lasso is an example of:

Why: Selection happens inside training via the L1 penalty.

Q3What is the main advantage of filter methods compared to wrapper methods?

Why: Filters rank features using statistical metrics (such as mutual information or Pearson correlation) directly against the target. They require zero model training iterations, making them scalable to tens of thousands of features.

Q4What does Mutual Information $I(X; Y) = 0$ between a feature $X$ and target $Y$ indicate?

Why: Mutual information is non-negative and equals zero if and only if $p(x, y) = p(x)p(y)$, meaning $X$ and $Y$ share no statistical dependence, linear or non-linear.

Q5Why can filtering features purely by Pearson correlation with the target cause you to discard critical predictive features?

Why: If $y = x^2$ for $x \in [-1, 1]$, the Pearson correlation $r \approx 0$ despite a deterministic relationship. Similarly, XOR interactions have zero marginal correlation with the outcome.

Q6What is the critical danger of performing feature selection on the complete dataset before splitting into cross-validation folds?

Why: If features are selected using the entire dataset, validation fold targets have already influenced the feature set. To obtain an honest out-of-sample estimate, feature selection must be fitted solely inside the training fold of each CV split.

Q7Why is mean decrease in impurity (Gini importance) unreliable when evaluating feature importance in decision trees and random forests?

Why: In decision trees, features with many distinct levels provide exponentially more split opportunities, allowing the tree to reduce impurity on noise. Permutation importance on validation data corrects this bias.

Q8Two input features $X_1$ and $X_2$ are almost perfectly collinear ($r = 0.99$) and both are strongly predictive of the target. When evaluated by permutation importance in a Random Forest, what typically happens?

Why: When correlated features are present, permuting $X_1$ does not severely hurt performance because the tree splits on $X_2$ to compensate. Dropping one of the collinear pair often causes the remaining feature's permutation importance to surge.

Q9How does Recursive Feature Elimination (RFE) select features?

Why: RFE is a greedy backward-selection wrapper: it trains the estimator, removes the feature with the smallest coefficient or feature importance, and refits on the remaining set until the target subset size is reached.

Q10For a dataset with $p = 10$ features, how many total non-empty feature subsets would an exhaustive, brute-force search have to train and evaluate?

Why: The number of possible non-empty subsets of $p$ items is $2^p - 1$. For $p = 10$, $2^{10} - 1 = 1{,}024 - 1 = 1{,}023$ candidate models. For large $p$, exhaustive search becomes computationally intractable, necessitating wrappers (greedy RFE) or embedded methods (Lasso).

Q11In a permutation importance test on a validation set of 1,000 samples, the baseline model achieves an $R^2$ of $0.82$. When column $X_3$ is randomly shuffled, the model's $R^2$ drops to $0.74$. What is the permutation importance $\mathrm{PI}_3$ of feature $X_3$, and how is it interpreted?

Why: Permutation importance is defined as $\mathrm{score}(X) - \mathrm{score}(X^{\pi_j})$. Here, $\mathrm{PI}_3 = 0.82 - 0.74 = 0.08$. A positive drop of $0.08$ indicates that the model relies meaningfully on $X_3$ for generalisation.

Q12Suppose discrete variables $X \in \{0, 1\}$ and $Y \in \{0, 1\}$ have joint distribution: $P(X=0, Y=0) = 0.50$, $P(X=1, Y=1) = 0.50$, and $P(X=0, Y=1) = P(X=1, Y=0) = 0$. What is the mutual information $I(X; Y)$ in nats? (Recall $\ln(2) \approx 0.693$).

Why: Marginals: $P(X=0) = 0.5$, $P(X=1) = 0.5$, and $P(Y=0) = 0.5$, $P(Y=1) = 0.5$. $I(X; Y) = \sum_{x,y} P(x,y)\ln\frac{P(x,y)}{P(x)P(y)}$. For $(0,0)$: $0.5 \ln\frac{0.5}{0.5 \times 0.5} = 0.5 \ln(2) \approx 0.5(0.693) = 0.3466$. For $(1,1)$: $0.5 \ln\frac{0.5}{0.5 \times 0.5} = 0.5 \ln(2) \approx 0.3466$. Total $I(X; Y) = 2 \times 0.3466 = 0.693$ nats. Since $X = Y$ perfectly, $I(X; Y) = H(X) = \ln(2) \approx 0.693$ nats.
