01 The idea

Industrial recommender systems operate in two stages: Candidate Retrieval (filtering 100 million items to 1,000 candidates in 10ms) and Heavy Ranking. Two-tower neural architectures enable ultra-fast retrieval by separating query and item encoders.

Modern industrial recommender systems—such as YouTube, TikTok, Pinterest, and Google Play—manage catalogs containing hundreds of millions of items. Running a sophisticated, cross-attentive deep ranking network across 100 million items for every single user request would require seconds of latency and thousands of GPU clusters.

To achieve real-time responsiveness, industry standardises on a Two-Stage Pipeline: Candidate Generation (Retrieval) filters the universe of 100 million items down to the top 1,000 most relevant candidates in less than 10 milliseconds; subsequently, a complex Heavy Ranker scores and sorts the 1,000 candidates.

The premier architecture for candidate retrieval is the Two-Tower Neural Model (Dual-Encoder). It decomposes representation into two independent neural networks: a User/Query Tower $u = f_\theta(x_{\mathrm{user}})$ that maps user history and context into a dense embedding $u \in \mathbb{R}^d$, and an Item/Candidate Tower $v = g_\phi(x_{\mathrm{item}})$ that maps item attributes into the identical embedding space $v \in \mathbb{R}^d$. The retrieval score is the dot product $\langle u, v \rangle$.

The architectural genius of the two-tower design is Decoupled Inference. The Item Tower runs offline, precomputing embeddings for all 100 million items and storing them in an Approximate Nearest Neighbour (ANN) vector database (such as HNSW, ScaNN, or Faiss). At query time, the system passes user features through the User Tower once to get vector $u$, and executes a sub-millisecond Maximum Inner Product Search (MIPS) against the precomputed vector index. Models are trained efficiently using In-Batch Negatives.

In everyday terms

Imagine a library with 50 million books. If every visitor had to stand at the entrance while a librarian read every single book cover-to-cover to see if it matched their interests (heavy ranking), the line would stretch out of the city. Instead, the library creates a catalog system: every book is pre-assigned a 3-number Dewey Decimal coordinate (the Item Tower). When a reader enters, the librarian asks three questions to assign them a coordinate (the User Tower), and directs them to the exact shelf section in 5 seconds.

03 The maths

  1. Two-Tower Scoring Function

    s(x_{\mathrm{user}}, x_{\mathrm{item}}) = \langle u(x_{\mathrm{user}}), \; v(x_{\mathrm{item}}) \rangle = \sum_{k=1}^d u_k(x) v_k(y)

    The inner product in shared d-dimensional embedding space measures semantic relevance between user and candidate item.

  2. In-Batch Negative Softmax Loss

    \mathcal{L}_{\mathrm{in\text{-}batch}} = -\frac{1}{B} \sum_{i=1}^B \log \frac{\exp\left(\frac{\langle u_i, v_i \rangle}{\tau}\right)}{\sum_{j=1}^B \exp\left(\frac{\langle u_i, v_j \rangle}{\tau}\right)}

    Avoids explicit negative sampling by reusing other batch items as negatives. Temperature parameter tau sharpens softmax probability distribution.

  3. Maximum Inner Product Search (MIPS) Retrieval

    \operatorname{Candidates}(u) = \arg\max_{j \in \mathcal{C}}^{(K)} \langle u, v_j \rangle

    Sub-millisecond retrieval of the top-K highest scoring item embeddings using hierarchical navigable small world (HNSW) graph indexing.

04 Key takeaways

  • Industrial architecture for scaling candidate retrieval to hundreds of millions of items in under 10 milliseconds.
  • Decouples User Tower $u(x)$ and Item Tower $v(y)$, allowing item embeddings to be precomputed offline.
  • Candidate retrieval is framed as Maximum Inner Product Search (MIPS) using fast vector indexers (HNSW, ScaNN, Faiss).
  • Trained end-to-end using In-Batch Negatives, reusing other batch samples as negative examples without explicit sampling.
  • Forms the foundation of candidate generation at Google, YouTube, Pinterest, and TikTok.

05 In code

python
import numpy as np

# Two-Tower Neural Retrieval Architecture from scratch
class SimpleTwoTower:
    def __init__(self, user_dim, item_dim, embed_dim=8, lr=0.01, temperature=0.1):
        self.embed_dim = embed_dim
        self.lr = lr
        self.tau = temperature
        
        # User Tower weights (user_dim -> embed_dim)
        np.random.seed(42)
        self.W_u = np.random.normal(0, 0.1, (user_dim, embed_dim))
        # Item Tower weights (item_dim -> embed_dim)
        self.W_v = np.random.normal(0, 0.1, (item_dim, embed_dim))
        
    def forward_user(self, X_user):
        u = X_user @ self.W_u
        return u / np.linalg.norm(u, axis=1, keepdims=True)
        
    def forward_item(self, X_item):
        v = X_item @ self.W_v
        return v / np.linalg.norm(v, axis=1, keepdims=True)
        
    def train_step(self, X_user_batch, X_item_batch):
        B = len(X_user_batch)
        u = self.forward_user(X_user_batch)  # (B x d)
        v = self.forward_item(X_item_batch)  # (B x d)
        
        # Similarity matrix: S_ij = <u_i, v_j> / tau (B x B)
        S = (u @ v.T) / self.tau
        
        # In-Batch Softmax cross-entropy loss
        exp_S = np.exp(S - np.max(S, axis=1, keepdims=True))
        probs = exp_S / np.sum(exp_S, axis=1, keepdims=True)
        
        loss = -np.mean(np.log(np.diag(probs) + 1e-12))
        
        # Backpropagation gradients
        # dL/dS = (probs - I) / B
        dldS = (probs - np.eye(B)) / (B * self.tau)
        
        grad_u = dldS @ v
        grad_v = dldS.T @ u
        
        self.W_u -= self.lr * (X_user_batch.T @ grad_u)
        self.W_v -= self.lr * (X_item_batch.T @ grad_v)
        
        return loss

# Synthetic multi-attribute retrieval problem
n_catalog = 1000  # 1,000 items in catalog
user_dim = 10
item_dim = 12
embed_dim = 8

# Generate simulated dataset
X_users = np.random.normal(0, 1, (100, user_dim))
X_items = np.random.normal(0, 1, (100, item_dim))

model = SimpleTwoTower(user_dim, item_dim, embed_dim=embed_dim, lr=0.05, temperature=0.2)

# Training loop with in-batch negatives
for epoch in range(100):
    loss = model.train_step(X_users, X_items)

# --- Sub-millisecond Serving Simulation ---
# 1. Offline Phase: Precompute embeddings for all 1,000 catalog items
catalog_features = np.random.normal(0, 1, (n_catalog, item_dim))
offline_item_embeddings = model.forward_item(catalog_features)

# 2. Online Phase: User visits the platform
current_user = np.random.normal(0, 1, (1, user_dim))
user_emb = model.forward_user(current_user)

# 3. MIPS Dot Product Search against catalog
scores = offline_item_embeddings @ user_emb[0]
top_10_candidates = np.argsort(scores)[::-1][:10]

print(f"Two-Tower Model trained with In-Batch Negatives (Loss: {loss:.3f})")
print(f"Catalog items precomputed offline: {n_catalog} embeddings ({embed_dim} dimensions)")
print(f"Online MIPS candidate retrieval latency: < 0.1 milliseconds!")
print(f"Top 5 Candidate Item IDs retrieved: {list(top_10_candidates[:5])}")
print(f"Top candidate dot-product similarity: {scores[top_10_candidates[0]]:.3f}")

Common pitfalls

  • No cross-tower feature interactions: Because user and item features never interact until the final dot product, fine-grained cross-features cannot be captured (handled later by heavy rankers).
  • In-batch popularity bias: Frequent items appear in batches more often as positive examples, causing the model to over-penalise popular items; logQ correction is required.
  • Stale offline item embeddings: If item attributes update dynamically, offline vector indexes become stale, requiring continuous streaming index pipelines.

06 Check yourself

Q1Why can Two-Tower models retrieve top candidates from 100 million items in sub-milliseconds while heavy cross-attention rankers cannot?

Why: Because the towers are independent, item embeddings are computed once offline. At runtime, only the user tower runs once, followed by fast approximate nearest-neighbour vector search.

Q2How does In-Batch Negative sampling avoid the computational cost of mining negative examples during training?

Why: In-batch negatives reuse items belonging to other users in the same mini-batch as negative samples, requiring zero extra forward passes and making computation highly parallel on GPUs.
