Machine translation

Machine Translation (MT) automates the conversion of text from one natural language into another while preserving semantic fidelity and grammatical fluency. Modern Neural Machine Translation (NMT) relies on the encoder-decoder Transformer architecture: a bidirectional encoder constructs deep contextual representations of the source sentence, while an autoregressive decoder generates the target translation word by word via cross-attention. Search strategies like beam search explore multiple candidate hypotheses, and translations are evaluated using metrics such as BLEU and chrF.

01 The idea

Translating between human languages is vastly more complex than substituting words from a bilingual dictionary. Word order shifts across linguistic families (e.g. English Subject-Verb-Object versus Japanese Subject-Object-Verb), grammatical gender must be reconciled across articles and adjectives, and idioms cannot be translated literally. Neural Machine Translation solves these challenges by mapping sentences into a universal semantic geometry and generating target text guided by cross-attention.

The Sequence-to-Sequence (Seq2Seq) challenge: In text classification, a variable-length sentence maps to a single discrete class. In machine translation, an input sequence of length S in language X must map to an output sequence of variable length T in language Y. Because S and T are rarely equal, translation requires an encoder to compress the source into continuous vectors and a decoder to unpack those vectors into target tokens until a stop token ([EOS]) is emitted.

Cross-attention: The bridge between languages: In the original Transformer, cross-attention acts as the dynamic alignment engine. The queries Q come from the target language decoder (representing what the model wants to write next), while the keys K and values V come from the source language encoder (representing what the original sentence said). The attention softmax dynamically highlights which source words the decoder should focus on at each translation step, directly replicating human bilingual alignment.

Beam search versus greedy translation: When generating a target sentence, picking the single most probable word at each step (greedy search) is risky: an early poor choice can trap the model in a dead end. Full combinatorial search across all |V|^T possible translations is impossible. Beam search maintains a fixed pool of the top B most promising hypotheses (the beam width, typically B = 4 to 8), expanding and pruning candidates at each step to discover globally fluent translations.

In everyday terms

Think of an expert simultaneous interpreter at the United Nations. As a French delegate speaks, the interpreter does not wait for a complete dictionary lookup of each word. The interpreter listens to the French phrase, absorbs its holistic meaning into their working memory (the encoder), and begins speaking fluent English (the decoder). As they speak, their mental cross-attention constantly glances back at key nouns and verbs in the French statement to ensure no diplomatic nuance is lost, while their internal grammar monitors ensure natural English phrasing.

03 The maths

  1. Encoder-decoder cross-attention formulation

    \operatorname{CrossAttention}(Q_{\text{tgt}}, K_{\text{src}}, V_{\text{src}}) = \operatorname{softmax}\left( \frac{Q_{\text{tgt}} K_{\text{src}}^T}{\sqrt{d_k}} \right) V_{\text{src}}

    Here $Q_{\text{tgt}} \in \mathbb{R}^{T \times d_k}$ is projected from target decoder hidden states, while $K_{\text{src}}, V_{\text{src}} \in \mathbb{R}^{S \times d_k}$ are projected from source encoder states. This allows target tokens to query source representations dynamically.

  2. Bilingual Evaluation Understudy (BLEU) score

    \operatorname{BLEU} = \operatorname{BP} \cdot \exp\left( \sum_{n=1}^N w_n \ln p_n \right), \quad \operatorname{BP} = \begin{cases} 1 & \text{if } c > r \\ \exp\left(1 - \frac{r}{c}\right) & \text{if } c \le r \end{cases}

    Here $p_n$ is clipped $n$-gram precision, $w_n = 1/N$ (typically $N = 4$), $c$ is candidate translation length, and $r$ is effective reference corpus length. The brevity penalty $\operatorname{BP}$ penalises candidates shorter than reference translations.

  3. Beam search length normalisation objective

    Because summing negative log-probabilities naturally favours shorter sequences, length penalty $\operatorname{LP}(Y)$ with parameter $\alpha \in [0.6, 0.8]$ normalises hypothesis scores to prevent premature termination.

04 Key takeaways

  • Neural Machine Translation maps variable-length source sentences to variable-length target sentences across languages.
  • The encoder-decoder Transformer uses bidirectional source encoding and causal target decoding linked via cross-attention.
  • Cross-attention dynamically aligns target generation steps with relevant source words, replacing heuristic statistical phrase tables.
  • Beam search tracks multiple high-probability translation hypotheses with length normalisation to avoid greedy sub-optimal traps.
  • BLEU evaluates translation quality by combining modified n-gram precision (n=1 to 4) with an exponential brevity penalty.

05 In code

python
import math
from collections import Counter

class BLEUEvaluator:
    """
    Sentence-level BLEU score calculation with modified n-gram
    precision and brevity penalty from scratch.
    """
    @staticmethod
    def modified_precision(candidate, reference, n):
        # Extract n-grams
        cand_ngrams = [tuple(candidate[i:i+n]) for i in range(len(candidate) - n + 1)]
        ref_ngrams = [tuple(reference[i:i+n]) for i in range(len(reference) - n + 1)]
        
        if not cand_ngrams:
            return 0.0
            
        cand_counts = Counter(cand_ngrams)
        ref_counts = Counter(ref_ngrams)
        
        # Clipped counts: count cannot exceed maximum occurrences in reference
        clipped_matches = sum(min(count, ref_counts.get(ng, 0)) for ng, count in cand_counts.items())
        total_cand = len(cand_ngrams)
        
        return clipped_matches / total_cand

    @classmethod
    def compute_bleu(cls, candidate_tokens, reference_tokens, max_n=4):
        c = len(candidate_tokens)
        r = len(reference_tokens)
        
        if c == 0:
            return 0.0
            
        # 1. Compute Brevity Penalty (BP)
        if c > r:
            bp = 1.0
        else:
            bp = math.exp(1.0 - (r / c))
            
        # 2. Geometric mean of precisions p_1 .. p_max_n
        log_prec_sum = 0.0
        weights = 1.0 / max_n
        
        for n in range(1, max_n + 1):
            p_n = cls.modified_precision(candidate_tokens, reference_tokens, n)
            if p_n == 0.0:
                # Smoothing: avoid log(0)
                p_n = 1e-9
            log_prec_sum += weights * math.log(p_n)
            
        bleu = bp * math.exp(log_prec_sum)
        return bleu, bp

# Example candidate translation and reference
reference = ["the", "cat", "sat", "on", "the", "mat"]
candidate_good = ["the", "cat", "was", "sitting", "on", "the", "mat"]
candidate_bad = ["the", "the", "the", "the", "the", "the"]

print("Reference Translation:  ", " ".join(reference))
print("Candidate 1 (Good):     ", " ".join(candidate_good))
print("Candidate 2 (Repeated): ", " ".join(candidate_bad))

bleu1, bp1 = BLEUEvaluator.compute_bleu(candidate_good, reference)
bleu2, bp2 = BLEUEvaluator.compute_bleu(candidate_bad, reference)

print("\nEvaluation Results:")
print(f"Candidate 1 -> BLEU: {bleu1 * 100:.2f}% (Brevity Penalty: {bp1:.4f})")
print(f"Candidate 2 -> BLEU: {bleu2 * 100:.2f}% (Brevity Penalty: {bp2:.4f})")
print("Notice how clipped precision prevents repeated 'the' from cheating!")

Common pitfalls

  • Evaluating translation without a brevity penalty: Without the brevity penalty, a candidate translation that outputs a single high-confidence word ("the") achieves 100% n-gram precision. Always enforce the BLEU brevity penalty.
  • Setting beam width too large: In beam search, setting beam width B too large (e.g. B > 30) paradoxically degrades BLEU scores by biasing search towards unnaturally short, generic hypotheses. Optimal beam width is typically B in [4, 8].
  • Tokenising languages with whitespace splitting: Languages such as Chinese, Japanese, and Thai do not use spaces between words. Naive tokenisation fails completely; use sentence-piece or character-level subword models (BPE/Unigram).
  • Hallucination under low-resource or out-of-domain input: Seq2Seq decoders can detach from source cross-attention when encountering unknown words or noisy text, generating fluent but completely fabricated target sentences.

06 Check yourself

Q1What is the primary role of the cross-attention mechanism in the encoder-decoder Transformer for Machine Translation?

Why: Cross-attention uses queries from the target decoder and keys/values from the source encoder. This allows the decoder to focus dynamically on the relevant source words as it generates each target token, replacing classical word alignment tables.

Q2Why does the BLEU metric include a Brevity Penalty (BP)?

Why: Precision only measures the fraction of proposed words that are correct. Without a brevity penalty, translating a 30-word sentence into just "The" yields 100% precision. The Brevity Penalty penalises candidates shorter than the reference: BP = exp(1 - r/c).

Q3Why is Beam Search preferred over simple greedy decoding in Neural Machine Translation?

Why: Greedy search picks the highest-probability word at each step independently. If that choice forces poor options later, greedy search cannot backtrack. Beam search explores the top B paths simultaneously, discovering globally fluent translations.
