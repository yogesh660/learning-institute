01 The idea

Object detection requires answering two questions simultaneously: where are the objects (localization), and what are they (classification)? While one-stage detectors (YOLO, SSD) prioritize inference speed by predicting boxes in a single dense pass, two-stage detectors prioritize localization precision. Tracing the evolutionary arc from original R-CNN to Fast R-CNN and Faster R-CNN explains how region proposals, RoI pooling, and the Region Proposal Network (RPN) unified detection into a single end-to-end trainable deep network.

Original R-CNN (Girshick et al., 2014) used classical Selective Search to generate $\approx 2,000$ candidate region proposals per image, warped each crop to $227 \times 227$ pixels, and ran each crop independently through AlexNet. This took 47 seconds per image and consumed gigabytes of disk space for cached features.

Fast R-CNN (2015) solved the redundant compute bottleneck: it passes the entire image through the convolutional backbone once, extracting a single global feature map. Region of Interest (RoI) Pooling then extracts a fixed-size $7 \times 7$ feature vector from the shared feature map for each proposal, accelerating inference by $146\times$.

However, Fast R-CNN was still bottle-necked by Selective Search on CPU ($approx 2$ seconds per image). Faster R-CNN (Ren et al., 2015) eliminated Selective Search entirely by introducing the Region Proposal Network (RPN): a small fully convolutional network that slides across the shared feature map, evaluating multi-scale Anchor Boxes to predict candidate proposals in 10 milliseconds.

The two-stage paradigm divides detection into: Stage 1 (RPN generates a few hundred high-recall candidate bounding boxes) and Stage 2 (Fast R-CNN head refines box coordinates and classifies categories). This separation produces high precision on small and crowded objects.

In everyday terms

Imagine an art appraiser and a museum guard inspecting a crowded gallery. In original R-CNN, the guard cuts out 2,000 physical patches from the canvas with scissors and carries them one by one to the appraiser's office. In Fast R-CNN, the appraiser takes one high-resolution photograph of the entire gallery and simply glances at different areas of the master photo. In Faster R-CNN, the appraiser replaces the manual guard with an automated laser pointer (the RPN) that highlights candidate paintings in real time.

02 Step by step

  1. Extract shared feature maps: Pass input image through convolutional backbone (e.g. ResNet-50 with Feature Pyramid Network) to generate feature maps.
  2. Slide Region Proposal Network (RPN): At each feature map cell, evaluate $k$ anchor boxes (e.g. 3 scales $\times$ 3 aspect ratios = 9 anchors).
  3. Classify objectness and regress proposals: RPN predicts binary objectness logits (foreground vs background) and 4 bounding box regression deltas $(\Delta x, \Delta y, \Delta w, \Delta h)$.
  4. Filter proposals with NMS: Select top 2,000 proposals during training (300 during inference) using Non-Maximum Suppression (IoU threshold 0.7).
  5. Extract fixed-size vectors via RoIAlign: Extract $7 \times 7$ feature maps for each proposal using bilinear interpolation (RoIAlign) to prevent quantization misalignment.
  6. Classify and refine (Stage 2): Pass pooled RoI features through fully connected heads to output $C$-class softmax probabilities and final category-specific bounding box offsets.

03 The maths

  1. Bounding Box Regression Delta Formulation

    t_x = \frac{x - x_a}{w_a}, \quad t_y = \frac{y - y_a}{h_a}, \quad t_w = \ln\left(\frac{w}{w_a}\right), \quad t_h = \ln\left(\frac{h}{h_a}\right)

    Parameterises ground truth box $(x, y, w, h)$ relative to anchor $(x_a, y_a, w_a, h_a)$ using translation normalisation and log-scale variance.

  2. Faster R-CNN Multi-Task Loss Objective

    \mathcal{L}(p, u, t, v) = \mathcal{L}_{\mathrm{cls}}(p, u) + \lambda [u \ge 1] \sum_{i \in \{x, y, w, h\}} \operatorname{Smooth}_{L_1}(t_i - v_i)

    Combines cross-entropy classification loss $\mathcal{L}_{\mathrm{cls}}$ with $\operatorname{Smooth}_{L_1}$ regression loss, active strictly for positive foreground boxes ($u \ge 1$).

  3. Smooth L1 Robust Regression Loss

    \operatorname{Smooth}_{L_1}(x) = \begin{cases} 0.5 x^2 & \text{if } |x| < 1 \\ |x| - 0.5 & \text{otherwise} \end{cases}

    Behaves as quadratic $L_2$ loss for small errors (preventing gradient oscillations) and linear $L_1$ loss for large errors (robust against outlier boxes).

04 Key takeaways

  • Two-stage detectors divide detection into proposal generation (Stage 1) and classification/refinement (Stage 2).
  • Fast R-CNN introduced RoI pooling on a single shared feature map, eliminating redundant forward passes.
  • Faster R-CNN introduced the Region Proposal Network (RPN), replacing CPU Selective Search with real-time GPU anchors.
  • RoIAlign replaced RoIPool, using bilinear interpolation to eliminate sub-pixel spatial rounding errors.

05 In code

python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SimpleRPNHead(nn.Module):
    """Educational demonstration of Region Proposal Network (RPN) head."""
    def __init__(self, in_channels: int = 256, num_anchors: int = 9):
        super().__init__()
        # 3x3 intermediate conv
        self.conv = nn.Conv2d(in_channels, in_channels, kernel_size=3, padding=1)
        # 1x1 conv for binary objectness (foreground vs background)
        self.cls_head = nn.Conv2d(in_channels, num_anchors * 2, kernel_size=1)
        # 1x1 conv for 4 bounding box deltas per anchor (dx, dy, dw, dh)
        self.reg_head = nn.Conv2d(in_channels, num_anchors * 4, kernel_size=1)

    def forward(self, feature_map: torch.Tensor):
        # feature_map shape: [batch, in_channels, H, W]
        t = F.relu(self.conv(feature_map))
        
        # Objectness logits: [batch, 2 * num_anchors, H, W]
        cls_logits = self.cls_head(t)
        # Box deltas: [batch, 4 * num_anchors, H, W]
        bbox_deltas = self.reg_head(t)
        return cls_logits, bbox_deltas

# Test on feature map (e.g. ResNet stride 16 on 224x224 image -> 14x14 grid)
rpn = SimpleRPNHead(in_channels=256, num_anchors=9)
feat = torch.randn(2, 256, 14, 14)
scores, deltas = rpn(feat)

total_anchors = 14 * 14 * 9
print(f"Feature map grid: 14x14 cells with 9 anchors per cell")
print(f"Total candidate proposals evaluated in parallel: {total_anchors:,} anchors per image")
print(f"Objectness scores shape: {scores.shape} | Box deltas shape: {deltas.shape}")

Common pitfalls

  • RoIPool quantization misalignment: In original Fast R-CNN, `RoIPool` rounded floating point coordinates to integers ($16.8 \to 16$), causing compounding spatial misalignments that ruined small object detection; use `RoIAlign`.
  • Extreme anchor class imbalance: 99.9% of anchors in an image belong to the background; if trained naively, the RPN predicts "background" everywhere; sample balanced minibatches with 1:1 or 1:3 positive-to-negative ratios.
  • Inference latency: While accurate, two-stage detectors require sequential proposal filtering and per-RoI forward passes, running at 10–25 FPS compared to YOLO's 60–120 FPS.

06 Check yourself

Q1What critical innovation in Faster R-CNN (Ren et al., 2015) enabled real-time end-to-end object detection?

Why: Fast R-CNN took 2 seconds per image because Selective Search ran on the CPU. Faster R-CNN replaced it with the neural RPN running in 10ms on the GPU.

Q2Why did Mask R-CNN replace `RoIPool` with `RoIAlign`?

Why: RoIPool rounded floating-point boundary coordinates, causing pixel drifts that broke pixel-level segmentation. RoIAlign uses bilinear interpolation without quantization.

Q3What is the role of Anchor Boxes in the Region Proposal Network (RPN)?

Why: Anchors provide multiscale reference templates (e.g. tall for pedestrians, wide for cars). The RPN simply predicts minor regression deltas relative to these known templates.
