Dynamic programming: value and policy iteration

Dynamic programming provides exact mathematical algorithms for solving Markov Decision Processes when the environmental dynamics (transition probabilities and reward functions) are fully known. Policy Iteration decomposes control into alternating stages of Policy Evaluation (computing true state values via the Bellman Expectation equation) and Policy Improvement (acting greedily with respect to evaluated values). Value Iteration condenses this into a single Bellman Optimality backup per sweep, iteratively propagating optimal values until convergence under the contraction mapping theorem.

01 The idea

If you possess a complete map of a maze—knowing every corridor, trap, and prize with exact probabilistic certainty—how should you compute the optimal navigation path? When an agent has complete knowledge of environmental physics, trial-and-error exploration is unnecessary. Dynamic programming applies Bellman's principle of optimality to compute the exact value of every state and extract the mathematically optimal policy without taking a single physical step.

Policy Evaluation as fixed-point relaxation: Given an arbitrary policy pi (for instance, walking in random directions), how good is it? Policy evaluation repeatedly applies the Bellman expectation backup across all states: V_{k+1}(s) = sum_a pi(a | s) sum_s' P(s' | s, a) [ R(s, a, s') + gamma V_k(s') ]. Because the Bellman operator is a contraction mapping, starting from any arbitrary initial vector (even all zeros), repeated sweeps converge monotonically to the true state values V^pi.

The Policy Improvement Theorem: Once state values V^pi are known, can we construct a better policy? The Policy Improvement Theorem proves that if an agent chooses an action greedily with respect to downstream values—selecting pi'(s) = argmax_a sum_s' P(s' | s, a) [ R(s, a, s') + gamma V^pi(s') ]—the new policy pi' is guaranteed to be strictly better than or equal to pi in every single state. Repeating this cycle guarantees reaching the globally optimal policy in finite steps.

Value Iteration: Truncating policy evaluation: Full policy iteration requires waiting for policy evaluation to converge completely before updating the policy. Value Iteration observes that complete evaluation is redundant: by immediately updating each state with the maximum possible action value—V_{k+1}(s) = max_a sum_s' P(s' | s, a) [ R(s, a, s') + gamma V_k(s') ]—it combines evaluation and improvement into a single unified sweep, dramatically reducing total computation.

In everyday terms

Think of planning a train network across an entire country. Policy Iteration is like designing a fixed train timetable, running passenger simulations for six months until ticket revenues stabilise completely (policy evaluation), and then asking station masters for improvements (policy improvement), repeating this slow cycle. Value Iteration is like a dynamic traffic computer that looks at the current travel times between adjacent cities and immediately updates the fastest route across every station simultaneously every evening. Both methods arrive at the identical optimal railway schedule, but Value Iteration avoids waiting for stagnant simulations.

03 The maths

  1. Policy Improvement Theorem guarantee

    q_\pi(s, \pi'(s)) \ge v_\pi(s) \implies v_{\pi'}(s) \ge v_\pi(s), \quad \forall s \in \mathcal{S}

    If selecting action $\pi'(s)$ greedily yields an expected return at least as high as current policy $\pi$, then following $\pi'$ thereafter guarantees equal or strictly superior state values across the entire state space.

  2. Value Iteration Bellman Optimality backup

    V_{k+1}(s) = \max_{a \in \mathcal{A}} \sum_{s' \in \mathcal{S}} P(s' \mid s, a) \left[ R(s, a, s') + \gamma V_k(s') \right]

    The Value Iteration update combines policy evaluation and greedy improvement in a single step. By Banach's fixed-point theorem, $V_k$ converges to unique optimal value $V^*$ at geometric rate $\gamma^k$.

  3. Value Iteration error bound and stopping condition

    \|V_{k+1} - V_k\|_\infty < \theta \implies \|V_{k+1} - V^*\|_\infty < \frac{2 \theta \gamma}{1 - \gamma}

    When the maximum change in state values across a sweep drops below $\theta$, the distance between the current estimate and the true optimal value $V^*$ is bounded by $\frac{2 \theta \gamma}{1 - \gamma}$, ensuring controlled error tolerance.

04 Key takeaways

  • Dynamic programming computes exact optimal policies in Markov Decision Processes with known transition and reward models.
  • Policy Iteration alternates between complete policy evaluation and greedy policy improvement until the policy stabilises.
  • The Policy Improvement Theorem guarantees that greedy action selection produces monotonically improving policies.
  • Value Iteration truncates policy evaluation to a single sweep, updating states directly via the Bellman Optimality operator.
  • Both methods converge to the identical optimal policy pi* and optimal value function V*.

05 In code

python
import numpy as np

class GridworldDP:
    """
    Comparison of Policy Iteration vs Value Iteration
    on a 4-state linear gridworld: [0] <-> [1] <-> [2] <-> [3 (Goal)]
    """
    def __init__(self, gamma=0.9):
        self.num_states = 4
        self.gamma = gamma
        self.actions = [0, 1]  # 0: Left, 1: Right
        
    def step(self, s, a):
        if s == 3:
            return 3, 0.0, True
        if a == 1:  # Right
            s_next = min(3, s + 1)
            reward = 10.0 if s_next == 3 else 0.0
        else:       # Left
            s_next = max(0, s - 1)
            reward = 0.0
        return s_next, reward, (s_next == 3)

    def policy_iteration(self, theta=1e-6):
        # Initialize random policy (all Left) and zero values
        policy = np.zeros(self.num_states - 1, dtype=int)
        V = np.zeros(self.num_states)
        eval_sweeps = 0
        policy_steps = 0
        
        while True:
            policy_steps += 1
            # 1. Policy Evaluation
            while True:
                delta = 0.0
                eval_sweeps += 1
                V_new = np.copy(V)
                for s in range(self.num_states - 1):
                    a = policy[s]
                    s_prime, r, _ = self.step(s, a)
                    V_new[s] = r + self.gamma * V[s_prime]
                    delta = max(delta, abs(V_new[s] - V[s]))
                V = V_new
                if delta < theta:
                    break
                    
            # 2. Policy Improvement
            policy_stable = True
            for s in range(self.num_states - 1):
                old_action = policy[s]
                # Find best action
                action_values = []
                for a in self.actions:
                    s_prime, r, _ = self.step(s, a)
                    action_values.append(r + self.gamma * V[s_prime])
                best_action = int(np.argmax(action_values))
                if best_action != old_action:
                    policy_stable = False
                policy[s] = best_action
                
            if policy_stable:
                break
                
        return V, policy, policy_steps, eval_sweeps

    def value_iteration(self, theta=1e-6):
        V = np.zeros(self.num_states)
        sweeps = 0
        while True:
            sweeps += 1
            delta = 0.0
            V_new = np.copy(V)
            for s in range(self.num_states - 1):
                q_vals = [self.step(s, a)[1] + self.gamma * V[self.step(s, a)[0]] for a in self.actions]
                V_new[s] = max(q_vals)
                delta = max(delta, abs(V_new[s] - V[s]))
            V = V_new
            if delta < theta:
                break
                
        # Extract policy
        policy = np.zeros(self.num_states - 1, dtype=int)
        for s in range(self.num_states - 1):
            q_vals = [self.step(s, a)[1] + self.gamma * V[self.step(s, a)[0]] for a in self.actions]
            policy[s] = int(np.argmax(q_vals))
            
        return V, policy, sweeps

dp = GridworldDP(gamma=0.9)
v_pi, pi_pi, p_steps, e_sweeps = dp.policy_iteration()
v_vi, pi_vi, vi_sweeps = dp.value_iteration()

print("1. Policy Iteration Results:")
print(f"  Converged in {p_steps} policy improvement steps ({e_sweeps} total evaluation sweeps)")
print(f"  Values: {[round(x, 2) for x in v_pi]}")
print(f"  Policy: {['Left' if a == 0 else 'Right' for a in pi_pi]}")

print("\n2. Value Iteration Results:")
print(f"  Converged in {vi_sweeps} total sweeps")
print(f"  Values: {[round(x, 2) for x in v_vi]}")
print(f"  Policy: {['Left' if a == 0 else 'Right' for a in pi_vi]}")

print("\nNotice: Both algorithms produce mathematically identical optimal values and policies!")

Common pitfalls

  • Asynchronous state overwriting bugs: When implementing Value Iteration, updating state values in-place (Gauss-Seidel style) converges faster, but must be implemented deliberately; mixing old and new values in synchronous updates causes subtle mathematical divergence.
  • Assuming dynamic programming scales to high-dimensional continuous domains: Full DP requires iterating over all |S| states and |A| actions at every sweep. For problems with continuous states (such as robotics), tabular DP suffers from the curse of dimensionality and requires function approximation.
  • Failing to anchor terminal state values: If terminal absorbing states are not clamped permanently to zero reward and zero value, discount loops accumulate infinitely, corrupting surrounding states.
  • Setting stopping threshold theta too loose: Terminating value iteration when theta is large produces sub-optimal policy extraction, particularly when discount factor gamma is close to 1.

06 Check yourself

Q1What does the Policy Improvement Theorem guarantee when constructing an updated policy pi' that acts greedily with respect to V^pi?

Why: The Policy Improvement Theorem proves that acting greedily with respect to the value function of policy pi produces a new policy pi' whose expected return V^{pi'}(s) >= V^{pi}(s) for all states s, guaranteeing monotonic convergence toward the optimal policy.

Q2How does Value Iteration differ operationally from Policy Iteration?

Why: Policy Iteration runs iterative policy evaluation to full convergence between policy improvements. Value Iteration truncates evaluation to a single sweep, updating each state directly with the max over actions (Bellman optimality).

Q3Why is dynamic programming incapable of solving complex real-world control tasks like autonomous driving directly in tabular form?

Why: Tabular DP requires enumerating all states in S. In real-world environments like driving, state variables (positions, velocities, angles) are continuous and high-dimensional, resulting in an infinite state space that cannot be indexed in a table.
