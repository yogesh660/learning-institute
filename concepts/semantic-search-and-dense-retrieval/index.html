Semantic search and dense retrieval

Semantic search and dense retrieval transcend lexical keyword matching by projecting queries and documents into a shared continuous vector space. While traditional inverted indexes rely on exact token overlaps (failing on synonyms and paraphrases), dense retrieval uses dual-encoder neural networks to encode passages and queries into dense embeddings. Matched via inner products or cosine similarity and accelerated by Approximate Nearest Neighbour (ANN) indexing, dense retrieval retrieves conceptually relevant documents even when zero exact keywords match.

01 The idea

If you search an enterprise knowledge base for "how to fix a flickering monitor", a classical BM25 keyword index returns nothing if the internal engineering documentation is titled "resolving display panel refresh instability". The vocabulary mismatch problem cripples lexical search because humans express the same concept in myriad linguistic forms. Semantic search solves this: by mapping queries and passages into dense continuous representations, "flickering monitor" and "display panel refresh instability" map to neighboring points in semantic space.

The dual-encoder (two-tower) architecture: Rather than evaluating queries and documents through a heavy cross-encoder, dense retrieval uses two independent encoder networks: a Query Tower E_Q(q) and a Passage Tower E_D(d). Because document representations are independent of the query, an entire multi-million document corpus can be encoded once offline and indexed into high-performance vector databases (such as FAISS or HNSW). Query evaluation reduces to a single forward pass through the query tower followed by an inner product search.

Contrastive learning and in-batch negative sampling: Training a dual-encoder requires teaching the model to pull relevant query-document pairs close together while pushing irrelevant pairs apart. Computing negative pairs across the whole corpus is computationally intractable. Dense retrieval models employ in-batch negative sampling: for a batch of B query-passage pairs, the other B-1 passages in the batch serve as negative distractors for each query, providing B^2 - B training pairs for the price of B forward passes.

Hard negative mining: If training only uses random in-batch negatives, the model quickly learns trivial heuristics (e.g. separating medical text from sports text) but fails to discriminate between closely related passages within the same domain. Hard negative mining deliberately exposes the model to deceptive distractors—such as passages retrieved by BM25 that share query keywords but fail to answer the question—forcing the encoder to learn deep semantic nuances.

In everyday terms

Think of locating a book in an enormous university library. Lexical search is like a strict catalog clerk who will only direct you to a book if your search query matches words printed verbatim on the book's cover title. If you ask for "curing canine fever" and the book is titled "Veterinary Canine Therapeutics", the clerk insists the library has no such book. Dense retrieval is like a knowledgeable professor who has read every book in the building: they understand the conceptual essence of your inquiry and immediately guide you to the exact shelf containing the relevant canine medical treatise, regardless of the words on the cover.

03 The maths

  1. Dual-encoder similarity scoring function

    \operatorname{Score}(q, d) = \langle E_Q(q), \, E_D(d) \rangle = \frac{E_Q(q) \cdot E_D(d)}{\|E_Q(q)\|_2 \|E_D(d)\|_2}

    Here $E_Q$ and $E_D$ are deep neural encoders mapping text strings to $d$-dimensional continuous vectors. When vectors are $L_2$-normalised, inner product search is mathematically identical to cosine similarity.

  2. InfoNCE contrastive loss with in-batch negatives

    \mathcal{L}(q_i, d_i^+) = -\log \frac{\exp\left( \operatorname{Score}(q_i, d_i^+) / \tau \right)}{\exp\left( \operatorname{Score}(q_i, d_i^+) / \tau \right) + \sum_{j \ne i} \exp\left( \operatorname{Score}(q_i, d_j^+) / \tau \right)}

    Here $d_i^+$ is the true relevant document for query $q_i$, $d_j^+$ (for $j \ne i$) are negative passages borrowed from other queries in the minibatch, and $\tau > 0$ is the softmax temperature hyperparameter.

  3. Reciprocal Rank Fusion (RRF) for hybrid retrieval

    \operatorname{RRF}(d) = \sum_{m \in \{\text{dense}, \text{sparse}\}} \frac{1}{k + r_m(d)}

    Hybrid search combines BM25 lexical rank $r_{\text{sparse}}(d)$ and dense retrieval rank $r_{\text{dense}}(d)$ using a smoothing constant $k \approx 60$, delivering robust performance across exact keywords and abstract semantics.

04 Key takeaways

  • Dense retrieval maps queries and documents into a shared continuous embedding space to resolve vocabulary mismatch.
  • The dual-encoder architecture allows offline pre-computation of document embeddings for sub-millisecond retrieval.
  • In-batch negative contrastive training provides quadratic negative pairs without additional forward-pass compute overhead.
  • Hard negative mining exposes the encoder to challenging lexical distractors, driving fine-grained semantic discrimination.
  • Hybrid retrieval combining BM25 and dense retrieval via Reciprocal Rank Fusion provides the industry standard for production search.

05 In code

python
import numpy as np

class DenseRetrievalSimulator:
    """
    Simulation of two-tower dense semantic retrieval,
    in-batch negative contrastive loss, and top-k search.
    """
    def __init__(self, dim=4, temperature=0.07):
        self.dim = dim
        self.tau = temperature
        self.doc_index = []
        self.doc_texts = []

    def normalize(self, v):
        norm = np.linalg.norm(v, axis=-1, keepdims=True)
        return v / np.clip(norm, 1e-9, None)

    def index_documents(self, documents, mock_vectors):
        """Index precomputed normalized document vectors."""
        self.doc_texts = list(documents)
        self.doc_index = self.normalize(mock_vectors)

    def contrastive_loss(self, query_embs, pos_doc_embs):
        """
        Compute InfoNCE loss with in-batch negatives.
        query_embs: (B, dim)
        pos_doc_embs: (B, dim)
        """
        q = self.normalize(query_embs)
        d = self.normalize(pos_doc_embs)
        
        # Similarity matrix: (B x B)
        sim_matrix = np.dot(q, d.T) / self.tau
        
        # Diagonal elements are true positives
        B = q.shape[0]
        labels = np.arange(B)
        
        # Softmax cross entropy
        exp_sim = np.exp(sim_matrix - np.max(sim_matrix, axis=1, keepdims=True))
        probs = exp_sim / np.sum(exp_sim, axis=1, keepdims=True)
        
        loss = -np.mean(np.log(np.clip([probs[i, labels[i]] for i in range(B)], 1e-9, None)))
        return loss

    def search(self, query_vector, top_k=2):
        q = self.normalize(query_vector)
        # Inner products equal cosine similarity for normalized vectors
        scores = np.dot(self.doc_index, q)
        ranked_indices = np.argsort(-scores)[:top_k]
        return [(idx, self.doc_texts[idx], scores[idx]) for idx in ranked_indices]

# Documents illustrating semantic matching without exact keyword overlap
docs = [
    "Troubleshooting computer display panel refresh instability and screen flickering.",
    "Baking artisan sourdough bread using wild yeast fermentation cultures.",
    "Cardiovascular endurance training through high intensity interval intervals."
]

# Simulated 4-dimensional normalized embeddings for documents
doc_vectors = np.array([
    [0.90, 0.40, 0.10, 0.05],  # Tech/Hardware
    [0.05, 0.10, 0.95, 0.25],  # Culinary/Baking
    [0.10, 0.85, 0.20, 0.45]   # Fitness/Cardio
])

searcher = DenseRetrievalSimulator(dim=4)
searcher.index_documents(docs, doc_vectors)

# Query: "how to fix a flickering computer monitor" (Shares semantic direction with Doc 0)
query_vec = np.array([0.88, 0.35, 0.08, 0.02])

print(f"Indexed {len(docs)} documents into dense index.")
print("\nQuery: 'how to fix a flickering computer monitor'")
print("Notice: Document 0 shares almost zero exact keywords, but matches semantically!")

results = searcher.search(query_vec, top_k=3)
for rank, (idx, text, score) in enumerate(results, 1):
    print(f"\nRank {rank} [Cosine Similarity: {score:.4f}]:")
    print(f"  Doc {idx}: '{text}'")

# Compute sample In-Batch Negative Contrastive Loss
loss = searcher.contrastive_loss(doc_vectors, doc_vectors)
print(f"\nIn-Batch Negative Contrastive Loss for batch size {len(docs)}: {loss:.4f}")

Common pitfalls

  • Neglecting exact keyword search in dense-only setups: Pure dense retrieval models frequently fail on rare part numbers, acronyms, or proper names with little pre-training frequency. Always pair dense retrieval with sparse BM25 in hybrid configurations.
  • Unnormalised vector dot products: If query and document embeddings are not L2-normalised, vector magnitude dominates dot products, causing long or generic passages with large norms to dominate search results.
  • Document chunking boundary truncation: Splitting a document in the middle of a vital sentence separates questions from their answers. Use overlapping sliding chunks (e.g. 300 tokens with 50-token stride) to preserve context.
  • Evaluating on unrepresentative synthetic queries: Evaluating dense retrieval purely on questions identical to training text creates false confidence; validate on real user search logs containing typos, shorthand, and varied query lengths.

06 Check yourself

Q1Why does dense semantic retrieval resolve the vocabulary mismatch problem that limits classical keyword search engines?

Why: Dense retrieval maps text to dense continuous vectors where proximity reflects semantic meaning. Synonyms and paraphrases (e.g. "flickering monitor" and "display panel refresh instability") map to adjacent vectors, overcoming lexical vocabulary gaps.

Q2What is the primary architectural difference between a dual-encoder (bi-encoder) and a cross-encoder in search pipelines?

Why: Because dual-encoders encode documents independently of queries, millions of document vectors can be pre-computed, indexed, and searched in milliseconds. Cross-encoders require computing multi-head cross-attention over query-document pairs on the fly.

Q3Why is hard negative mining crucial when training dual-encoders for dense retrieval?

Why: Random in-batch negatives are too easy to differentiate (e.g. distinguishing medicine from music). Hard negatives—such as high-scoring BM25 passages that do not answer the query—train the encoder to capture deep semantic relevance rather than superficial topical overlap.
