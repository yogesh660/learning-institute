Agent evaluation and test harnesses

Evaluating autonomous multi-step agents requires moving beyond static single-turn benchmarks to interactive simulation harnesses and trajectory-level audits. Unlike simple question-answering systems, agents alter environmental state, invoke APIs, navigate dynamic graphs, and make sequential decisions under uncertainty. Rigorous agent evaluation balances outcome-based verification (did the agent successfully modify the database, fix the software bug, or complete the purchase?) with trajectory-based diagnostic metrics (action efficiency, tool call error rates, cyclic loop detection, and safety violations).

01 The idea

If evaluating a single-turn LLM is like scoring a written multiple-choice test, evaluating an autonomous agent is like administering a driving test in live traffic. An agent might eventually reach the desired destination, but did it take three unnecessary detours, exceed speed limits, or ignore stop signs along the way? Worse, did it get caught in an infinite loop calling the same broken endpoint fifty times? Developing robust agent systems requires deterministic test harnesses, sandboxed mock environments, trajectory log analysis, and regression suites.

Outcome vs Trajectory Evaluation: - Outcome Evaluation: Assesses the final state of the task environment. In SWE-bench, this means running unit tests to check if the patch resolves the issue without regressions. In WebArena, it means inspecting whether the order was placed with the correct shipping address. - Trajectory Evaluation: Assesses the path taken to reach the outcome. An agent that solves a task in 3 efficient tool calls is vastly superior in speed, cost, and reliability to one that takes 28 calls filled with syntax errors, retries, and hallucinations.

The Core Failure Modes of Autonomous Agents: - Infinite Loops / Thrashing: Repeating identical failed actions without learning from error observations. - Tool Hallucination: Inventing nonexistent tools or fictitious parameter names not in the schema. - Premature Termination: Declaring victory before completing necessary prerequisites. - Cascading Error Propagation: Basing subsequent reasoning on a faulty intermediate assumption. - Side-Effect Leakage: Modifying state destructively (e.g. deleting files) in attempts to explore.

Deterministic Sandboxed Test Harnesses: Live external web APIs are non-deterministic, rate-limited, and subject to external changes. Robust evaluation harnesses employ mock sandboxes (recorded HTTP cassettes, isolated Docker containers, virtual filesystems) that reset to identical initial states prior to each test run, ensuring reproducible evaluations.

In everyday terms

Consider testing an autopilot flight system in commercial aviation. You would never evaluate the autopilot solely by checking whether the aeroplane touched down on the runway at the end of the journey (outcome only). If the autopilot stalled twice, exceeded G-force limits, burned twice the allotted fuel, and deviated 200 miles off course before landing, the flight was a catastrophic failure. A comprehensive flight simulator test harness (agent test harness) records altitude, pitch, telemetry, and pilot command interactions at every second (trajectory evaluation) while measuring touchdown precision and passenger safety (outcome evaluation).

03 The maths

  1. Trajectory Efficiency and Path Optimality

    \text{Efficiency}(\tau) = \frac{|\tau^*|}{\max\big(|\tau|, |\tau^*|\big)} \in (0, 1]

    Let \tau^* be the minimal golden path trajectory (optimal number of tool calls) and \tau be the observed agent trajectory. If an agent completes a task in 3 steps when the golden path is 3, efficiency is 1.0. If the agent meanders for 12 steps before succeeding, efficiency drops to 0.25.

  2. Loop Detection and Action Repetition Index

    \text{RepetitionScore}(A) = \frac{1}{T - 1} \sum_{t=1}^{T-1} \mathbb{I}(a_{t+1} = a_t), \quad A = (a_1, a_2, \dots, a_T)

    Detects consecutive thrashing loops where an agent blindly repeats an identical action command despite receiving error feedback. An agent with repetition score > 0 exhibits pathological stuck loops requiring circuit-breaker interventions.

  3. Composite Benchmark Scorecard with Resource Penalty

    \text{Score} = \text{Success} \times \left(w_1 \cdot \text{Efficiency}(\tau) + w_2 \cdot (1 - \text{ToolErrorRate})\right) \cdot \exp\left(-\lambda \cdot \frac{\text{Tokens}}{\text{TokenBudget}}\right)

    Holistic agent scoring penalises inefficient or error-prone trajectories even when the ultimate objective is reached, scaling down rewards when token usage approaches the budget ceiling.

04 Key takeaways

  • Agent evaluation requires evaluating both final outcome correctness and trajectory quality (efficiency, loop avoidance, error frequency).
  • Deterministic sandboxed simulation environments with state reset capabilities prevent external API drift and ensure test reproducibility.
  • Trajectory audits detect pathological failure modes such as thrashing loops, parameter schema hallucinations, and cascading error propagation.
  • Composite benchmarks balance binary task completion with resource consumption penalties (step count and token budget).

05 In code

python
"""
Autonomous Agent Evaluation Test Harness
Demonstrating deterministic sandboxed execution, trajectory logging,
loop detection, and outcome verification.
"""

from typing import List, Dict, Any, Callable
import copy

class MockDatabaseSandbox:
    """Deterministic stateful environment fixture."""
    def __init__(self):
        self._initial_state = {
            "users": {"u1": {"name": "Alice", "balance": 100}, "u2": {"name": "Bob", "balance": 50}},
            "transactions": []
        }
        self.state = copy.deepcopy(self._initial_state)

    def reset(self):
        self.state = copy.deepcopy(self._initial_state)

    def transfer(self, from_user: str, to_user: str, amount: int) -> str:
        if from_user not in self.state["users"] or to_user not in self.state["users"]:
            return "Error: Invalid user ID."
        if self.state["users"][from_user]["balance"] < amount:
            return "Error: Insufficient funds."
        self.state["users"][from_user]["balance"] -= amount
        self.state["users"][to_user]["balance"] += amount
        self.state["transactions"].append({"from": from_user, "to": to_user, "amount": amount})
        return f"Success: Transferred {amount} from {from_user} to {to_user}."

class TrajectoryStep:
    def __init__(self, step_idx: int, thought: str, action: str, params: Dict[str, Any], observation: str, success: bool):
        self.step_idx = step_idx
        self.thought = thought
        self.action = action
        self.params = params
        self.observation = observation
        self.success = success

class AgentTestHarness:
    def __init__(self, sandbox: MockDatabaseSandbox):
        self.sandbox = sandbox

    def evaluate_trajectory(self, trajectory: List[TrajectoryStep], golden_steps: int = 1) -> Dict[str, Any]:
        """Compute diagnostic metrics across the execution trace."""
        total_steps = len(trajectory)
        if total_steps == 0:
            return {"efficiency": 0.0, "error_rate": 1.0, "loops_detected": 0}

        # 1. Trajectory Efficiency
        efficiency = round(golden_steps / max(total_steps, golden_steps), 3)

        # 2. Tool Execution Error Rate
        errors = sum(1 for step in trajectory if not step.success)
        error_rate = round(errors / total_steps, 3)

        # 3. Thrashing / Consecutive Loop Detection
        loops = 0
        for i in range(len(trajectory) - 1):
            curr = (trajectory[i].action, str(trajectory[i].params))
            next_step = (trajectory[i+1].action, str(trajectory[i+1].params))
            if curr == next_step and not trajectory[i].success:
                loops += 1

        return {
            "total_steps": total_steps,
            "efficiency": efficiency,
            "error_rate": error_rate,
            "loops_detected": loops,
        }

    def verify_outcome(self) -> bool:
        """Run programmatic assertions against the environment state."""
        # Task: Transfer 40 from u1 to u2
        state = self.sandbox.state
        u1_ok = state["users"]["u1"]["balance"] == 60
        u2_ok = state["users"]["u2"]["balance"] == 90
        tx_ok = len(state["transactions"]) == 1 and state["transactions"][0]["amount"] == 40
        return u1_ok and u2_ok and tx_ok

# --- Simulation Demonstration ---
sandbox = MockDatabaseSandbox()
harness = AgentTestHarness(sandbox)

# Scenario A: Highly efficient golden agent (1 step)
sandbox.reset()
obs_a = sandbox.transfer("u1", "u2", 40)
trace_efficient = [
    TrajectoryStep(1, "Transfer 40 from u1 to u2", "transfer", {"from": "u1", "to": "u2", "amount": 40}, obs_a, True)
]
outcome_a = harness.verify_outcome()
metrics_a = harness.evaluate_trajectory(trace_efficient, golden_steps=1)

print("=== Scenario A: Efficient Agent ===")
print("Task Succeeded:", outcome_a)
print("Trajectory Metrics:", metrics_a)

# Scenario B: Flawed agent with bad parameters, repetition loop, then recovery
sandbox.reset()
obs_b1 = sandbox.transfer("u1", "u99", 40)  # Invalid user error
obs_b2 = sandbox.transfer("u1", "u99", 40)  # Repeated mistake (loop!)
obs_b3 = sandbox.transfer("u1", "u2", 40)   # Corrected action

trace_flawed = [
    TrajectoryStep(1, "Transfer to u99", "transfer", {"from": "u1", "to": "u99", "amount": 40}, obs_b1, False),
    TrajectoryStep(2, "Retry transfer to u99", "transfer", {"from": "u1", "to": "u99", "amount": 40}, obs_b2, False),
    TrajectoryStep(3, "Correct target to u2", "transfer", {"from": "u1", "to": "u2", "amount": 40}, obs_b3, True),
]
outcome_b = harness.verify_outcome()
metrics_b = harness.evaluate_trajectory(trace_flawed, golden_steps=1)

print("\n=== Scenario B: Flawed Trajectory Agent ===")
print("Task Succeeded:", outcome_b)
print("Trajectory Metrics:", metrics_b)

Common pitfalls

  • Relying exclusively on outcome metrics: An agent that succeeds only after twenty broken retries and heavy hallucination is fragile and will fail catastrophically in production.
  • Evaluating against live production APIs: Unsandboxed testing is non-deterministic, introduces rate limits, risks destructive state modification, and cannot be reproduced.
  • Ignoring looping behaviour: Agents that lack loop detection will exhaust maximum context length and incur massive API bills when tools return errors.

06 Check yourself

Q1Why is evaluating an agent's trajectory just as important as verifying its final outcome?

Why: An agent that accidentally reaches the goal after 40 failing API calls and massive hallucination is brittle, expensive, and unsafe. Trajectory evaluation measures whether the agent reasoned effectively and acted efficiently.

Q2What constitutes a 'thrashing' or infinite loop failure mode in autonomous agents?

Why: Thrashing occurs when an agent fails to assimilate error feedback in its Thought step, blindly repeating the identical failed tool invocation until hitting hard execution step limits.

Q3Why must test harnesses for autonomous agents utilise sandboxed mock environments with reset capabilities?

Why: Sandboxes ensure that every test run starts with an identical pristine state fixture, isolating tests from live API changes, flakiness, rate limits, or accidental data destruction.
