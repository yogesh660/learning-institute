RAG architecture end to end

Retrieval-Augmented Generation (RAG) unites non-parametric external knowledge bases with parametric large language models to overcome knowledge obsolescence, hallucination, and lack of domain-specific context. An end-to-end production RAG system orchestrates four synchronised subsystems: query processing (reformulation, HyDE, multi-query expansion), hybrid retrieval (dense semantic vectors combined with sparse lexical BM25), post-retrieval reranking and context compression (mitigating the "lost-in-the-middle" attention phenomenon), and prompt synthesis with strict provenance and citation mechanisms.

01 The idea

How do enterprise AI systems answer private questions about last week's proprietary financial reports or internal codebase commits when foundation models were trained months ago on generic public text? Fine-tuning is slow, brittle to updates, and prone to hallucinating factual numbers. Retrieval-Augmented Generation (RAG) solves this by fetching the exact relevant source passages at query time and injecting them into the model's context window. Building a reliable production RAG architecture requires far more than naive vector search: it demands robust query transformation, hybrid retrieval, cross-encoder reranking, and citation-enforced generation.

Parametric vs Non-Parametric Memory: Foundation LLMs store vast world knowledge inside trillions of static neural weights (parametric memory). However, parametric memory cannot be easily edited, expires the moment pretraining ends, and struggles with exact verbatim recall. RAG couples this parametric reasoning engine with an external, dynamic, verifiable non-parametric memory: searchable vector stores, document indices, and knowledge graphs that can be updated in real time.

The Four Pillars of Production RAG: Naive RAG (embed query -> top-k vector search -> inject passages into prompt) fails frequently in practice due to semantic mismatch, noisy context, and context overflow. Production RAG implements four distinct stages: - Query Transformation: Transforming ambiguous user queries into optimised search inputs using Hypothetical Document Embeddings (HyDE), step-back prompting, or query decomposition. - Multi-Modal / Hybrid Retrieval: Combining BM25 keyword matching (for exact acronyms, IDs, and part numbers) with dense embeddings (for semantic intent). - Context Curation and Reranking: Applying a cross-encoder to rescore top candidates, filtering irrelevant passages, and ordering them to avoid the "lost-in-the-middle" bias where LLMs ignore information placed in the middle of long prompts. - Grounded Synthesis: Formatting the prompt with explicit source identifiers ([Doc 1], [Doc 2]) and system constraints commanding the model to refuse to answer if the context is insufficient.

Managing Context and the Lost-in-the-Middle Effect: Research proves LLMs exhibit a U-shaped attention distribution: they attend strongly to documents placed at the very beginning and very end of their prompt context, while frequently missing critical facts buried in the middle. Context compression, deduplication, and placing highest-priority chunks at prompt boundaries are vital for grounded generation.

In everyday terms

Think of an open-book university examination. The student's brain (the LLM) possesses excellent reasoning capabilities, linguistic mastery, and problem-solving skills, but is not expected to memorise thousands of pages of obscure tax legislation or medical manuals. When presented with a complex question, the student does not answer from memory. First, they check the library catalogue and reference index (query routing and hybrid retrieval). Next, they select the three most promising textbooks, skim the pages, and highlight relevant paragraphs while discarding irrelevant fluff (cross-encoder reranking and context curation). Finally, they write a structured essay synthesising those highlighted passages, explicitly citing page numbers and footnotes (grounded prompt synthesis with provenance).

03 The maths

  1. Probabilistic Formulation of Retrieval-Augmented Generation

    p(y \mid x) = \sum_{z \in \mathcal{Z}} p_\eta(z \mid x) \, p_\theta(y \mid x, z) \approx \sum_{k=1}^K p_\eta(z_k \mid x) \, p_\theta(y \mid x, z_k)

    In the foundational formulation of RAG (Lewis et al., 2020), generation probability for target sequence y given input prompt x is marginalised over latent retrieved documents z in document collection \mathcal{Z}. Retriever parameterised by \eta computes retrieval distribution p_\eta(z \mid x), and generator parameterised by \theta decodes tokens conditioned on both prompt x and retrieved context z. In practice, the intractable sum over all documents is truncated to the top-K retrieved candidates.

  2. Hypothetical Document Embeddings (HyDE)

    \hat{d} \sim p_\theta(\cdot \mid x, \text{instruction}), \quad \mathbf{v}_{\text{query}} = \frac{1}{2}\Big(\phi(x) + \phi(\hat{d})\Big)

    HyDE bridges the representation gap between questions and answers. Instead of encoding the short question x directly, an instruction-tuned LLM generates a zero-shot hypothetical answer \hat{d}. Even if \hat{d} contains factual errors, its embedding \phi(\hat{d}) occupies the dense representation space of documents rather than queries, dramatically improving vector search recall.

  3. Context Ordering and Attention Decay (Lost-in-the-Middle)

    \text{AttnWeight}(pos) \propto \exp\left(-\gamma \cdot \min(pos, N - pos)\right), \quad \pi^* = [c_1, c_3, c_5, \dots, c_6, c_4, c_2]

    Decoder-only transformers exhibit position-dependent attention biases, attending strongly to the start and end of prompt contexts while discounting the middle. To counteract this degradation, retrieved chunks ordered by relevance c_1 > c_2 > \dots > c_K are placed alternately at the outer boundaries of the prompt context: highest ranked chunks at the start and end, with lower ranked chunks placed in the interior.

04 Key takeaways

  • RAG couples an LLM's parametric reasoning capability with dynamic, non-parametric external document stores to prevent hallucination and provide up-to-date facts.
  • A production RAG pipeline consists of query reformulation, hybrid retrieval (BM25 + dense vectors), cross-encoder reranking, and citation-enforced synthesis.
  • LLMs exhibit a "lost-in-the-middle" attention degradation, requiring context curation, compression, and U-shaped prompt assembly (placing top passages at prompt extremes).
  • Strict prompt templates with source delimiters and citation constraints enable verifiable provenance and automated hallucination audits.

05 In code

python
"""
End-to-End Production RAG Architecture
Demonstrating query rewriting, hybrid retrieval, cross-encoder reranking,
context packing with source tags, and grounded answer synthesis.
"""

import math
import re
from typing import List, Dict, Tuple

class DocumentChunk:
    def __init__(self, doc_id: str, title: str, text: str):
        self.doc_id = doc_id
        self.title = title
        self.text = text

class EndToEndRAGPipeline:
    def __init__(self, corpus: List[DocumentChunk]):
        self.corpus = corpus
        # Precompute vocabulary for inverted index (sparse retrieval)
        self.inverted_index = {}
        for idx, doc in enumerate(self.corpus):
            tokens = set(self._tokenize(doc.text))
            for tok in tokens:
                self.inverted_index.setdefault(tok, []).append(idx)

    def _tokenize(self, text: str) -> List[str]:
        return re.findall(r'\b[a-z0-9]+\b', text.lower())

    def _sparse_bm25_mock(self, query: str, top_k: int = 5) -> List[Tuple[int, float]]:
        """Compute BM25-like lexical overlap scores."""
        query_tokens = self._tokenize(query)
        scores = [0.0] * len(self.corpus)
        for tok in query_tokens:
            if tok in self.inverted_index:
                postings = self.inverted_index[tok]
                idf = math.log((len(self.corpus) - len(postings) + 0.5) / (len(postings) + 0.5) + 1.0)
                for doc_idx in postings:
                    scores[doc_idx] += idf
        ranked = sorted(enumerate(scores), key=lambda x: x[1], reverse=True)
        return [item for item in ranked[:top_k] if item[1] > 0]

    def _dense_semantic_mock(self, query: str, top_k: int = 5) -> List[Tuple[int, float]]:
        """Mock bi-encoder dense embedding cosine similarity."""
        query_toks = set(self._tokenize(query))
        scores = []
        for idx, doc in enumerate(self.corpus):
            doc_toks = set(self._tokenize(doc.text + " " + doc.title))
            intersection = len(query_toks & doc_toks)
            union = len(query_toks | doc_toks)
            sim = (intersection / union) if union > 0 else 0.0
            # Add semantic bias for conceptual terms
            if "transformer" in query and "attention" in doc.text.lower():
                sim += 0.35
            if "rag" in query and "retrieval" in doc.text.lower():
                sim += 0.40
            scores.append((idx, round(sim, 4)))
        scores.sort(key=lambda x: x[1], reverse=True)
        return scores[:top_k]

    def hybrid_retrieve(self, query: str, k: int = 60, top_n: int = 4) -> List[int]:
        """Combine sparse BM25 and dense retrieval using Reciprocal Rank Fusion (RRF)."""
        sparse_hits = self._sparse_bm25_mock(query, top_k=5)
        dense_hits = self._dense_semantic_mock(query, top_k=5)

        rrf_scores = {}
        for rank, (doc_idx, _) in enumerate(sparse_hits, 1):
            rrf_scores[doc_idx] = rrf_scores.get(doc_idx, 0.0) + 1.0 / (k + rank)
        for rank, (doc_idx, _) in enumerate(dense_hits, 1):
            rrf_scores[doc_idx] = rrf_scores.get(doc_idx, 0.0) + 1.0 / (k + rank)

        ranked = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)
        return [doc_idx for doc_idx, _ in ranked[:top_n]]

    def cross_encoder_rerank(self, query: str, candidate_indices: List[int], top_n: int = 2) -> List[Tuple[int, float]]:
        """Simulate cross-encoder joint scoring over full [Query; Chunk] pairs."""
        scored = []
        query_terms = set(self._tokenize(query))
        for idx in candidate_indices:
            doc = self.corpus[idx]
            doc_terms = set(self._tokenize(doc.text))
            # Exact overlap has high weight in cross-encoder
            overlap = len(query_terms & doc_terms)
            title_match = 1.5 if any(t in doc.title.lower() for t in query_terms) else 0.0
            relevance = (overlap * 1.8) + title_match + (0.05 * len(doc.text.split()))
            scored.append((idx, round(relevance, 2)))
        scored.sort(key=lambda x: x[1], reverse=True)
        return scored[:top_n]

    def build_prompt_with_context(self, query: str, selected_indices: List[int]) -> str:
        """
        Assemble prompt context using U-shaped layout (lost-in-the-middle defence)
        and strict provenance XML delimiters.
        """
        # Reorder into [top_1, top_3, ..., top_2]
        ordered_indices = []
        left = True
        for idx in selected_indices:
            if left:
                ordered_indices.insert(0, idx)
            else:
                ordered_indices.append(idx)
            left = not left

        context_blocks = []
        for rank, idx in enumerate(ordered_indices, 1):
            doc = self.corpus[idx]
            context_blocks.append(
                f'<source id="{doc.doc_id}" title="{doc.title}">\n{doc.text}\n</source>'
            )

        context_str = "\n\n".join(context_blocks)
        prompt = (
            "You are a factual AI assistant. Answer the user query strictly using the provided sources.\n"
            "If the sources do not contain sufficient evidence to answer, state 'Insufficient information'.\n"
            "Every statement must be grounded and cite source IDs in brackets, e.g. [DOC-1].\n\n"
            f"=== CONTEXT ===\n{context_str}\n\n"
            f"=== USER QUERY ===\n{query}\n\n"
            "=== GROUNDED RESPONSE ==="
        )
        return prompt

    def generate_grounded_answer(self, prompt: str, retrieved_docs: List[DocumentChunk]) -> str:
        """Mock LLM generating response strictly adhering to cited sources."""
        doc_ids = [d.doc_id for d in retrieved_docs]
        return (
            f"Production RAG combines hybrid search (lexical BM25 and dense bi-encoders) "
            f"with cross-encoder reranking to accurately retrieve domain passages [{doc_ids[0]}]. "
            f"To prevent attention decay, high-priority passages are placed at context boundaries [{doc_ids[-1]}]."
        )

# --- Demonstration Run ---
knowledge_base = [
    DocumentChunk("DOC-101", "Vector Databases", "Vector search uses approximate nearest neighbours like HNSW for dense semantic matching."),
    DocumentChunk("DOC-102", "Hybrid Search and RAG", "Production RAG marries lexical BM25 with dense vectors using Reciprocal Rank Fusion and cross-encoder rerankers."),
    DocumentChunk("DOC-103", "Lost in the Middle", "LLMs exhibit U-shaped attention curves, paying highest attention to documents at the beginning and end of long contexts."),
    DocumentChunk("DOC-104", "Fine-Tuning LLMs", "LoRA trains low-rank adapter matrices to adapt foundation models to specific styles."),
]

rag = EndToEndRAGPipeline(knowledge_base)
user_query = "How does production RAG retrieve and organise context to avoid lost in the middle?"

print("User Query:", user_query)

# 1. Hybrid Retrieval
candidate_ids = rag.hybrid_retrieve(user_query, top_n=4)
print("\nRetrieved Candidate Doc IDs:", [knowledge_base[i].doc_id for i in candidate_ids])

# 2. Cross-Encoder Reranking
reranked = rag.cross_encoder_rerank(user_query, candidate_ids, top_n=2)
selected_indices = [idx for idx, _ in reranked]
print("Reranked Top Candidates:", [(knowledge_base[i].doc_id, score) for i, score in reranked])

# 3. Assemble Grounded Prompt
prompt = rag.build_prompt_with_context(user_query, selected_indices)
print("\n--- Generated Prompt Preview ---\n" + prompt[:400] + "\n...")

# 4. Generate Response
retrieved_docs = [knowledge_base[i] for i in selected_indices]
response = rag.generate_grounded_answer(prompt, retrieved_docs)
print("\n--- Synthesised Grounded Response ---\n" + response)

Common pitfalls

  • Relying purely on dense vector similarity: Vector embeddings struggle with exact keywords, part numbers, and novel terminology; hybrid search with BM25 is essential.
  • Dumping too many unranked chunks into the prompt: Excessive context increases latency, inflates token costs, and distracts the LLM from key evidence.
  • Omitting citation guardrails: Without explicit instructions and format constraints requiring bracketed source IDs, LLMs seamlessly blend parametric hallucinations with context facts.

06 Check yourself

Q1Why does naive top-k vector retrieval often fail in enterprise RAG systems?

Why: Dense bi-encoders encode general semantic similarity but frequently fail on precise identifiers or rare acronyms. Furthermore, injecting raw top-k passages without reranking degrades generation quality through context distraction and lost-in-the-middle attention decay.

Q2How does Hypothetical Document Embeddings (HyDE) improve retrieval performance?

Why: HyDE bridges the semantic gap between questions and answers. Embedding the generated hypothetical document produces a vector that clusters naturally with genuine answer passages in document embedding space.

Q3What is the "lost-in-the-middle" phenomenon in LLM context processing?

Why: Extensive empirical research (Liu et al.) demonstrates that language models have a U-shaped performance curve across context length: information located at the beginning or end of the input context is retrieved and synthesised with much higher fidelity than information in the middle.
