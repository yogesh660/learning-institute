Isolation Forest

Tree-based anomaly detection that isolates anomalies through random recursive partitioning, exploiting the fact that outliers require fewer random cuts to separate.

01 The idea

Traditional anomaly detection algorithms model the normal data profile using density estimation, distance clustering, or convex hulls, which causes quadratic computational bottlenecks and degrades in high dimensions. Isolation Forest inverts this paradigm: instead of constructing an expensive model of normality, it explicitly isolates anomalies by building an ensemble of completely randomised binary decision trees, isolating outliers near the root with linear time complexity.

Consider a large group of people gathered closely in the centre of a town square, with a solitary pedestrian wandering 50 metres away on the empty perimeter. If an observer draws random straight lines across the square, how many cuts will it take to isolate the solitary pedestrian from everyone else? A single random cut that falls between the wanderer and the square isolates them immediately. In contrast, isolating an individual standing shoulder-to-shoulder inside the central crowd requires dozens of precise, finely placed cuts.

This geometric property forms the core intuition of Isolation Forest. Anomalies are "few and different": they occur in sparse regions of feature space far from normal data clusters. When a binary tree recursively chooses a feature at random and cuts it at a uniform random value between that feature's minimum and maximum, anomalies are isolated into individual leaf nodes after very few splits (short path length). Normal instances, packed together in high-density regions, require many recursive splits (long path length) to isolate.

Because the algorithm relies solely on relative path lengths rather than pairwise Euclidean distances or probability densities, it eliminates the curse of dimensionality and distance distortion. Subsampling data into small subsets (typically 256 instances per tree) prevents two classic anomaly detection pathologies: swamping (falsely labelling inliers as anomalies because they sit near outlier clusters) and masking (clusters of outliers masking each other by appearing locally dense).

In everyday terms

Slicing through a wooden board with random saw cuts: a knothole protruding off the outer edge gets severed in one or two quick passes, whereas isolating a single wood grain deep within the centre requires countless cuts.

02 Step by step

  1. Subsample the training dataset without replacement into small bags of size $\psi$ (typically $\psi = 256$), mitigating masking and swamping while dramatically accelerating tree construction.
  2. Build an ensemble of $t$ completely randomised isolation trees (iTrees), setting the maximum tree depth to $\lceil \log_2(\psi) \rceil$.
  3. At each tree node, randomly choose a feature $q$ uniformly from the available feature columns.
  4. Select a split value $p$ uniformly at random between the minimum and maximum values of feature $q$ in the current node's data subset.
  5. Partition the data into left ($x_q < p$) and right ($x_q \ge p$) child nodes, recursing until instances are isolated ($|X| \le 1$), all feature values are identical, or max depth is reached.
  6. Pass each evaluation sample $x$ through all $t$ trees, recording the path length $h_i(x)$ (edges traversed plus the average path length correction $c(n)$ if terminated at an un-isolated node).
  7. Compute the normalised anomaly score $s(x, \psi) = 2^{-\mathbb{E}[h(x)] / c(\psi)}$; flag instances with $s(x, \psi) > 0.6$ as anomalies.

03 The maths

  1. Recursive partitioning and path length h(x)

    $$h(x) = e + c(|X_{\text{leaf}}|)$$

    An isolation tree (iTree) is a proper binary tree where every node has either zero or two children. The path length $h(x)$ of sample $x$ is the number of edges $e$ traversed from the root node to a terminating leaf node, augmented by the unbuilt tree correction $c(|X_{\text{leaf}}|)$ if early stopping was reached.

  2. Average path length of unsuccessful search in a BST

    $$c(n) = 2 \left( \ln(n - 1) + \gamma \right) - \frac{2(n - 1)}{n}$$

    where $\gamma \approx 0.5772156649$ is Euler's constant. Because iTrees share the exact mathematical structure of random binary search trees, $c(n)$ provides the theoretical average path length of an instance across $n$ randomly inserted items, serving as an exact normalisation constant.

  3. Normalised anomaly score formulation

    $$s(x, n) = 2^{-\frac{\mathbb{E}[h(x)]}{c(n)}}$$

    where $\mathbb{E}[h(x)]$ is the average path length across all trees in the forest. When $\mathbb{E}[h(x)] \to 0$, $s \to 1$, indicating an unambiguous anomaly isolated in very few splits. When $\mathbb{E}[h(x)] \to c(n)$, $s \to 0.5$, representing an ordinary instance indistinguishable from random data. When $\mathbb{E}[h(x)] \to n - 1$, $s \to 0$, signifying a deeply embedded inlier.

04 Key takeaways

  • Directly isolates anomalies instead of profiling normal instances, achieving linear $O(t \cdot \psi \log \psi)$ computational complexity.
  • Employs subsampling ($\psi = 256$) to eliminate swamping and masking while keeping memory consumption negligible.
  • Uses the average path length of a binary search tree $c(n)$ to normalise scores objectively between 0 and 1.
  • Operates effectively without distance metrics, avoiding distance concentration in high-dimensional spaces.

05 In code

python
import numpy as np

def c_factor(n):
    return 2.0 * (np.log(n - 1) + 0.5772156649) - 2.0 * (n - 1) / n if n > 2 else (1.0 if n == 2 else 0.0)

def build_tree(X, depth, max_depth, rng):
    if len(X) <= 1 or depth >= max_depth:
        return {'size': len(X)}
    feat = rng.integers(0, X.shape[1])
    f_min, f_max = X[:, feat].min(), X[:, feat].max()
    if f_min == f_max:
        return {'size': len(X)}
    split = rng.uniform(f_min, f_max)
    left = build_tree(X[X[:, feat] < split], depth + 1, max_depth, rng)
    right = build_tree(X[X[:, feat] >= split], depth + 1, max_depth, rng)
    return {'feat': feat, 'split': split, 'left': left, 'right': right}

def path_length(x, node, depth):
    if 'size' in node:
        return depth + c_factor(node['size'])
    return path_length(x, node['left'], depth + 1) if x[node['feat']] < node['split'] else path_length(x, node['right'], depth + 1)

rng = np.random.default_rng(42)
X_train = rng.normal(0, 1, size=(200, 2))
trees = [build_tree(X_train[rng.choice(len(X_train), 64, replace=False)], 0, 6, rng) for _ in range(50)]

test_pts = np.array([[0.1, 0.1], [4.5, 4.5]])
for pt, label in zip(test_pts, ['Normal inlier', 'Extreme outlier']):
    avg_path = np.mean([path_length(pt, t, 0) for t in trees])
    score = 2.0 ** (-avg_path / c_factor(64))
    print(f"{label} path: {avg_path:.2f} | score: {score:.3f}")

Common pitfalls

  • Axis-aligned partition bias: Standard iTrees use axis-parallel orthogonal cuts. Anomalies that reside in empty corners between correlated features (such as diagonal bands) may require more splits to isolate, though extended isolation forests address this with hyperplanes.
  • Over-subsampling vs under-subsampling: Setting subsample size $\psi$ too large causes swamping and masking, whereas setting $\psi$ too small fails to capture the true multivariate structure. The default $\psi = 256$ is empirically proven optimal across diverse domains.
  • Noise features: If a dataset contains hundreds of irrelevant, completely random features, uniformly selecting features at each split introduces noise and dilutes the path length separation of true anomalies.
  • Global score interpretation: Anomaly scores are relative to the dataset; a fixed threshold like 0.5 or 0.6 must be calibrated against business requirements and false alarm tolerances.

06 Check yourself

Q1Why does Isolation Forest deliberately use small subsamples (such as $\psi = 256$) instead of training trees on the entire dataset?

Why: Subsampling prevents "swamping" (normal instances surrounded by outliers being falsely flagged) and "masking" (dense clusters of outliers hiding each other). It also makes tree training extraordinarily fast.

Q2If an instance $x$ yields an anomaly score $s(x, n) = 0.5$, what does this score indicate?

Why: When $\mathbb{E}[h(x)] = c(n)$, the exponent is $-1$, yielding $s = 2^{-1} = 0.5$. This indicates the instance's path length is indistinguishable from that of an average sample in a random BST.

Q3What role does Euler's constant $\gamma \approx 0.5772$ play in the Isolation Forest algorithm?

Why: The harmonic number approximation $H_{n-1} = \ln(n-1) + \gamma$ yields the expected path length $c(n) = 2(\ln(n-1) + \gamma) - \frac{2(n-1)}{n}$ for binary search trees, which acts as the normalising denominator.

Q4How does an anomaly differ geometrically from an inlier during Isolation Forest recursive splitting?

Why: Anomalies are few and topologically isolated. Random cuts readily separate them from the rest of the dataset within few splits, resulting in small path lengths $h(x) \ll c(n)$.
