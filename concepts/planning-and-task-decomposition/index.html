01 The idea

When presented with complex, open-ended tasks, language models that attempt direct zero-shot execution frequently stumble or enter repetitive loops. Structured task decomposition—from Chain-of-Thought (CoT) and Least-to-Most prompting to Tree-of-Thoughts (ToT) and Plan-and-Solve frameworks—enables agents to formulate hierarchical roadmaps, evaluate branch states, and backtrack dynamically upon failure.

Autoregressive language models predict tokens one by one from left to right. When faced with a complex reasoning problem (like writing an entire software library or solving a mathematical proof), the model has no "thinking buffer" if forced to answer immediately: whatever token it generates first commits the entire future output trajectory to that initial hypothesis.

Decomposition frameworks decouple problem planning from execution: 1) Plan generation: the agent breaks down the overarching goal into a directed acyclic graph (DAG) of modular sub-tasks; 2) Sub-task execution: the agent executes each discrete step using targeted tools; 3) Self-reflection and re-planning: the agent observes intermediate tool outputs, assesses progress against the plan, and dynamically modifies subsequent steps if obstacles emerge.

In everyday terms

Imagine being asked to build an entire house. If you just grab a hammer and start nailing random boards together on day one, the structure will collapse. An experienced general contractor first drafts an architectural blueprint (Task Decomposition), schedules plumbers before drywallers (Dependency Ordering), and inspects each stage before proceeding (Self-Evaluation and Re-planning).

02 Step by step

  1. Prompt decomposition strategy: instruct the LLM to output an ordered plan of discrete sub-goals before issuing any execution tool calls.
  2. Formulate dependency graph: identify predecessor and successor constraints across sub-tasks to determine which steps can run in parallel.
  3. Execute step-by-step: dispatch the first unblocked sub-task to specialized executor agents or specific tool harnesses.
  4. Evaluate execution outcomes: compare tool observation outputs against expected sub-goal validation criteria.
  5. Dynamic re-planning: if an execution step fails or returns unexpected data, prompt the planner to adjust subsequent steps without starting from scratch.
  6. Synthesize final objective: combine validated intermediate results into the final comprehensive solution.

03 The maths

  1. Tree-of-Thoughts (ToT) Node Evaluation

04 Key takeaways

  • Decomposing complex goals into discrete sub-tasks prevents language models from committing prematurely to flawed output paths.
  • Tree-of-Thoughts enables multi-branch exploration, heuristic state evaluation, and systematic backtracking.
  • Dynamic re-planning allows agents to recover gracefully from tool execution failures during long-horizon tasks.

05 In code

python
class TaskDecomposer:
    """Demonstrates Plan-and-Solve task decomposition with dynamic execution."""
    def __init__(self):
        self.subtasks = []
        self.completed = []

    def create_plan(self, high_level_goal):
        """Simulates decomposing a complex user request into ordered sub-tasks."""
        # Simulated decomposition output from an LLM planner
        if "market analysis" in high_level_goal.lower():
            self.subtasks = [
                {"id": 1, "task": "Search industry report statistics", "status": "pending"},
                {"id": 2, "task": "Extract competitor pricing models", "status": "pending"},
                {"id": 3, "task": "Synthesise SWOT matrix and revenue forecast", "status": "pending"}
            ]
        return self.subtasks

    def execute_next(self, mock_tool_result):
        """Executes current pending subtask and updates plan status."""
        for step in self.subtasks:
            if step["status"] == "pending":
                step["status"] = "completed"
                step["result"] = mock_tool_result
                self.completed.append(step)
                return step
        return None

decomposer = TaskDecomposer()
plan = decomposer.create_plan("Perform market analysis for enterprise AI software")

print("Generated Agent Execution Plan:")
for step in plan:
    print(f"  Step {step['id']}: {step['task']} [{step['status']}]")

# Execute steps incrementally
s1 = decomposer.execute_next("Found 4 market reports: projected 28% CAGR")
s2 = decomposer.execute_next("Competitors A & B charge $30/user/mo")

print(f"\nExecuted Step 1 Result: {s1['result']}")
print(f"Executed Step 2 Result: {s2['result']}")
remaining = [s for s in decomposer.subtasks if s['status'] == 'pending']
print(f"Remaining Sub-tasks to complete: {len(remaining)}")

Common pitfalls

  • Decomposing into sub-tasks that are too fine-grained, generating excessive latency and API cost with minimal reasoning benefit.
  • Blindly executing static plans without monitoring intermediate tool outputs, blindly carrying flawed assumptions through all subsequent steps.

06 Check yourself

Q1How does Tree-of-Thoughts (ToT) improve upon standard Chain-of-Thought (CoT) prompting?

Why: CoT is a single linear chain. ToT explores multiple branches of thoughts, evaluates candidate paths, and backtracks when a path hits a dead end.

Q2Why is dynamic re-planning critical for autonomous agents operating in external environments?

Why: In real-world environments, tools encounter errors or missing data. A rigid static plan fails, whereas dynamic re-planning adapts subsequent actions.

Q3What is the "compounding error" problem in long-horizon sequential agent plans?

Why: In sequential plans without active verification, the probability of complete success decays exponentially with the number of dependent steps.
