Monte Carlo Tree Search (MCTS): Selection, Expansion, Simulation, and Backpropagation

01 The idea

Monte Carlo Tree Search (MCTS) revolutionized automated game playing and sequential decision making where exhaustive minimax search is computationally intractable. By combining asymmetric tree expansion, Upper Confidence Bound for Trees (UCT), and random or neural rollout simulations, MCTS concentrates computation on the most promising tactical variations.

In games with massive state spaces like Go or chess, minimax search with alpha-beta pruning fails because the game tree branch factor is enormous and crafting a hand-engineered heuristic evaluation function for arbitrary board states is extraordinarily difficult.

MCTS solves this by building an asymmetric search tree incrementally across four repeating phases: Selection (following high-confidence paths via UCB1), Expansion (adding a new leaf node), Simulation (playing out the game to termination using random moves or a rollout policy), and Backpropagation (updating visit counts and win rates up the ancestor chain).

In everyday terms

Imagine an explorer navigating an uncharted maze of caves. Instead of attempting to survey every dead-end branch equally, the explorer takes quick running sprints down unknown paths, takes note of which routes brought them closer to daylight, and focuses subsequent detailed mapping on the tunnels that led to the best breakthroughs.

02 Step by step

  1. Selection: starting from the root state, descend the tree by choosing actions that maximise the Upper Confidence Bound (UCT) formula until reaching an unexpanded node.
  2. Expansion: create one or more child nodes corresponding to available legal actions from the selected leaf state.
  3. Simulation (Rollout): play the game out to a terminal state from the new child node using a fast default policy (e.g. uniform random moves).
  4. Backpropagation: evaluate the terminal reward (e.g. +1 for win, 0 for loss) and propagate the result upward, incrementing visit counts $N(s)$ and value sums $W(s)$ for all visited ancestors.

03 The maths

  1. Upper Confidence Bound for Trees (UCT)

    \text{UCT}(s, a) = Q(s, a) + c \sqrt{\frac{\ln N(s)}{N(s, a)}}, \quad Q(s, a) = \frac{W(s, a)}{N(s, a)}

    Balances exploitation of the empirical average win rate $Q(s, a)$ with exploration of rarely visited actions weighted by exploration constant $c \approx \sqrt{2}$.

  2. Value Backpropagation Update

    N(s, a) \leftarrow N(s, a) + 1, \quad W(s, a) \leftarrow W(s, a) + v

    Increments the edge visit count and accumulates the rollout terminal outcome $v \in \{-1, 0, 1\}$ back to the root.

04 Key takeaways

  • MCTS grows asymmetric decision trees towards high-potential game trajectories using UCT selection.
  • The UCB1 exploration term guarantees that every legal action is eventually explored while prioritizing proven winning lines.
  • Deep reinforcement learning architectures like AlphaZero replace random rollouts with trained neural value networks.

05 In code

python
import numpy as np

class MCTSNode:
    def __init__(self, state, parent=None):
        self.state = state
        self.parent = parent
        self.children = {}
        self.visits = 0
        self.value = 0.0

    def is_fully_expanded(self, legal_actions):
        return len(self.children) == len(legal_actions)

    def best_child(self, c_param=1.414):
        choices = []
        for action, child in self.children.items():
            # UCT formula: exploitation + exploration
            exploit = child.value / child.visits
            explore = c_param * np.sqrt(np.log(self.visits) / child.visits)
            choices.append((exploit + explore, action, child))
        return max(choices, key=lambda x: x[0])[2]

def simulate_rollout(state):
    """Simulates random rollout to termination."""
    # Toy coin game: target is reaching 10 points
    current = state
    while current < 10:
        current += np.random.choice([1, 2])
    return 1.0 if current == 10 else 0.0

def mcts_search(root_state, iterations=100):
    root = MCTSNode(root_state)
    for _ in range(iterations):
        node = root
        # 1. Selection
        legal_actions = [1, 2] if node.state < 10 else []
        while node.is_fully_expanded(legal_actions) and legal_actions:
            node = node.best_child()
            legal_actions = [1, 2] if node.state < 10 else []

        # 2. Expansion
        unexplored = [a for a in legal_actions if a not in node.children]
        if unexplored:
            action = unexplored[0]
            child_node = MCTSNode(node.state + action, parent=node)
            node.children[action] = child_node
            node = child_node

        # 3. Simulation
        reward = simulate_rollout(node.state)

        # 4. Backpropagation
        while node is not None:
            node.visits += 1
            node.value += reward
            node = node.parent

    # Choose action with most visits
    best_action = max(root.children.items(), key=lambda x: x[1].visits)[0]
    return best_action, root.children[best_action].visits

action, visits = mcts_search(root_state=6, iterations=200)
print(f"MCTS Recommended Action from state 6: +{action} (Explored {visits} times)")

Common pitfalls

  • Setting exploration constant $c$ too high causes the search to devolve into uniform random search; setting it too low traps the agent in premature local optima.
  • Using pure random rollouts in games requiring tactical traps where a single random blunder in the rollout ruins accurate value estimation.

06 Check yourself

Q1What is the role of the $\sqrt{\ln N(s) / N(s, a)}$ term in the UCT formula?

Why: The square root term increases as parent visits $N(s)$ grow but decreases as the specific action visits $N(s, a)$ grow, incentivizing exploration of neglected actions.

Q2Which action does MCTS typically select as the final move after search completes?

Why: In MCTS, visit count is the most stable and noise-resistant signal of move quality because UCT naturally allocates the majority of iterations to the superior branch.

Q3How did AlphaGo and AlphaZero improve upon classical MCTS rollouts?

Why: Random rollouts are noisy and computationally slow; AlphaZero replaced rollouts with a single forward evaluation of a deep value network $V(s)$.
