Information and Relation Extraction: OpenIE, Distant Supervision, and Knowledge Graph Construction

Relation Extraction classifies semantic relationships existing between marked entity mentions within a sentence or document. Open Information Extraction (OpenIE) extracts arbitrary relational triples $(s, r, o)$ directly from text without a predefined schema or target relation ontology. Distant supervision aligns existing knowledge bases (e.g. Wikidata) with raw text corpora to automatically create massive, weakly labelled training datasets. Graph construction merges extracted triples into persistent knowledge graphs, resolving entity aliases through link prediction and graph embeddings.

01 The idea

Information Extraction (IE) transforms unstructured natural language text into structured knowledge tuples (subject, relation, object). From open information extraction (OpenIE) to distant supervision and modern relation classification, IE powers enterprise search, automated knowledge graph construction, and biomedical entity discovery.

If you want a computer to answer questions like "Which tech companies were founded in California?", an AI cannot afford to read 100 million web pages every time a user asks a question. Instead, it needs a structured database: a Knowledge Graph. Information Extraction (IE) is the automated factory that builds this graph from raw prose. Given a sentence like "Steve Jobs co-founded Apple in Cupertino", IE first runs Named Entity Recognition to find "Steve Jobs" (Person), "Apple" (Organization), and "Cupertino" (Location). Next, Relation Extraction identifies the links between them: `(Steve Jobs, Founded, Apple)` and `(Apple, HeadquarteredIn, Cupertino)`. By storing these triples in a graph, computers can instantly query relationships, trace corporate ownership, or discover drug-disease interactions across millions of biomedical papers.

In everyday terms

Imagine reading through thousands of historical letters and filing index cards in a library card catalogue. Instead of keeping the entire letter, you write a concise index card with three boxes: Subject: "Napoleon", Relation: "Exiled to", Object: "Saint Helena". Anyone visiting the library can now search the index cards instantly without reading through centuries of personal correspondence.

02 Step by step

  1. Detect named entities: tag person, organization, location, and domain-specific entities using NER models.
  2. Insert special entity markers: delimit candidate entity pairs in the sentence using tags like `[E1]`, `[/E1]`, `[E2]`, and `[/E2]`.
  3. Encode marked sequence: pass the augmented sequence through a bidirectional transformer encoder.
  4. Extract entity pair representations: extract and concatenate the hidden states corresponding to the entity markers.
  5. Classify candidate relation: project concatenated embeddings through an MLP classifier to predict relation labels or output `no_relation`.
  6. Link entities to knowledge base: resolve surface strings to canonical entity IDs (e.g. Q312 for Apple Inc.) and insert the triple into the knowledge graph.

04 Key takeaways

  • Relation extraction converts unstructured sentences into factual $(s, r, o)$ triples to populate structured knowledge graphs.
  • Distant supervision scales dataset creation using existing knowledge bases, managed via multi-instance learning to filter label noise.
  • Entity marker insertion provides modern transformer encoders with precise span boundaries for highly accurate relation classification.

05 In code

python
import numpy as np

def score_relation_candidates(entity1, entity2, sentence_features, relation_matrix):
    """Simulates classifying relations between marked entities."""
    # Concatenate entity representation vectors
    pair_repr = np.concatenate([entity1, entity2, sentence_features])
    
    # Linear projection to relation logits
    logits = np.dot(relation_matrix, pair_repr)
    
    # Softmax probabilities
    exp_logits = np.exp(logits - np.max(logits))
    probs = exp_logits / np.sum(exp_logits)
    return probs

# Setup simulated relation classes
relations = ["no_relation", "founded_by", "headquartered_in", "subsidiary_of"]

np.random.seed(42)
d = 4
e_org = np.array([1.2, 0.8, -0.2, 0.5])      # "Apple"
e_person = np.array([0.9, -0.4, 1.1, 0.3])   # "Steve Jobs"
feat_founded = np.array([0.8, 1.5, 0.2, -0.1]) # "co-founded with"

# Synthetic classifier weights
W = np.random.randn(len(relations), 3 * d) * 0.5
# Bias founded_by row to respond to founder feature combinations
W[1, :d] = 0.8
W[1, d:2*d] = 0.9

probs = score_relation_candidates(e_org, e_person, feat_founded, W)
best_rel_idx = np.argmax(probs)

print("Relation Extraction Simulation:")
print(f"  Entity 1: 'Apple' (ORG)")
print(f"  Entity 2: 'Steve Jobs' (PERSON)")
print("Predicted Relation Probabilities:")
for rel, p in zip(relations, probs):
    print(f"  {rel:18} -> {p * 100:.2f}%")

print(f"\nExtracted Triple: (Apple, {relations[best_rel_idx]}, Steve Jobs)")

Common pitfalls

  • Assuming distant supervision yields clean labels; distant supervision generates significant false positives when sentences mention two entities without expressing the relation.
  • Ignoring directionality in asymmetric relations (e.g. confusing `founded_by(A, B)` with `founded_by(B, A)`).
  • Failing to predict a `no_relation` class, forcing the model to hallucinate relations for unrelated entities co-occurring in the same paragraph.

06 Check yourself

Q1What is the core premise of distant supervision in relation extraction?

Why: Distant supervision heuristically labels text by assuming that if knowledge base triple $(e_1, r, e_2)$ exists, sentences mentioning both $e_1$ and $e_2$ likely express relation $r$.

Q2Why do modern relation extractors insert special marker tokens (e.g. `[E1]`, `[E2]`) into input text?

Why: Entity markers tell the transformer encoder exactly which tokens comprise entity 1 and entity 2, allowing the network to focus attention on their relational interaction.

Q3How does Open Information Extraction (OpenIE) differ from traditional Relation Extraction?

Why: Traditional relation extraction classifies pairs into a fixed ontology (e.g. 50 predefined relations), whereas OpenIE extracts open-vocabulary relational verbs directly from sentence text.
