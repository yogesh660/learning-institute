Permutation and Impurity Feature Importance

Contrasting training-set impurity reduction (MDI) with held-out permutation testing (PFI) to measure genuine feature predictive power.

01 The idea

When tree ensembles rank feature importances, practitioners frequently rely on default Mean Decrease in Impurity (MDI). However, MDI suffers from severe structural bias toward high-cardinality features and evaluates importance exclusively on training data, causing overfit noise to appear falsely critical. Permutation Feature Importance (PFI) measures the true drop in model performance when feature values are randomly shuffled on held-out validation data, breaking feature-target associations to quantify genuine generalisable signal.

Imagine an employer evaluating job candidates based on three criteria: university grades, relevant industry experience, and employee ID badge numbers. A complex decision tree can easily memorise the training records by splitting on the unique employee ID badge numbers, partitioning candidates perfectly into individual leaf nodes. If you ask the tree which feature reduced training classification errors most aggressively, it will proudly answer: the employee ID badge numbers (high impurity reduction). Yet in the real world, ID numbers carry zero predictive capability for future hires.

This flaw is the Achilles heel of Mean Decrease in Impurity (Gini importance). Because continuous variables and high-cardinality categoricals offer countless potential split thresholds, trees split on them disproportionately often. Furthermore, because MDI is computed entirely on training data, any feature that helps the tree memorise training noise is crowned as "important".

Permutation Feature Importance provides the scientific antidote by asking a simple question: "If I destroy the relationship between this feature and the target on unseen validation data, how badly does the model suffer?" By shuffling the values of one feature across validation rows while leaving all other columns intact, PFI preserves the feature's marginal distribution while obliterating its correlation with the outcome. If shuffling a column causes validation error to spike, the model genuinely relied on that feature. If shuffling causes zero change (or even improves performance), the feature was merely redundant noise.

In everyday terms

Assessing which engine component is essential to a car's speed by temporarily disconnecting each wire on a test track and measuring how much lap time degrades.

02 Step by step

  1. Train the predictive model on the training dataset using standard cross-validation or hyperparameter tuning.
  2. Evaluate the baseline performance metric (e.g. MSE, cross-entropy, or ROC-AUC) on an untouched held-out validation dataset: $L_{\text{base}} = L(y_{\text{val}}, \hat{f}(X_{\text{val}}))$.
  3. For each feature column $j \in \{1, \dots, d\}$, generate a permuted validation set $X_{\text{val}}^{\text{perm}(j)}$ by randomly shuffling row values in column $j$ while keeping all other columns unchanged.
  4. Pass the permuted matrix through the trained model to record the degraded performance metric: $L_{\text{perm}}(j) = L(y_{\text{val}}, \hat{f}(X_{\text{val}}^{\text{perm}(j)}))$.
  5. Compute the importance score as the difference $\Delta L(j) = L_{\text{perm}}(j) - L_{\text{base}}$ (or ratio for bounded metrics); repeat across multiple random shuffles to compute confidence intervals.
  6. Inspect correlated feature clusters: if two features are strongly collinear, group them together or evaluate conditional permutations to avoid underestimating shared influence.

03 The maths

  1. Mean Decrease in Impurity (MDI / Gini importance)

    $$\operatorname{MDI}(j) = \frac{1}{T} \sum_{t=1}^T \sum_{n \in \mathcal{N}_t: v(n) = j} p(n) \, \Delta I(n)$$

    where $T$ is the number of trees, $\mathcal{N}_t$ is the set of internal nodes in tree $t$, $v(n)$ denotes the feature split at node $n$, $p(n) = N_n / N_{\text{total}}$ is the proportion of training samples reaching node $n$, and $\Delta I(n) = I(n) - \frac{N_L}{N_n}I(n_L) - \frac{N_R}{N_n}I(n_R)$ is the reduction in impurity (Gini or variance). Because continuous features offer more split opportunities, MDI exhibits an inherent cardinality bias.

  2. Permutation Feature Importance (PFI)

    $$\operatorname{PFI}(j) = \mathbb{E}\left[ L\big(y, \, \hat{f}(X^{\pi_j})\big) \right] - \mathbb{E}\left[ L\big(y, \, \hat{f}(X)\big) \right]$$

    where $X^{\pi_j}$ denotes the feature matrix where column $j$ has been randomly permuted, breaking the joint distribution $P(X_j, Y)$ while strictly preserving the marginal distribution $P(X_j)$. When evaluated on test data, uninformative features yield $\operatorname{PFI} \le 0$, while critical features yield large positive values.

  3. Standard error of permutation importance across shuffles

    $$\operatorname{SE}\big(\operatorname{PFI}(j)\big) = \frac{s_j}{\sqrt{B}}, \qquad s_j = \sqrt{\frac{1}{B - 1} \sum_{b=1}^B \big(\Delta L_b(j) - \overline{\Delta L}(j)\big)^2}$$

    where $B$ is the number of independent random permutations (typically $B = 5$ to $10$). Computing the standard error over permutations verifies whether a feature's measured importance is statistically distinct from random baseline noise.

04 Key takeaways

  • MDI evaluates training split reductions and artificially favours high-cardinality variables like unique IDs or continuous noise.
  • PFI evaluates held-out validation loss degradation and reflects genuine generalisable predictive value.
  • Shuffling breaks feature-target association while preserving the empirical marginal distribution of the feature.
  • For correlated predictors, grouped permutation or conditional importance is necessary to avoid mutual dilution.

05 In code

python
import numpy as np

# Synthetic dataset: x0 is predictive, x1 is noise, x2 is high-cardinality ID
rng = np.random.default_rng(42)
n = 200
x0 = rng.normal(0, 1, n)
x1 = rng.normal(0, 1, n)
x2 = np.arange(n, dtype=float)
y = 2.5 * x0 + rng.normal(0, 0.5, n)
X = np.column_stack([x0, x1, x2])

# Train / validation split
X_tr, y_tr = X[:120], y[:120]
X_val, y_val = X[120:], y[120:]
w = np.linalg.lstsq(X_tr, y_tr, rcond=None)[0]

# Baseline validation error
base_mse = np.mean((y_val - X_val @ w) ** 2)

# Compute Permutation Feature Importance (PFI) on held-out validation data
pfi = []
for j in range(3):
    X_perm = X_val.copy()
    X_perm[:, j] = rng.permutation(X_perm[:, j])
    perm_mse = np.mean((y_val - X_perm @ w) ** 2)
    pfi.append(perm_mse - base_mse)

print(f"Baseline validation MSE: {base_mse:.4f}")
print(f"PFI (x0 - true signal):  {pfi[0]:.4f}")
print(f"PFI (x1 - noise):        {pfi[1]:.4f}")
print(f"PFI (x2 - unique ID):    {pfi[2]:.4f}")

Common pitfalls

  • Misinterpreting correlated features: If two features are almost perfectly collinear (e.g. height in centimetres and height in inches), permuting one leaves the model able to use the other, causing PFI to artificially underestimate the importance of both.
  • Evaluating PFI on training data: Running permutation tests on training data rather than validation data reintroduces memorisation bias, failing to penalise overfit features.
  • Extrapolation into impossible feature spaces: Permuting correlated features can generate physically impossible combinations (e.g. an pregnant male or an 8-bedroom studio apartment), forcing the model to evaluate out-of-distribution regions.
  • Ignoring negative importance values: Features with slightly negative PFI scores indicate that permuting them actually reduced error, signalling noisy or overfitted inputs that should be pruned.

06 Check yourself

Q1Why is default Mean Decrease in Impurity (MDI / Gini importance) dangerous when evaluating tree ensembles on datasets with mixed feature types?

Why: MDI evaluates impurity reduction strictly on training data. Continuous features and high-cardinality categoricals offer far more split candidates, allowing trees to split on them frequently to memorise noise, creating a severe false importance bias.

Q2What is the core operational principle behind Permutation Feature Importance (PFI)?

Why: By shuffling a feature column across validation instances, PFI breaks the correlation between that feature and the target while keeping its marginal distribution intact. The resulting drop in validation performance quantifies the model's true reliance on that feature.

Q3If two input features $X_1$ and $X_2$ are nearly 100% correlated and both strongly drive the target $Y$, what does standard Permutation Feature Importance report for them?

Why: When two features carry redundant information, permuting $X_1$ leaves $X_2$ completely intact. The model compensates using $X_2$, resulting in a negligible increase in error and misleadingly low PFI scores for both features.

Q4What does a negative Permutation Feature Importance score (e.g. $\operatorname{PFI} = -0.015$) indicate about a feature?

Why: A negative score means validation error decreased when the feature was scrambled. This confirms that the model's reliance on that feature was harmful to generalisation, identifying it as a candidate for feature pruning.
