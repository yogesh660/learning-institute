01 The idea

Modern compound AI systems consist of multi-turn agent loops, chained tool calls, retrieval pipelines, and multiple LLM invocations. Debugging and monitoring these systems requires end-to-end observability: capturing OpenTelemetry-standardised distributed traces, tracking token usage and latency waterfalls, and detecting silent degradation through automated evaluation pipelines.

In traditional web applications, debugging is straightforward: functions return deterministic codes and error stack traces point to line numbers. In LLM applications, failures are silent: the model produces fluent prose that subtly hallucinates a tool argument or fails to call a necessary retrieval function. Without telemetry, identifying whether a failure originated in bad chunking, poor reranking, or prompt drift is impossible.

AI observability instruments applications using distributed tracing: 1) Trace: the complete end-to-end lifecycle of a user request; 2) Spans: timed units of work within the trace (e.g. Embedding generation span: 45ms, Vector search span: 120ms, LLM generation span: 1.8s); 3) Metadata attributes: recording prompt text, completion tokens, costs, model IDs, and automated evaluation scores for every execution span.

In everyday terms

Running a complex agent without observability is like managing an international airline using only a paper notepad. When a flight is delayed 4 hours, you have no idea whether it was caused by maintenance, luggage loading, air traffic control, or weather. Distributed tracing is flight telemetry: it instruments every second of the plane's journey, pinning down the exact 12-minute maintenance hangup.

02 Step by step

  1. Instrument application lifecycle: wrap agent workflows, tool calls, and LLM API invocations with OpenTelemetry-compliant trace spans.
  2. Record span metadata: capture input tokens, completion tokens, model parameters (temperature), latency, and monetary cost per call.
  3. Correlate multi-step agent trajectories: propagate parent-child span IDs across sub-agent calls and asynchronous task executions.
  4. Configure automated online evaluations: evaluate sample traces asynchronously using LLM-as-a-judge for faithfulness and toxicity.
  5. Aggregate metrics dashboards: visualise latency percentiles (P50, P95, P99), token consumption trends, error rates, and cache hit ratios.
  6. Set automated alerting thresholds: trigger alerts on cost anomalies, rate limit spikes, or sudden drops in task success rates.

03 The maths

  1. Total Trace Latency Waterfall

    T_{\text{total}} = \sum_{s \in \text{Sequential}} T_s + \max_{p \in \text{Parallel}} T_p

    Calculates overall request duration by summing sequential execution spans and bottleneck parallel asynchronous spans.

  2. Total Session Operational Cost

    \text{Cost} = \sum_{i=1}^M \left( N_{\text{prompt}}^{(i)} \cdot P_{\text{in}} + N_{\text{comp}}^{(i)} \cdot P_{\text{out}} \right)

    Aggregates token consumption across $M$ distinct spans weighted by input price $P_{\text{in}}$ and output price $P_{\text{out}}$.

04 Key takeaways

  • Observability instruments multi-step agent systems with distributed traces, spans, and execution metadata.
  • Telemetry captures token consumption, latency waterfalls, and monetary cost breakdowns per request.
  • Continuous evaluation and automated LLM-as-a-judge monitoring detect silent quality regressions in production.

05 In code

python
import time

class SimpleSpan:
    def __init__(self, name, parent=None):
        self.name = name
        self.parent = parent
        self.start_time = None
        self.end_time = None
        self.attributes = {}

    def __enter__(self):
        self.start_time = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.end_time = time.time()

    def set_attribute(self, key, value):
        self.attributes[key] = value

    @property
    def duration_ms(self):
        return (self.end_time - self.start_time) * 1000

# Simulate an instrumented RAG pipeline trace
trace_spans = []

def run_instrumented_rag(query):
    with SimpleSpan("rag_pipeline") as root_span:
        root_span.set_attribute("query", query)
        
        # Child Span 1: Embedding
        with SimpleSpan("embed_query", parent=root_span) as s1:
            time.sleep(0.02)  # Simulate 20ms embedding
            s1.set_attribute("model", "text-embedding-3")
        trace_spans.append(s1)
        
        # Child Span 2: Vector Search
        with SimpleSpan("vector_search", parent=root_span) as s2:
            time.sleep(0.05)  # Simulate 50ms search
            s2.set_attribute("results_count", 3)
        trace_spans.append(s2)
        
        # Child Span 3: LLM Generation
        with SimpleSpan("llm_generation", parent=root_span) as s3:
            time.sleep(0.12)  # Simulate 120ms generation
            s3.set_attribute("prompt_tokens", 850)
            s3.set_attribute("completion_tokens", 140)
            s3.set_attribute("cost_usd", 0.0032)
        trace_spans.append(s3)
        
    trace_spans.append(root_span)

run_instrumented_rag("Explain quantum computing")

print("LLM Observability Trace Report:")
for span in trace_spans:
    parent_info = f" (parent: {span.parent.name})" if span.parent else " [ROOT]"
    print(f"  Span: {span.name:18} | Duration: {span.duration_ms:5.1f} ms{parent_info}")
    if "cost_usd" in span.attributes:
        print(f"    --> Tokens: {span.attributes['prompt_tokens']} in / {span.attributes['completion_tokens']} out | Cost: ${span.attributes['cost_usd']:.4f}")

Common pitfalls

  • Logging sensitive user personal identifiable information (PII) directly into unencrypted telemetry span payloads.
  • Running synchronous evaluations on every single production request, doubling user latency; use asynchronous sampling instead.

06 Check yourself

Q1What is a "span" in distributed tracing for AI systems?

Why: In OpenTelemetry, a trace represents the end-to-end request, while spans represent individual timed operations within that request.

Q2Why are traditional software error stack traces insufficient for debugging compound AI applications?

Why: A model can return an incorrect or hallucinated answer with status code 200 without throwing an exception, requiring semantic monitoring and tracing.

Q3How should evaluation metrics (e.g. faithfulness, toxicity) be collected in high-throughput production environments?

Why: Asynchronous evaluation on a sampled stream avoids adding latency to end users while maintaining statistical visibility over system health.
