Hyperparameter Search: Grid, Random, Successive Halving

Strategies for navigating hyperparameter configurations, from brute-force grid search to distribution sampling and resource-adaptive successive halving.

01 The idea

Machine learning models rely on external hyperparameters—such as regularisation strength, tree depth, and learning rates—that cannot be estimated directly through gradient descent. Exhaustive grid search scales exponentially with dimensionality and wastes trials exploring uninformative parameters. Random search and multi-fidelity successive halving dramatically accelerate discovery by sampling continuous spaces and aggressively terminating unpromising configurations early.

Imagine searching for the perfect recipe for baking sourdough bread. You have three knobs to adjust: baking temperature, proofing time, and oven rack height. If you set up an exhaustive grid testing 5 temperatures, 5 proofing times, and 4 rack heights, you must bake $5 \times 5 \times 4 = 100$ individual loaves. Worse, after tasting them all, you discover that oven rack height makes virtually zero difference to the bread's texture. Because you used a rigid grid, you baked the same 25 temperature-time combinations four times over, testing only 5 distinct temperatures.

Random search breaks this gridlock. Instead of locking hyperparameters to discrete intersections, it samples configurations randomly from continuous distributions. In 100 random loaves, you test roughly 100 distinct temperatures and 100 distinct proofing times. As Bergstra and Bengio (2012) proved mathematically, most machine learning problems have low effective dimensionality—only a fraction of hyperparameters drive performance. By scattering trials across the space, random search explores the critical dimensions far more granularly for the exact same computational budget.

But why bake every trial loaf for the full 45 minutes? If a loaf fails to rise after 10 minutes, you already know it will not win. Successive halving formalises this intuition as a multi-fidelity bandit problem. It begins by launching dozens of configurations on tiny budgets (e.g. 5 epochs or 10% of the training data). At regular checkpoints, it ranks all candidates, prunes the bottom half (or bottom two-thirds), and doubles the resource budget for the survivors. By focusing compute only on configurations that show early promise, successive halving identifies superior hyperparameters up to an order of magnitude faster.

In everyday terms

Running an audition for an orchestra: listening to a hundred musicians play a 30-second scale, inviting the top twenty to play a full piece, and giving the top three a full rehearsal to choose the winner.

02 Step by step

  1. Define the search space: specify bounds, categorical choices, and prior probability distributions (e.g. log-uniform for learning rates and regularisation penalties).
  2. Select an exploration strategy: choose random search over grid search whenever the hyperparameter dimensionality exceeds two or three variables.
  3. Configure a multi-fidelity schedule: choose an allocation factor $\eta$ (typically 2 or 3), a minimum resource budget $r_{\min}$ (e.g. 1 epoch or 100 samples), and a maximum resource budget $R$.
  4. Initialise candidates: sample $N = \eta^s$ configurations uniformly across the defined search space.
  5. Run successive halving rounds: evaluate all active configurations on resource budget $r$, rank by validation loss, retain the top $1/\eta$ fraction, multiply budget $r \leftarrow r \cdot \eta$, and repeat until survivors reach $R$.
  6. Refit the winning configuration on the full dataset using maximum compute to produce the final production model.

03 The maths

  1. Grid search complexity and the curse of dimensionality

    $$N_{\text{grid}} = \prod_{i=1}^d k_i = k^d$$

    Evaluating $k$ discrete values across $d$ hyperparameters requires exponential computational effort. If only $d_{\text{eff}} \ll d$ hyperparameters actually influence model performance, grid search wastes $k^d - k^{d_{\text{eff}}}$ model evaluations re-testing redundant configurations along uninformative axes.

  2. Random search sample efficiency

    $$P(\text{finding within top } \alpha \text{ percentile}) = 1 - (1 - \alpha)^n$$

    To achieve a 95% probability of sampling at least one configuration within the top 5% of the parameter space ($\alpha = 0.05$), random search requires only $n = \frac{\ln(1 - 0.95)}{\ln(1 - 0.05)} \approx 59$ trials, completely independent of the number of hyperparameter dimensions $d$.

  3. Successive halving resource allocation

    $$N_k = \left\lfloor \frac{N_{k-1}}{\eta} \right\rfloor, \qquad R_k = R_{k-1} \cdot \eta, \qquad \sum_{k=0}^K N_k R_k \approx N_0 r_{\min} (K + 1)$$

    where $\eta$ is the reduction factor and $K = \lfloor \log_\eta(R / r_{\min}) \rfloor$ is the number of halving rungs. By discarding the worst $(1 - 1/\eta)$ configurations at each rung, the total compute allocated across all configurations scales logarithmically with maximum resource depth.

04 Key takeaways

  • Random search consistently outperforms grid search on high-dimensional spaces because it evaluates far more unique values along critical dimensions.
  • Successive halving allocates compute dynamically by evaluating many candidates on cheap budgets and pruning unpromising configurations early.
  • Logarithmic prior distributions are mandatory for scale-invariant parameters like learning rate, L2 penalty, and kernel width.
  • Hyperband extends successive halving by looping over multiple trade-offs between initial candidate count and minimum resource budget.

05 In code

python
import numpy as np

# Synthetic linear data with 5 features
rng = np.random.default_rng(42)
X_full = rng.normal(0, 1, (200, 5))
y_full = X_full[:, 0] * 2.0 - X_full[:, 1] * 1.5 + rng.normal(0, 0.5, 200)

# Sample 16 random hyperparameter candidates for Ridge (log-alpha in [-3, 3])
alphas = np.exp(rng.uniform(-3, 3, 16))
budgets = [25, 50, 100, 200]  # training subsample sizes

current_alphas = alphas.copy()
for b in budgets[:-1]:
    X_sub, y_sub = X_full[:b], y_full[:b]
    losses = []
    for a in current_alphas:
        w = np.linalg.solve(X_sub.T @ X_sub + a * np.eye(5), X_sub.T @ y_sub)
        val_mse = np.mean((y_full[100:] - X_full[100:] @ w) ** 2)
        losses.append(val_mse)
    survivors = np.argsort(losses)[:len(current_alphas) // 2]
    print(f"Budget n={b:3d} | Candidates: {len(current_alphas):2d} | Best MSE: {min(losses):.4f}")
    current_alphas = current_alphas[survivors]

# Final evaluation on full data
w_best = np.linalg.solve(X_full.T @ X_full + current_alphas[0] * np.eye(5), X_full.T @ y_full)
final_mse = np.mean((y_full - X_full @ w_best) ** 2)
print(f"Best alpha: {current_alphas[0]:.4f} | Full data MSE: {final_mse:.4f}")

Common pitfalls

  • Early-stage ranking noise: If the initial resource budget $r_{\min}$ is set too low (e.g. only 1 epoch or 10 samples), learning rates with slow warmup or deep architectures may perform poorly early on and get discarded despite having superior asymptotic performance.
  • Uniform sampling on linear scale for scale-sensitive parameters: Sampling learning rates or regularisation parameters linearly between $10^{-5}$ and $1.0$ allocates 90% of trials to values above $0.1$. Multiplicative parameters must be sampled on a logarithmic scale (log-uniform).
  • Data leakage during subsample evaluation: Subsampling data for resource scaling must preserve class label distributions via stratified sampling; otherwise minority classes may be entirely absent from low-resource rungs.
  • Overfitting the validation set: Evaluating thousands of hyperparameter configurations against a single validation split inevitably selects for validation set noise (the winner's curse), requiring nested cross-validation or an untouched holdout test set.

06 Check yourself

Q1Why does random search consistently outperform exhaustive grid search when tuning machine learning models with 5 or more hyperparameters?

Why: In most machine learning models, only 1 or 2 hyperparameters strongly dictate performance (e.g. learning rate and regularisation). While grid search wastes compute repeatedly testing the same few values of the important parameter against unimportant variations, random search tests a unique value on every single trial.

Q2How many random trials $n$ are required to have a 95% probability of sampling at least one configuration within the top 5% ($\alpha = 0.05$) of all possible hyperparameter settings?

Why: Setting $1 - (1 - 0.05)^n \ge 0.95$ yields $(0.95)^n \le 0.05$. Taking logarithms gives $n \ge \ln(0.05) / \ln(0.95) \approx -2.9957 / -0.05129 \approx 58.4$ (or 59 trials). Remarkably, this probability is completely independent of dimensionality.

Q3What is the core mechanism of the Successive Halving algorithm?

Why: Successive halving allocates compute efficiently by testing $N$ configurations on a small initial budget (e.g. subsamples or epochs), pruning the bottom fraction (e.g. 50%), and doubling the budget for the survivors over successive rungs.

Q4Why should hyperparameters like regularisation weight $\lambda$ or learning rate $\eta$ be sampled from a log-uniform distribution rather than a uniform distribution?

Why: A shift from $10^{-4}$ to $10^{-3}$ has a comparable structural impact to a shift from $10^{-1}$ to $1.0$. Sampling uniformly on $[10^{-4}, 1.0]$ would allocate 90% of samples to values between 0.1 and 1.0, virtually ignoring the smaller decades.
