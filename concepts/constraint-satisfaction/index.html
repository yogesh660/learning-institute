Constraint Satisfaction Problems: Backtracking, Arc Consistency (AC-3), and Heuristics

A formal problem-solving paradigm that models states as variables with discrete domains and solutions as complete assignments satisfying all relational constraints.

01 The idea

Constraint Satisfaction Problems (CSPs) represent state spaces declaratively through variables, domains, and relational constraints. By combining depth-first backtracking search with constraint propagation algorithms like AC-3 and variable-ordering heuristics (MRV, Degree heuristic), CSP solvers efficiently resolve scheduling, timetabling, and circuit layout problems.

In standard search algorithms (BFS, A*), states are black-box atomic entities evaluated by heuristic distance functions. In contrast, a Constraint Satisfaction Problem (CSP) gives internal structure to the state: a state is defined by a set of variables $X_i$, each taking values from a domain $D_i$, subject to a set of explicit constraints $C_j$.

Because constraints are explicit mathematical relations, solvers can detect dead ends long before reaching leaf nodes. Constraint propagation algorithms like AC-3 prune values from variable domains that cannot possibly participate in any valid solution, pruning billions of doomed search branches before backtracking search even visits them.

In everyday terms

Solving a CSP is like arranging seating for an opinionated wedding party. Each guest is a variable, each chair is a domain value, and social rules are constraints ("Aunt Jane cannot sit next to Uncle Bob"). Rather than trying all quadrillion seating combinations, you immediately discard tables that violate constraints as you seat guests one by one.

02 Step by step

  1. Define problem specification: identify variables $X$, domain sets $D$, and relational constraints $C$ (unary, binary, or global).
  2. Apply initial constraint propagation: execute AC-3 over all directed constraint arcs to eliminate domain values with no valid support.
  3. Select unassigned variable: apply the Minimum Remaining Values (MRV) heuristic (fail-first principle) and Degree heuristic as tie-breaker.
  4. Order candidate domain values: test values using the Least Constraining Value (LCV) heuristic to maximise options for remaining unassigned variables.
  5. Recursive assignment and backtracking: tentatively assign the value, execute forward checking or MAC (Maintaining Arc Consistency), and backtrack if any domain becomes empty.

03 The maths

  1. Arc Consistency Definition

    \forall x \in D_i, \quad \exists y \in D_j \quad \text{such that} \quad (x, y) \in C_{ij}

    A directed arc $(X_i, X_j)$ is arc-consistent if for every value $x$ in domain $D_i$, there exists at least one legal value $y$ in $D_j$ satisfying constraint $C_{ij}$.

  2. AC-3 Algorithm Complexity

    \mathcal{O}(c \cdot d^3)

    Worst-case time complexity of the AC-3 propagation algorithm on a CSP with $c$ binary constraint arcs and maximum domain size $d$.

04 Key takeaways

  • CSPs represent problems through variables, domains, and relational constraints, enabling general domain-independent solvers.
  • AC-3 enforces pairwise arc consistency by pruning unsupported domain values prior to or during backtracking.
  • The MRV (fail-first) and LCV (fail-last) heuristics drastically shrink the search tree compared to naive depth-first search.

05 In code

python
def ac3(domains, constraints):
    """Executes the AC-3 arc consistency constraint propagation algorithm."""
    # Queue of all directed constraint arcs
    queue = [(xi, xj) for xi in domains for xj in domains if (xi, xj) in constraints]
    
    while queue:
        xi, xj = queue.pop(0)
        # Check if any value in D_i lacks support in D_j
        revised = False
        allowed_pairs = constraints.get((xi, xj), set())
        
        new_di = []
        for x in domains[xi]:
            # Is there any y in D_j such that (x, y) is allowed?
            if any((x, y) in allowed_pairs for y in domains[xj]):
                new_di.append(x)
            else:
                revised = True
                
        if revised:
            domains[xi] = new_di
            if len(domains[xi]) == 0:
                return False  # Inconsistent CSP
            # Recheck neighbours of xi
            for xk in domains:
                if xk != xi and xk != xj and (xk, xi) in constraints:
                    queue.append((xk, xi))
    return True

# Map Colouring CSP: 3 regions (WA, NT, SA), colours: {Red, Green}
domains = {
    'WA': ['R', 'G'],
    'NT': ['R'],
    'SA': ['R', 'G']
}

# Constraint: adjacent regions cannot share colour
neq = {(c1, c2) for c1 in ['R', 'G'] for c2 in ['R', 'G'] if c1 != c2}
constraints = {
    ('WA', 'NT'): neq, ('NT', 'WA'): neq,
    ('WA', 'SA'): neq, ('SA', 'WA'): neq,
    ('NT', 'SA'): neq, ('SA', 'NT'): neq
}

consistent = ac3(domains, constraints)
print(f"AC-3 Consistency Result: {consistent}")
print(f"Pruned Domains after Arc Consistency: {domains}")

Common pitfalls

  • Applying standard AC-3 without backtracking; arc consistency does not guarantee that a global solution exists, only that all binary arcs have local support.
  • Representing global constraints (like `AllDifferent`) as dozens of pairwise binary constraints, missing powerful filtering algorithms like bipartite matching.

06 Check yourself

Q1What is the rationale behind the Minimum Remaining Values (MRV) variable selection heuristic?

Why: By choosing the variable with the fewest legal values left, the search discovers unavoidable dead ends early before expanding deep subtrees.

Q2What occurs when AC-3 reduces a variable's domain to an empty set?

Why: An empty domain means that variable has no valid assignment that satisfies the constraints with its neighbours, proving the current path is impossible.

Q3What does the Least Constraining Value (LCV) heuristic do?

Why: LCV aims to maximise future flexibility by choosing the value that leaves the maximum number of legal options open for subsequent variables.
