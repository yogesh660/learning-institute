Causal graphs (DAGs) and adjustment

Causal Directed Acyclic Graphs (DAGs) and Pearl's structural causal framework provide the mathematical language to differentiate mere statistical correlation from genuine causal effect. By formalising causal assumptions as directional graphical models (X -> Y), causal DAGs systematically identify confounding, mediation, and collider structures. The Backdoor Criterion and d-separation establish exactly which set of covariates Z must be controlled for—and crucially, which variables must NOT be conditioned on (to avoid collider stratification bias)—to eliminate spurious confounding and identify causal effects from observational data.

01 The idea

"Correlation does not imply causation"—every data scientist knows this axiom, yet when building predictive models, how do you decide which variables to include as regression controls? Adding more control variables is not always safe: controlling for the wrong variable can create massive spurious correlations that did not exist in the raw data! Pearl's causal DAGs provide the mathematical calculus to identify true causal pathways, avoid collider bias, and determine whether observational data can answer causal questions.

The Three Fundamental Causal Junctions: Any causal graph is built from three 3-node patterns: - Chain (Mediation): X -> M -> Y. X causes M, which causes Y. Conditioning on mediator M blocks the causal path between X and Y. - Fork (Confounder): X <- Z -> Y. Confounder Z causes both X and Y, creating a spurious non-causal association. Conditioning on Z blocks the spurious correlation. - Collider: X -> C <- Y. Both X and Y independently cause collider C. In the unconditioned data, X and Y are independent! But if you condition on collider C (or a descendant of C), you open a spurious path and induce artificial correlation between X and Y!

The Danger of Bad Controls (Collider Stratification Bias): Suppose being a brilliant actor (X) and having movie star looks (Y) are completely independent in the general population. But to be cast in Hollywood films (C), you need either talent or looks (X -> C <- Y). If you only analyse Hollywood actors (conditioning on C), you will find a strong negative correlation: talented actors seem less attractive, and attractive actors seem less talented! This is Berkson's fallacy / collider bias.

The Backdoor Criterion: To find the true causal effect of treatment X on outcome Y, you must block all "backdoor paths" (paths that start with an arrow pointing into X: X <- ... -> Y) by conditioning on a valid adjustment set Z, without conditioning on any collider or descendant of X.

In everyday terms

Imagine water flowing through a plumbing pipe network from tap X to drain Y. A backdoor path is an accidental cross-connection through an upstream water tower Z that leaks into both pipes. Conditioning on a confounder is closing a valve on the leak so only water from tap X reaches drain Y. A collider is a shared flood sensor that is normally dry; if you tamper with it (condition on it), you inadvertently create an electrical short that connects two previously isolated pipe valves together.

03 The maths

  1. The do-Operator and Causal Effect Identification

    P(Y = y \mid \text{do}(X = x)) \neq P(Y = y \mid X = x), \qquad P(Y = y \mid \text{do}(X = x)) = \sum_{\mathbf{z}} P(Y = y \mid X = x, \mathbf{Z} = \mathbf{z}) \, P(\mathbf{Z} = \mathbf{z})

    The do-operator \text{do}(X=x) represents a physical intervention that severs all incoming arrows into X, setting X to value x. When the set of covariates \mathbf{Z} satisfies the Backdoor Criterion, the causal effect is identified from purely observational data using the adjustment formula.

  2. The Backdoor Criterion (Pearl)

    \mathbf{Z} \text{ satisfies Backdoor Criterion for } (X, Y) \iff \begin{cases} (1) \; \text{No node in } \mathbf{Z} \text{ is a descendant of } X \\ (2) \; \mathbf{Z} \text{ d-separates (blocks) every path } X \leftarrow \dots \to Y \end{cases}

    Condition (1) ensures that causal mechanisms mediated by X are not accidentally blocked. Condition (2) ensures that all spurious non-causal confounding associations are completely blocked.

  3. Collider Conditioning Bias (Berkson's Paradox)

    X \perp Y \quad \text{but} \quad X \not\perp Y \mid C \quad \text{for collider junction } X \to C \leftarrow Y

    Two independent causes X and Y become conditionally dependent when conditioning on their common effect C (or any descendant of C). Conditioning on a collider induces spurious negative or positive correlation where none exists in the population.

04 Key takeaways

  • Causal DAGs represent causal mechanisms via directed acyclic graphs, distinguishing correlation from causation.
  • The three fundamental junctions are Chains (mediation), Forks (confounding), and Colliders (common effects).
  • Confounders must be controlled for to block spurious backdoor paths; colliders must NOT be conditioned on, as conditioning opens spurious association.
  • The Backdoor Criterion provides the graphical rules for identifying valid adjustment sets from observational data.

05 In code

python
"""
Causal DAG Simulation: Confounding vs Collider Bias
Demonstrating that adding control variables can eliminate confounding
OR artificially introduce collider bias (Berkson's fallacy).
"""

import numpy as np

# Ground Truth Causal Data Generating Process:
# Z (Confounder: Socioeconomic status) -> X (Education) and Y (Health)
# True Causal Effect of Education on Health = 2.0
# C (Collider: Hospital admission) <- X (Education) and Y (Health)
np.random.seed(42)
N = 10000

# 1. Confounder Z
z_socioeconomic = np.random.normal(loc=0.0, scale=1.0, size=N)

# 2. Treatment X (caused by Z + independent noise)
x_education = 1.5 * z_socioeconomic + np.random.normal(0, 1, size=N)

# 3. Outcome Y (caused by X with true effect beta=2.0 + Z + noise)
true_causal_beta = 2.0
y_health = true_causal_beta * x_education + 2.5 * z_socioeconomic + np.random.normal(0, 1, size=N)

# 4. Collider C (caused by BOTH X and Y)
# e.g. Admission to a specialised clinic: C = 1 if 0.8*X + 0.8*Y + noise > 2.0
collider_score = 0.8 * x_education + 0.8 * y_health + np.random.normal(0, 1, size=N)
c_admitted = (collider_score > 1.5).astype(int)

def fit_ols(y_vec, *x_vecs):
    """Simple OLS solver returning slope coefficients."""
    X_mat = np.column_stack([np.ones(len(y_vec))] + list(x_vecs))
    beta = np.linalg.inv(X_mat.T @ X_mat) @ (X_mat.T @ y_vec)
    return beta

print("=== Causal Inference Demonstration: True Causal Effect beta = 2.00 ===")

# Model 1: Naive Regression (No controls: Y ~ X)
# Confounded by Z!
beta_naive = fit_ols(y_health, x_education)
print(f"1. Naive Regression (Y ~ X):                   Estimated beta = {beta_naive[1]:.3f} (Severely Confounded!)")

# Model 2: Valid Backdoor Adjustment (Y ~ X + Z)
# Blocks the backdoor path X <- Z -> Y
beta_adjusted = fit_ols(y_health, x_education, z_socioeconomic)
print(f"2. Valid Backdoor Adjustment (Y ~ X + Z):      Estimated beta = {beta_adjusted[1]:.3f} (Recovers True Effect!)")

# Model 3: Bad Control - Conditioning on Collider C (Y ~ X + Z + C)
# Inadvertently opens the collider path X -> C <- Y!
beta_collider = fit_ols(y_health, x_education, z_socioeconomic, collider_score)
print(f"3. Bad Control / Collider Bias (Y ~ X + Z + C):Estimated beta = {beta_collider[1]:.3f} (Biased by Collider!)")

# Model 4: Berkson's Fallacy (Analysing only the admitted subpopulation C == 1)
mask = (c_admitted == 1)
beta_subpop = fit_ols(y_health[mask], x_education[mask], z_socioeconomic[mask])
print(f"4. Stratified on Collider (Subset where C=1):   Estimated beta = {beta_subpop[1]:.3f} (Berkson's Bias!)")

Common pitfalls

  • The 'kitchen sink' regression trap: Adding all available features as control variables often controls for colliders or mediators, destroying causal validity.
  • Controlling for post-treatment variables: Conditioning on an outcome of treatment (mediator) blocks the very causal mechanism being measured.
  • Assuming causal DAGs can be discovered purely from data without assumptions: Observational data can identify Markov equivalence classes, but orienting arrows requires domain knowledge or physical interventions.

06 Check yourself

Q1In a causal DAG, what happens when you condition on a collider node (X -> C <- Y)?

Why: An unconditioned collider naturally blocks association between X and Y. Conditioning on the collider opens the path, creating an artificial statistical association between its independent causes.

Q2What two conditions must a set of covariates Z satisfy to meet the Backdoor Criterion for (X, Y)?

Why: Pearl's Backdoor Criterion requires that Z blocks all confounding paths (X <- ... -> Y) without conditioning on any downstream consequence of treatment X (descendant).

Q3What is the difference between P(Y | X=x) and P(Y | do(X=x))?

Why: Observational conditioning P(Y | X=x) filters existing data (and includes confounding associations). The do-operator P(Y | do(X=x)) simulates an intervention that fixes X, establishing genuine causal impact.
