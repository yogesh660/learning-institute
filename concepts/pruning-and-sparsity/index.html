Pruning and Sparsity: Structural Compression and the Lottery Ticket Hypothesis

Eliminating redundant parameters using magnitude pruning, structured channel removal, and sparse sub-network discovery via the Lottery Ticket Hypothesis.

01 The idea

Over-parameterised deep neural networks contain massive redundancy: up to 80%–95% of weights can be set to zero without degrading final test accuracy. However, unconstrained training does not produce sparse models on its own. Pruning identifies and eliminates non-essential weights, reducing model storage, memory footprints, and accelerating inference on hardware that supports sparse computation.

Pruning removes parameters from a trained network based on an importance metric (most commonly weight magnitude $|w|$).

Unstructured Pruning sets individual scalar weights to zero, creating sparse weight tensors. While it dramatically reduces theoretical parameter counts, standard hardware (CPUs/GPUs) cannot easily accelerate unstructured random zero patterns unless running on specialized sparse Tensor Cores (e.g. NVIDIA 2:4 structured sparsity).

Structured Pruning removes entire architectural blocks—entire convolutional channels, attention heads, or linear rows/columns. This directly reduces tensor matrix dimensions, delivering immediate latency speedups on any standard hardware without specialized sparse software libraries.

The Lottery Ticket Hypothesis (Frankle & Carbin, 2018) discovered that dense, randomly-initialised networks contain sparse sub-networks ("winning lottery tickets") that, when trained in isolation from their original initialisation, can match the test accuracy of the original dense network in an equal number of training iterations.

In everyday terms

Imagine a sprawling bonsai tree. When left to grow wildly, the tree develops thousands of tiny overlapping branches that block light from one another. A master gardener prunes away non-essential twigs and weak branches: the tree not only retains its essential artistic shape and health, but requires less water, fits in a smaller ceramic pot, and thrives under focused nutrition.

02 Step by step

  1. Train dense baseline network: Train the full over-parameterised network to target convergence.
  2. Select pruning granularity: Choose unstructured pruning (for compression and 2:4 sparse accelerators) or structured pruning (for general latency reduction on CPUs/GPUs).
  3. Compute importance scores: Evaluate weight magnitudes $|w_{ij}|$, first-order gradient Taylor expansion, or channel activation norms.
  4. Apply binary pruning mask: Zero out the lowest $P\%$ of weights by applying a binary indicator mask $\mathbf{M} \in \{0, 1\}$.
  5. Iterative fine-tuning (Retraining): Fine-tune the remaining unmasked weights at a lower learning rate to recover lost accuracy.
  6. Iterative Pruning Schedule: Repeat prune-and-finetune cycles gradually (e.g. pruning 20% per cycle over 5 rounds) rather than pruning 80% in one shot (One-Shot Pruning).

03 The maths

  1. Magnitude-Based Unstructured Pruning Mask

    m_{ij} = \mathbb{I}\left( |w_{ij}| \ge \tau_p \right), \quad \tilde{\mathbf{W}} = \mathbf{M} \odot \mathbf{W}

    Applies binary mask $\mathbf{M}$ keeping only weights whose absolute magnitude meets or exceeds threshold percentile $\tau_p$.

  2. L1-Norm Structured Channel Pruning

    s_c = \frac{1}{C_{\mathrm{in}} \times K \times K} \sum_{j=1}^{C_{\mathrm{in}}} \sum_{u=1}^K \sum_{v=1}^K |W_{c, j, u, v}|

    Measures the importance of output channel $c$ by the average magnitude of its convolutional kernel weights, removing bottom channels entirely.

  3. Lottery Ticket Hypothesis Formulation

    \exists \mathbf{M} \in \{0, 1\}^{|\theta|} : \|\mathbf{M}\|_0 \ll |\theta| \;\land\; \operatorname{Train}(\mathbf{M} \odot \theta_0) \approx \operatorname{Train}(\theta_0)

    A winning ticket sub-network $(\mathbf{M} \odot \theta_0)$ achieves test accuracy comparable to the original dense network $\theta_0$ when trained from identical initialisation.

04 Key takeaways

  • Pruning eliminates redundant parameters to compress networks and reduce inference latency.
  • Unstructured pruning zeros individual weights; structured pruning eliminates entire channels or attention heads.
  • Iterative pruning with fine-tuning recovers accuracy far more effectively than one-shot pruning.
  • The Lottery Ticket Hypothesis proves small sub-networks can match dense accuracy if initialized identically.

05 In code

python
import torch
import torch.nn as nn
import torch.nn.utils.prune as prune

# Create a small convolutional model
model = nn.Sequential(
    nn.Conv2d(1, 16, kernel_size=3, padding=1),
    nn.ReLU(),
    nn.Linear(16, 10)
)

conv_layer = model[0]
print("Dense weight non-zero count:", torch.count_nonzero(conv_layer.weight).item())

# Apply 50% L1 unstructured magnitude pruning to conv weights
prune.l1_unstructured(conv_layer, name='weight', amount=0.5)

print("Pruned weight non-zero count:", torch.count_nonzero(conv_layer.weight).item())
print("Weight sparsity percentage:  50.0%")
print("Mask applied:", hasattr(conv_layer, 'weight_mask'))

# To permanently remove parameters and bake mask into weights:
prune.remove(conv_layer, 'weight')
print("Permanent sparsity verified:", (conv_layer.weight == 0).sum().item(), "zeros out of", conv_layer.weight.numel())

Common pitfalls

  • Expecting latency speedups from unstructured sparsity on standard hardware: Zeroing out 70% of weights at random does not make standard dense BLAS libraries faster; it only reduces file compression size unless using 2:4 sparse accelerators.
  • One-shot aggressive pruning: Pruning 80% of parameters in a single step causes catastrophic accuracy collapse; always prune iteratively with fine-tuning recovery.
  • Pruning without fine-tuning: Forgetting to fine-tune after pruning leaves the remaining network in a degraded state without adapting to the missing weights.

06 Check yourself

Q1Why does unstructured magnitude pruning often fail to deliver real-world wall-clock latency speedups on standard GPUs?

Why: Dense GEMM routines process dense matrices uniformly. Random irregular zeros require sparse indexing overhead that negates FLOP savings on standard hardware unless structured (e.g. 2:4 sparsity).

Q2What is the central finding of the "Lottery Ticket Hypothesis" (Frankle & Carbin, 2018)?

Why: The hypothesis proves that dense over-parameterisation serves primarily to help gradient descent find lucky "winning ticket" sub-networks during early initialisation.

Q3How does structured pruning differ from unstructured pruning?

Why: Structured pruning drops complete channels or rows, producing smaller dense matrices that run faster on any standard CPU or GPU without sparse execution libraries.
