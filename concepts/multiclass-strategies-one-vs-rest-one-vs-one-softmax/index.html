Multiclass Strategies: One-vs-Rest, One-vs-One and Softmax

Multiclass classification decomposes multi-category targets into binary sub-problems via One-vs-Rest or One-vs-One, or predicts class probabilities jointly via Softmax regression.

01 The idea

Many foundational classification algorithms—such as standard Support Vector Machines, perceptrons, and linear margins—are inherently binary. To predict among $K > 2$ classes, algorithms either adopt architectural reductions (One-vs-Rest or One-vs-One tournaments) or formulate a native multinomial likelihood using the Softmax function.

Imagine sorting incoming emails into three categories: Work, Personal, and Finance. If your classifier only knows how to answer yes-or-no queries, how do you proceed? The most common heuristic is **One-vs-Rest (OvR)**, also known as One-vs-All. You train three separate binary models: Model 1 asks "Is this Work or not?", Model 2 asks "Is this Personal or not?", and Model 3 asks "Is this Finance or not?". Each model scores the document, and you assign the email to whichever classifier reports the highest decision margin.

An alternative decomposition is **One-vs-One (OvO)**. Instead of pitting each class against the pooled remainder of the dataset, you organise a round-robin tournament between every unique pair of classes. For 3 categories, you train $3(2)/2 = 3$ binary classifiers: Work vs Personal, Work vs Finance, and Personal vs Finance. Each classifier votes for its preferred class, and the class with the most aggregate votes wins. Although OvO trains $K(K-1)/2$ models, each model trains on a much smaller dataset ($2/K$ of the data), making it exceptionally fast for algorithms with super-linear computational scaling.

Rather than decomposing multi-class problems into disconnected binary tasks, **Softmax regression** solves the problem natively. It maintains a separate weight vector for each class, computes linear logits $z_k = x^T w_k$, and exponentiates and normalises them so the resulting probabilities across all $K$ categories sum to exactly 1.0. By jointly optimising a single multinomial cross-entropy loss, Softmax accounts for direct competition between classes, avoiding the uncalibrated score comparisons that can compromise OvR.

In everyday terms

OvR is like holding separate individual referendum votes on every candidate, OvO is a round-robin boxing tournament where every contender fights every other contender, and Softmax is a single ballot where voters allocate a unified probability distribution across all contenders simultaneously.

02 Step by step

  1. Determine the class count $K$ and establish whether base estimators natively support multinomial likelihoods or require binary reduction.
  2. For One-vs-Rest (OvR), construct $K$ binary classification tasks, setting class $k$ as positive (+1) and pooling all other $K-1$ classes as negative (0).
  3. For One-vs-One (OvO), train $K(K-1)/2$ binary models on paired subsets $\mathcal{D}_{ij} = \\{ (x, y) \mid y \in \\{i, j\\} \\}.
  4. For Softmax regression, parameterise a weight matrix $W \in \mathbb{R}^{p \times K}$ and compute class probabilities via normalised exponentials.
  5. Aggregate classifications: select $\arg\max$ of continuous decision margins in OvR, tally pairwise majority votes in OvO, or pick the maximum posterior probability in Softmax.
  6. Diagnose probability calibration and resolve ties or ambiguous multi-class boundaries.

03 The maths

  1. One-vs-Rest (OvR) decision rule

    $$\hat{y} = \arg\max_{k \in \\{1, \dots, K\\}} f_k(x), \quad f_k(x) = x^T w_k + b_k$$

    $f_k(x)$ represents the decision margin of binary classifier $k$ trained to separate class $k$ from all other classes. When binary models output uncalibrated scores, the $\arg\max$ operator can be skewed toward models with artificially wide margin scales.

  2. One-vs-One (OvO) model count and voting rule

    $$M = \frac{K(K - 1)}{2}, \quad \hat{y} = \arg\max_{k} \sum_{j \ne k} \mathbb{I}\big(f_{kj}(x) = k\big)$$

    $M$ is the number of pairwise binary classifiers. Each model $f_{kj}$ votes for either class $k$ or class $j$. The class accumulating the highest vote tally across all pairwise duels is selected, with ties broken by sum of decision margins.

  3. The Softmax function and categorical cross-entropy

    $$P(Y = k \mid x) = \frac{e^{x^T w_k}}{\sum_{j=1}^K e^{x^T w_j}}, \quad \mathcal{L}_{\text{CE}}(W) = -\sum_{i=1}^n \sum_{k=1}^K \mathbb{I}(y_i = k) \log P(Y = k \mid x_i)$$

    Logits $z_k = x^T w_k$ are exponentiated and normalised by the partition denominator $\sum_{j=1}^K e^{z_j}$, ensuring probabilities remain strictly positive and sum to 1.0. Gradient descent updates weights based on prediction error residuals $(p_{ik} - y_{ik}) x_i$.

04 Key takeaways

  • OvR trains $K$ classifiers on full dataset size $n$; OvO trains $K(K-1)/2$ classifiers on smaller sub-samples ($2n/K$).
  • OvO is computationally advantageous for algorithms with super-linear scaling $\mathcal{O}(n^2)$ (like kernel SVMs), as the sum of squared sub-sample sizes is smaller than $K n^2$.
  • Softmax regression produces mutually exclusive, globally calibrated posterior probabilities that naturally sum to 1.0.
  • OvR introduces severe class imbalance as $K$ increases: in a 20-class dataset, each OvR classifier faces a 1:19 imbalance ratio.

05 In code

python
import numpy as np

np.random.seed(42)
n_per_class, K = 60, 3
centres = [[-1.5, -1.0], [1.5, -1.0], [0.0, 1.8]]
X = np.vstack([np.random.normal(c, 0.6, (n_per_class, 2)) for c in centres])
y = np.repeat([0, 1, 2], n_per_class)
N, p = X.shape
X_b = np.column_stack([np.ones(N), X])

# 1. Softmax regression
W = np.zeros((p + 1, K))
lr = 0.1
for _ in range(250):
    logits = X_b @ W
    exp_z = np.exp(logits - np.max(logits, axis=1, keepdims=True))
    P = exp_z / np.sum(exp_z, axis=1, keepdims=True)
    Y_onehot = np.eye(K)[y]
    W -= lr * (X_b.T @ (P - Y_onehot)) / N

softmax_acc = np.mean(np.argmax(X_b @ W, axis=1) == y)

# 2. One-vs-Rest (OvR) binary logistic models
ovr_probs = np.zeros((N, K))
for k in range(K):
    y_bin = (y == k).astype(float)
    w_bin = np.zeros(p + 1)
    for _ in range(250):
        p_bin = 1.0 / (1.0 + np.exp(-np.clip(X_b @ w_bin, -15, 15)))
        w_bin -= lr * (X_b.T @ (p_bin - y_bin)) / N
    ovr_probs[:, k] = 1.0 / (1.0 + np.exp(-np.clip(X_b @ w_bin, -15, 15)))

ovr_acc = np.mean(np.argmax(ovr_probs, axis=1) == y)

print("Softmax classification accuracy:", round(float(softmax_acc), 3))
print("One-vs-Rest classification accuracy:", round(float(ovr_acc), 3))
print("Sample Softmax row sum:", round(float(np.sum(P[0])), 3))
print("Sample OvR row sum (not constrained to 1):", round(float(np.sum(ovr_probs[0])), 3))

Common pitfalls

  • Comparing uncalibrated margins in OvR: binary SVM decision function values have different scales; taking $\arg\max$ directly favours classifiers with higher variance.
  • OvO combinatorial explosion: for problems with $K > 100$ categories, OvO requires thousands of models, creating severe latency and memory bottlenecks.
  • Softmax overconfidence: the exponential function in Softmax aggressively exaggerates logit gaps, often assigning >99% confidence to inputs far from the training data.
  • Applying Softmax to multi-label problems: Softmax enforces a single mutually exclusive winner; multi-label classification requires independent sigmoid outputs.

06 Check yourself

Q1How many binary classifiers must be trained to solve a $K$-class problem using the One-vs-One (OvO) strategy?

Why: OvO trains a separate binary classifier for every unique pair of classes, resulting in $\binom{K}{2} = \frac{K(K-1)}{2}$ models.

Q2Why can One-vs-One (OvO) train faster than One-vs-Rest (OvR) when using non-linear Support Vector Machines?

Why: Because kernel SVM training complexity scales super-linearly with $n$, training $\approx K^2/2$ models on small datasets of size $2n/K$ requires far less computation than training $K$ models on the full dataset of size $n$.

Q3What is a major limitation of One-vs-Rest (OvR) when the number of classes $K$ is large?

Why: In an OvR setup with $K$ classes, each binary classifier compares 1 class against $K-1$ combined classes, exposing the binary learner to severe label imbalance.

Q4How does Softmax regression ensure that predicted class probabilities are mutually consistent?

Why: The Softmax denominator $\sum_{j=1}^K e^{z_j}$ acts as a normalising partition function, ensuring all outputs are positive and sum to 1.0.
