RAG evaluation

Evaluating Retrieval-Augmented Generation (RAG) pipelines requires decomposing the system into distinct retrieval and generation components rather than relying solely on end-to-end black-box assessment. The standard industry methodology—formalised in frameworks like RAGAS and TruLens—evaluates the "RAG Triad": Context Relevance (did the retriever return pertinent chunks without extraneous noise?), Groundedness / Faithfulness (is the generated answer strictly supported by the retrieved context, devoid of hallucination?), and Answer Relevance (does the response directly address the user's initial question?).

01 The idea

When an enterprise RAG application gives an unsatisfactory response, where did the failure occur? Did the retriever fail to find the necessary technical documents? Did the retriever bring back the right document alongside nine distracting paragraphs that led the model astray? Or did the LLM hallucinate an incorrect statistic despite having the correct facts in front of it? Evaluating RAG systems requires isolating each stage of the pipeline with dedicated metrics, synthetic evaluation datasets, and calibrated LLM-as-a-judge evaluators.

The RAG Triad: Three fundamental vectors govern RAG quality: - Context Relevance: High signal-to-noise ratio in retrieved passages. Evaluates precision of retriever: are the retrieved chunks actually relevant to answering the query, or is context space cluttered with irrelevant filler? - Faithfulness / Groundedness: Faithfulness measures whether every factual claim in the generated answer can be directly inferred from the retrieved context. A hallucinated statement receives a strict penalty. - Answer Relevance: Measures whether the generated text actually answers the user's inquiry, irrespective of whether the facts are true. A model that repeats the retrieved facts verbatim but ignores the user's specific question scores zero.

Component-Level vs End-to-End Metrics: - Retrieval metrics: Mean Reciprocal Rank (MRR), Hit Rate @ K, NDCG @ K, Context Recall (fraction of ground-truth reference points retrieved), and Context Precision (ranking relevant chunks higher than irrelevant ones). - Generation metrics: Faithfulness, Answer Semantic Similarity against golden references, and Semantic Answer Relevance (using directional query generation).

Synthetic Evaluation Data Generation: Building manual test datasets of hundreds of question-context-answer triples is prohibitively expensive. Modern RAG evaluation synthesises test sets by taking raw document chunks, using an LLM to generate candidate questions of varying complexity (factoid, reasoning, multi-hop), and identifying corresponding ground truth.

In everyday terms

Imagine a court trial involving a detective (the retriever), the evidence log (the context), and the prosecuting attorney (the generator). To evaluate the trial: 1. Context Relevance: Did the detective bring relevant physical evidence to the courtroom, or did they dump boxes of irrelevant grocery receipts on the table? 2. Faithfulness / Groundedness: Did the prosecutor base their closing speech strictly on the admitted evidence, or did they make up unsubstantiated accusations not found in the documents? 3. Answer Relevance: Did the prosecutor actually answer the judge's specific legal question, or did they deliver a passionate monologue about a completely different topic?

03 The maths

  1. Context Precision and Context Recall

    \text{Context Precision@K} = \frac{\sum_{k=1}^K \text{Precision@}k \times v_k}{\sum_{k=1}^K v_k}, \quad \text{Context Recall} = \frac{|\mathcal{S}_{\text{ground\_truth}} \cap \mathcal{S}_{\text{retrieved}}|}{|\mathcal{S}_{\text{ground\_truth}}|

    Context Precision evaluates whether relevant chunks are placed at the top of the retrieved ranking list. Here v_k \in \{0, 1\} indicates relevance of the chunk at rank k. Context Recall measures the proportion of key ground-truth factual statements \mathcal{S}_{\text{ground\_truth}} captured within the retrieved contexts.

  2. Faithfulness / Groundedness Formulation

    \text{Faithfulness} = \frac{\sum_{i=1}^{|C(y)|} \mathbb{I}\Big(c_i \in \text{Entailment}(\mathcal{K})\Big)}{|C(y)|}

    Let C(y) = \{c_1, c_2, \dots, c_m\} be the decomposed set of atomic factual claims extracted from generated answer y, and let \mathcal{K} denote the retrieved context. The indicator function equals 1 if claim c_i is logically entailed by \mathcal{K}, and 0 otherwise. A score of 1.0 indicates perfect groundedness devoid of hallucination.

  3. Answer Relevance via Directional Embedding Similarity

    \text{Answer Relevance} = \frac{1}{M} \sum_{j=1}^M \frac{\mathbf{e}(q)^\top \mathbf{e}(\hat{q}_j)}{\|\mathbf{e}(q)\| \, \|\mathbf{e}(\hat{q}_j)\|}, \quad \hat{q}_j \sim p_{\text{judge}}(\cdot \mid y)

    To prevent reward-hacking where a model repeats the context verbatim without addressing the user question, the judge model generates M candidate questions \hat{q}_j that the answer y would naturally address. Cosine similarity between generated question embeddings and the original user query q measures answer relevance.

04 Key takeaways

  • RAG evaluation must isolate retrieval quality from generation quality; relying purely on black-box end-to-end metrics obscures the root cause of failures.
  • The RAG Triad evaluates Context Relevance (retriever noise ratio), Faithfulness (freedom from hallucination), and Answer Relevance (direct query alignment).
  • Faithfulness is quantified by decomposing responses into atomic claims and checking logical entailment against retrieved context passages.
  • Synthetic test sets generated by LLMs from raw document chunks provide scalable, reproducible ground-truth benchmarks for continuous integration.

05 In code

python
"""
Comprehensive RAG Evaluation Framework (The RAG Triad)
Calculates Context Relevance, Faithfulness (Groundedness),
and Answer Relevance using structured claim verification.
"""

from typing import List, Dict, Tuple
import re

class RAGEvaluationSample:
    def __init__(self, query: str, contexts: List[str], response: str, ground_truth: str = ""):
        self.query = query
        self.contexts = contexts
        self.response = response
        self.ground_truth = ground_truth

class RAGEvaluator:
    def __init__(self):
        pass

    def _tokenize(self, text: str) -> List[str]:
        return re.findall(r'\b[a-z0-9]+\b', text.lower())

    def extract_atomic_claims(self, text: str) -> List[str]:
        """Decompose response into atomic factual claims."""
        sentences = [s.strip() for s in re.split(r'[.!?]', text) if s.strip()]
        claims = []
        for s in sentences:
            # Further split compound clauses joined by 'and' or 'while'
            clauses = re.split(r'\b(?:and|while|furthermore)\b', s, flags=re.IGNORECASE)
            for c in clauses:
                clean = c.strip()
                if len(clean.split()) >= 3:
                    claims.append(clean)
        return claims

    def evaluate_context_relevance(self, query: str, contexts: List[str]) -> float:
        """Measure fraction of context sentences relevant to the user query."""
        query_words = set(self._tokenize(query))
        all_sentences = []
        for ctx in contexts:
            sentences = [s.strip() for s in re.split(r'[.!?]', ctx) if s.strip()]
            all_sentences.extend(sentences)

        if not all_sentences:
            return 0.0

        relevant_count = 0
        for s in all_sentences:
            s_words = set(self._tokenize(s))
            overlap = len(query_words & s_words)
            # Sentence is relevant if it shares at least two content words with query
            if overlap >= 2:
                relevant_count += 1

        return round(relevant_count / len(all_sentences), 3)

    def evaluate_faithfulness(self, response: str, contexts: List[str]) -> Tuple[float, List[Tuple[str, bool]]]:
        """Verify if each atomic claim in response is entailed by retrieved contexts."""
        claims = self.extract_atomic_claims(response)
        if not claims:
            return 1.0, []

        full_context_text = " ".join(contexts).lower()
        context_words = set(self._tokenize(full_context_text))

        entailment_results = []
        entailed_count = 0

        for claim in claims:
            claim_words = self._tokenize(claim)
            # Verify if key claim words exist within context
            matched = sum(1 for w in claim_words if w in context_words)
            support_ratio = matched / len(claim_words) if claim_words else 0.0
            
            # Deem entailed if >= 75% of content terms are substantiated by context
            is_entailed = support_ratio >= 0.75
            if is_entailed:
                entailed_count += 1
            entailment_results.append((claim, is_entailed))

        score = round(entailed_count / len(claims), 3)
        return score, entailment_results

    def evaluate_answer_relevance(self, query: str, response: str) -> float:
        """Measure semantic alignment between user query and generated response."""
        query_words = set(self._tokenize(query))
        resp_words = set(self._tokenize(response))
        if not resp_words or not query_words:
            return 0.0

        overlap = len(query_words & resp_words)
        # Jaccard semantic overlap proxy
        sim = overlap / len(query_words | resp_words)
        # Scale to 0.0 - 1.0 range based on expected keyword retention
        scaled_relevance = min(1.0, sim * 4.0)
        return round(scaled_relevance, 3)

    def compute_triad_scorecard(self, sample: RAGEvaluationSample) -> Dict[str, float]:
        """Compute full RAG Triad report with harmonic mean."""
        ctx_rel = self.evaluate_context_relevance(sample.query, sample.contexts)
        faith, claims_audit = self.evaluate_faithfulness(sample.response, sample.contexts)
        ans_rel = self.evaluate_answer_relevance(sample.query, sample.response)

        # Harmonic mean (penalises severely if any single pillar collapses)
        denom = (1.0 / max(ctx_rel, 0.01)) + (1.0 / max(faith, 0.01)) + (1.0 / max(ans_rel, 0.01))
        harmonic_mean = round(3.0 / denom, 3)

        return {
            "context_relevance": ctx_rel,
            "faithfulness": faith,
            "answer_relevance": ans_rel,
            "rag_triad_composite": harmonic_mean,
            "claims_audit": claims_audit,
        }

# --- Demonstration Run ---
evaluator = RAGEvaluator()

sample_good = RAGEvaluationSample(
    query="What is the operating temperature of the sensor and its battery life?",
    contexts=[
        "The Model-X sensor operates reliably between -20C and 60C. It features a sealed enclosure.",
        "The integrated lithium battery provides up to 5 years of continuous operational life in standby mode."
    ],
    response="The Model-X sensor operates between -20C and 60C and provides up to 5 years of battery life."
)

sample_hallucinated = RAGEvaluationSample(
    query="What is the operating temperature of the sensor and its battery life?",
    contexts=[
        "The Model-X sensor operates reliably between -20C and 60C. It features a sealed enclosure."
    ],
    response="The Model-X sensor operates between -20C and 60C and includes a 10-year solar rechargeable battery."
)

print("=== Evaluating Grounded RAG Response ===")
report_good = evaluator.compute_triad_scorecard(sample_good)
for k, v in report_good.items():
    if k != "claims_audit":
        print(f"  {k}: {v}")

print("\n=== Evaluating Hallucinated RAG Response ===")
report_hallucinated = evaluator.compute_triad_scorecard(sample_hallucinated)
for k, v in report_hallucinated.items():
    if k != "claims_audit":
        print(f"  {k}: {v}")

print("\nClaim Entailment Breakdown (Hallucinated Sample):")
for claim, supported in report_hallucinated["claims_audit"]:
    status = "ENTAILED [OK]" if supported else "HALLUCINATED [FAIL]"
    print(f"  - '{claim}' -> {status}")

Common pitfalls

  • Using standard BLEU or ROUGE against arbitrary references: Surface n-gram overlap metrics fail to detect semantic equivalence and penalise correct paraphrased answers.
  • Evaluating only the final answer: A pipeline with terrible retrieval can get lucky if the LLM answers from its parametric memory, masking broken retrieval components.
  • Ignoring context pollution: Including excessive irrelevant text may not immediately hurt faithfulness, but degrades latency, token cost, and long-context reasoning.

06 Check yourself

Q1In the RAG Triad framework, what does 'Faithfulness' measure?

Why: Faithfulness (also called Groundedness) verifies that every proposition in the response can be directly inferred from the retrieved passages, penalising any parametric or fabricated claims.

Q2Why is decomposing generated answers into atomic claims essential for evaluating faithfulness?

Why: A single sentence such as 'The device operates up to 60C and lasts 10 years' may have its temperature substantiated by context while the battery lifespan is a total fabrication. Breaking text into atomic claims isolates exactly which assertions are true to evidence.

Q3What failure mode occurs when Context Relevance is low but Faithfulness is high?

Why: When context relevance is low, the context contains irrelevant documents. If the model is strictly faithful, it will faithfully discuss those irrelevant documents, completely missing the user's actual question.
