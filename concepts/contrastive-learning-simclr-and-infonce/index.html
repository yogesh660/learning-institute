01 The idea

Supervised visual models require millions of manually annotated labels, which are costly, labour-intensive, and prone to annotator bias. Contrastive self-supervised learning—epitomised by SimCLR (Chen et al. 2020) and the InfoNCE loss—trains neural backbones to learn invariant semantic representations by pulling differently augmented views of the same image together while pushing representations of different images apart.

If you show a child a photograph of a dog, and then show them a cropped, colour-distorted version of that same dog, they instantly recognize it as the same animal. If you then show them a photograph of a bicycle, they immediately recognize it as distinct. Human visual perception relies on learning representations that remain invariant to trivial changes in viewpoint, lighting, and framing while remaining sensitive to genuine semantic differences.

**Contrastive Learning** operationalises this principle without any human labels: 1. Sample an unlabelled mini-batch of $N$ images. 2. For each image, apply two stochastic data augmentations (such as random cropping, colour jittering, and Gaussian blur) to create two distinct views. These two views form a **positive pair**. 3. All other $2(N-1)$ augmented images in the mini-batch serve as **negative pairs**. 4. Pass both views through an encoder backbone (such as a ResNet) to produce representation $h$, and then through a small non-linear projection head (a 2-layer MLP) to produce latent vector $z$. 5. The **InfoNCE loss** (Information Noise-Contrastive Estimation) treats the positive view as the target class in a multi-class softmax classification task, pulling positive views together while driving negative views apart.

A critical empirical discovery in SimCLR was the role of the non-linear projection head $g(h) = z$. Because the contrastive objective forces $z$ to be completely invariant to transformations, $z$ actively discards information like orientation, cropping bounds, and colour palette. However, downstream tasks often benefit from knowing colour or spatial layout! By throwing away the projection head $g$ after pre-training and using the intermediate representation $h$, practitioners retain richer, more generalisable features for linear probing and transfer learning.

In everyday terms

Like training a facial recognition algorithm with identical twins in different outfits: the model learns that photos of the same twin under different lighting and angles must map to the same identity, while photos of different people must never overlap.

02 Step by step

  1. Generate stochastic augmented pairs: for each image $x_i$ in mini-batch of size $N$, apply two distinct data augmentations to produce $2N$ views.
  2. Extract representations with an encoder: pass each view through backbone network $f(\cdot)$ to extract representation vectors $h_i = f(\tilde{x}_i)$.
  3. Map through a projection head: project representations into lower-dimensional space using 2-layer MLP $z_i = g(h_i)$ and $L_2$-normalise each vector ($\lVert z_i \rVert_2 = 1$).
  4. Calculate pairwise cosine similarities: compute scaled dot-product matrix $S_{i,j} = z_i^T z_j / \tau$, where $\tau$ is the temperature hyperparameter.
  5. Evaluate InfoNCE contrastive loss: for each anchor, compute cross-entropy classifying its positive partner against all $2(N-1)$ negative candidates in the batch.
  6. Discard projection head for downstream tasks: detach $g(\cdot)$ and use backbone representations $h$ for downstream linear classification or fine-tuning.

03 The maths

  1. The InfoNCE loss (NT-Xent in SimCLR)

    $$\ell_{i,j} = -\log \frac{\exp\big(\operatorname{sim}(z_i, z_j) / \tau\big)}{\sum_{k=1}^{2N} \mathbb{I}_{[k \ne i]} \exp\big(\operatorname{sim}(z_i, z_k) / \tau\big)}, \qquad \operatorname{sim}(u, v) = \frac{u^T v}{\lVert u \rVert_2 \lVert v \rVert_2}$$

    $z_i$ and $z_j$ are $L_2$-normalised latent projections of positive views of the same image, $\tau$ is the temperature parameter (typically $0.07$ to $0.1$), and $2N$ is the total number of augmented views in the batch. The loss is symmetric across both views in each pair.

  2. Mutual information lower bound connection

    $$I(X_1; X_2) \ge \log(K) - \mathcal{L}_{\text{InfoNCE}}, \qquad K = 2N - 1$$

    $K$ is the number of negative samples. Minimising InfoNCE loss directly maximises a lower bound on the mutual information between the representations of two views of the same data sample.

04 Key takeaways

  • SimCLR learns representations by maximising agreement between differently augmented views of the same image while minimising agreement with negative batch samples.
  • The temperature parameter $\tau$ modulates penalty sharpness: smaller $\tau$ penalises hard negatives with high cosine similarity more aggressively.
  • Discarding the projection head $g(h)$ after pre-training preserves rich semantic features in $h$ that would otherwise be discarded due to forced augmentation invariance.

05 In code

python
import numpy as np

# Simulate InfoNCE loss on 2 positive pairs (4 views total), embedding dimension D = 3
np.random.seed(42)
# Pair 0: views 0 & 1 (similar); Pair 1: views 2 & 3 (similar)
z = np.array([
    [1.0, 0.1, 0.0],
    [0.95, 0.15, 0.0],
    [0.0, 0.9, 0.1],
    [0.0, 0.95, 0.15]
])

# L2-normalise embeddings
z = z / np.linalg.norm(z, axis=1, keepdims=True)

tau = 0.1  # Temperature parameter
sim_matrix = (z @ z.T) / tau
np.fill_diagonal(sim_matrix, -1e9)  # Mask self-similarity

# Compute InfoNCE loss for anchor 0 (positive partner is view 1)
exp_sim = np.exp(sim_matrix)
loss_anchor_0 = -float(np.log(exp_sim[0, 1] / np.sum(exp_sim[0])))

pos_sim = float(np.dot(z[0], z[1]))
neg_sim = float(np.dot(z[0], z[2]))

print(f"Cosine similarity - positive pair (0, 1): {pos_sim:.4f}")
print(f"Cosine similarity - negative pair (0, 2): {neg_sim:.4f}")
print(f"InfoNCE contrastive loss for anchor 0:   {loss_anchor_0:.4f}")

Common pitfalls

  • Using small mini-batch sizes: contrastive learning relies on large numbers of negative pairs to prevent representation collapse; SimCLR requires batch sizes of 2,048 to 4,096 (or memory queues like MoCo).
  • Weak data augmentations: without aggressive colour jittering, the network cheats by simply matching colour histograms between crops rather than learning shape and structure.
  • Deploying projection vectors $z$ instead of representations $h$ for downstream tasks, which reduces transfer accuracy because $z$ has stripped away useful task-specific details.

06 Check yourself

Q1Why does SimCLR discard the projection head $g(h)$ and use the pre-projection representation $h$ for downstream evaluation?

Why: Chen et al. showed that forcing representations to be fully invariant to augmentations removes fine-grained spatial and chromatic information from $z$; intermediate representation $h$ retains this information, yielding higher linear probe accuracy.

Q2What role does the temperature hyperparameter $\tau$ play in the InfoNCE loss?

Why: Because similarities are divided by $\tau$ inside the exponential, a small $\tau$ creates sharp probability distributions, heavily penalising any negative sample that lies close to the anchor.

Q3Why is aggressive colour jittering essential when creating augmented views for contrastive learning?

Why: If two random crops come from the same photo, they share identical colour palettes. Without colour jittering, the network trivially matches colour distributions without learning object semantics.

Q4Why does standard SimCLR require exceptionally large batch sizes (e.g. 2,048 to 4,096)?

Why: Contrastive learning relies on negative examples to push the representation space outwards. With too few negatives, the encoder can collapse representations into a narrow subspace.
