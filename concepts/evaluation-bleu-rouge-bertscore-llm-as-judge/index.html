Evaluation: BLEU, ROUGE, BERTScore, LLM-as-judge

Evaluating natural language generation (NLG) is notoriously challenging because a single prompt can have hundreds of distinct, equally valid human responses. Evaluation methodologies have evolved across four generations: precision-oriented n-gram matching (BLEU for translation), recall-oriented n-gram and sequence overlap (ROUGE for summarisation), semantic contextual embedding alignment (BERTScore), and model-based LLM-as-a-judge evaluators. Understanding their mathematical assumptions, biases, and trade-offs is crucial for rigorous benchmarking.

01 The idea

Suppose a human reference summary reads "The central bank lowered interest rates to stimulate economic expansion", and an AI model generates "To boost financial growth, the monetary authority reduced borrowing costs". A traditional word-overlap metric like BLEU or ROUGE gives this generation a near-zero score because almost none of the exact words match. Yet semantically, the model's summary is flawless. Automated evaluation must reconcile superficial lexical divergence with deep semantic truth.

The one-to-many dilemma of natural language generation: Unlike classification where an image is either a cat or a dog, natural language generation has no single ground truth. Paraphrasing, varying sentence structure, active versus passive voice, and synonym choice mean that two humans writing about the same event will produce completely different word sequences. Evaluation metrics must balance exact factual alignment with syntactic flexibility.

BLEU vs ROUGE: Precision vs Recall: BLEU was designed for machine translation, where generating superfluous or hallucinated words is disastrous; it strictly measures modified n-gram precision penalised by a brevity penalty. ROUGE was designed for summarisation, where the primary risk is omitting key facts; it measures n-gram recall (ROUGE-1, ROUGE-2) and longest common subsequences (ROUGE-L) to reward coverage of reference ideas.

BERTScore and the shift to continuous semantic matching: BERTScore bypasses surface string matching altogether. It computes pairwise cosine similarities between contextual token embeddings of the candidate and reference from a pre-trained Transformer. Greedy bipartite matching pairs each candidate token with the most similar reference token, capturing synonyms, paraphrases, and morphological derivations seamlessly.

LLM-as-a-Judge and cognitive biases: Powerful LLMs (such as GPT-4) can evaluate complex open-ended attributes like coherence, helpfulness, and factual grounding using detailed rubrics. However, LLM judges exhibit systematic cognitive biases: position bias (favouring whichever candidate is presented first or second), verbosity bias (favouring longer, more elaborate responses regardless of factual depth), and self-enhancement bias (favouring outputs generated by their own model family). Debiasing via position swapping and chain-of-thought grading is essential.

In everyday terms

Think of grading an essay exam in an English literature class. A naive automated scanner (BLEU/ROUGE) compares the student's essay word-for-word against the teacher's model answer key; if the student writes "monarch" instead of "king", the scanner docks marks. An embedding-based grader (BERTScore) recognizes that "monarch" and "king" mean the same thing in this historical context, awarding credit. An expert human examiner (LLM-as-a-judge) reads the entire argument, appreciates the student's rhetoric, checks whether the thesis is logically supported by evidence, but must consciously guard against grading long-winded, verbose essays higher purely because they look authoritative.

03 The maths

  1. ROUGE-L Longest Common Subsequence (LCS) recall

    R_{\text{LCS}} = \frac{\operatorname{LCS}(\text{Ref}, \text{Cand})}{m}, \quad P_{\text{LCS}} = \frac{\operatorname{LCS}(\text{Ref}, \text{Cand})}{n}, \quad \operatorname{ROUGE-L} = \frac{(1 + \beta^2) R_{\text{LCS}} P_{\text{LCS}}}{R_{\text{LCS}} + \beta^2 P_{\text{LCS}}}

    Here $m$ is reference length, $n$ is candidate length, and $\operatorname{LCS}$ is the length of the longest common subsequence of tokens. ROUGE-L captures sentence-level structural similarity without requiring consecutive n-gram matches.

  2. BERTScore recall and precision via greedy matching

    R_{\text{BERT}} = \frac{1}{|x|} \sum_{i \in x} \max_{j \in \hat{x}} \mathbf{x}_i^\top \hat{\mathbf{x}}_j, \quad P_{\text{BERT}} = \frac{1}{|\hat{x}|} \sum_{j \in \hat{x}} \max_{i \in x} \mathbf{x}_i^\top \hat{\mathbf{x}}_j

    Here $\mathbf{x}_i$ is the pre-trained contextual embedding for reference token $i$, and $\hat{\mathbf{x}}_j$ is the embedding for candidate token $j$ (both $L_2$-normalised). Greedy matching pairs each token with its highest-scoring semantic partner.

  3. Spearman rank correlation with human judgment

    \rho = 1 - \frac{6 \sum_{i=1}^n d_i^2}{n(n^2 - 1)}

    Here $d_i$ is the difference between the metric's rank and the human gold standard rank for item $i$, and $n$ is the total number of evaluated items. Higher rank correlation indicates greater alignment with human qualitative assessment.

04 Key takeaways

  • Automated evaluation of natural language generation must account for linguistic polysemy and multiple valid surface expressions.
  • BLEU measures precision for machine translation; ROUGE measures recall and subsequence overlap for summarisation.
  • BERTScore aligns contextual token embeddings using greedy bipartite matching, providing robustness against vocabulary mismatch.
  • LLM-as-a-judge provides holistic qualitative evaluations of reasoning and nuance, but requires debiasing against position and verbosity biases.
  • Metric efficacy is validated by measuring Spearman and Pearson rank correlations against human qualitative judgments.

05 In code

python
import numpy as np

def lcs_length(x, y):
    """Compute Longest Common Subsequence (LCS) length via dynamic programming."""
    m, n = len(x), len(y)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if x[i - 1] == y[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]

def compute_rouge_l(candidate_tokens, reference_tokens, beta=1.2):
    """Compute ROUGE-L Precision, Recall, and F-score."""
    lcs = lcs_length(candidate_tokens, reference_tokens)
    if len(candidate_tokens) == 0 or len(reference_tokens) == 0:
        return 0.0, 0.0, 0.0
        
    prec = lcs / len(candidate_tokens)
    rec = lcs / len(reference_tokens)
    
    if prec + rec == 0:
        f_score = 0.0
    else:
        f_score = ((1 + beta**2) * prec * rec) / (rec + (beta**2) * prec)
    return prec, rec, f_score

def simulate_bertscore(candidate_embs, reference_embs):
    """
    Simulate BERTScore greedy maximum bipartite matching.
    candidate_embs: (len_cand, dim) normalized
    reference_embs: (len_ref, dim) normalized
    """
    # Pairwise cosine similarity matrix: (len_cand, len_ref)
    sim_matrix = np.dot(candidate_embs, reference_embs.T)
    
    # Recall: For each reference token, find best matching candidate token
    rec = np.mean(np.max(sim_matrix, axis=0))
    # Precision: For each candidate token, find best matching reference token
    prec = np.mean(np.max(sim_matrix, axis=1))
    f1 = 2 * prec * rec / (prec + rec) if (prec + rec) > 0 else 0.0
    return prec, rec, f1

# Example Reference and Candidate summaries
reference_text = ["the", "bank", "lowered", "interest", "rates", "to", "stimulate", "economic", "growth"]
candidate_lexical = ["the", "bank", "reduced", "interest", "rates", "to", "promote", "economic", "expansion"]

print("Reference Summary: ", " ".join(reference_text))
print("Candidate Summary: ", " ".join(candidate_lexical))

# 1. Evaluate ROUGE-L
p_lcs, r_lcs, f_lcs = compute_rouge_l(candidate_lexical, reference_text)
print("\n1. ROUGE-L Evaluation:")
print(f"  Precision: {p_lcs * 100:.1f}%")
print(f"  Recall:    {r_lcs * 100:.1f}%")
print(f"  F-measure: {f_lcs * 100:.1f}%")

# 2. Simulate BERTScore on continuous embeddings
np.random.seed(42)
d = 4
# Mock embeddings where synonyms have high similarity (>0.85)
cand_embs = np.random.randn(len(candidate_lexical), d)
cand_embs = cand_embs / np.linalg.norm(cand_embs, axis=1, keepdims=True)

ref_embs = cand_embs + np.random.randn(len(candidate_lexical), d) * 0.15
ref_embs = ref_embs / np.linalg.norm(ref_embs, axis=1, keepdims=True)

bs_p, bs_r, bs_f1 = simulate_bertscore(cand_embs, ref_embs)
print("\n2. BERTScore Evaluation (Contextual Semantic Alignment):")
print(f"  Precision: {bs_p:.4f}")
print(f"  Recall:    {bs_r:.4f}")
print(f"  F1-Score:  {bs_f1:.4f}")

Common pitfalls

  • Relying on BLEU for open-ended creative generation: BLEU assumes overlap with a specific reference string; for creative writing or dialogue, valid responses have zero n-gram overlap, rendering BLEU meaningless.
  • Verbosity bias in LLM judges: Large language models systematically award higher marks to longer, verbose responses even if they are repetitive or contain hallucinated details. Normalise or explicitly instruct judges to penalise bloat.
  • Evaluating without position swap in pairwise judging: An LLM judge presented with option A followed by option B frequently picks option A 65% of the time purely due to positional primacy. Always run reciprocal evaluations.
  • Ignoring token normalisation in ROUGE: Failing to lowercase and stem tokens prior to computing ROUGE causes words like "running" and "runs" to be treated as complete mismatches, artificially depressing scores.

06 Check yourself

Q1Why was ROUGE designed primarily as a recall-focused metric for text summarisation while BLEU was designed as a precision-focused metric for machine translation?

Why: In translation, every word matters: generating ungrounded extra words is catastrophic, so BLEU measures precision. In summarisation, compressing 1,000 words to 100 requires retaining essential ideas; ROUGE measures how much of the gold summary was covered (recall).

Q2How does BERTScore overcome the vocabulary mismatch limitation of BLEU and ROUGE?

Why: BERTScore passes candidate and reference through a pre-trained Transformer. Contextual token embeddings for synonyms (like "lowered" and "reduced") are proximate in vector space. Greedy bipartite matching pairs them, awarding credit where surface string metrics fail.

Q3What is position bias in LLM-as-a-judge evaluation frameworks, and how is it mitigated?

Why: Empirical benchmarks show LLM judges often select candidate A over candidate B >60% of the time purely because option A appeared first. Position debiasing evaluates both (A, B) and (B, A) prompt orderings, declaring a tie if judgment flips.
