01 The idea

Machine learning models trained on sensitive user data are vulnerable to membership inference and training data reconstruction attacks. Privacy-Preserving Machine Learning (PPML) mitigates these threats through rigorous mathematical frameworks: Differential Privacy (DP) guarantees plausible deniability via calibrated noise injection, while Federated Learning (FL) trains models collaboratively across decentralised edge devices without centralizing private data.

Deep neural networks have enormous capacity and can memorise rare training outliers (like a patient's clinical diagnosis or a user's credit card number). An attacker with model access can launch a Membership Inference Attack to determine if a specific person was in the training dataset, or prompt an LLM to regurgitate memorised secrets.

Differential Privacy (DP) provides a rigorous mathematical definition of privacy: the output of a computation should be virtually indistinguishable whether any single individual's data is included or excluded from the dataset. In DP-SGD (Differentially Private Stochastic Gradient Descent), this is achieved by clipping per-sample gradients to a maximum norm $C$ and adding Gaussian noise $\sigma$. Federated Learning complements this by keeping data on client devices (e.g. mobile phones) and transmitting only model weight updates, aggregated via algorithms like FedAvg.

In everyday terms

Imagine a public survey asking citizens if they have committed tax fraud. If respondents answer truthfully, nobody participates for fear of prosecution. Under randomised response (Differential Privacy), every participant flips a coin: if heads, they answer truthfully; if tails, they answer "yes". A statistician can still reconstruct the exact population percentage mathematically, yet any individual respondent has complete legal plausible deniability.

02 Step by step

  1. Define privacy budget $(\epsilon, \delta)$: establish the maximum allowable privacy loss $\epsilon$ and failure probability $\delta$ for the application.
  2. Implement per-sample gradient clipping: during training, clip the $L_2$ norm of every individual sample gradient to maximum threshold $C$.
  3. Inject calibrated noise: add Gaussian noise scaled by noise multiplier $\sigma$ and clipping bound $C$ to the aggregated mini-batch gradient.
  4. Track cumulative privacy loss: monitor privacy budget consumption across training iterations using Rényi Differential Privacy (RDP) accountants.
  5. Distribute decentralised training (FL): broadcast global model weights to participating edge clients, train locally for $E$ epochs on device data.
  6. Aggregate model updates (FedAvg): average client parameter updates on the central server weighted by each client's local dataset size.

03 The maths

  1. Differential Privacy Definition ($(\epsilon, \delta)$-DP)

    P(\mathcal{M}(D) \in S) \le e^\epsilon P(\mathcal{M}(D') \in S) + \delta

    Guarantees that randomised mechanism $\mathcal{M}$ outputs nearly identical distributions on any two neighbouring datasets $D, D'$ differing by at most one individual.

  2. Federated Averaging (FedAvg) Update

    w_{t+1} = \sum_{k=1}^K \frac{n_k}{n} w_{t+1}^k, \quad w_{t+1}^k = w_t - \eta \nabla F_k(w_t)

    Aggregates decentralised weights from $K$ client devices weighted by their local sample count $n_k$ relative to total samples $n$.

04 Key takeaways

  • Differential Privacy mathematically bounds the privacy risk of individuals contributing to a machine learning dataset.
  • DP-SGD clips per-sample gradients and adds calibrated Gaussian noise to prevent memorisation of outliers.
  • Federated Learning trains models collaboratively across decentralised devices, ensuring raw training data never leaves client hardware.

05 In code

python
import numpy as np

def dp_sgd_step(gradients, clip_norm=1.0, noise_multiplier=0.5):
    """Simulates a Differentially Private SGD gradient aggregation step."""
    # 1. Per-sample gradient clipping
    clipped_grads = []
    for g in gradients:
        norm = np.linalg.norm(g)
        clip_factor = min(1.0, clip_norm / max(norm, 1e-8))
        clipped_grads.append(g * clip_factor)
        
    clipped_grads = np.array(clipped_grads)
    
    # 2. Sum clipped gradients
    summed_grad = np.sum(clipped_grads, axis=0)
    
    # 3. Add calibrated Gaussian noise
    sigma = noise_multiplier * clip_norm
    noise = np.random.normal(0, sigma, size=summed_grad.shape)
    
    # Private average gradient
    private_grad = (summed_grad + noise) / len(gradients)
    return private_grad

def federated_averaging(client_weights, client_sizes):
    """Computes FedAvg weighted parameter aggregation across clients."""
    total_samples = sum(client_sizes)
    global_weights = np.zeros_like(client_weights[0])
    for w, n in zip(client_weights, client_sizes):
        global_weights += (n / total_samples) * w
    return global_weights

# Simulation: 5 sample gradients
np.random.seed(42)
sample_grads = [np.array([2.5, -1.2, 0.4]), np.array([0.1, 0.2, 0.1]), 
                np.array([8.0, 4.0, -2.0])] # Sample 3 is an outlier!

priv_grad = dp_sgd_step(sample_grads, clip_norm=1.5, noise_multiplier=0.8)
print("Differentially Private Aggregated Gradient:")
print(f"  Private Gradient: {priv_grad.round(4)}")

# Federated Averaging simulation across 3 clients
client_w = [np.array([1.2, 0.8]), np.array([1.4, 0.7]), np.array([1.1, 0.9])]
client_n = [1000, 500, 1500]
fed_w = federated_averaging(client_w, client_n)
print(f"\nFederated Averaged Global Weights: {fed_w.round(4)}")

Common pitfalls

  • Clipping gradients too aggressively (norm too small), destroying gradient signal and causing model underfitting.
  • Assuming Federated Learning alone guarantees privacy; gradient updates themselves can leak training data via inversion attacks unless combined with Differential Privacy.

06 Check yourself

Q1What is the operational meaning of the parameter $\epsilon$ (epsilon) in Differential Privacy?

Why: In $(\epsilon, \delta)$-DP, $\epsilon$ quantifies the worst-case privacy budget; smaller values enforce tighter privacy guarantees.

Q2Why does DP-SGD require clipping per-sample gradients before adding noise?

Why: Noise calibration requires knowing the maximum potential impact (sensitivity) of a single record; clipping to $C$ sets that sensitivity bound.

Q3What is a major challenge in Federated Learning known as "Non-IID client data"?

Why: Different users exhibit vastly different language, photo, or typing habits. Non-IID distributions cause local client gradients to pull in conflicting directions.
