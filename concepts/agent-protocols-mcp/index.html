01 The idea

Connecting AI agents to databases, local filesystems, developer tools, and external APIs historically required fragile, bespoke integration code for every tool and platform. The Model Context Protocol (MCP) establishes an open, standard client-server protocol enabling models to discover tools, query context resources, and execute commands through safe, interoperable interfaces.

In early agent implementations, every company wrote custom function calling wrappers. If you wanted an agent to access GitHub, Postgres, and Slack, you had to write 3 custom wrappers, maintain separate authentication handlers, and adapt prompts whenever tool signatures changed. If you switched LLM providers, you often had to rewrite the integrations.

The Model Context Protocol (MCP) solves this by decoupling the agent client (the LLM application) from the capability server (the tool/resource provider). MCP defines standard JSON-RPC 2.0 primitives: 1) Resources: passive data the agent can read (like file contents or database tables); 2) Tools: active executable functions the agent can invoke with arguments; 3) Prompts: reusable prompt templates surfaced by servers. This standard allows developers to build an MCP server once and have it work instantly across Claude, Gemini, IDE assistants, and custom agents.

In everyday terms

Before USB, every computer peripheral needed its own custom cable and port: round mouse plugs, printer parallel ports, joystick ports, and SCSI connectors. MCP is the USB-C of the AI agent era: a single universal connector and communication standard that lets any language model plug into any data source, code sandbox, or tool server seamlessly.

02 Step by step

  1. Establish JSON-RPC transport: configure stdio (for local subprocess tools) or SSE/HTTP (for remote networked services).
  2. Execute client-server handshake: exchange protocol versions and client/server capability declarations (`resources`, `tools`, `prompts`).
  3. Discover available tools: client calls `tools/list` to retrieve JSON schema descriptions of available functions and argument specifications.
  4. Execute tool call: when the model decides to invoke a tool, the client dispatches a `tools/call` JSON-RPC message with validated parameters.
  5. Enforce security and sandboxing: implement human-in-the-loop confirmation or capability gating before executing dangerous operations (e.g. file deletion, database writes).
  6. Stream tool response: return stdout, stderr, or structured content blocks back to the agent client context.

03 The maths

  1. MCP JSON-RPC 2.0 Request-Response Protocol

    \text{Req} = \{ \text{jsonrpc}: \text{"2.0"}, \text{id}: k, \text{method}: m, \text{params}: p \}, \quad \text{Resp} = \{ \text{jsonrpc}: \text{"2.0"}, \text{id}: k, \text{result}: r \}

    Standard asynchronous client-server messaging standard with unique request identifiers $k$ for concurrent tool execution.

  2. Tool Selection Likelihood Formulation

    P(\text{Tool} = t_i \mid \mathbf{x}, \{S_1, \dots, S_K\}) = \text{softmax}\left( \mathbf{w}_{\text{tool}}^T \text{LLM}(\mathbf{x}, S_i) \right)

    Probability of selecting tool $t_i$ given user request $\mathbf{x}$ and JSON schema definitions $S_i$.

04 Key takeaways

  • The Model Context Protocol (MCP) establishes an open standard for connecting AI models to data sources and tools.
  • MCP defines standardised primitives for Resources (passive data), Tools (executable actions), and Prompts (templates).
  • Decoupling client applications from tool servers allows tool integrations to be shared universally across different AI assistants.

05 In code

python
import json

class MockMCPServer:
    """Demonstrates Model Context Protocol (MCP) server primitives."""
    def __init__(self, name="file_server"):
        self.name = name
        self.files = {"data.txt": "Model Context Protocol standardises tool connectivity."}

    def handle_request(self, json_rpc_msg):
        request = json.loads(json_rpc_msg)
        req_id = request.get("id")
        method = request.get("method")
        params = request.get("params", {})

        if method == "tools/list":
            tools = [{
                "name": "read_file",
                "description": "Reads contents of a file by path",
                "inputSchema": {
                    "type": "object",
                    "properties": {"path": {"type": "string"}},
                    "required": ["path"]
                }
            }]
            return json.dumps({"jsonrpc": "2.0", "id": req_id, "result": {"tools": tools}})

        elif method == "tools/call":
            tool_name = params.get("name")
            args = params.get("arguments", {})
            if tool_name == "read_file":
                content = self.files.get(args.get("path"), "Error: File not found")
                return json.dumps({"jsonrpc": "2.0", "id": req_id, "result": {"content": [{"type": "text", "text": content}]}})
                
        return json.dumps({"jsonrpc": "2.0", "id": req_id, "error": {"code": -32601, "message": "Method not found"}})

server = MockMCPServer()

# 1. Discover tools
req_list = json.dumps({"jsonrpc": "2.0", "id": 1, "method": "tools/list"})
resp_list = server.handle_request(req_list)
print("MCP Tool Discovery Response:")
print(json.dumps(json.loads(resp_list), indent=2))

# 2. Invoke tool
req_call = json.dumps({"jsonrpc": "2.0", "id": 2, "method": "tools/call", 
                       "params": {"name": "read_file", "arguments": {"path": "data.txt"}}})
resp_call = server.handle_request(req_call)
print("\nMCP Tool Execution Response:")
print(json.dumps(json.loads(resp_call), indent=2))

Common pitfalls

  • Granting unrestricted tool execution permissions to an MCP server without human-in-the-loop approval on destructive operations.
  • Over-saturating the model context with dozens of heavy tool schemas, degrading function-calling accuracy.

06 Check yourself

Q1What problem does the Model Context Protocol (MCP) solve for AI developers?

Why: MCP acts as a universal communication standard between AI host applications and external tool/resource servers.

Q2What is the fundamental difference between an MCP "Resource" and an MCP "Tool"?

Why: In MCP, Resources represent readable context streams, whereas Tools represent executable operations that produce computational side effects.

Q3What message protocol standard does MCP use for client-server communication?

Why: MCP specifies JSON-RPC 2.0 as its messaging format, running locally over stdio subprocess pipes or over HTTP/SSE for remote services.
