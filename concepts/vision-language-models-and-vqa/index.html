01 The idea

For decades, computer vision and natural language processing developed in separate silos: vision classified image categories, while language models predicted text tokens. Vision-Language Models (VLMs) unify both modalities into a multimodal cognitive architecture. By projecting visual feature patches into the word embedding space of a frozen Large Language Model (e.g. LLaVA, Flamingo), VLMs can hold conversations about visual scenes, reason about charts, and solve complex Visual Question Answering (VQA) queries.

Modern VLMs (such as LLaVA; Liu et al.) connect three components: 1) A Vision Encoder (typically a pretrained CLIP ViT) that transforms an image into a sequence of visual patch tokens; 2) A Multimodal Projector (a lightweight MLP or cross-attention Resampler) that projects visual embeddings into the exact hidden dimension of the LLM; 3) A Pretrained LLM (Vicuna, Llama) that processes visual and textual tokens jointly.

Training typically proceeds in two stages: Stage 1 (Feature Alignment): The vision encoder and LLM are frozen, training strictly the projector MLP on millions of image-caption pairs so the LLM learns to comprehend visual tokens; Stage 2 (Visual Instruction Tuning): The LLM and projector are fine-tuned jointly on conversational dialogue, visual reasoning, and VQA datasets.

During forward inference, an image is converted into $P$ visual tokens (e.g. 576 tokens for a 24x24 patch grid). These visual tokens are prepended directly to the user's tokenized text prompt (`[IMG_1] ... [IMG_576] What is the person holding?`), allowing the autoregressive Transformer to generate natural language answers with full visual grounding.

In everyday terms

Imagine a brilliant writer who was born blind, possessing vast knowledge of language, history, and logic (a frozen LLM). A visual translator (the multimodal projector) attaches a high-definition digital camera (vision encoder) to the writer's desk and converts visual light rays directly into Braille words. The writer does not need a brain transplant; they simply read the visual Braille tokens alongside normal text questions and answer fluently.

02 Step by step

  1. Extract visual patch embeddings: Pass $336 \times 336$ image through frozen CLIP ViT-L/14, extracting penultimate layer patch activations (e.g. 576 tokens of dimension 1024).
  2. Project across modalities: Pass visual tokens through a two-layer MLP projector with GELU activations to map dimension $1024 \to 4096$ (matching LLM hidden dimension).
  3. Tokenize text prompt: Tokenize user prompt and format with multimodal chat template (e.g. `Human: \nDescribe this photo. Assistant:`).
  4. Concatenate multimodal token sequence: Replace the `` placeholder token with the sequence of 576 projected continuous visual embeddings.
  5. Autoregressive language generation: Feed concatenated embeddings through the LLM decoder; generate answers token by token using standard causal language modelling.
  6. Instruction fine-tuning: Fine-tune projector and LLM parameters using LoRA or full backpropagation on high-quality multi-turn visual conversations.

03 The maths

  1. Multimodal Linear Projector Alignment

    \mathbf{H}_v = \mathbf{W}_2 \cdot \operatorname{GELU}\left( \mathbf{W}_1 \cdot \mathbf{Z}_v + \mathbf{b}_1 \right) + \mathbf{b}_2, \quad \mathbf{Z}_v = g_{\mathrm{vision}}(I)

    Projects visual tokens $\mathbf{Z}_v \in \mathbb{R}^{P \times d_v}$ into the LLM token embedding space $\mathbf{H}_v \in \mathbb{R}^{P \times d_{\mathrm{text}}}$.

  2. Multimodal Autoregressive Likelihood Objective

    P(\mathbf{Y} \mid \mathbf{X}_v, \mathbf{X}_t) = \prod_{i=1}^L P\left( y_i \;\middle|\; \mathbf{H}_v, \; \mathbf{X}_{t,

    Models the probability of response text sequence $\mathbf{Y}$ conditioned jointly on projected image tokens $\mathbf{H}_v$ and preceding text tokens.

  3. Flamingo Perceiver Resampler Compression

    \mathbf{Q} = \mathbf{L}_{\mathrm{queries}}, \quad \mathbf{K}, \mathbf{V} = [\mathbf{Z}_v \parallel \mathbf{L}_{\mathrm{queries}}], \quad \mathbf{Z}_{\mathrm{compressed}} = \operatorname{CrossAttn}(\mathbf{Q}, \mathbf{K}, \mathbf{V})

    Compresses thousands of variable-length visual feature tokens into a fixed small set of latent tokens (e.g. 64) via learned cross-attention queries.

04 Key takeaways

  • Vision-Language Models fuse visual perception with general-purpose language reasoning.
  • LLaVA connects a frozen vision encoder (CLIP) to an LLM using a lightweight MLP projector.
  • Visual patches are treated as pseudo-text tokens, prepended directly to the user's token prompt.
  • Training separates into initial feature alignment followed by visual instruction fine-tuning.

05 In code

python
import torch
import torch.nn as nn

class MiniVLMProjector(nn.Module):
    """Educational demonstration of a LLaVA-style multimodal MLP projection layer."""
    def __init__(self, vision_dim: int = 768, llm_dim: int = 2048):
        super().__init__()
        self.projector = nn.Sequential(
            nn.Linear(vision_dim, llm_dim),
            nn.GELU(),
            nn.Linear(llm_dim, llm_dim)
        )

    def forward(self, visual_tokens: torch.Tensor, text_embeddings: torch.Tensor):
        # visual_tokens:   [batch, num_patches, vision_dim] (from CLIP)
        # text_embeddings: [batch, text_seq_len, llm_dim]   (from LLM embedding table)
        
        # 1. Project visual tokens to LLM dimension
        projected_visual = self.projector(visual_tokens)  # [batch, num_patches, llm_dim]
        
        # 2. Concatenate: [Visual Tokens ... Text Tokens]
        multimodal_input = torch.cat([projected_visual, text_embeddings], dim=1)
        return multimodal_input

# Simulate: Image produces 16 patch tokens (dim 768); Text prompt has 8 words (dim 2048)
vlm_proj = MiniVLMProjector(vision_dim=768, llm_dim=2048)
vision_feat = torch.randn(1, 16, 768)
text_feat   = torch.randn(1, 8, 2048)

joint_input = vlm_proj(vision_feat, text_feat)
print(f"Projected Multimodal Sequence Shape: {joint_input.shape}")
print("16 visual tokens seamlessly prepended to 8 text tokens for the LLM decoder!")

Common pitfalls

  • Visual token context consumption: High-resolution images produce hundreds or thousands of patch tokens, consuming huge fractions of the LLM's limited context window.
  • Object hallucination: VLMs frequently hallucinate objects that are not in the image due to strong textual prior biases in the LLM language decoder; mitigate with DPO alignment.
  • Spatial reasoning limitations: Standard VLMs struggle with fine-grained spatial coordinates (e.g. exact bounding box coordinates or counting crowded coins); requires high-res vision encoders.

06 Check yourself

Q1How does an architecture like LLaVA feed image information into a Large Language Model (LLM)?

Why: LLaVA uses a vision encoder to extract visual patch tokens, projects them into the text embedding space via an MLP, and inputs them directly to the LLM.

Q2What is "object hallucination" in Vision-Language Models (VLMs)?

Why: Language models have strong prior associations (e.g. "a kitchen has a refrigerator"). When uncertain, the LLM hallucinates objects that logically fit the scene text.

Q3Why is training divided into two stages in modern VLM development (Feature Alignment then Instruction Tuning)?

Why: Freezing the LLM in Stage 1 teaches the projector the visual-to-text mapping without degrading the LLM's general knowledge before jointly fine-tuning in Stage 2.
