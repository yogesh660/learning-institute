01 The idea

While large language models exhibit impressive reasoning, their memory is bounded by fixed context window limits and linear memory scaling during generation. Architecting robust AI agents requires decoupling memory into short-term working context (KV caching, sliding windows) and long-term persistent episodic memory (external vector stores and memory compaction).

Transformers process tokens through an in-context working memory: self-attention allows all tokens within the context window to attend to each other. During autoregressive decoding, recomputing key and value representations for all past tokens at every step is wasteful $\mathcal{O}(N^2)$ work. The Key-Value (KV) cache stores past token key and value projections in GPU memory, reducing per-token generation step complexity to $\mathcal{O}(N)$.

However, KV-cache size grows linearly with sequence length, batch size, and layer count, easily demanding 40+ GB of VRAM for long documents. Long-running AI systems overcome this constraint through hierarchical memory: short-term active context managed via sliding-window attention and memory compaction, paired with long-term semantic stores queried through dense retrieval.

In everyday terms

An LLM's context window is like a student's desk. It holds open notebooks and reference pens for whatever problem is being actively solved right now. But the desk has finite surface area. When the desk fills up, the student must either file older notes into a filing cabinet in the corner (an external vector database) or write a 1-page summary index card to clear space on the desk.

02 Step by step

  1. Allocate KV-cache buffers: allocate pre-allocated tensors in GPU memory to store key and value states for past tokens.
  2. Append incremental token states: at each decoding step, compute $\mathbf{k}_t, \mathbf{v}_t$ for the newest token and append to the active cache.
  3. Monitor memory footprint: calculate VRAM consumption using the formula $2 \times 2 \times n_{\text{layers}} \times d_{\text{model}} \times N \times B$ bytes.
  4. Trigger context compaction: when token count nears window limits, generate an abstractive summary of older conversation turns.
  5. Offload to external storage: persist episodic memories and user profile details to an indexed vector store for semantic retrieval on demand.

03 The maths

  1. KV-Cache Memory Footprint (FP16)

    \text{Memory}_{\text{KV}} = 4 \cdot b \cdot s \cdot l \cdot h \cdot d_k \quad \text{bytes}

    Calculates the memory in bytes for batch size $b$, sequence length $s$, layers $l$, attention heads $h$, and head dimension $d_k$ in 16-bit precision.

  2. Sliding Window Attention Complexity

    \mathcal{O}(N \cdot W \cdot d), \quad \text{where } W \ll N

    Restricts self-attention to a localized window of $W$ previous tokens, reducing quadratic scaling to linear scaling with sequence length $N$.

04 Key takeaways

  • KV caching transforms autoregressive token generation from quadratic time $\mathcal{O}(N^2)$ to linear time $\mathcal{O}(N)$.
  • The linear memory growth of KV caches necessitates multi-query attention (MQA), grouped-query attention (GQA), and paged memory.
  • Hierarchical memory combines immediate working context windows with external vector indices for long-term agent persistence.

05 In code

python
import numpy as np

def calculate_kv_cache_size(batch_size, seq_len, num_layers, num_heads, head_dim, precision_bytes=2):
    """Calculates KV cache memory footprint in gigabytes."""
    # 2 matrices (Key and Value) per layer
    total_elements = 2 * batch_size * seq_len * num_layers * num_heads * head_dim
    total_bytes = total_elements * precision_bytes
    return total_bytes / (1024 ** 3)

class SlidingWindowKVCache:
    """Demonstrates sliding-window working memory for autoregressive decoding."""
    def __init__(self, window_size=4, dim=8):
        self.window_size = window_size
        self.dim = dim
        self.keys = []
        self.values = []

    def update(self, new_key, new_val):
        self.keys.append(new_key)
        self.values.append(new_val)
        # Evict oldest tokens beyond window size
        if len(self.keys) > self.window_size:
            self.keys.pop(0)
            self.values.pop(0)
            
    def get_context(self):
        return np.array(self.keys), np.array(self.values)

# 1. Memory benchmark for 70B parameter model
vram_gb = calculate_kv_cache_size(batch_size=4, seq_len=32768, num_layers=80, num_heads=64, head_dim=128)
print(f"KV Cache VRAM for 70B model (Batch 4, 32k Context): {vram_gb:.2f} GB")

# 2. Sliding window working memory simulation
cache = SlidingWindowKVCache(window_size=3, dim=4)
for t in range(5):
    cache.update(new_key=np.ones(4) * t, new_val=np.zeros(4) * t)

keys, _ = cache.get_context()
print(f"Active Tokens Retained in Sliding Window (t=5): {keys[:, 0]}")

Common pitfalls

  • Running out of GPU memory during batch inference due to unmanaged KV-cache allocation when users submit long documents.
  • Truncating conversation history naively with hard cut-offs rather than structured summary compaction, causing the model to lose instructions.

06 Check yourself

Q1What is the primary function of the KV cache in LLM inference engines?

Why: Without a KV cache, generating the $N$-th token requires recomputing self-attention over all previous $N-1$ tokens from scratch.

Q2How does Grouped-Query Attention (GQA) reduce KV-cache memory consumption?

Why: In GQA (used by Llama 2/3), several query heads share each key/value head, reducing cache memory bandwidth and VRAM usage by 4x to 8x.

Q3What is "context compaction" in conversational agent architectures?

Why: Context compaction prevents context overflow by periodically distilling historical turns into an executive summary that retains salient facts.
