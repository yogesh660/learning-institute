Data Leakage

Diagnosing and preventing the insidious contamination of training data with information available only at inference or in the future.

01 The idea

Data leakage occurs when information from outside the training partition—or information unavailable at the real-time moment of prediction—inadvertently contaminates model training. Leakage produces deceptively flawless cross-validation scores that abruptly collapse into catastrophic failures in production. Recognizing target leakage, feature leakage, and preprocessing leakage is essential for reliable machine learning.

Imagine training a machine learning model to predict whether a hospital patient will develop severe pneumonia. During feature engineering, you include a column called "Antibiotic IV Dosage Administered". In offline validation, the model achieves a miraculous 99.8% ROC-AUC. But in clinical practice, doctors only prescribe high-dose IV antibiotics after pneumonia has already been diagnosed! The model did not predict pneumonia; it merely detected the physician's reaction to pneumonia. This is classic target leakage—including a feature that is a downstream consequence of the target rather than a genuine antecedent predictor.

A subtler, pervasive trap is preprocessing leakage. Suppose you standardise a dataset by subtracting the mean and dividing by the standard deviation. If you compute the mean and variance across the entire table before splitting into training and test sets, the training data has absorbed statistical parameters derived from the test set. If you perform feature selection or target encoding across the entire table, test labels directly influence the features selected for training, manufacturing artificial predictive power out of pure noise.

The diagnostic hallmark of data leakage is performance that appears "too good to be true". Whenever a model achieves near-perfect metrics on a notoriously noisy or uncertain task, the cause is almost never an algorithmic breakthrough—it is almost always data leakage. Building strict isolation firewalls around the point of prediction ensures models rely solely on information that genuinely exists at decision time.

In everyday terms

Studying for a medical licensing exam with a stolen copy of the answer key: you score 100% on practice exams, but fail in the clinic when answers are no longer provided.

02 Step by step

  1. Define the point of prediction: fix the exact real-world timestamp $T_{\text{pred}}$ when inference executes in production.
  2. Audit feature timelines: systematically eliminate any feature created, updated, or recorded after $T_{\text{pred}}$ (downstream consequence of the target).
  3. Fit all transformers inside cross-validation: enforce that scalers, imputers, and encoders call fit strictly on training folds and transform on validation folds.
  4. Isolate target encoding out-of-fold: ensure target-based categorical encodings exclude the current record's label to prevent self-referential leakage.
  5. Stress-test with temporal holdouts: validate models on a strictly future time block; a dramatic divergence between cross-validation and holdout exposes leakage.

03 The maths

  1. Mutual information target leakage condition

    I(X_{\text{leaked}}; Y \mid T_{\text{pred}}) \gg I(X_{\text{valid}}; Y \mid T_{\text{pred}})

    Where $X_{\text{leaked}}$ represents information generated chronologically after decision timestamp $T_{\text{pred}}$. Such features exhibit spurious high mutual information with target $Y$ during backtesting that disappears under true live inference.

  2. Global preprocessing parameter mismatch

    \hat{\mu}_{\text{leaked}} = \frac{1}{n_{\text{tr}} + n_{\text{val}}} \sum_{i \in \mathcal{D}_{\text{tr}} \cup \mathcal{D}_{\text{val}}} x_i \ne \hat{\mu}_{\text{train}} = \frac{1}{n_{\text{tr}}} \sum_{i \in \mathcal{D}_{\text{tr}}} x_i

    Estimating transformation parameters (such as mean $\hat{\mu}$ or variance $\hat{\sigma}^2$) across the pooled dataset introduces an out-of-fold bias of order $\mathcal{O}(n_{\text{val}} / n)$, breaking the statistical independence assumption between training and validation partitions.

  3. Out-of-fold target encoding formulation

    \hat{S}_{i, c} = \frac{\sum_{j \in \mathcal{D}_{\text{tr}} \setminus \{i\}, X_j = c} y_j + m \bar{y}_{\text{tr}}}{n_{c, \text{tr},-i} + m}

    Target encoding must be computed by explicitly excluding sample $i$ (or via out-of-fold cross-fitting), preventing observation $i$'s own target label $y_i$ from leaking directly into its feature representation.

04 Key takeaways

  • Target leakage introduces features that are downstream effects or proxies of the outcome rather than causes.
  • Preprocessing leakage occurs whenever transformation parameters (means, medians, vocabularies) are learned on pooled train and test data.
  • Feature selection leakage across the entire dataset can make pure noise appear 80%+ accurate in cross-validation.

05 In code

python
import numpy as np

# Simulate feature selection leakage on pure noise (100 samples, 500 noise features)
np.random.seed(42)
n_samples, n_features = 100, 500
X = np.random.normal(0, 1, size=(n_samples, n_features))
y = np.random.binomial(1, 0.5, size=n_samples)  # independent random binary targets

# 1. LEAKED: Select top 5 correlated features using the FULL dataset before splitting
corrs = np.array([np.abs(np.corrcoef(X[:, j], y)[0, 1]) for j in range(n_features)])
top_leaked = np.argsort(corrs)[-5:]

# Nearest centroid classification on test set using leaked features
train_idx, test_idx = np.arange(70), np.arange(70, 100)
c1_leak = np.mean(X[train_idx][y[train_idx] == 1][:, top_leaked], axis=0)
c0_leak = np.mean(X[train_idx][y[train_idx] == 0][:, top_leaked], axis=0)
preds_leak = (np.linalg.norm(X[test_idx][:, top_leaked] - c1_leak, axis=1) <
              np.linalg.norm(X[test_idx][:, top_leaked] - c0_leak, axis=1)).astype(int)
acc_leak = np.mean(preds_leak == y[test_idx])

# 2. CLEAN: Select features using ONLY training partition
corrs_clean = np.array([np.abs(np.corrcoef(X[train_idx, j], y[train_idx])[0, 1]) for j in range(n_features)])
top_clean = np.argsort(corrs_clean)[-5:]
c1_clean = np.mean(X[train_idx][y[train_idx] == 1][:, top_clean], axis=0)
c0_clean = np.mean(X[train_idx][y[train_idx] == 0][:, top_clean], axis=0)
preds_clean = (np.linalg.norm(X[test_idx][:, top_clean] - c1_clean, axis=1) <
               np.linalg.norm(X[test_idx][:, top_clean] - c0_clean, axis=1)).astype(int)
acc_clean = np.mean(preds_clean == y[test_idx])

print(f"Test accuracy with feature selection leakage: {acc_leak:.2f}")
print(f"Test accuracy with clean in-fold selection:   {acc_clean:.2f}")

Common pitfalls

  • Calling fit_transform on the full dataset before splitting into train, validation, and test partitions.
  • Performing unsupervised or supervised feature selection on the entire dataset prior to cross-validation.
  • Including database record update timestamps, transaction IDs, or account closure dates that are logged concurrently with the target event.

06 Check yourself

Q1A machine learning engineer achieves 99.5% accuracy predicting loan defaults, but in production the model performs no better than random guessing. What is the most probable cause?

Why: Features that are populated or updated as a consequence of the target event (like referral to collections) leak future outcome knowledge into training, creating deceptive offline performance that fails live.

Q2Why is computing StandardScaler mean and standard deviation across an entire dataset prior to cross-validation considered data leakage?

Why: Fitting transformers on the full dataset allows test set statistical information to seep into the training set, causing optimistic validation scores.

Q3How does out-of-fold target encoding prevent target leakage in high-cardinality categorical variables?

Why: If a row's own target label is included when calculating its category's mean target value, the feature directly leaks the label, especially for rare categories with sample count 1.
