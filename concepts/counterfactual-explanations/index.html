01 The idea

When a bank loan is denied or job application rejected by an AI, knowing which features had the highest Shapley values does not tell the applicant what to do. Counterfactual explanations provide concrete, actionable recourse: what minimal changes would flip the decision from denied to approved?

Traditional model interpretability tools (like feature importance, SHAP, and LIME) explain the past: they inform a user which features contributed most to a rejected mortgage application. However, telling an applicant that their "Credit Score" had a Shapley value of $-0.42$ offers zero actionable guidance. What the applicant needs is algorithmic recourse: "What concrete steps must I take to get approved?"

Sandra Wachter, Brent Mittelstadt, and Chris Russell (2017) formalised Counterfactual Explanations to satisfy the legal "Right to Explanation" under GDPR. A counterfactual explanation finds a hypothetical alternative instance $x^*$ that is as close as possible to original input $x$, but produces the desired target prediction: $f(x^*) = y^*$.

For example: "If your monthly savings were £200 higher and your credit card debt were £1,500 lower, your loan would have been approved." This bridges the gap between passive attribution and actionable recourse.

Mathematically, counterfactual search is an optimisation problem balancing prediction loss (pushing $f(x^*)$ toward target class $y^*$) against a distance penalty $d(x, x^*)$ (ensuring changes are minimal). Crucially, valid recourse must enforce domain constraints: distinguishing between mutable features (income, debt) and immutable features (age, biological sex, birthplace), and ensuring the counterfactual lies on the plausible data manifold.

In everyday terms

Imagine a student who scored 48% on a final exam and failed by two marks. An attribution explanation tells them: "You failed because of your weak history essay score." A counterfactual explanation gives actionable advice: "If you had answered question 3 on the history essay correctly, your score would have been 51% and you would have passed." It identifies the minimum effort path across the passing threshold.

03 The maths

  1. Wachter Counterfactual Optimisation Problem

    \arg\min_{x^*} \ell\left(f(x^*), y^*\right) + \lambda d(x, x^*) \quad \text{subject to } x_j^* = x_j \; \forall j \in \mathcal{I}_{\mathrm{immutable}}

    Finds counterfactual x* that minimises discrepancy to desired outcome y* while penalising distance from original instance x.

  2. MAD-Normalised Manhattan Distance Metric

    d(x, x^*) = \sum_{j=1}^p \frac{|x_j - x_j^*|}{\operatorname{MAD}_j}, \quad \operatorname{MAD}_j = \operatorname{median}\left(|X_j - \operatorname{median}(X_j)|\right)

    Normalises distance by Median Absolute Deviation of each feature, making penalties scale-invariant and robust to outliers while promoting sparsity (changing few features).

  3. Data Manifold Plausibility Penalty (Mahalanobis / VAE)

    \mathcal{L}_{\mathrm{plausible}}(x^*) = (x^* - \mu)^T \Sigma^{-1} (x^* - \mu) \quad \text{or} \quad \|x^* - g(z^*)\|^2

    Prevents adversarial or impossible counterfactuals by penalising points that fall off the empirical data manifold.

04 Key takeaways

  • Provides actionable algorithmic recourse: identifies minimal perturbations required to flip an adverse model decision.
  • Optimises a composite objective balancing target prediction loss with normalised distance from the original instance.
  • Enforces domain constraints by distinguishing between mutable features (debt, savings) and immutable features (age, sex, ethnicity).
  • Normalised Manhattan distance ($L_1 / \operatorname{MAD}$) induces sparsity, requiring changes across as few features as possible.
  • Crucial for regulatory compliance (e.g. EU GDPR Right to Explanation) in lending, employment, and medical diagnosis.

05 In code

python
import numpy as np
from scipy.optimize import minimize
from sklearn.linear_model import LogisticRegression

# Counterfactual Explanations with Actionability Constraints from scratch
np.random.seed(42)
n_train = 400

# 4 Features: [Age (Immutable), AnnualIncome, CreditCardDebt, Savings]
# Units: Age (years), Income (£k), Debt (£k), Savings (£k)
feature_names = ['Age (Immutable)', 'AnnualIncome (£k)', 'Debt (£k)', 'Savings (£k)']
immutable_indices = [0]  # Age cannot be changed!

# Generate synthetic credit underwriting data
X = np.random.normal(loc=[40, 50, 15, 10], scale=[10, 15, 6, 8], size=(n_train, 4))
X = np.maximum(X, [18, 10, 0, 0])  # Realistic bounds

# True underwriting rule: High income + high savings - high debt
latent = 0.08 * X[:, 1] - 0.15 * X[:, 2] + 0.12 * X[:, 3] - 1.5
y = (latent > 0).astype(int)  # 1 = Approved, 0 = Denied

clf = LogisticRegression()
clf.fit(X, y)

# Denied applicant to provide recourse for
# 45 years old, £35k income, £22k debt, £3k savings -> Denied!
x_denied = np.array([45.0, 35.0, 22.0, 3.0])
orig_prob = clf.predict_proba(x_denied.reshape(1, -1))[0, 1]
print(f"Original Applicant Approval Probability: {orig_prob*100:.1f}% (DENIED)")

# Feature Median Absolute Deviations (MAD) for scale normalisation
mads = np.median(np.abs(X - np.median(X, axis=0)), axis=0)
mads[mads == 0] = 1.0

# Counterfactual Optimisation Objective
def counterfactual_loss(x_candidate, x_orig, model, target_class=1, lambda_dist=0.5):
    # 1. Prediction loss: binary cross-entropy to target class 1
    prob = model.predict_proba(x_candidate.reshape(1, -1))[0, target_class]
    pred_loss = -np.log(max(prob, 1e-12))
    
    # 2. Distance penalty: MAD-normalised Manhattan L1 distance
    dist_loss = np.sum(np.abs(x_candidate - x_orig) / mads)
    
    return pred_loss + lambda_dist * dist_loss

# Bounds and constraints
bounds = [
    (x_denied[0], x_denied[0]),  # Age is rigidly fixed (immutable!)
    (10.0, 120.0),               # Income bound
    (0.0, 50.0),                 # Debt bound
    (0.0, 100.0)                 # Savings bound
]

# Run optimisation from x_denied starting point
res = minimize(
    counterfactual_loss,
    x0=x_denied,
    args=(x_denied, clf, 1, 0.3),
    bounds=bounds,
    method='L-BFGS-B'
)

x_cf = res.x
cf_prob = clf.predict_proba(x_cf.reshape(1, -1))[0, 1]

print(f"\nCounterfactual Found! New Approval Probability: {cf_prob*100:.1f}% (APPROVED)")
print("\n--- Actionable Recourse Recommendations ---")
for i, name in enumerate(feature_names):
    delta = x_cf[i] - x_denied[i]
    if abs(delta) > 0.1:
        action = "increase by" if delta > 0 else "reduce by"
        print(f"  {name:20s}: Current = {x_denied[i]:5.1f} -> Target = {x_cf[i]:5.1f} ({action} {abs(delta):.1f})")
    else:
        print(f"  {name:20s}: No change required ({x_denied[i]:.1f})")

Common pitfalls

  • Adversarial vulnerability: Gradient-based counterfactual search can discover adversarial noise perturbations that flip model output without representing genuine real-world plausibility.
  • Actionability violations: Proposing unachievable recourse (such as "reduce age by 5 years" or "double income in 2 days") invalidates practical utility.
  • Causal confounding: Features are rarely independent; increasing income might causally affect debt or tax brackets; pure geometric counterfactuals ignore causal dependencies.

06 Check yourself

Q1Why are Counterfactual Explanations considered more actionable for loan applicants than SHAP or feature importance?

Why: Feature importances explain what caused the past decision, but do not provide actionable recourse. Counterfactuals provide concrete targets (e.g. reduce debt by £3,000) to reverse the decision.

Q2Why must immutable features (like Age or Race) be constrained during counterfactual search?

Why: Recourse must be humanly achievable. Recommending that an applicant become 10 years younger or alter their biological traits is impossible in reality.
