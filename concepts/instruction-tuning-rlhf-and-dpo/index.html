Instruction Tuning, RLHF, and Direct Preference Optimisation (DPO)

Base language models optimise next-token prediction, frequently producing toxic, repetitive, or unhelpful completions when prompted with instructions. Supervised Fine-Tuning (SFT) trains models on curated instruction-response dialogues, teaching conversational format and task execution. RLHF trains a reward model on pairwise human comparisons, optimising the policy using PPO while constraining policy drift via KL divergence penalties. Direct Preference Optimisation (DPO) derives an exact closed-form algebraic substitution that optimises preference loss directly on policy weights without a separate reward model or RL loop.

01 The idea

Pretrained base language models are raw sequence completers that mimic internet text rather than helpful assistants. Transforming base models into aligned, instruction-following assistants requires supervised fine-tuning (SFT), Reinforcement Learning from Human Feedback (RLHF) with reward modelling, and modern reference-model-implicit formulations such as Direct Preference Optimisation (DPO).

If you give a base, un-tuned LLM the prompt "Write a poem about the ocean", it might complete the text with "and explain its metre. Chapter 3: Poetry Analysis" because it treats your prompt as an excerpt from a high school textbook. It lacks the concept of being an assistant that obeys instructions. Supervised Fine-Tuning (SFT) fixes this by training the model on hundreds of thousands of instruction-answer pairs. However, SFT alone struggles when there are multiple valid answers or nuanced trade-offs between conciseness, tone, and correctness. RLHF solves this by asking humans to rank multiple candidate answers (e.g. "Response A is better than Response B"). A reward model learns this human preference function, and the LLM is updated using reinforcement learning. DPO achieves the exact same mathematical objective as RLHF, but eliminates the complex reinforcement learning machinery by proving that the optimal policy can be trained directly on preferred vs dispreferred pairs using simple binary cross-entropy.

In everyday terms

Teaching an LLM is like training an apprentice chef. Pretraining is reading every recipe book in the national archives. SFT is culinary school, where the apprentice cooks exact dishes following instructor demonstrations. RLHF is having a food critic taste two dishes side-by-side and give critique scores. DPO is giving the apprentice a clear side-by-side photo journal of delicious dishes versus burnt dishes, allowing them to adjust their seasoning directly without needing the critic present in the kitchen.

02 Step by step

  1. Pretrain base foundation model: train autoregressive transformer on trillion-token web corpora for raw next-token prediction.
  2. Perform Supervised Fine-Tuning (SFT): fine-tune base weights on high-quality demonstration datasets of user instructions and ideal responses.
  3. Collect preference data: sample multiple candidate completions $(y_1, y_2)$ for prompt $x$ and collect human or AI annotator rankings $(y_w \succ y_l)$.
  4. Train reward model (in classical RLHF): train scalar regression model $r_\psi(x, y)$ using pairwise ranking loss.
  5. Optimise policy via PPO (classical RLHF): update policy network with actor-critic reinforcement learning and KL divergence penalty.
  6. Alternatively, apply DPO directly: compute implicit reward margins using policy $\pi_\theta$ and frozen reference model $\pi_{\text{ref}}$, updating $\theta$ via standard gradient backpropagation.

04 Key takeaways

  • Alignment bridges the gap between raw web completion and reliable, helpful assistant behaviour.
  • RLHF combines human preference ranking, reward modelling, and KL-regularised PPO policy optimisation.
  • DPO achieves equivalent mathematical alignment using a stable, closed-form binary cross-entropy loss directly on the policy network.

05 In code

python
import numpy as np

def sigmoid(z):
    """Numerically stable sigmoid function."""
    return 1.0 / (1.0 + np.exp(-np.clip(z, -30, 30)))

def dpo_loss(pi_logps_win, pi_logps_lose, ref_logps_win, ref_logps_lose, beta=0.1):
    """Computes Direct Preference Optimisation (DPO) loss and implicit rewards.
    
    pi_logps: sum of token log-probabilities under policy network pi_theta
    ref_logps: sum of token log-probabilities under frozen reference network pi_ref
    """
    # Compute log-ratios for winning and losing responses
    pi_diff = pi_logps_win - pi_logps_lose
    ref_diff = ref_logps_win - ref_logps_lose
    
    # Margin: beta * [log(pi_w / ref_w) - log(pi_l / ref_l)]
    logits = beta * (pi_diff - ref_diff)
    
    # DPO Loss = -log(sigmoid(logits))
    loss = -np.log(sigmoid(logits) + 1e-12)
    
    # Implicit reward scores
    reward_win = beta * (pi_logps_win - ref_logps_win)
    reward_lose = beta * (pi_logps_lose - ref_logps_lose)
    
    return loss, reward_win, reward_lose

# Simulation: Prompt = "Explain why the sky is blue"
# Response Winner (clear, helpful): y_w
# Response Loser (toxic, incorrect): y_l

# Initial reference log-probabilities (frozen SFT model)
ref_win = -12.4
ref_lose = -13.1

# Policy before alignment (similar likelihoods)
pi_win_initial = -12.3
pi_lose_initial = -13.0

loss_initial, r_w_init, r_l_init = dpo_loss(
    pi_win_initial, pi_lose_initial, ref_win, ref_lose, beta=0.1
)

# Policy after DPO training (increased probability on winner, decreased on loser)
pi_win_trained = -10.5
pi_lose_trained = -16.2

loss_trained, r_w_opt, r_l_opt = dpo_loss(
    pi_win_trained, pi_lose_trained, ref_win, ref_lose, beta=0.1
)

print(f"Initial DPO Loss: {loss_initial:.4f} | Margin: {(r_w_init - r_l_init):.3f}")
print(f"Trained DPO Loss: {loss_trained:.4f} | Margin: {(r_w_opt - r_l_opt):.3f}")
print(f"Implicit Reward (Winner): {r_w_opt:.3f} | Implicit Reward (Loser): {r_l_opt:.3f}")

Common pitfalls

  • Allowing policy drift without KL divergence regularisation; the model exploits imperfections in the reward model (reward hacking), producing nonsensical repetitive prose.
  • Applying DPO without an initial Supervised Fine-Tuning (SFT) phase; DPO assumes the reference policy is already in-distribution for the prompt format.
  • Using noisy, inconsistent preference annotations where annotators disagree on subjective quality, creating conflicting gradient signals.

06 Check yourself

Q1What is the primary role of the KL divergence penalty $\beta \mathbb{D}_{\text{KL}}(\pi \,\|\, \pi_{\text{ref}})$ during RLHF training?

Why: Without the KL constraint, the reinforcement learning policy exploits imperfections in the learned reward model (reward hacking), collapsing text coherence.

Q2How does Direct Preference Optimisation (DPO) simplify the alignment pipeline compared to standard PPO-based RLHF?

Why: DPO shows that the reward function can be analytically substituted with policy log-ratios, transforming preference alignment into a straightforward supervised binary classification loss.

Q3What is the purpose of the initial Supervised Fine-Tuning (SFT) stage before preference alignment?

Why: Base models are pre-trained for raw web text completion; SFT teaches the model the basic instruction-following and question-answering dialogue format.
