Named entity recognition and IOB tagging

Named Entity Recognition (NER) is the information extraction task of identifying spans of text that denote real-world entities (such as people, organisations, and locations) and classifying them into structured categories. Because named entities often span multiple consecutive tokens, NER reframes text chunking as sequence labelling using boundary schemes such as IOB2 (BIO) and BIOES, modelled through linear-chain CRFs or Transformer token classifiers.

01 The idea

If you ask an AI assistant to summarise a news article, it must quickly identify the key actors: Did "Apple" refer to the multinational tech titan or a piece of fruit? Was "Washington" referring to George Washington the historical figure, Washington State, or the United States federal government? Named Entity Recognition extracts these multi-word semantic entities from unstructured prose and classifies them into structured knowledge representations.

Why entity chunking requires boundary schemes: Unlike part-of-speech tagging where each word receives one isolated tag, named entities frequently span multiple words: "New York University", "Bank of England", "Marie Curie". If we only tagged words as ORG or PER, the system would not know whether two adjacent ORG tokens represent two separate organisations or one combined entity. Boundary schemes like IOB2 (Beginning, Inside, Outside) solve this by assigning B-ORG to the first token and I-ORG to continuation tokens.

The BIOES advantage for boundary precision: The standard IOB2 scheme uses B-c for both singleton entities and the beginning of multi-word entities. BIOES (Beginning, Inside, Outside, End, Singleton) extends this by providing separate tags for single-token entities (S-c) and terminal tokens (E-c). This explicit distinction provides strong inductive bias to sequence models, preventing them from prematurely truncating long company or geographical names.

Guardrails against illegal transitions via CRFs: When training a deep neural network (like a BiLSTM or BERT) for token classification with independent softmax outputs, the model has no built-in awareness of sequence grammar. It might predict O followed immediately by I-PER (an illegal transition). A Conditional Random Field (CRF) layer adds a global transition constraint matrix, penalising illegal boundary sequences with negative infinity and ensuring that every predicted entity path is structurally valid.

In everyday terms

Think of highlighting text in a study guide with coloured markers. If you highlight words individually without notes, someone reading your guide later cannot tell if "United" and "Airlines" were meant to be read together as one company or two separate terms. IOB tagging is like drawing brackets around your highlights: a green opening bracket marked B-ORG at "United", an internal green mark I-ORG at "Airlines", and a closing bracket before returning to unhighlighted text (O). Anyone reading your annotations knows the exact boundaries and identity of every entity you marked.

03 The maths

  1. Linear-chain CRF sequence scoring function

    s(X, Y) = \sum_{t=1}^T P_{t, y_t} + \sum_{t=0}^T A_{y_t, y_{t+1}}

    Here $P_{t, j}$ is the emission score of token $t$ for label $j$ from the neural encoder, and $A \in \mathbb{R}^{(K+2) \times (K+2)}$ is the learnable transition matrix modelling grammatical tag transitions between consecutive steps.

  2. Conditional sequence probability (Softmax over paths)

    P(Y \mid X) = \frac{\exp(s(X, Y))}{\sum_{Y' \in \mathcal{Y}^T} \exp(s(X, Y'))}

    The CRF defines a normalised probability distribution over all $|\mathcal{Y}|^T$ possible label sequences. The normalisation constant (partition function $Z(X)$) is computed efficiently using the forward dynamic programming algorithm.

  3. Strict span-level precision, recall, and F1

    \operatorname{Precision} = \frac{|\mathcal{E}_{\text{gold}} \cap \mathcal{E}_{\text{pred}}|}{|\mathcal{E}_{\text{pred}}|}, \quad \operatorname{Recall} = \frac{|\mathcal{E}_{\text{gold}} \cap \mathcal{E}_{\text{pred}}|}{|\mathcal{E}_{\text{gold}}|}, \quad F_1 = \frac{2 \cdot P \cdot R}{P + R}

    Here an entity span is an exact triple $(c, \text{start}, \text{end})$. Any boundary offset mismatch yields zero credit, preventing token-level outside class imbalance from distorting evaluation metrics.

04 Key takeaways

  • Named Entity Recognition extracts structured entities (person, organisation, location) from unstructured text and classifies them into predefined types.
  • IOB2 (BIO) and BIOES schemes convert chunk boundary identification into standard discrete sequence labelling tasks.
  • BIOES provides distinct tags for singleton entities (S-) and multi-token endings (E-), reducing boundary ambiguity.
  • Linear-chain CRFs model label transition dynamics A_{i, j}, enforcing sequence validity and preventing illegal transitions like O -> I-PER.
  • NER must be evaluated using strict span-level Precision, Recall, and F1; token-level accuracy is heavily skewed by the overwhelming prevalence of the outside (O) class.

05 In code

python
class IOBSpanEvaluator:
    """
    Parser and strict span-level evaluator for IOB2 (BIO) sequence labelling.
    Converts token tags to entity spans and computes CoNLL precision, recall, and F1.
    """
    @staticmethod
    def extract_entities(tokens, tags):
        entities = []
        current_cat = None
        start_idx = None
        
        for idx, (tok, tag) in enumerate(zip(tokens, tags)):
            if tag == 'O':
                if current_cat is not None:
                    span_text = " ".join(tokens[start_idx:idx])
                    entities.append((current_cat, start_idx, idx - 1, span_text))
                    current_cat = None
                    start_idx = None
            elif tag.startswith('B-'):
                if current_cat is not None:
                    span_text = " ".join(tokens[start_idx:idx])
                    entities.append((current_cat, start_idx, idx - 1, span_text))
                current_cat = tag[2:]
                start_idx = idx
            elif tag.startswith('I-'):
                tag_cat = tag[2:]
                if current_cat == tag_cat:
                    continue
                else:
                    if current_cat is not None:
                        span_text = " ".join(tokens[start_idx:idx])
                        entities.append((current_cat, start_idx, idx - 1, span_text))
                    current_cat = tag_cat
                    start_idx = idx
                    
        if current_cat is not None:
            span_text = " ".join(tokens[start_idx:len(tokens)])
            entities.append((current_cat, start_idx, len(tokens) - 1, span_text))
            
        return entities

    @classmethod
    def evaluate(cls, tokens, gold_tags, pred_tags):
        gold_spans = cls.extract_entities(tokens, gold_tags)
        pred_spans = cls.extract_entities(tokens, pred_tags)
        
        gold_set = {(cat, s, e) for cat, s, e, _ in gold_spans}
        pred_set = {(cat, s, e) for cat, s, e, _ in pred_spans}
        
        true_positives = len(gold_set & pred_set)
        false_positives = len(pred_set - gold_set)
        false_negatives = len(gold_set - pred_set)
        
        prec = true_positives / len(pred_set) if len(pred_set) > 0 else 0.0
        rec = true_positives / len(gold_set) if len(gold_set) > 0 else 0.0
        f1 = (2.0 * prec * rec) / (prec + rec) if (prec + rec) > 0 else 0.0
        
        return {
            "precision": prec,
            "recall": rec,
            "f1": f1,
            "gold_entities": gold_spans,
            "pred_entities": pred_spans,
            "tp": true_positives,
            "fp": false_positives,
            "fn": false_negatives
        }

tokens = ["Alan", "Turing", "joined", "Bletchley", "Park", "in", "the", "United", "Kingdom", "."]

gold_tags = [
    "B-PER", "I-PER",
    "O",
    "B-ORG", "I-ORG",
    "O",
    "O",
    "B-LOC", "I-LOC",
    "O"
]

pred_tags = [
    "B-PER", "I-PER",
    "O",
    "B-ORG", "O",
    "O",
    "O",
    "B-LOC", "I-LOC",
    "O"
]

metrics = IOBSpanEvaluator.evaluate(tokens, gold_tags, pred_tags)

print("Named Entity Recognition Span Evaluation:")
print(f"Tokens: {' '.join(tokens)}")
print("\nGold Entities:")
for cat, s, e, text in metrics["gold_entities"]:
    print(f"  [{cat}] tokens {s}..{e}: '{text}'")

print("\nPredicted Entities:")
for cat, s, e, text in metrics["pred_entities"]:
    print(f"  [{cat}] tokens {s}..{e}: '{text}'")

print("\nStrict Evaluation Metrics (CoNLL 2003 protocol):")
print(f"  True Positives:  {metrics['tp']}")
print(f"  False Positives: {metrics['fp']} (boundary/type mismatches)")
print(f"  False Negatives: {metrics['fn']}")
print(f"  Precision:       {metrics['precision'] * 100:.1f}%")
print(f"  Recall:          {metrics['recall'] * 100:.1f}%")
print(f"  F1 Score:        {metrics['f1'] * 100:.1f}%")

Common pitfalls

  • Evaluating NER using token-level accuracy: Because 90% of tokens in typical prose are O, a trivial baseline predicting O everywhere achieves 90% accuracy while extracting zero entities. Always report span-level CoNLL F1.
  • Allowing illegal label transitions: Independent token classifiers often produce invalid sequences like O directly followed by I-ORG. Use a CRF layer or an explicit Viterbi transition mask during inference.
  • Subword tokenisation misalignment: Modern subword tokenisers split rare names into multiple fragments. Training loss must either mask non-initial subwords using an ignore index (-100) or maintain consistent subword alignment to avoid corrupting span boundaries.
  • Treating nested entities as flat sequences: IOB sequence labelling fundamentally cannot represent nested structures (such as Bank of America where America is a nested location). Nested extraction requires span-based classification or generative decoders.

06 Check yourself

Q1Why is token-level accuracy an unsuitable metric for evaluating Named Entity Recognition models?

Why: Extreme class imbalance makes token accuracy misleading. Since most words in natural text are not named entities (O), a model that classifies every single word as O gets ~90% accuracy while having a true entity detection F1 score of 0%.

Q2In the IOB2 (BIO) tagging scheme, which of the following label transitions is grammatically invalid and should be penalised by a CRF?

Why: In IOB2, an inside tag (I-c) can only occur immediately after a beginning tag of the same entity category (B-c) or another inside tag of that category. Transitioning directly from O to I-ORG is an illegal orphan boundary.

Q3What advantage does the BIOES (BILOU) tagging scheme provide over the standard IOB2 (BIO) scheme?

Why: In standard IOB2, the tag B-c is ambiguous: it represents both single-word entities and the start of multi-word entities. BIOES uses S-c for singletons and E-c for entity endings, making entity length and boundary conditions explicit to the classifier.
