01 The idea

Commercial LLM applications face steep cost and latency hurdles when processing repetitive prompts or routing all queries to massive flagship models. Combining exact prefix prompt caching, semantic vector caching (GPTCache), and dynamic model routing (LLM cascade routers) reduces operational serving costs by 60–85% while cutting response latency.

In typical enterprise applications, users ask semantically similar questions ("How do I reset my password?" vs "Steps to change my login password") or submit queries with massive shared system prompts (like 10,000 tokens of documentation). Standard systems blindly run full inference on every request, paying full token rates.

Systems engineering solves this with two complementary layers: 1) Caching: Prompt Caching preserves pre-computed KV-cache states for identical prompt prefixes across requests, while Semantic Caching stores past Q&A pairs in a vector database, returning cached answers when cosine similarity exceeds a high threshold (e.g. 0.95); 2) Model Routing: A lightweight classifier routes simple queries to small, inexpensive models (e.g. 8B parameters) and escalates complex multi-step reasoning to frontier models (e.g. 400B parameters).

In everyday terms

Imagine a customer service department. If every single customer who walks in is sent to meet the CEO, the company wastes millions on executive salary and wait times explode. A smart organisation places a frequently-asked-questions kiosk at the entrance (Semantic Cache) and assigns junior reps to handle routine inquiries, escalating only complex legal questions to senior leadership (Model Routing).

02 Step by step

  1. Check exact prefix cache: verify if input prompt prefix matches existing GPU KV-cache blocks, skipping recomputation for static system prompts.
  2. Query semantic vector cache: embed user query and search vector cache; if cosine similarity $\ge \tau_{\text{cache}}$, return cached answer immediately.
  3. Evaluate query complexity: compute difficulty score using a small routing classifier or prompt length/intent heuristics.
  4. Select model tier: route easy queries to tier-1 models (fast, cheap) and hard reasoning queries to tier-2 flagship models.
  5. Execute model generation: stream generation to client while asynchronously updating the semantic cache with the newly synthesized response pair.

03 The maths

  1. Semantic Cache Hit Criterion

    \text{Hit}(q) = \begin{cases} \text{Return } A(q^*) & \text{if } \max_{q^* \in \mathcal{C}} \cos(\mathbf{e}(q), \mathbf{e}(q^*)) \ge \tau_{\text{cache}} \\ \text{Forward to LLM} & \text{otherwise} \end{cases}

    Returns cached answer $A(q^*)$ if embedding cosine similarity between incoming query and cached query exceeds threshold $\tau_{\text{cache}}$.

  2. Cascade Routing Expected Cost

    \mathbb{E}[\text{Cost}] = P(\text{Easy}) \cdot C_{\text{small}} + P(\text{Hard}) \cdot (C_{\text{small}} + C_{\text{flagship}})

    Quantifies significant cost reduction when the majority of user queries are resolved by smaller model tiers.

04 Key takeaways

  • Prompt prefix caching reuses precomputed KV activations, slashing first-token latency on shared system prompts.
  • Semantic caching serves repeated queries from vector databases, achieving near-zero latency and zero API cost.
  • Dynamic model routing directs requests to the most cost-effective model tier capable of satisfying the query complexity.

05 In code

python
import numpy as np

class SemanticCacheAndRouter:
    """Demonstrates semantic caching and tier-based model routing."""
    def __init__(self, cache_threshold=0.92):
        self.cache = {}
        self.threshold = cache_threshold

    def query(self, query_text, query_emb):
        # 1. Semantic Cache Lookup
        for cached_text, (cached_emb, cached_ans) in self.cache.items():
            sim = np.dot(query_emb, cached_emb) / (np.linalg.norm(query_emb) * np.linalg.norm(cached_emb))
            if sim >= self.threshold:
                return f"[CACHE HIT (sim: {sim:.2f})] {cached_ans}", "cache"
                
        # 2. Dynamic Model Routing
        # Heuristic: queries with keywords like 'analysee', 'prove', 'refactor' route to flagship
        is_complex = any(k in query_text.lower() for k in ["analyse", "prove", "architect", "synthesise"])
        if is_complex:
            routed_model = "Flagship-400B ($20/M tokens)"
            answer = f"Comprehensive synthesized answer generated by {routed_model}."
        else:
            routed_model = "Economy-8B ($0.20/M tokens)"
            answer = f"Concise direct response generated by {routed_model}."
            
        # Store in cache
        self.cache[query_text] = (query_emb, answer)
        return f"[ROUTED: {routed_model}] {answer}", routed_model

router = SemanticCacheAndRouter()

# Mock embeddings (dim=3)
q1_emb = np.array([1.0, 0.0, 0.2])
q2_emb = np.array([0.98, 0.05, 0.2])  # Near identical to Q1!
q3_emb = np.array([0.1, 1.0, 0.0])

ans1, tier1 = router.query("What is the capital of France?", q1_emb)
ans2, tier2 = router.query("Which city is France's capital?", q2_emb)
ans3, tier3 = router.query("Synthesise an enterprise architecture plan", q3_emb)

print(ans1)
print(ans2)
print(ans3)

Common pitfalls

  • Setting semantic cache similarity thresholds too low ($< 0.85$), returning answers that answer a different question.
  • Caching time-sensitive or personalised queries without session isolation, leaking private user data across accounts.

06 Check yourself

Q1What is the operational benefit of Prompt Prefix Caching (e.g. Anthropic Prompt Caching)?

Why: Prefix caching reuses the computed KV representations of static headers and documents across queries, avoiding redundant attention recomputation.

Q2How does a Semantic Cache differ from a traditional Redis key-value cache in NLP systems?

Why: Users phrase identical questions differently ("reset password" vs "change login password"). Semantic caching matches paraphrases using embedding distance.

Q3What is the goal of a dynamic model cascade router (e.g. FrugalGPT)?

Why: Cascade routers evaluate query difficulty and direct simple requests to small models, cutting operational costs substantially with little quality loss.
