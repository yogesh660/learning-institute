01 The idea

Online controlled experiments, or A/B tests, represent the gold standard of causal inference in modern software and product engineering. By randomly allocating users between a control variant and an experimental treatment, A/B tests guarantee that observed differences are caused by the feature change rather than confounding factors. Designing an end-to-end test requires disciplined sample sizing, Sample Ratio Mismatch (SRM) validation, statistical testing, and tracking guardrail metrics.

Imagine an e-commerce company testing a "Buy with 1-Click" button against the standard 3-step checkout. Over two weeks, 40,000 users are randomly assigned: 20,000 to Control (A) and 20,000 to Treatment (B). In Control, 1,600 users purchase (8.0% conversion). In Treatment, 1,760 users purchase (8.8% conversion)—an apparent absolute uplift of 0.8 percentage points (a 10% relative increase).

How does the team verify this win? First, they audit experiment integrity using a Sample Ratio Mismatch (SRM) test. If the randomisation server delivered 19,200 Control users and 20,800 Treatment users, a chi-square goodness-of-fit test against the expected 50/50 split yields $p < 0.0001$. This indicates that the experiment is fundamentally broken—perhaps buggy JavaScript crashed older browsers in Treatment, silently dropping users and invalidating the sample.

When the allocation passes the SRM test ($p = 1.000$), the team runs a two-proportion $z$-test: the 0.8 percentage point lift with standard error $0.00277$ gives $z = 2.884$ and $p = 0.0039$. Because $p < 0.05$, the lift is statistically significant, with a 95% confidence interval spanning $[0.26\%, 1.34\%]$. Finally, they inspect guardrail metrics: did 1-Click checkout cause a surge in accidental orders and customer support refunds? Only when guardrails remain healthy is the winning variant safely rolled out.

In everyday terms

An A/B test is like a randomised medical clinical trial: patients receive either a placebo or the active drug under identical conditions so that health improvements can be attributed solely to the molecule, not to weather, diet, or doctor optimism.

02 Step by step

  1. Formulate a falsifiable causal hypothesis and define the primary evaluation metric and secondary guardrail metrics.
  2. Choose the unit of randomisation (e.g. user ID, cookie, device ID) to prevent cross-contamination across sessions.
  3. Determine the required sample size based on baseline conversion, Minimum Detectable Effect (MDE), significance level $\alpha = 0.05$, and power $1 - \beta = 0.80$.
  4. Run an initial Sample Ratio Mismatch (SRM) chi-square test to verify that traffic allocation matches the design split.
  5. Collect data for a pre-determined duration that encompasses full weekly cycles (minimum 1 to 2 weeks) without early peeking.
  6. Compute the test statistic, confidence interval for the treatment effect, and p-value; check guardrail metrics before rolling out.

03 The maths

  1. Two-Sample Proportion Test Statistic

    $$z = \frac{\hat{p}_B - \hat{p}_A}{\sqrt{\hat{p}_{\text{pool}}(1 - \hat{p}_{\text{pool}})\left(\frac{1}{n_A} + \frac{1}{n_B}\right)}}, \qquad \hat{p}_{\text{pool}} = \frac{x_A + x_B}{n_A + n_B}$$

    Here $x_A, x_B$ are conversion counts, $n_A, n_B$ are sample sizes, and $\hat{p}_{\text{pool}}$ is the pooled proportion. Under the null hypothesis $H_0: p_A = p_B$, the test statistic $z$ asymptotically follows the standard normal distribution $\mathcal{N}(0, 1)$.

  2. Sample Ratio Mismatch (SRM) Test

    $$\chi_{\text{SRM}}^2 = \sum_{v \in \{A, B\}} \frac{(n_v - E_v)^2}{E_v} \sim \chi^2(1), \qquad E_A = E_B = \frac{n_A + n_B}{2}$$

    The SRM test checks whether observed traffic counts conform to the planned 50/50 allocation ratio. A significant discrepancy ($p < 0.001$) signals severe tracking bugs, redirect delays, or platform-specific crashes that invalidate all downstream statistical inference.

  3. Sample Size Determination Formula

    $$n = \frac{2\left(z_{1 - \alpha/2} + z_{1 - \beta}\right)^2 p(1 - p)}{\delta^2}$$

    Here $p$ is the baseline conversion probability and $\delta = |p_B - p_A|$ is the Minimum Detectable Effect. Sizing experiments to achieve 80% power at $\alpha = 0.05$ requires fixing $n$ in advance to avoid underpowered experiments and inflated false discovery rates.

04 Key takeaways

  • A/B testing isolates causality by ensuring treatment and control cohorts differ exclusively by the experimental intervention.
  • The Sample Ratio Mismatch (SRM) test is a mandatory hygiene check: an SRM failure invalidates all downstream metrics regardless of p-values.
  • Experiments must run across complete business cycles (typically 7 or 14 full days) to account for weekday versus weekend behavioural shifts.
  • Guardrail metrics ensure that optimising the primary metric does not silently degrade user experience, system stability, or long-term retention.

05 In code

python
import numpy as np
import scipy.stats as stats

# A/B test results: 20,000 visitors per variant
n_a, n_b = 20000, 20000
x_a, x_b = 1600, 1760  # Conversions
p_a, p_b = x_a / n_a, x_b / n_b

# 1. Sample Ratio Mismatch (SRM) check (expected 50/50 split)
chi2_srm, p_srm = stats.chisquare([n_a, n_b], [20000, 20000])

# 2. Two-proportion z-test
p_pool = (x_a + x_b) / (n_a + n_b)
se_diff = np.sqrt(p_pool * (1.0 - p_pool) * (1.0 / n_a + 1.0 / n_b))
z_stat = (p_b - p_a) / se_diff
p_val = 2.0 * (1.0 - stats.norm.cdf(abs(z_stat)))

lift = p_b - p_a
ci_low = lift - 1.96 * se_diff
ci_high = lift + 1.96 * se_diff

print(f"SRM check p-value: {p_srm:.4f} (Valid allocation)")
print(f"Control conversion:   {p_a:.1%}")
print(f"Treatment conversion: {p_b:.1%} (Lift: {lift:+.2%})")
print(f"z-statistic: {z_stat:.3f}, p-value: {p_val:.4f}")
print(f"95% Confidence Interval: [{ci_low:.4f}, {ci_high:.4f}]")

Common pitfalls

  • Peeking at p-values daily and stopping the test early as soon as significance is reached, multiplying the true false positive rate.
  • Ignoring Sample Ratio Mismatches (SRMs), treating severe traffic drop-offs as legitimate experimental outcomes.
  • Seasonality and novelty effects: enthusiastic initial adoption of a new UI that fades after novelty wears off.
  • Twyman's law: "Any figure that looks interesting or different is usually wrong"—unexpectedly massive uplifts almost always reflect instrumentation bugs.

06 Check yourself

Q1Why does daily "peeking" at accumulated A/B test results and stopping early as soon as $p < 0.05$ invalidate the experiment?

Why: Continuous monitoring gives random sampling noise multiple opportunities to cross the significance boundary, drastically inflating false discovery rates.

Q2What does a statistically significant result ($p < 0.0001$) in a Sample Ratio Mismatch (SRM) test indicate?

Why: An SRM failure indicates that users were systematically dropped or misallocated between variants, violating the fundamental assumption of unbiased random assignment.

Q3Why must A/B tests typically run for a minimum duration of 7 or 14 full consecutive days?

Why: User behaviour varies systematically across weekdays and weekends; running experiments in full 7-day multiples balances day-of-week cyclicality.

Q4What is the primary role of "guardrail metrics" in online controlled experiments?

Why: Guardrail metrics monitor critical operational and business vitals (e.g. page load latency, crash rates, refund requests) to prevent destructive wins.
