Intelligent agents and environments

An intelligent agent is an autonomous entity that perceives its environment through sensors and acts upon it through actuators to achieve specified goals. Russell and Norvig's foundational framework categorises agents through PEAS specifications (Performance measure, Environment, Actuators, Sensors) and environmental dimensions (observable, deterministic, episodic, static, discrete, multi-agent). Agents progress across an architectural hierarchy: from simple condition-action reflex systems to model-based, goal-directed, and utility-maximising learning agents.

01 The idea

What distinguishes an intelligent AI agent from a simple calculator or static script? A calculator executes a deterministic arithmetic formula blindly. An intelligent agent operates within an external, often uncertain world: it perceives changes, maintains beliefs about hidden states, plans sequences of actions towards objectives, and adapts its future behaviour based on feedback. Understanding the formal agent-environment boundary is the essential cornerstone of classical AI, reinforcement learning, and modern autonomous LLM systems.

The Agent-Environment duality: Formally, an agent is defined by an agent function f: P* -> A that maps any sequence of perceptual histories P* into an action a in A. The environment is everything external to the agent that reacts to the agent's actions and produces fresh percepts. The boundary between agent and environment is defined not by physical anatomy, but by control: anything that the agent cannot arbitrarily control is part of the environment.

The PEAS Specification: When designing any AI system, engineers must first formalise its PEAS criteria: - Performance Measure: The objective numerical criterion used to evaluate the agent's success (e.g. passenger safety, travel time, fuel efficiency for an autonomous vehicle). - Environment: The external arena in which the agent operates (e.g. city streets, pedestrians, weather). - Actuators: The mechanism by which the agent exerts physical or digital action (e.g. accelerator, steering wheel, brakes). - Sensors: The intake hardware or data feeds through which the agent gathers observations (e.g. LiDAR, cameras, GPS).

The Agent Architectural Hierarchy: Agents evolve through increasing degrees of cognitive sophistication: 1. Simple Reflex Agents: Select actions based strictly on current percepts using condition-action rules (if car_in_front_braking then brake). 2. Model-Based Reflex Agents: Maintain an internal state to track aspects of the partially observable world that cannot be seen right now. 3. Goal-Based Agents: Combine internal state with explicit goal descriptions, using search and planning to evaluate which actions achieve the goal. 4. Utility-Based Agents: Weigh trade-offs using a continuous utility function U(s) to make rational decisions when goals conflict or outcomes are uncertain. 5. Learning Agents: Separate performance elements from learning elements, using an internal critic to adapt behaviour towards higher rewards.

In everyday terms

Think of an automated thermostat compared to an autonomous robotic vacuum cleaner. A simple thermostat is a simple reflex agent: if temperature < 19°C, turn on heating; if temperature > 22°C, turn off. It has no memory and no goals. An autonomous robotic vacuum is a model-based goal-directed agent: it cannot see through walls (partially observable), so it builds an internal occupancy grid map as it moves (internal state), plans paths to vacuum unvisited rooms (goal-based planning), and navigates around moving pets (dynamic environment) while avoiding battery exhaustion (utility management).

03 The maths

  1. Mathematical definition of an agent function

    f: \mathcal{P}^* \to \mathcal{A}

    Here $\mathcal{P}^*$ represents the set of all possible historical percept sequences up to the current time step, and $\mathcal{A}$ is the discrete or continuous action space. An agent program implements function $f$ on physical hardware.

  2. Principle of Maximum Expected Utility (Rationality)

    a^* = \arg\max_{a \in \mathcal{A}} \sum_{s'} P(s' \mid s, a) \, U(s')

    A rational agent selects an action that maximises expected utility, where $P(s' \mid s, a)$ is the probability that action $a$ in state $s$ leads to outcome state $s'$, and $U(s')$ is the utility of that state. Rationality evaluates expected success given current information, distinct from omniscience.

  3. Model-based state update recurrence

    s_t = g(s_{t-1}, a_{t-1}, p_t)

    Under partial observability, the agent's estimated internal state $s_t$ is updated recursively by function $g$ combining the previous state estimate $s_{t-1}$, the last action executed $a_{t-1}$, and the new incoming sensory percept $p_t$.

04 Key takeaways

  • An intelligent agent perceives its environment through sensors and acts upon it via actuators to maximise a performance measure.
  • Rationality is defined by expected success based on current knowledge and percept history, distinct from perfection or omniscience.
  • PEAS specifications (Performance, Environment, Actuators, Sensors) formalise the requirements for any AI agent.
  • Task environments are classified along key axes: observable, deterministic, episodic, static, discrete, and multi-agent.
  • Agent architectures scale from simple reflex and model-based systems to goal-directed, utility-maximising, and learning agents.

05 In code

python
class Environment:
    """A simple 1D discrete environment with two rooms: A and B."""
    def __init__(self):
        self.locations = {"A": "Dirty", "B": "Dirty"}
        self.agent_location = "A"

    def get_percept(self):
        """Returns (current_location, current_dirt_status)."""
        return (self.agent_location, self.locations[self.agent_location])

    def step(self, action):
        """Execute action: 'Suck', 'Right', 'Left', 'NoOp'."""
        if action == "Suck":
            self.locations[self.agent_location] = "Clean"
        elif action == "Right":
            self.agent_location = "B"
        elif action == "Left":
            self.agent_location = "A"

class ModelBasedReflexVacuumAgent:
    """
    Model-based reflex agent that maintains an internal belief state
    tracking the cleanliness of both rooms.
    """
    def __init__(self):
        self.model = {"A": "Unknown", "B": "Unknown"}
        self.history = []

    def select_action(self, percept):
        loc, status = percept
        # Update internal model with incoming percept
        self.model[loc] = status

        # Decision logic based on model state
        if status == "Dirty":
            action = "Suck"
        elif loc == "A" and self.model["B"] != "Clean":
            action = "Right"
        elif loc == "B" and self.model["A"] != "Clean":
            action = "Left"
        else:
            action = "NoOp"  # Both rooms known to be clean

        self.history.append((loc, status, action))
        return action

# Simulate Agent-Environment interaction loop
env = Environment()
agent = ModelBasedReflexVacuumAgent()

print("Initial Environment State:", env.locations)
print("Agent starts at location:", env.agent_location)
print("\nSimulation Steps:")

for step in range(1, 6):
    percept = env.get_percept()
    action = agent.select_action(percept)
    print(f"  Step {step}: Percept={percept} -> Internal Model={agent.model} -> Action='{action}'")
    env.step(action)
    if action == "NoOp":
        print("  Goal achieved: All rooms are clean. Agent halts.")
        break

print("\nFinal Environment State:", env.locations)

Common pitfalls

  • Confusing rationality with omniscience: An omniscient agent knows the actual outcome of its actions and is impossible in the real world. A rational agent makes the best possible decision given its current percepts and uncertainty.
  • Designing myopic performance measures: Rewarding an agent for sub-goals (e.g. rewarding a cleaning robot for sweeping dirt) can cause degenerate reward hacking (the robot repeatedly dumps dirt on the carpet to sweep it again). Measure desired end states.
  • Assuming fully observable environments: Designing an agent assuming complete state visibility causes catastrophic failure when sensors suffer occlusions, noise, or communication delays. Always incorporate belief states for partial observability.
  • Neglecting environmental dynamism: Assuming the environment remains frozen while the agent computes a plan fails in dynamic worlds where other agents move during planning. Bound planning latency.

06 Check yourself

Q1In Russell and Norvig's agent framework, what does the PEAS acronym stand for?

Why: PEAS formalises the complete problem specification for an intelligent agent: the numerical Performance measure to evaluate success, the external Environment, the physical Actuators for action, and the sensory Sensors for observation.

Q2What is the critical capability that distinguishes a Model-Based Reflex Agent from a Simple Reflex Agent?

Why: Simple reflex agents look only at the current percept, failing when the world is partially observable. Model-based agents maintain an internal state tracking past history and unobserved dynamics.

Q3How does a rational agent differ from an omniscient agent?

Why: Omniscience requires impossible foreknowledge of all future events. Rationality requires making the mathematically optimal choice that maximises expected utility given available sensory evidence and uncertainty.
