Bootstrap Aggregating and Extremely Randomised Trees

Bagging reduces variance by averaging unpruned decision trees trained on bootstrap samples, while Extra-Trees adds split-threshold randomisation for faster training and greater decorrelation.

01 The idea

Individual decision trees suffer from high variance: minor fluctuations in training data can completely alter their tree architecture. Bootstrap aggregating (bagging) stabilises predictions by growing an ensemble of deep, low-bias trees on independent bootstrap resamples and aggregating their votes. Extremely Randomised Trees (Extra-Trees) pushes this decorrelation further by choosing split cut-points completely at random, significantly accelerating training speed while suppressing variance on noisy data.

Imagine seeking a medical diagnosis from 50 physicians rather than relying on a single doctor. If all 50 studied the exact same textbooks and evaluated the patient under identical hospital protocols, they might share the same diagnostic blind spots. However, if each doctor trained at a different hospital on a distinct mix of case files (bootstrap sampling), their individual errors tend to cancel out. Averaging their assessments produces a consensus diagnosis that is far more reliable than any individual prognosis.

Bagging works because averaging $B$ independent, identically distributed estimators leaves bias unchanged while reducing variance by a factor of $1/B$. In practice, because all trees draw from the same finite training pool, their predictions remain positively correlated ($\rho > 0$). When trees are correlated, variance reduction hits an irreducible floor of $\rho \sigma^2$. Decorrelating individual trees is therefore the primary mechanism for improving ensemble performance.

Extra-Trees (Extremely Randomised Trees) tackles tree correlation directly. At each node, rather than scanning all possible threshold values to find the split that maximises the Gini impurity drop, Extra-Trees draws random cut-points from a uniform distribution for each candidate feature and selects the best among them. By abandoning exhaustive threshold searches, Extra-Trees trains drastically faster than standard Random Forests while producing highly diverse, decorrelated trees that often generalise better on noisy datasets.

In everyday terms

Bagging is like taking a consensus vote among independent analysts reviewing randomly shuffled case folders, while Extra-Trees speeds up the deliberation by forcing analysts to evaluate proposals against random benchmark hurdles.

02 Step by step

  1. Draw $B$ independent bootstrap datasets $\mathcal{D}_1, \dots, \mathcal{D}_B$ of size $n$ by sampling from the original dataset with replacement.
  2. For standard Bagging, grow deep, unpruned decision trees on each bootstrap resample using all available features.
  3. For Extra-Trees, train trees on the full dataset (or bootstrap draws) and, at each split node, draw split thresholds at random for each feature subset.
  4. Track Out-of-Bag (OOB) samples—the $\approx 36.8\\%$ of instances omitted from each bootstrap draw—to compute honest cross-validation metrics on the fly.
  5. Aggregate tree outputs: compute majority voting (or soft probability averages) for classification, and arithmetic means for regression.
  6. Evaluate ensemble convergence: verify that test error stabilises asymptotically as tree count $B$ grows without risk of overfitting.

03 The maths

  1. Variance reduction in an ensemble of correlated estimators

    $$\operatorname{Var}\big(\bar{f}(x)\big) = \rho \\, \sigma^2 + \frac{1 - \rho}{B} \\, \sigma^2$$

    $\sigma^2$ is the variance of a single tree, $B$ is the number of trees in the ensemble, and $\rho = \operatorname{Corr}(f_i, f_j)$ is the average pairwise correlation between trees. As $B \to \infty$, the second term vanishes, leaving the irreducible variance floor $\rho \sigma^2$. Extra-Trees achieves superior variance reduction by actively driving down $\rho$.

  2. Out-of-Bag (OOB) sample probability derivation

    $$P(\text{point } i \text{ is never selected in } n \text{ draws}) = \Big(1 - \frac{1}{n}\Big)^n \xrightarrow{n \to \infty} \frac{1}{e} \approx 0.3679$$

    For a sample of size $n$, each observation has probability $1 - 1/n$ of being omitted in a single draw. Compounding over $n$ independent draws with replacement shows that roughly $36.8\\%$ of data points remain unused per tree, providing a free validation set.

  3. Aggregation rules (hard voting vs soft voting)

    $$\hat{y}_{\text{hard}} = \operatorname{mode}\big(\\{f_b(x)\\}_{b=1}^B\big), \quad \hat{p}(k \mid x) = \frac{1}{B}\sum_{b=1}^B p_b(k \mid x)$$

    Hard voting selects the majority class label across all $B$ binary decision trees. Soft voting averages the continuous predicted class probability vectors across trees, yielding smoother decision boundaries and lower log-loss.

04 Key takeaways

  • Pure variance reduction: bagging cannot rectify high-bias models (e.g. linear models or depth-1 stumps); it requires flexible, low-bias base learners.
  • Out-of-Bag (OOB) scoring: provides an unbiased cross-validation estimate without requiring an explicit held-out test split.
  • Extra-Trees trades a small increase in individual tree bias for a significant reduction in ensemble variance and massive computational speed-ups.
  • Ensemble size immunity: bagging cannot overfit by simply increasing the number of trees $B$; error asymptotically plateaus.

05 In code

python
import numpy as np

np.random.seed(42)
n = 200
x = np.linspace(-3, 3, n)
y = (np.sin(x) > 0).astype(int)
noise = np.random.choice([0, 1], size=n, p=[0.85, 0.15])
y_noisy = np.bitwise_xor(y, noise)

B = 40
tree_preds = np.zeros((B, n))

for b in range(B):
    idx = np.random.choice(n, n, replace=True)
    best_gain, best_thresh, best_pred = -1, 0, (0, 1)
    for _ in range(6):
        th = np.random.uniform(-2.5, 2.5)
        left = idx[x[idx] < th]
        right = idx[x[idx] >= th]
        if len(left) < 5 or len(right) < 5: continue
        p1 = np.mean(y_noisy[left])
        p2 = np.mean(y_noisy[right])
        gain = len(left) * abs(p1 - 0.5) + len(right) * abs(p2 - 0.5)
        if gain > best_gain:
            best_gain = gain
            best_thresh = th
            best_pred = (int(p1 >= 0.5), int(p2 >= 0.5))
    tree_preds[b] = np.where(x < best_thresh, best_pred[0], best_pred[1])

single_acc = np.mean([np.mean(tree_preds[b] == y) for b in range(B)])
ensemble_pred = (np.mean(tree_preds, axis=0) >= 0.5).astype(int)
ens_acc = np.mean(ensemble_pred == y)

print("Single tree mean accuracy:", round(float(single_acc), 3))
print("Ensemble accuracy:", round(float(ens_acc), 3))
print("Theoretical OOB fraction 1/e:", round(float(1 / np.e), 3))

Common pitfalls

  • Bagging high-bias models: averaging multiple linear models or shallow trees produces essentially the same line, offering zero performance gain.
  • Data pre-processing leakage: scaling, normalisation, or feature selection performed on the full dataset before bootstrap resampling leaks information across folds.
  • Dominant feature masking: if one feature is overwhelmingly predictive, standard bagging trees will all select it at the root, maintaining high pairwise correlation $\rho$.
  • Applying standard bootstrap to temporal sequences: random sampling with replacement shuffles temporal order and destroys auto-regressive structure.

06 Check yourself

Q1Why does Bagging reduce prediction error when applied to deep decision trees?

Why: Deep decision trees have low bias but high variance; averaging across diverse bootstrap resamples cancels out random variance without inflating bias.

Q2What key algorithmic distinction differentiates Extra-Trees from standard Random Forests?

Why: At each node, Extra-Trees draws random cut-points for each candidate feature from a uniform distribution, avoiding the exhaustive search for the optimal Gini threshold.

Q3What is the theoretical proportion of unique training observations omitted from each bootstrap sample of size $n$ as $n \to \infty$?

Why: The probability that an item is never selected in $n$ independent draws with replacement converges to $(1 - 1/n)^n \to 1/e \approx 0.3679$.

Q4Why does Bagging fail to improve performance when applied to shallow linear regression models?

Why: Bagging is strictly a variance-reduction tool. Because linear models have low variance and high bias, averaging multiple linear fits leaves the error unchanged.
